## Note errors claimed by the writer — verdicts

09 Amortized Analysis
- p. 7 focus-array invariant with 0 and 1 exchanged: **confirmed.** Printed version fails at count 1 (F[0] = 1, it
  predicts 0) and count 2 (F[1] = 2, predicts 1); at count 0 too if B[−1] = 1. The page's version (B[j] = 1, B[j−1] = 0
  → F[j] = smallest k > j with B[k] = 0, else j; B[−1] = 0) holds in every state for n ≤ 10 (own check). The note's G/F
  table is right.
- p. 6 $4 tax argument incomplete: **confirmed** (imprecision, not a wrong bound). The note's fact (set→clear ≥ 2^i
  operations) pays the clearing flips only. The page's lemma (any two flips of P[i] or N[i] ≥ 2^i apart, first at
  operation ≥ 2^i) is true (own brute force, length 16, tight for i = 0, 1, 2, including clear→set) and its proof is
  correct: L = low-part value stays in [−(2^i−1), 2^i−1], changes by ±1 in operations that stop below i, an operation
  reaches position i only at L = ±(2^i−1) and leaves L = 0.
- Typos (p. 6 "G[j] = 1 − G[j]"; p. 7 table shows F[3..0]): **confirmed**. Further typos, not reflected: p. 3 "changes
  of not", "where is it collected", "there would at most two blocks"; p. 4 Σc = Σa − Φ_n drops Φ_0 (fine only with
  Φ_0 = 0, which the boxed version assumes); p. 6 "increment of decrement", "Thus, so".

10 Scapegoat and Splay Trees

- p. 6 floored ranks break the Access Lemma: **confirmed.** (8, 9, 13) → (13, 8, 4) is a valid roller-coaster
  (|A| = 4, |B| = 3, |C| = 0, |D| = 3), amortized 2 − 1 = 1 > 3·0. Whole splays too: own search found e.g. n = 58,
  size(x) = 34, 5 rotations, amortized 2 > 1 + 3(5 − 5) = 1. Real ranks: no violation.
- p. 6 "plus the drop in potential" → plus the increase: **confirmed.**
- p. 6 "at most 3 lg n − 1" → 1 + 3 lg n: **confirmed** (the sum gives 1 + 3⌊lg n⌋ − 3 rank(v); one-node tree 0 > −1).
- p. 7 zig-zag line 2 spurious r′(x): **confirmed** (line 3 equals line 2 without it).
- p. 7 roller-coaster "r(x) ≥ r(y)" → r(y) ≥ r(x): **confirmed** (y is x's parent; the step needs −r(y) ≤ −r(x)).
- p. 8 Pettie's bound O(mα*(n)) → O((m+n)α*(m+n)): **confirmed** — arXiv:0707.2160, Theorem 5.1 (read via WebFetch):
  "Starting with an n-node splay tree, the time required for m deque operations is O((m+n)α*(m+n))". The printed form
  fails for m ≪ n (the first operation can cost Θ(n)).
- Precisions: positive weights (zero weight → rank −∞): confirmed; static finger additive constant: confirmed (and the

## Changes
1. 09 §9.4: "finding that bit naively … takes Θ(log n) time in the worst case and O(1) amortized, exactly like the
   binary counter" → "… in the worst case — O(1) amortized for increments alone, but Θ(log n) per operation when
   increments and decrements alternate — exactly like the binary counter". Why: the sentence sits in the
   increment/decrement context; scanning for the lowest 1 costs k + 1 per operation when alternating between
   2^k − 1 and 2^k (new check in n09.py; Sources mentions it).
2. 10 §10.1 convention box: "changes no statement below" → "changes only constants below, not the arguments". Why:
   with null leaves counted, Imbal ≤ 2 after a build and each insertion changes Imbal by 2, height bound α lg(2n+1).
3. 10 §10.2: "paid for by a tax of $2 per deletion" → "$3". Why: old tree N ≤ 2m plus new tree ≤ m is ≤ 3m, not 2m.
   n10.py now counts old + new and checks ≤ 3 × deletions; page check added; Sources updated.
4. 10 §10.7 static optimality: O(log(T/t(x))) → O(1 + log(T/t(x))) in the theorem box (with "The note writes
   O(log T − log t(x)); … the constant term is needed"), total O(Σ t log(T/t)) → O(T + Σ t log(T/t)), and the Summary.
   Why: every access costs ≥ 1; t = (10^6, 1) gives Σ t lg(T/t) ≈ 21.4 ≪ T (new check). Same fix the writer made for
   the static finger bound. Sources precision updated.
5. 10 §10.7 "Stated without proof, with much harder proofs" + "(each bound up to an additive constant, as above)".
   Why: O(log D) and O(log dist(x, y)) are 0 for D = 1, x = y.
