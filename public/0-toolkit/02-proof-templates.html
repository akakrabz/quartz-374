How to use a template on the exam

  1. Recognize the problem type. The table at the end maps each type to its template, its rubric and a worked problem.
  2. Write the boilerplate first, word for word, with several blank lines in every case.
  3. Fill in the claim and the hypothesis — or the set F, the names of the machines, the states of M′ — in full, with variable names that do not clash.
  4. Only then think about the real work (the inductive step, the suffix z, the machine M′), and write it into the gaps.
  5. Reread every line for its reason: a definition, the hypothesis, a lemma, arithmetic. Never “clearly”.

The frame alone earns points: on the induction rubric, an arbitrary string, an explicit strong hypothesis and cases that cover every string are 5 of the 10 points, before any algebra. Templates marked assembled here have no boilerplate on their chapter page; they are built from that section’s recipe and worked examples, in its words where possible.

1. Induction on strings

Use it for any claim about every string — the Midterm 1 problem on a newly defined recursive string function, and identities such as (w∙x)R=xR∙wR.

Template — induction on strings

Let w be an arbitrary string.
Assume, for every string x with ∣x∣<∣w∣, that [the claim holds for x].
There are two cases to consider.
Case w=ε. … Therefore [the claim holds for w].
Case w=ax for some symbol a and string x. The induction hypothesis implies that [the claim holds for x]. … Therefore [the claim holds for w].
In both cases, [the claim holds for w]. ■

Variants (§1.4): peel the last symbol, w=xa; split w=a or w=u∙v with u, v non-empty (two base cases); or follow a definition with more cases, such as w=abx (base cases ε and every single symbol). If the hypothesis is applied with other values of the other arguments, it must say “for all” of them.

Source §1.3 · rubric induction, out of 10: 1 arbitrary object · 2 explicit strong hypothesis · 2 exhaustive cases · 1 base cases · 2 correct use of the hypothesis · 2 other details (details) · worked sorting a string

2. Writing up a regular expression or a grammar

Use it for “give a regular expression for L” (half of the Midterm 1 DFA problem) and “give a context-free grammar for L” (half of the non-regularity problem). Assembled here from the worked examples of §2.3 and §5.4, which all have this shape.

Template — writing up a regular expression or a grammar

Idea. [how a typical string of L decomposes: into blocks that a star can repeat; by nesting; at the first point where a count balances; or by cases]
Answer: [the expression — or the rules, one line per nonterminal]
In English: [what each piece of the expression stands for — or, for a grammar, a description of the language of every nonterminal that makes sense on its own]
Test: [ε and the shortest strings of L] are generated; [short strings outside L] are not.

Source §2.3 (Examples 1 and 2), §5.4 (Examples 1 and 2) · rubric regular expressions and grammars: 2 syntax · 8 correctness on exams, with deductions twice the homework ones — 2 for one mistake (often ε), 4 for a few wrong strings, all 8 for infinitely many; ∅ or Σ∗ earns nothing; ambiguity costs nothing; homework also needs the English (details) · worked 01 exactly twice (b), fooling set and grammar (b)

3. Induction on regular expressions

Use it for any claim about every regular expression — and, through an expression that represents it, about every regular language (§2.7).

Template — induction on regular expressions

Let R be an arbitrary regular expression.
Assume that every proper subexpression of R [has the property].
There are five cases to consider.
Case R=∅. … Therefore R [has the property].
Case R is a single string w (possibly ε). … Therefore R [has the property].
Case R=S+T for some regular expressions S and T. The induction hypothesis implies that S and T [have the property]. …
Case R=ST for some regular expressions S and T. The induction hypothesis implies that S and T [have the property]. …
Case R=S∗ for some regular expression S. The induction hypothesis implies that S [has the property]. …
In all five cases, R [has the property]. ■

Notes. Inducting on the size of R gives the same five cases. In the case R=S∗ the hypothesis covers S, not S∗. If a case gets stuck, strengthen the claim, as in Lemma 2.5.

Source §2.6 · rubric induction (details) · worked the proof of Lemma 2.4 in §2.6

4. Proving a DFA correct

Use it for “prove that your DFA accepts exactly L”. Midterm-1-style DFA problems need no proof, but the meanings of step 1 are exactly what mnemonic state names should convey.

Template — proving L(M)=L for a DFA

  1. Give each state q a meaning Pq​, and claim: ”δ∗(s,w)=q if and only if w has property Pq​.”
  2. Induct on w. Either peel the first symbol (w=ax) — then state the claim for every possible start state, as in §3.3 — or peel the last symbol (w=xa) and use δ∗(s,xa)=δ(δ∗(s,x),a), which needs the claim only from s.
  3. Conclude: w∈L(M)⟺δ∗(s,w)∈A⟺w has one of the accepting properties ⟺w∈L.

Source §3.3 · rubric induction (details) · worked the odd-number-of-1s proof in §3.3; state meanings in 01 exactly twice (a)

5. Describing a DFA

Use it for “give a DFA for L; no proof required” — with a regular expression for the same language, one of the five Midterm 1 problems. Assembled here from §3.2, §3.5 and the DFA rubric.

Template — describing a DFA

[A drawing: an arrow from nowhere into the start state, double circles on the accepting states, a label on every edge — or, in text, the start state, the accepting states and the complete transition table.]
“All missing transitions go to a dump state.” [Only if some are missing.]
States: [for each state, a mnemonic name and what it remembers about the input read so far — e.g. ”last1: no 11 yet, and the last symbol read was 1”].

Source §3.2 (a total transition function; the dump state), §3.5 (name each state after what it remembers) · rubric DFAs: 2 unambiguous, complete description · 6 correctness (on exams) · 2 mnemonic state names; an NFA where a DFA was asked earns half credit (details) · worked 01 exactly twice (a)

6. Writing up a product construction

Use it for a DFA for ”L1​ and L2​”, ”L1​ or L2​”, ”L1​ but not L2​” — any boolean combination of languages that have simple DFAs.

Template — writing up a product construction

Let M1​=(Σ,Q1​,s1​,A1​,δ1​) be a DFA for L1​: [its states and what each means, start, accepting states, transitions — or a drawing].
Let M2​=(Σ,Q2​,s2​,A2​,δ2​) be a DFA for L2​: [likewise].
Define M:=(Σ, Q1​×Q2​, (s1​,s2​), A, δ) with δ((p,q),a):=(δ1​(p,a),δ2​(q,a)),
and with A := [the accepting pairs from the table].
By Lemma 3.1, M accepts w iff [the boolean combination], so L(M)= [the target language].

Source §3.6 (the definition, the table of accepting sets, Lemma 3.1, how it is graded); the template is the one on product construction · rubric DFAs — for a product, the complete description defines each factor completely, then the product’s states, start state, transitions and accepting states (details) · worked a product, written formally

7. Fooling-set proof

Use it for “prove that L is not regular” — on Midterm 1, paired with a grammar for the same language.

Template — fooling-set proof (as in Lemma 3.6)

Let F= [an explicit infinite set, e.g. 0∗].
Let x and y be arbitrary distinct strings in F.
The definition of F implies x= […] and y= […] for some integers i=j.
Let z= [a suffix that may depend on i and j].
Then xz= […] ∈L, because […].
And yz= […] ∈/L, because […].
So z distinguishes x and y. We conclude that F is a fooling set for L.
Because F is infinite, L cannot be regular. ■

Choosing F. A simple language with one star and no union — 0∗, 10∗1, (01)∗ — or L itself; the standard cases are tabulated in §3.8. Keep i=j: "i<j" needs “without loss of generality” and a symmetric argument.

Source §3.8 · rubric fooling sets: 4 an explicit infinite set that really is a fooling set (a finite set earns nothing) · 2 explicit suffix z · 2 one of xz, yz in L · 2 the other not (details) · worked fooling set and grammar (a)

8. Non-regularity by closure

Use it for a short non-regularity proof when the problem does not prescribe a method, and for true/false justifications. Assembled here from “the closure alternative” in §3.8.

Template — non-regularity by closure

Suppose for the sake of argument that L is regular.
The language R= [e.g. 0∗1∗] is regular, because [it is described by a regular expression].
Regular languages are closed under [intersection, complement, …], so L′= [e.g. L∩R] is regular too.
But L′= [a language known to be non-regular, e.g. {0n1n∣n≥0}], which is not regular by [Lemma 3.6, or a fooling set].
This contradiction shows that L is not regular. ■

Only in this direction: if L∩R turns out to be regular, nothing follows about L.

Source §3.8, closure properties · rubric none of its own — a problem that asks for a fooling set wants a fooling set · worked the closure alternative in fooling set and grammar

9. Language transformation

Use it for “prove that f(L) is regular for every regular language L” — the two-part Midterm 1 problem.

Template — regular language transformation

Let M=(Σ,Q,s,A,δ) be a DFA that accepts L.
We construct an NFA M′=(Σ,Q′,s′,A′,δ′) with ε-transitions that accepts [the new language].
In English: M′ remembers [each component of its state, and what it means], guesses [what, and when], and accepts when […].
Formally: Q′= […], s′= […], A′= […],
δ′(q′,a)= […] for every state q′ and every symbol a,
δ′(q′,ε)= […] for every state q′ (write ∅ where there are none).
Why: M′ can be in state […] after reading x if and only if […]; so it accepts exactly [the new language].

Which kind of language? For “strings whose transform is in L”, {w∣f(w)∈L}, usually a DFA that simulates M on f(w) while reading w. For “transforms of strings in L”, {f(w)∣w∈L}, usually an NFA that simulates M on a guessed preimage, with ε-transitions guessing the symbols that f deleted.

Source §4.9 (Lemmas 4.4 and 4.5), where this template is copied from; a shorter version is on language transformations · rubric transformations: 2 formal, complete description of M′ built from an arbitrary DFA M (say DFA or NFA; list the ε-transitions) · 2 English explanation of the states and accepting states · 6 correctness — 1 states, 1 start state, 1 accepting states, 3 transitions; test L=∅, {ε}, 1∗, Σ∗ (details) · worked insert and delete a 1

10. Proving what a grammar generates

Use it for “prove that G generates exactly L” — and for convincing yourself that a grammar you designed is right.

Template — proving L(G)=L

  1. State the language of every nonterminal. If nonterminals use each other, the claims must be proved together, in one induction (mutual induction, §5.3).
  2. L⊆L(G). Let w∈L be arbitrary; assume every shorter string of L is generated (or induct on a parameter, like n in Lemma 5.1). Split w into pieces that match the right side of one rule, apply the hypothesis to the pieces, and assemble a derivation S⇝ω⇝∗w.
  3. L(G)⊆L. Let w∈L(G) be arbitrary and fix a derivation of w; assume every shorter generated string is in L. Write one case per rule the derivation can start with; in each case w splits into pieces derived from the symbols of the right side, the hypothesis applies to each piece, and the pieces together satisfy the definition of L.
  4. If the grammar has ε-rules, fix a shortest derivation of w (§5.3, “Careful with those epsilons”), or induct on the length of the derivation instead of the string.

Source §5.3 (Lemmas 5.1–5.4; careful with those epsilons; mutual induction) · rubric two inductions, each graded like an induction (details) · worked a grammar proof

11. Describing a Turing machine

Chapter 6 gives a recipe rather than a boilerplate. A design answer should contain:

  1. the algorithm in English, phase by phase — scan, mark, walk back;
  2. a transition table or diagram that implements exactly that description, with mnemonic state names and a one-line meaning for every state;
  3. the sentence “missing transitions reject”;
  4. a trace on ε, on a short string in the language, and on a near-miss.

Source §6.3 (the design recipe and “Writing a Turing machine on an exam”) · rubric none of its own; the DFA rubric’s demands — a complete, unambiguous description and mnemonic names — are the guide · worked the copy language

12. Undecidability by diagonalization

Use it for self-referential languages — defined by what a machine does with its own encoding — when no known undecidable language is easier to reduce from.

Template — undecidability by diagonalization

Suppose for the sake of argument that some Turing machine Dec decides L.
Build a new machine Wrap from Dec: [swap Dec‘s accept and reject states / redirect its accepting transitions to a looping state / …].
Then for every Turing machine M: Wrap [accepts, or halts on] ⟨M⟩ if and only if M [does not …] ⟨M⟩.
In particular, take M=Wrap.
If Wrap [accepts] ⟨Wrap⟩, then by the line above Wrap does not [accept] ⟨Wrap⟩ — a contradiction.
If Wrap does not [accept] ⟨Wrap⟩, then by the line above Wrap [accepts] ⟨Wrap⟩ — a contradiction.
So Dec does not exist, and L is undecidable. ■

Against an acceptor (to prove L not acceptable, as in Theorem 9): assume only that Dec accepts L, turn its rejections into endless loops (Lemma 1), and derive ”Wrap halts on ⟨Wrap⟩ if and only if it diverges on ⟨Wrap⟩”.

Source §7.7 (the template, Theorems 7–9), §7.5 (Theorem 6, the model argument) · rubric diagonalization: 4 wrapper machine · 6 contradiction, 3 per case (details) · worked the proof of Theorem 6 in §7.5; a doubled input on diagonalization

13. Undecidability by reduction

Use it for “prove that L is undecidable” when L is not self-referential: reduce from Accept, Halt, or any language already known to be undecidable.

Template — undecidability by reduction from Accept

Suppose for the sake of argument that some Turing machine DecideL decides L.
Consider the following machine DecideAccept. Given ⟨M,w⟩, it writes the encoding ⟨M′⟩ of the machine
M′(x): [for example: ignore x; run M on w; then …]
and then runs DecideL on ⟨M′⟩ and returns its answer.
⇒ Suppose M accepts w. Then M′ […], so ⟨M′⟩∈L. So DecideL accepts ⟨M′⟩, and DecideAccept accepts ⟨M,w⟩.
⇐ Suppose M does not accept w — it rejects or diverges. Then M′ […], so ⟨M′⟩∈/L. So DecideL rejects ⟨M′⟩, and DecideAccept rejects ⟨M,w⟩.
In both cases DecideAccept is correct, and it always halts. So DecideAccept decides Accept, which is impossible.
We conclude that DecideL does not exist: L is undecidable. ■

Opposite answers. If ⟨M′⟩∈L exactly when M does not accept w, let DecideAccept return the opposite of DecideL‘s answer, as in the proof of Theorem 13 (§7.10).

Source §7.9 · rubric reduction: 4 the reduction (the new decider and M′, in the right direction) · 3 for each direction (details) · worked AtLeastTwo (a); Theorem 13 in §7.10

14. Undecidability by Rice’s theorem

Use it for {⟨M⟩∣Accept(M) has some property} — a property of the language M accepts, not of M or of its behavior. Assembled here from the recipe “Using Rice’s theorem” in §7.11.

Template — undecidability by Rice's theorem

Let L:= [an explicit set of languages], so that the language in question is AcceptIn(L)={⟨M⟩∣Accept(M)∈L}. [Check: two machines with the same language are both in it or both out.]
Let Y:= [a concrete machine, e.g. MAccept​]. Then Accept(Y)= […] ∈L, because […].
Let N:= [a concrete machine, e.g. MReject​]. Then Accept(N)= […] ∈/L, because […].
By Rice’s theorem, AcceptIn(L) is undecidable. ■

Variants. If membership depends on Reject(M), Halt(M) or Diverge(M), or on the language M decides, use RejectIn, HaltIn, DivergeIn or DecideIn throughout, and describe Y and N by that language. Not for behavior (ThisIsSparta is decidable), self-reference (RevAccept needs a reduction) or trivial properties — and Rice’s theorem never proves “not acceptable”.

Source §7.11 (the recipe, Corollary 15, the variants) · rubric Rice: 4 a machine whose language has the property · 4 a machine whose language does not · 2 details, including the right variant of the theorem (details) · worked AtLeastTwo (b); the witnesses of Corollary 15 in §7.11

15. Acceptable by dovetailing

Use it for “prove that L is acceptable” when membership of ⟨M⟩ is witnessed by finitely many accepting runs of M — "Accept(M)=∅", ”M accepts at least two strings”. Assembled here from §7.10 and §9.5.

Template — acceptable by dovetailing

The following machine accepts L. Given ⟨M⟩ [if the input encodes no machine, reject]:
for t=1,2,3,…, run M for t steps on each of the first t strings of Σ∗ [in shortlex order], and accept as soon as [the runs so far show membership, e.g. two different strings have been accepted].
If ⟨M⟩∈L: [the witnesses x1​,…,xk​] are each accepted within some s steps, so in round t= [the largest of s and the positions of x1​,…,xk​] all of them run long enough, and the machine accepts.
If ⟨M⟩∈/L: no round ever [shows membership], so the machine never accepts — it runs forever, which an acceptor may do. ■

Why not one string at a time? If M runs forever on the first string tried, the search never reaches the others. Simpler cases need no dovetailing: SelfAccept is accepted by running U on ⟨M,⟨M⟩⟩ (Theorem 10).

Source §7.10 (an acceptor for the complement of NeverAccept), §9.5 (dovetailing) · rubric none of its own · worked AtLeastTwo (d)

16. Not acceptable, by Lemma 5

Use it for “prove that L is not acceptable” when its complement is acceptable but undecidable — NeverAccept, Diverge, the complement of SelfAccept. Assembled here from Lemma 5 and its consequence in §7.3.

Template — not acceptable, by Lemma 5

The complement L=Σ∗∖L is acceptable: [a machine that accepts it — run U, or dovetail].
L is undecidable: [by diagonalization, a reduction or Rice’s theorem — or because L is undecidable, and decidable languages are closed under complement].
If L were acceptable too, the acceptable language L would have an acceptable complement, so it would be decidable by Lemma 5 — a contradiction.
So L is not acceptable. ■

Strings that encode no machine form a decidable set; counting them in L or in L changes nothing. Other routes: diagonalization against an acceptor (Theorem 9), or Lemma 17 for a property that is not monotone (§7.12).

Source §7.3 · rubric none of its own · worked AtLeastTwo (d); NeverAccept in §7.10
