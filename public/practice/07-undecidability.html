Every concrete machine in the solutions has been checked by a script. Conventions as in §7.1: ”M does not accept w” means that M rejects w or diverges on it (a crash counts as diverging), and L=Σ∗∖L. MAccept​, MReject​ and MDiverge​ are the machines of §7.11 that accept at once, reject at once, and move right forever.

Easy

7.1 Closure facts, true or false

Easy · true or false · closure of decidable languages · acceptable vs decidable

All languages are over a fixed alphabet Σ. Answer each statement Yes (always true) or No, with a one-sentence reason; for a No, give a counterexample.

(a) If L is decidable, then L is decidable.

(b) If L is acceptable, then every subset of L is acceptable.

(c) If L1​ and L2​ are decidable, then their concatenation L1​∙L2​ is decidable.

(d) If L1​∪L2​ is decidable, then L1​ and L2​ are both decidable.

(e) If L and L are both acceptable, then L is decidable.

(f) If L is undecidable and L′ is decidable, then L∖L′ is undecidable.

Source: original.

Hint

Σ∗ and ∅ are decidable, Halt is acceptable but undecidable, and SelfDiverge is not even acceptable. Most of the No’s need nothing more.

Solution

(a) Yes. Swap the accept and reject states of a decider for L (Lemma 1(a)); the new machine still halts on every input, and it decides L.

(b) No. Σ∗ is acceptable (even decidable), but its subset SelfDiverge is not acceptable (Theorem 9).

(c) Yes. Given w, try all ∣w∣+1 ways to write w=xy, running the decider for L1​ on x and the decider for L2​ on y, and accept if some split passes both tests; there are finitely many splits and every test halts, so this machine halts on every input.

(d) No. Halt∪Halt=Σ∗ is decidable, but Halt is not (Theorem 12).

(e) Yes. This is Lemma 5: run an acceptor for L and one for L in parallel on w; exactly one of them eventually accepts, and which one tells you whether w∈L.

(f) No. Take L′=Σ∗: then L∖L′=∅, which is decidable whatever L is. (Corollary 3 runs the other way: if L′ is decidable and L∖L′ is undecidable, then L is undecidable.)

Watch out: “try every split” in (c) works because each test halts. For two acceptable languages the concatenation is still acceptable, but the splits must be tested in parallel, one step at a time — a test that runs forever would block the rest.

Answer. (a) Yes (b) No (c) Yes (d) No (e) Yes (f) No.

7.2 Decidable, acceptable, or neither

Easy · true or false · acceptable vs decidable · Rice's theorem

Answer each statement Yes or No, with a one-sentence reason. Then put each language in one of three classes: decidable, acceptable but undecidable, or not acceptable.

(a) {⟨M⟩∣M accepts at least one string} is acceptable.

(b) {⟨M⟩∣M accepts no string} is acceptable.

(c) By Rice’s theorem, {⟨M⟩∣some transition of M writes the symbol #} is undecidable.

(d) {⟨M,w⟩∣M halts on w within ∣w∣2 steps} is decidable.

(e) {⟨M⟩∣M halts on every input of length 3} is decidable.

(f) {⟨M⟩∣Accept(M) is finite} is undecidable.

Source: original.

Hint

An acceptor only has to say yes on the yes-instances; it may run forever on the others. So “acceptable” asks: is there a search that succeeds exactly when the answer is yes? For a language that is not acceptable, use Lemma 5 or Corollary 18.

Solution

(a) Yes. Dovetail: in round t=1,2,3,…, run M for t steps on each of the first t strings of Σ∗, and accept as soon as one of these runs accepts; if M accepts the ith string within s steps, this happens by round max(i,s). Acceptable but undecidable — undecidable by Rice’s theorem with Y=MAccept​ and N=MReject​.

(b) No. This is NeverAccept. Its complement — the language of (a) together with the strings that encode no machine — is acceptable (Lemma 4), so if NeverAccept were acceptable as well, Lemma 5 would make it decidable, contradicting Theorem 13. Not acceptable.

(c) No. Whether some transition writes # can be read off the encoding ⟨M⟩ by scanning its list of transitions, so the language is decidable. Rice’s theorem does not apply because this is a property of the transition table, not of Accept(M): adding a new state that is never entered, with a transition that writes #, changes membership but not the language.

(d) Yes. Simulate M on w for ∣w∣2 steps with the universal machine, counting steps; accept if M has halted, otherwise reject. Decidable.

(e) No. Run M on each of the finitely many inputs of length 3, one after another, and accept if every run halts: this accepts the language, but it runs forever when some run does. The language is undecidable by Rice’s halting theorem, with L={L∣L contains every string of length 3}, Y=MAccept​ (Halt(Y)=Σ∗∈L) and N=MDiverge​ (Halt(N)=∅∈/L). Acceptable but undecidable.

(f) Yes. Rice’s theorem with L={L∣L is finite}, Y=MReject​ (it accepts ∅, which is finite) and N=MAccept​ (it accepts Σ∗, which is not). In fact this language is not acceptable (Corollary 18(a)), and neither is {⟨M⟩∣Accept(M) is infinite} (Corollary 18(b)).

the language: {⟨M⟩∣…}class
(a)M accepts at least one stringacceptable but undecidable
(b)M accepts no stringnot acceptable
(c)some transition of M writes #decidable
(d)M halts on w within ∣w∣2 steps (pairs ⟨M,w⟩)decidable
(e)M halts on every input of length 3acceptable but undecidable
(f)Accept(M) is finitenot acceptable

Watch out: in (b), “the complement of NeverAccept is acceptable” is not a contradiction by itself — Lemma 5 needs both a language and its complement to be acceptable before it says anything. The argument is: the complement is acceptable and NeverAccept is undecidable, so NeverAccept cannot be acceptable.

Answer. (a) Yes (b) No (c) No (d) Yes (e) No (f) Yes; classes as in the table.

7.3 A reduction that proves nothing

Easy · find the error · reductions

Let EvenAccept:={⟨M⟩∣M accepts at least one string of even length}. A student writes:

“Claim: EvenAccept is undecidable. Proof: Suppose some machine DecideAccept decides Accept. Given ⟨M⟩, build the machine M′ that ignores its own input and runs M on all strings of even length in parallel (dovetailing), accepting as soon as M accepts one of them. Then M′ accepts ε if and only if ⟨M⟩∈EvenAccept. So the machine that writes ⟨M′,ε⟩ and runs DecideAccept on it decides EvenAccept. Since Accept is undecidable, EvenAccept is undecidable.”

Every step of the construction is correct. What is wrong with the proof? Fix it.

Source: original.

Hint

Which language does the student’s argument assume can be decided, and which one does it then decide? Compare with the boxed rule in §7.9.

Solution

The slip: the reduction goes in the wrong direction. The student decides EvenAccept using a decider for Accept — a reduction from EvenAccept to Accept. That proves only “if Accept were decidable, EvenAccept would be decidable too”, which says nothing, because Accept is not decidable. The same kind of argument “reduces” decidable languages to Accept — for example {⟨M⟩∣M has three states} — so it cannot prove undecidability.

The fix: reduce Accept to EvenAccept. Suppose for the sake of argument that DecideEven decides EvenAccept. Build DecideAccept: given ⟨M,w⟩, write the encoding of the machine

Mw​(x): ignore x; run M on w; accept if M accepts,

then run DecideEven on ⟨Mw​⟩ and return its answer.

  • If M accepts w, then Mw​ accepts every string, in particular ε, which has even length; so ⟨Mw​⟩∈EvenAccept, DecideEven accepts, and DecideAccept accepts.
  • If M does not accept w (it rejects or runs forever), then Mw​ accepts no string at all; so ⟨Mw​⟩∈/EvenAccept, DecideEven rejects, and DecideAccept rejects.

So DecideAccept decides Accept, which is impossible; hence DecideEven does not exist. (Rice’s theorem gives the same in one line: L={L∣L contains a string of even length}, Y=MAccept​, N=MReject​.)

What the student did prove. Running the universal machine on ⟨M′,ε⟩ accepts EvenAccept. So EvenAccept is acceptable — and, by the fix, undecidable.

Answer. The reduction goes from EvenAccept to Accept, which proves nothing; reduce Accept to EvenAccept instead, with Mw​ (“ignore the input, run M on w”).

Medium

7.4 Rice with the right variant

Medium · Rice's theorem

Prove that each language is undecidable, using Rice’s theorem or one of its variants for rejection, halting, divergence or deciding (§7.11). For each, write the language as AcceptIn(L), RejectIn(L), HaltIn(L), … with an explicit property L, and give concrete machines Y and N. Machines have input alphabet {0,1}.

(a) RevClosed:={⟨M⟩∣for every string w, if M accepts w then M accepts wR}.

(b) RejectOne:={⟨M⟩∣M rejects exactly one string}.

(c) AcceptEqualsReject:={⟨M⟩∣Accept(M)=Reject(M)}.

Source: original.

Hint

(a) needs a machine whose language contains some string but not its reversal. In (b), whether ⟨M⟩ belongs depends on Reject(M): two machines with the same Accept(M) can disagree. In (c), what is Accept(M)∩Reject(M)?

Solution

Idea. Rice’s theorem applies to a property of one of the four languages of a machine. First find which one decides membership, then exhibit one machine whose language has the property and one whose language does not.

(a) Rice’s theorem. RevClosed=AcceptIn(La​) with La​={L∣wR∈L for every w∈L}: membership depends only on Accept(M).

  • Y=MAccept​: Accept(Y)=Σ∗ contains every reversal, so it is in La​.
  • N accepts exactly {01}: δ(start,0)=(saw0,0,+1), δ(saw0,1)=(saw01,1,+1), δ(saw01,□)=(accept,□,+1), all other transitions reject. 01∈Accept(N) but 10∈/Accept(N), so Accept(N)∈/La​.

By Rice’s theorem, RevClosed is undecidable.

(b) Rice’s rejection theorem. RejectOne=RejectIn(Lb​) with Lb​={L∣L has exactly one element}.

  • Y: δ(start,□)=(reject,□,+1) and δ(start,a)=(accept,a,+1) for a∈{0,1}. It rejects ε and accepts everything else: Reject(Y)={ε}∈Lb​.
  • N=MAccept​: Reject(N)=∅, which has no element, so it is not in Lb​.

By Rice’s rejection theorem, RejectOne is undecidable. The plain (accepting) version does not fit: change Y to move right forever on □ instead of rejecting. The new machine accepts the same strings as Y, but rejects none, so it is not in RejectOne — membership is not determined by Accept(M).

(c) Rice’s halting theorem. No machine both accepts and rejects the same string, so Accept(M)∩Reject(M)=∅, and the two sets can be equal only if both are empty — that is, if M halts on no input. So AcceptEqualsReject=HaltIn({∅}).

  • Y=MDiverge​: Halt(Y)=∅.
  • N=MAccept​: Halt(N)=Σ∗=∅.

By Rice’s halting theorem, AcceptEqualsReject is undecidable.

Check. N on 01 goes start→saw0→saw01 and accepts at the blank; on 10, start reads 1 and has no transition, so it rejects; on 011, saw01 reads 1 and rejects. Y in (b) reads □ at once on ε and rejects, and accepts every other input in one step. In (c), MDiverge​ accepts and rejects nothing (∅=∅), while MAccept​ accepts Σ∗=∅.

Watch out: the rubric gives 2 of the 10 points for the details, including the right variant. Citing the plain theorem in (b) or (c) — and describing Y and N by the strings they accept — proves nothing there, because membership is not decided by Accept(M).

Answer. (a) AcceptIn(La​), Y=MAccept​, N accepts exactly {01}. (b) RejectIn({L:∣L∣=1}), Y rejects exactly ε, N=MAccept​. (c) HaltIn({∅}), Y=MDiverge​, N=MAccept​.

7.5 Two behaviors, two answers

Medium · TM behavior · reductions

Decide whether each language is decidable, and prove your answer. Machines have input alphabet {0,1} and any finite tape alphabet; # is a fixed symbol that may or may not belong to a machine’s tape alphabet.

(a) Reach374:={⟨M,w⟩∣M, run on input w, at some time has its head on cell 374}.

(b) WritesHash:={⟨M,w⟩∣M, run on input w, writes the symbol # in some step}.

Why does Rice’s theorem settle neither question?

Source: original.

Hint

(a) A run that never reaches cell 374 lives inside a box of 374 cells. How many different configurations fit in that box? (b) Modify M so that it writes # exactly when it is about to accept — and think about what happens if M‘s step into accept moves left from cell 0.

Solution

Idea. A behavior that confines the machine to finitely many configurations is decidable by bounded simulation; a behavior that a simulation can avoid, and then perform on purpose, is undecidable by reduction (§7.13).

(a) Decidable. Let Q and Γ be M‘s states and tape alphabet. As long as the head stays among cells 0,…,373, the cells from 374 on are never read or written, so they keep their initial contents, and the configuration is determined by the state, the head position, and the contents of cells 0,…,373: at most

N:=∣Q∣⋅374⋅∣Γ∣374

possibilities. The decider simulates M on w for up to N steps. It accepts as soon as the head is on cell 374, and rejects if M halts or crashes first. If N steps pass with neither, it rejects: two of the N+1 configurations seen so far are equal (pigeonhole), and since M is deterministic, the run cycles through the same configurations forever and never reaches cell 374. The decider halts after at most N simulated steps and is right in all three cases.

(b) Undecidable, by a reduction from Accept. Suppose for the sake of argument that DecideHash decides WritesHash. Build DecideAccept: given ⟨M,w⟩, it modifies M‘s transition table into a machine M′:

  1. if # is in M‘s tape alphabet, rename it to a new symbol everywhere in the table;
  2. add a new state fin, and redirect every transition into accept to fin instead (same symbol written, same move);
  3. for every tape symbol c, let δ′(fin,c)=(accept,#,+1).

Then it runs DecideHash on ⟨M′,w⟩ and returns its answer. Editing a finite table always terminates, and DecideHash halts, so DecideAccept halts on every input.

  • Suppose M accepts w. M′ makes exactly the same steps as M until M would enter accept; it enters fin instead and then writes #. So ⟨M′,w⟩∈WritesHash, DecideHash accepts, and DecideAccept accepts.
  • Suppose M does not accept w: it rejects, crashes or runs forever. M′ does the same and never enters fin, and step 1 guarantees that it writes no # along the way. So ⟨M′,w⟩∈/WritesHash, DecideHash rejects, and DecideAccept rejects.

So DecideAccept decides Accept, which is impossible; WritesHash is undecidable. (It is acceptable: simulate and wait for a #.)

Rice does not apply to either language, because both are about behavior, not about Accept(M). MAccept​ accepts every input after one step, never reaching cell 374 and never writing #; a machine that first walks 374 cells to the right, writing # as it goes, and then accepts, has the same language and belongs to both.

Check. Try the decider of (a) on three machines. MAccept​ moves to cell 1 and accepts: reject. A machine that moves right forever in one state is on cell 374 after 374 steps: accept. A machine that, on the empty input, steps right onto a blank and back left forever repeats its first configuration after two steps: reject, since it will never get further. In (b), if M accepts w after t steps, M′ writes # in step t+1; if M rejects w after t steps, so does M′, without writing #.

Watch out: it is tempting to write # in the step into accept itself. If that step moves left from cell 0, M crashes instead of accepting — yet the # has been written. The extra state fin, which always moves right, avoids this (the same trick is behind Theorem 20).

Answer. (a) Decidable: simulate ∣Q∣⋅374⋅∣Γ∣374 steps; a run that has not reached cell 374 by then has repeated a configuration and never will. (b) Undecidable: from M build M′ that writes # (in one extra step) exactly when M accepts w. Rice’s theorem is about Accept(M), and these are properties of the run.

7.6 Do two machines share a string

Medium · acceptable vs decidable · reductions

Let Overlap:={⟨M1​⟩⟨M2​⟩∣Accept(M1​)∩Accept(M2​)=∅}: some string is accepted by both machines.

(a) Show that Overlap is acceptable: describe an acceptor, and explain why “for each string x in turn, run M1​ on x and then M2​ on x” does not work.

(b) Show that Overlap is undecidable.

(c) Is Disjoint:={⟨M1​⟩⟨M2​⟩∣Accept(M1​)∩Accept(M2​)=∅} acceptable? Is it decidable?

Source: original.

Hint

(a) Interleave both the strings and the step counts. (b) Fix one of the two machines so that Overlap turns into a language you already know. (c) Lemma 5.

Solution

Idea. A yes-instance has a finite certificate — a string x and two accepting runs — so a patient search finds it; that makes Overlap acceptable. Fixing M2​=MAccept​ turns it into ”M1​ accepts something”, which is undecidable, and then Lemma 5 rules out the complement.

(a) An acceptor (dovetailing). On input ⟨M1​⟩⟨M2​⟩ (reject anything else): for t=1,2,3,…, for each of the first t strings x of Σ∗, run M1​ on x for t steps and M2​ on x for t steps; if both accept, accept. If the ith string is accepted by M1​ within s1​ steps and by M2​ within s2​ steps, the acceptor accepts by round max(i,s1​,s2​). If no string is accepted by both, it runs forever — which an acceptor may do. So it accepts exactly Overlap.

The serial search gets stuck on the first string on which M1​ or M2​ runs forever. Let M1​ accept 0, reject 1, and run forever on ε, and let M2​=MAccept​. The pair is in Overlap, because both machines accept 0, but the serial search runs M1​ on ε forever and never gets to 0. Dovetailing accepts in round 2.

(b) Undecidable, by a reduction from NeverAccept (Theorem 13). Suppose for the sake of argument that DecideOverlap decides Overlap. Build DecideNA: given a string, reject it if it is not an encoding ⟨M⟩; otherwise run DecideOverlap on ⟨M⟩⟨MAccept​⟩ and return the opposite answer. Since Accept(M)∩Σ∗=Accept(M):

  • If Accept(M)=∅, the intersection is empty, DecideOverlap rejects, and DecideNA accepts ⟨M⟩.
  • If M accepts some string x, then MAccept​ accepts x too, DecideOverlap accepts, and DecideNA rejects ⟨M⟩.

So DecideNA decides NeverAccept, which is impossible; Overlap is undecidable.

(c) Not acceptable, so not decidable. The complement of Overlap is Disjoint together with the strings that do not have the form ⟨M1​⟩⟨M2​⟩, which form a decidable set. If Disjoint were acceptable, then so would be this union (Lemma 4), so both Overlap (by (a)) and its complement would be acceptable, and Lemma 5 would make Overlap decidable — contradicting (b).

Check. On the pair in (a), round 1 runs both machines on ε for one step (M1​ is still running); round 2 runs them on ε and 0 for two steps each, and both accept 0 in their first step: accept. The serial search, in contrast, never gets past ε.

Answer. (a) Dovetail over strings and step counts; the serial search hangs on a string where M1​ or M2​ runs forever. (b) Undecidable: ⟨M⟩⟨MAccept​⟩∈Overlap exactly when Accept(M)=∅. (c) Disjoint is not acceptable (Lemma 5), hence not decidable.

Hard

7.7 Accepts epsilon, rejects itself

Hard · diagonalization · acceptable vs decidable

Let EpsSelfReject:={⟨M⟩∣M accepts ε and M rejects ⟨M⟩}.

(a) Prove that EpsSelfReject is undecidable by diagonalization (not by a reduction).

(b) Prove that EpsSelfReject is acceptable.

(c) Is the complement of EpsSelfReject acceptable?

(d) Explain why Rice’s theorem cannot be used here: give two machines that accept the same language, exactly one of them in EpsSelfReject, and two machines that reject the same language, exactly one of them in EpsSelfReject.

Source: original.

Hint

Build the wrapper so that it certainly accepts ε. On encodings, should it copy the decider’s answer or flip it? Try both on the wrapper’s own encoding, and keep the one that gives a contradiction in both cases.

Solution

Idea. Run a wrapper built from the hypothetical decider on its own encoding. The wrapper must make the side condition “accepts ε” true for itself, and on encodings it must copy the decider’s answer — the language is about rejecting, as in Theorem 6.

(a) Suppose for the sake of argument that some Turing machine Dec decides EpsSelfReject. Build the machine Wrap: on input x,

  • if x=ε, accept;
  • if x=⟨M⟩ for some machine M, run Dec on x and return its answer (accept if Dec accepts, reject if Dec rejects);
  • otherwise reject.

Wrap halts on every input, because Dec does, and it accepts ε. So ⟨Wrap⟩∈EpsSelfReject if and only if Wrap rejects ⟨Wrap⟩. Run Dec on ⟨Wrap⟩; it halts, so there are two cases.

  • If Dec accepts ⟨Wrap⟩, then Wrap accepts ⟨Wrap⟩, so Wrap does not reject ⟨Wrap⟩, so ⟨Wrap⟩∈/EpsSelfReject — yet Dec accepted it. Contradiction.
  • If Dec rejects ⟨Wrap⟩, then Wrap rejects ⟨Wrap⟩, and it accepts ε, so ⟨Wrap⟩∈EpsSelfReject — yet Dec rejected it. Contradiction.

Both cases are impossible, so Dec does not exist: EpsSelfReject is undecidable. ■

(b) EpsSelfReject=AccEps∩SelfReject, where AccEps:={⟨M⟩∣M accepts ε}. AccEps is acceptable (on ⟨M⟩, run M on ε with the universal machine), SelfReject is acceptable (Theorem 11), and the intersection of two acceptable languages is acceptable (Lemma 4). Concretely: reject non-encodings; run M on ε; if it accepts, run M on ⟨M⟩ and accept if that run rejects. If M runs forever on ε, so does this acceptor — which is fine, since then ⟨M⟩∈/EpsSelfReject.

(c) No. EpsSelfReject is acceptable by (b) and undecidable by (a), so by Lemma 5 its complement is not acceptable.

(d) Let M1​ accept if its input is empty and reject otherwise, and M2​ accept if its input is empty and run forever otherwise. Both accept exactly {ε}. But M1​ rejects every non-empty string — its own encoding included — so ⟨M1​⟩∈EpsSelfReject, while M2​ rejects nothing, so ⟨M2​⟩∈/EpsSelfReject. Next, let M3​ run forever if its input is empty and reject otherwise: it rejects the same strings as M1​, but it does not accept ε, so ⟨M3​⟩∈/EpsSelfReject. Membership is decided neither by Accept(M) nor by Reject(M), so neither Rice’s theorem nor its rejection version applies. (The pair M1​, MAccept​ — both halt on every input, but MAccept​ rejects nothing — rules out the halting and divergence versions too.)

Watch out:

  • Flipping is the wrong reflex here. If Wrap returned the opposite of Dec‘s answer, both cases would be consistent: Dec accepts ⟨Wrap⟩, so Wrap rejects it and ⟨Wrap⟩∈EpsSelfReject — no contradiction; similarly for rejection. Work out both cases before committing to a wrapper.
  • Forgetting the ε clause breaks the proof too: a wrapper that does not accept ε is never in the language, so ”Dec rejects ⟨Wrap⟩” is perfectly consistent.
  • Say why the run of Dec on ⟨Wrap⟩ halts; otherwise there is a third case.

Grading. Out of 10: 4 for the wrapper (built from Dec, with its behavior on ε and on encodings stated) and 6 for the contradiction, 3 for each case.

Answer. (a) Wrap accepts ε and copies Dec‘s answer on encodings; on ⟨Wrap⟩ both answers of Dec are wrong. (b) AccEps∩SelfReject is acceptable by Lemma 4. (c) No, by Lemma 5. (d) M1​ and M2​ accept {ε}, but only M1​ is in the language; M1​ and M3​ reject every non-empty string, but only M1​ is in the language.

7.8 Both languages infinite

Hard · reductions · Rice's theorem

Let BothInfinite:={⟨M⟩∣Accept(M) and Reject(M) are both infinite}, for machines with input alphabet {0,1}.

(a) Show that neither Rice’s theorem nor Rice’s rejection theorem applies directly: give two machines that accept the same language, exactly one of them in BothInfinite, and two machines that reject the same language, exactly one of them in BothInfinite.

(b) Prove that BothInfinite is undecidable by a reduction, written out in full with both directions.

Source: original.

Hint

(a) Accept the strings of even length; decide what happens to the odd ones. (b) Build M′ that first runs M on w and then, only if M accepted, behaves like your machine from (a) that is in BothInfinite.

Solution

Idea. Membership depends on Accept(M) and Reject(M) together, so no single-language version of Rice fits; but the reduction behind Rice still works, with a target machine that both accepts and rejects infinitely many strings.

(a) Three parity machines, with start state even: on 0 or 1, even and odd swap and move right; on the blank they do this:

machineeven reads □odd reads □AcceptRejectin BothInfinite?
Pacceptrejecteven-length stringsodd-length stringsyes
P′acceptmove right, stay in oddeven-length strings∅no
P′′move right, stay in evenreject∅odd-length stringsno

(P′ runs forever on odd-length inputs, walking right over blanks; P′′ does the same on even-length ones.) Accept(P)=Accept(P′) but only P is in BothInfinite, so it is not AcceptIn(L) for any L; Reject(P)=Reject(P′′) but only P is in it, so it is not RejectIn(L) either.

(b) Suppose for the sake of argument that some Turing machine DecideBI decides BothInfinite. Consider the machine DecideAccept that, given ⟨M,w⟩, writes the encoding ⟨M′⟩ of the machine

M′(x): run M on w; if M accepts w: accept x if ∣x∣ is even, reject x if ∣x∣ is odd

(if M rejects w, M′ runs forever; if M runs forever or crashes on w, so does M′), and then runs DecideBI on ⟨M′⟩ and returns its answer. Writing ⟨M′⟩ always terminates and DecideBI always halts, so DecideAccept halts on every input.

  • Suppose M accepts w. Then on every input x, M′ finishes running M on w and accepts x if ∣x∣ is even and rejects it if ∣x∣ is odd. So Accept(M′) is the set of even-length strings and Reject(M′) the set of odd-length strings, both infinite: ⟨M′⟩∈BothInfinite. So DecideBI accepts ⟨M′⟩, and DecideAccept accepts ⟨M,w⟩.
  • Suppose M does not accept w. If M rejects w, then M′ runs forever on every input by construction; if M runs forever on w, then M′ never finishes its first phase. Either way M′ halts on no input, so Accept(M′)=Reject(M′)=∅: ⟨M′⟩∈/BothInfinite. So DecideBI rejects ⟨M′⟩, and DecideAccept rejects ⟨M,w⟩.

In both cases DecideAccept is correct, so it decides Accept — which is impossible. Hence DecideBI does not exist, and BothInfinite is undecidable. ■

Check. P is what M′ turns into when M accepts w. On 01 it goes even→odd→even and accepts at the blank; on 0, odd reads the blank and rejects; on ε it accepts at once. P′ on 0 walks right over blanks in state odd forever.

Watch out: the clause “if M rejects w, M′ runs forever” matters. If M′ went on to the parity phase whenever M halts on w, then a rejection of w would put ⟨M′⟩ in BothInfinite, and the second direction would fail. That version is a correct reduction from Halt instead; what breaks the proof is mixing the two.

Grading. Out of 10: 4 for the reduction (DecideAccept and M′ described, in the right direction), 3 for ”M accepts w ⇒ accept”, 3 for ”M rejects or diverges ⇒ reject”.

Answer. (a) P (accept even, reject odd) and P′ (accept even, run forever on odd) accept the same language; P and P′′ (reject odd, run forever on even) reject the same language; only P is in BothInfinite. (b) Reduce Accept: M′ runs M on w and, if M accepts, accepts even-length and rejects odd-length inputs.
