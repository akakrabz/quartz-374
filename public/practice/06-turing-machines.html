Easy

6.1 Deciding, crashing and variants

Easy · true or false · TM variants

Answer each statement Yes (always true) or No, with a one-sentence reason; for a No, give a counterexample. “Standard” means the model of §6.2.

(a) A Turing machine that never moves its head to the left can accept a language that is not regular.

(b) If a Turing machine M halts on every input and accepts every string in L, then M decides L.

(c) If a Turing machine M crashes on at least one input, then M decides no language at all.

(d) Every Turing machine that may also stay put (Δ=0) can be simulated by a standard Turing machine that takes at most twice as many steps.

(e) Every Turing machine whose tape is infinite in both directions can be simulated by a standard Turing machine with only a constant-factor slowdown.

(f) If a two-tape Turing machine decides L in O(n) time, then some standard Turing machine decides L in O(n) time.

Source: original.

Hint

For (a): can the machine ever look again at a cell it has left? For (b) and (c), go back to the exact definitions of accepts L and decides L. For (f), §6.6 names a language with a quadratic gap.

Solution

(a) No. Such a machine reads each input symbol exactly once, left to right, and after the input it reads only blanks, so its state at the end of the input determines everything that follows: it is a DFA in disguise, and Accept(M) is regular. (Concretely: a DFA with states Q∪{ACC,REJ} follows M‘s state symbol by symbol, and accepts in ACC and in every state from which M‘s walk over blanks reaches accept — a walk that depends on the state alone.)

(b) No. “Accepts every string in L” still allows accepting more. The machine MAccept​ that accepts at once halts on every input and accepts every string in L={ε}, but it also accepts 0; it decides Σ∗, not {ε}. With "Accept(M)=L" instead, the statement would be true.

(c) Yes. A decider must accept or reject every input, and on an input where M crashes it does neither: a crash is not a rejection.

(d) Yes. The construction of §6.4 with states Q×{0,1} replaces each stay-put step by a step right and a step back, and every other step by one step, so t steps become at most 2t.

(e) Yes. Fold the tape at cell 0 onto two tracks — the upper track of cell i≥0 holds cell i, the lower track holds cell −i−1 — mark cell 0, and keep the current track in the state; each simulated step costs one step, or two when the head crosses between cells 0 and −1 (plus two steps at the start to mark cell 0).

(f) No. The marked palindromes {w#wR∣w∈{0,1}∗}: two tapes decide them in O(n) steps — copy w onto tape 2, then compare it backwards with the part after the # — but every standard one-tape machine needs Ω(n2) time (§6.6). What is true is the simulation bound: one tape can always do it in O(n2) steps.

Watch out: (b) and (c) are pure definitions, and that is where exam points go. M accepts L means M accepts exactly the strings of L; M decides L means, in addition, that M halts — accepts or rejects, never crashes or runs forever — on every input.

Answer. (a) No (b) No (c) Yes (d) Yes (e) Yes (f) No.

6.2 Four ways a run ends

Easy · TM simulation

The machine M below has input alphabet {0,1}, tape alphabet {0,1,□} and states start, look, accept, reject; the blank entry is a missing transition.

01□
start(look,1,+1)(look,1,−1)
look(look,0,−1)(start,1,+1)(accept,1,−1)

(a) Write the run of M on input 000 as a sequence of configurations (q,x,i), and say how it ends.

(b) On each of the inputs ε, 1, 01 and 011, does M accept, reject, crash, or run forever? Justify each answer.

(c) Does M decide any language?

Source: original.

Hint

A configuration (q,x,i) lists the state, the tape without trailing blanks, and the head position. On 011, write configurations until one of them comes back.

Solution

(a) The run on 000:

stepconfigurationstepconfiguration
0(start,000,0)5(look,110,1)
1(look,100,1)6(start,110,2)
2(look,100,0)7(look,111,3)
3(start,100,1)8(accept,1111,2)
4(look,110,2)

M accepts after 8 steps. In state start it overwrites a 0 with 1 and steps right; look sees another 0, steps back onto the 1 it just wrote, and steps forward again in state start — three steps per cell. After the last 0, look reads the blank, writes 1 and accepts.

(b)

  • ε: reject. start reads □ and has no transition for it, so (start,ε,0)⇒(reject,ε,0).
  • 1: crash. start reads 1 on cell 0 and moves left; there is no next configuration.
  • 01: reject. (start,01,0)⇒(look,11,1)⇒(start,11,2), and start reads □.
  • 011: runs forever. (start,011,0)⇒(look,111,1)⇒(start,111,2)⇒(look,111,1). The configuration of step 1 has come back at step 3. A Turing machine is deterministic, so from then on it alternates between these two configurations forever.

(c) No. A machine that decides a language halts on every input, and M crashes on 1 and runs forever on 011.

Going further. Following the head on every input gives the complete picture. In state start on a 0, the machine uses up that 0 if the next symbol is 0, and the block 01 if it is 1 (look steps over the 1). So it reads the input as a sequence of blocks 0 and 01: it accepts if a lone 0 ends the input, rejects if a block 01 ends it, and loops as soon as a block 01 is followed by a 1:

Accept(M)crashes on ​=(0+01)∗0,1(0+1)∗,​Reject(M)runs forever on ​=ε+(0+01)∗01,(0+01)∗011(0+1)∗.​

Accept(M) is regular, so it is decidable — just not by M. Decidable describes a language; decides relates one machine to one language.

Answer. (a) Accepts after 8 steps, ending in (accept,1111,2). (b) ε: reject; 1: crash; 01: reject; 011: runs forever (a configuration repeats). (c) No: it crashes on 1 and runs forever on 011.

6.3 A decider that only accepts

Easy · find the error · Turing machine design

Let E={w∈{0,1}∗∣#(0,w)=#(1,w)}. A student designs a Turing machine for E and writes:

“The first symbol is overwritten with ⊢, which marks the left end and remembers one symbol still waiting for a partner. Then repeat: find an unmarked partner of the opposite kind to the right and mark it x; walk back to the ⊢; find the first unmarked symbol, mark it x, and look for its partner. When no unmarked symbol is left, accept. In the table, — means ‘write back the symbol read’, and missing transitions reject. My machine decides E.“

statereadwritemovenext state
start0⊢+1seek1
1⊢+1seek0
□—+1accept
seek10, x—+1seek1
1x−1rewind
□—+1seek1
seek01, x—+1seek0
0x−1rewind
rewind0, 1, x—−1rewind
⊢—+1next
nextx—+1next
0x+1seek1
1x+1seek0
□—+1accept

(a) Run the machine on 100. (b) What is wrong with the claim “my machine decides E”, and which entry causes it? Fix the machine. (c) Does the student’s machine accept E?

Source: original.

Hint

On 100, the first 1 finds its partner. What happens to the second 0?

Solution

(a) The first 1 is matched with the first 0; then the second 0 looks for a partner that does not exist:

​(start,100,0)⇒(seek0,⊢00,1)⇒(rewind,⊢x0,0)⇒(next,⊢x0,1)⇒(next,⊢x0,2)⇒(seek1,⊢xx,3)⇒(seek1,⊢xx,4)⇒(seek1,⊢xx,5)⇒⋯​

From step 5 on, seek1 reads a blank, moves right, and reads another blank: the machine runs forever.

(b) The slip is the entry δ(seek1,□)=(seek1,□,+1) — “keep looking for a 1” after the input has ended. Every cell past the input is blank, so once seek1 reaches the end it never halts. That happens on every string with more 0s than 1s (each round marks one 0 and one 1, so eventually a 0 is left without a partner), and a decider must halt on every input. Fix: delete that entry. Reaching the blank in seek1 means “this 0 has no partner”, so w∈/E, and the missing transition rejects — exactly what seek0 already does when it reaches a blank. With this change the machine decides E.

(c) Yes. The bad entry is used only when seek1 reaches the blank; on every other input the student’s machine and the fixed one behave identically. So the student’s machine accepts exactly E, rejects the strings with more 1s than 0s, and runs forever on the strings with more 0s than 1s: it accepts E but does not decide it.

Watch out: every “scan for something” state needs an answer to what if I reach the blank? “Skip every symbol that is not a 1” is exactly the thought that produces this bug.

Answer. (a) It runs forever: after matching the 1, seek1 walks right over blanks forever. (b) δ(seek1,□)=(seek1,□,+1) makes it loop on every string with more 0s than 1s; delete it, so that the blank rejects. (c) Yes: Accept(M)=E, but M is not a decider.

Medium

6.4 Palindromes by peeling both ends

Medium · Turing machine design

Design a Turing machine that decides Pal={w∈{0,1}∗∣w=wR}. Give

(a) the algorithm in English, as passes over the tape;

(b) a transition table with a one-line meaning for every state;

(c) an argument that your machine never crashes and halts on every input of length n within O(n2) steps.

Source: classic.

Hint

A string of length at least 2 is a palindrome exactly when its first and last symbols agree and the part between them is a palindrome. Remember the first symbol in the state, and erase symbols as you use them: the blank left behind at the front also tells the machine where to stop when it walks back.

Solution

Idea. Peel off the two ends: erase the first remaining symbol, remembering it in the state; walk to the end; compare and erase the last remaining symbol; walk back. Nothing left, or a lone middle symbol, means accept.

(a) Algorithm. Repeat:

  1. If the current cell is blank, nothing is left: accept. Otherwise erase the current symbol a and remember it.
  2. Walk right to the first blank, and step back onto the last remaining symbol.
  3. If that cell is blank, the erased a was the middle symbol: accept. If it holds the other symbol, reject. If it holds a, erase it.
  4. Walk left to the first blank, step right, and start over.

(b) Transition table (”—” means “write back the symbol read”; missing transitions reject):

statereadwritemovenext statemeaning
start0□+1have0erase the first remaining symbol, a 0 …
1□+1have1… or a 1
□—+1acceptnothing left: every pair matched
have00, 1—+1have0the first symbol was 0; walk to the end
□—−1last0step back onto the last remaining symbol
have10, 1—+1have1the first symbol was 1; walk to the end
□—−1last1
last00□−1backthe ends agree: erase the last symbol
□—+1acceptnothing after the erased 0: it was the middle
last11□−1backthe ends agree
□—+1acceptthe erased 1 was the middle
back0, 1—−1backwalk left over the remaining symbols
□—+1startthe blank in front of them: next round

The rejections are the missing transitions δ(last0,1) and δ(last1,0): the ends differ.

(c) No crash. The first step erases cell 0, so from then on cell 0 is blank and back stops there at the latest, moving right. The other left moves step from a blank onto the last remaining symbol, or from the last remaining symbol (which lies to the right of the erased first one) one cell left, never past cell 0. Running time. Each round erases two symbols (one in the final round of an odd-length input), so there are at most n/2+1 rounds, and each round walks across the remaining symbols and back, at most 2n+1 steps: O(n2) in all. Exactly, on a palindrome of length n the machine takes (n+1)(n+2)/2 steps (a round on m≥2 remaining symbols costs 2m+1 steps); on other inputs it rejects sooner.

Check. On 0110: round 1 erases both 0s and walks back to cell 0; round 2 erases both 1s; then start reads □ and accepts — 15 steps =5⋅6/2. On 0100: round 1 erases the outer 0s, then last1 reads 0 and rejects (13 steps). On 010: after round 1, start erases the 1, have1 reads □ at once, and last1 reads the blank where the 1 was: accept. On ε: accept in one step.

Answer. The six-state machine above (erase the first symbol, remember it, compare with the last, erase, walk back); it never crashes and takes (n+1)(n+2)/2=O(n2) steps on palindromes of length n.

6.5 Two tapes, linear time

Medium · TM variants · Turing machine design

A two-tape Turing machine has one finite control and two tapes, each with its own head. Its transition function has the form δ(p,(a1​,a2​))=(q,(b1​,b2​),(Δ1​,Δ2​)): it reads the symbols a1​,a2​ under the two heads, writes b1​ and b2​, and moves each head by Δk​∈{−1,0,+1} (in this problem a head may also stay put). The input is on tape 1, tape 2 is blank, both heads start on cell 0, and a head moving left from cell 0 crashes the machine.

(a) Design a two-tape machine that decides Z={0n1n0n∣n≥0} within O(∣w∣) steps on every input w. Describe it in English and give its transition table with a meaning for every state.

(b) Exactly how many steps does your machine take on 0k1k0k? Compare with the one-tape machine of §6.3, which takes 4k2+9k+1 steps.

(c) What running time does the simulation of §6.6 give for a one-tape machine built from yours? Does your machine show that two tapes can decide languages that one tape cannot?

Source: original.

Hint

Use tape 2 as a unary counter: one mark per 0 of the first block. Then walk tape 2’s head back over the marks while tape 1 reads the 1s, and forward again while tape 1 reads the last block. Make the mark in tape 2’s cell 0 special, so that its head knows where to stop.

Solution

Idea. One left-to-right pass over the input, with tape 2 counting: write one mark per 0 of the first block (the first one is ⊢, so that cell 0 of tape 2 is recognizable); match the 1s against the marks walking tape 2 left, then match the last block against the marks walking tape 2 right.

Construction. Missing transitions reject; ”—” means “write back the symbols read”.

stateread (a1​,a2​)writemovenext statemeaning
start(0,□)(0,⊢)(+1,+1)copyfirst 0: mark tape 2’s cell 0 with ⊢
(□,□)—(+1,+1)acceptε∈Z
copy(0,□)(0,x)(+1,+1)copyone mark per further 0 of block 1
(1,□)—(0,−1)match1block 1 is over: tape 2 steps back onto the last mark
match1(1,x)—(+1,−1)match1pair a 1 with a mark, walking tape 2 left
(1,⊢)—(+1,0)match0this 1 pairs with ⊢; tape 2 stays put
match0(0,⊢), (0,x)—(+1,+1)match0pair a 0 of block 3 with a mark, walking tape 2 right
(□,□)—(+1,+1)acceptinput and marks run out together

Every way to fail is a missing transition: start reading a 1 (no first block), copy reading (□,□) (no 1s), match1 reading a 0 or □ on tape 1 (too few 1s), and match0 reading a 1 (too many 1s, or a fourth block), (0,□) (block 3 too long), or (□,x) or (□,⊢) (block 3 too short). The tape-2 head moves left only from a cell holding x, which is never cell 0, so the machine never crashes. Tape 1’s head moves right in every step but one, so the machine halts within ∣w∣+2 steps.

(b) For k≥1: 1 step in start, k−1 in copy on the remaining 0s, 1 more when copy meets the first 1, k in match1, k in match0, and 1 to accept — 3k+2 steps (and 1 step for k=0). Against 4k2+9k+1: for k=100, 302 steps instead of 40,901.

(c) One tape simulates t steps of a two-tape machine in O(t2) steps when t≥n (two tracks per tape — contents and head mark — and one sweep over the used cells per simulated step). Here t=O(n), so the simulation decides Z in O(n2) steps on one tape, the same order as the machine of §6.3. No: every two-tape machine can be simulated by a one-tape machine, so both models decide exactly the same languages; the second tape saves time, not power.

Check. On 010: start writes ⊢; copy meets the 1 and backs tape 2 onto ⊢; match1 pairs the 1 with ⊢; match0 pairs the last 0 with ⊢, then reads (□,□): accept after 5 steps =3⋅1+2. On 0110, match0 reads (1,⊢) and rejects; on 00110, match0 reads (□,x) and rejects.

Answer. (a) The four-state machine above: count block 1 on tape 2, match block 2 walking tape 2 left, block 3 walking it right. (b) 3k+2 steps, against 4k2+9k+1 with one tape. (c) O(n2) by simulation; two tapes decide no new languages, they only run faster.

Hard

6.6 A machine that doubles its input

Hard · Turing machine design · TM simulation

A Turing machine computes a function as in §6.5: it has a single halting state halt, and its output is the tape contents when it halts, without trailing blanks. Design a one-tape Turing machine that computes the doubling function D(w)=ww for w∈{0,1}∗; for example D(10)=1010 and D(ε)=ε.

(a) Describe your algorithm in English as passes over the tape. You may add tape symbols.

(b) Give the transition table, with a one-line meaning for every state, and explain why your machine never moves left from cell 0.

(c) Trace your machine on input 10 (every configuration).

(d) Find the exact number of steps your machine takes on an input of length n, and conclude that it runs in Θ(n2) time.

Source: textbook exercise style.

Hint

Copy one symbol per round, left to right: mark it, carry it to the end in the state, write it there, and walk back. Write the copies as new symbols until the very end (what goes wrong otherwise?). And mark only the symbol you are copying right now: then the walk back always stops at that mark, and the machine never needs to find cell 0.

Solution

Idea. Round i copies the ith symbol: the state carries it to the right end. Two kinds of temporary symbols: copies are written as a (a copy of 0) and b (a copy of 1), so the machine can see where the original ends; and the one symbol being copied is written as 0^ or 1^, which is where the walk back stops.

(a) Algorithm.

  1. (next) If the current cell holds an original symbol c, overwrite it with c^ and carry c to the right. If it holds a copy, every symbol has been copied: go to step 4. If it is blank (only when w=ε), halt.
  2. (carry0, carry1) Move right over originals and copies to the first blank, write the copy of c there, and step left.
  3. (back) Move left to the hatted cell, restore it to c, step right, and go to step 1.
  4. (clean) Walk right turning a into 0 and b into 1; halt at the blank.

(b) Transition table (tape alphabet {0,1,0^,1^,a,b,□}; ”—” means “write back the symbol read”):

statereadwritemovenext statemeaning
next (start)00^+1carry0mark the symbol to copy, a 0 …

a0+1cleanthe first copy: every original is copied
b1+1clean

carry00, 1, a, b—+1carry0carrying a 0 to the end …
□a−1back… append its copy
carry10, 1, a, b—+1carry1carrying a 1 to the end …
□b−1back… append its copy
back0, 1, a, b—−1backwalk left to the hatted cell

1^1+1next

b1+1clean

The pairs not listed never occur. No crash: there are two kinds of left moves. carry steps left from the blank it has just filled, which lies to the right of the hatted cell; back walks left only until it reads the hatted cell, and exactly one cell — the one being copied — is hatted whenever back runs, so it turns right there, at cell 0 at the earliest.

(c) Trace on 10 (hats and copies as they stand on the tape):

stepconfigurationstepconfiguration
0(next,10,0)7(carry0,10^b,3)
1(carry1,1^0,1)8(back,10^ba,2)
2(carry1,1^0,2)9(back,10^ba,1)
3(back,1^0b,1)10(next,10ba,2)
4(back,1^0b,0)11(clean,101a,3)
5(next,10b,1)12(clean,1010,4)
6(carry0,10^b,2)13(halt,1010,5)

It halts after 13 steps with output 1010.

(d) Step count. Let n=∣w∣. The round that copies the symbol in cell i takes: 1 step in next; n−1 steps of carry over cells i+1,…,n+i−1 (the n−1−i remaining originals and the i copies so far); 1 step writing the copy in cell n+i; n−1 steps of back over cells n+i−1,…,i+1; and 1 step restoring cell i. That is 2n+1 steps per round, n(2n+1) for all n rounds. The finish takes 1 step in next on the first copy, n−1 steps of clean and 1 step at the blank: n+1 more. In total

T(n)=n(2n+1)+n+1=2n2+2n+1,

which is also right for n=0 (one step). Since 2n2≤T(n)≤5n2 for n≥1, the machine runs in Θ(n2) time. Check: T(2)=13, as in (c).

Watch out:

  • Writing each copy as a plain 0 or 1 breaks termination: after the last original, next sees the first copy, copies it, and the machine keeps copying its own copies forever.
  • Keeping every copied original hatted, and planning to unhat them all at the end while walking left, crashes: walking left over hatted symbols, the machine cannot tell when it has reached cell 0. Either hat only the current symbol (as here) or give cell 0 a mark of its own.
  • The final head position does not matter: the output is the tape contents.

Answer. (a)–(b) The five-state machine above (mark the current symbol, carry it to the end, append a temporary copy, walk back to the mark; finally clean up the copies). (c) 13 steps, ending in (halt,1010,5). (d) Exactly 2n2+2n+1 steps, so Θ(n2).
