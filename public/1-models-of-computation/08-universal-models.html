In one breath

A model of computation is universal if it can simulate every Turing machine. Anything that can simulate a Turing machine inherits both its power — it computes everything computable — and its undecidability: basic questions about the model, such as “does this run ever stop?”, become undecidable by a reduction from the halting problem. Astonishingly little suffices: two stacks, two counters, a list of fractions, a set of string dominoes, a few integer matrices, a system of mirrors, a set of square tiles, or three rewriting rules on strings of S, K and I. Each section below names a model, the encoding trick that lets it simulate a Turing machine, and what becomes undecidable.

The book presents this chapter as a rough sketch rather than a finished chapter, so this page is shorter than the others and fills in a few standard facts where the sketch is silent.

How universality spreads undecidability

  1. Simulate. Give an algorithm that turns any machine M and input w into an object PM,w​ of the new model (a program, an instance, a term) that “halts” if and only if M halts on w.
  2. Reduce. A decider for “does P halt?” would then decide the halting problem (§7.9), which is impossible. So halting is undecidable for the new model.
  3. Conversely, a Turing machine can usually simulate the new model, so the model computes exactly the computable functions — more evidence for the Church–Turing thesis.

8.1 Universal Turing machines

The first universal model is a single Turing machine: the universal machine U of §6.8 accepts ⟨M,w⟩ if and only if M accepts w, and rejects it if and only if M rejects w. It stores M‘s tape as a list of equal-length cells [⟨q⟩∙⟨a⟩] in which only the cell under the head carries a state other than reject. To take one step of M it finds that cell, looks up the matching block of ⟨δ⟩, rewrites the cell, and passes the state code to a neighboring cell. Every other model on this page is shown universal the same way: by simulating an arbitrary Turing machine, or a model already known to be universal.

8.2 Two-stack machines

A two-stack machine is a finite-state control with two stacks, with the input initially on one of them: in each step it may pop the top symbol of each stack, push symbols, and change state, depending on its state and the popped symbols. A Turing machine’s tape is two stacks — cut it at the head.

So one step of a Turing machine is a pop, a state change and a push — plus, for a move left, moving the top symbol of the left stack over to the right stack — and a move left with an empty left stack is a crash. Hence two-stack machines accept and decide exactly the same languages as Turing machines.

One stack is not enough

A finite-state machine that reads its input once, left to right, with one stack is essentially a recursive automaton: it accepts only context-free languages, so it cannot even recognize {0n1n0n∣n≥0}. Going from one stack to two jumps from the context-free languages straight to everything computable.

8.3 Counter machines

Definition — counter machine

A k-counter machine has a finite set of states and k counters, each holding a non-negative integer. In each step it looks at its state and at which counters are zero, then changes state and adds −1, 0 or +1 to each counter (never making one negative).

  • Three counters simulate a Turing machine. Read each half of the tape as a number in base ∣Γ∣, with □ as the digit 0 and the cells nearest the head as the least significant digits: one counter holds the part left of the head (with an extra leading digit 1, so that the machine can tell when that part is empty), another the head cell and everything to its right. Reading the head symbol is “right counter mod ∣Γ∣”. A move right multiplies the left counter by ∣Γ∣ and adds the written digit, and divides the right counter by ∣Γ∣; a move left is symmetric. Multiplying and dividing by a constant (with the remainder remembered in the state) are loops of ±1 steps that use the third counter as scratch space.
  • Two counters simulate three. Store three counters (a,b,c) as the single number 2a3b5c. Adding 1 to b multiplies it by 3, subtracting 1 from c divides it by 5, and ”c=0?” asks whether 5 fails to divide it — each again a ±1 loop, with the second counter as scratch. So two counters are universal; in particular, it is undecidable whether a given two-counter machine, started with both counters at 0, ever halts.
  • But the input format matters. To compute a function f with three counters, turn (n,0,0) into (2n,0,0), run the simulation to reach (2f(n),0,0), and turn that into (f(n),0,0). With only two counters, even turning (n,0) into (2n,0) is impossible — a hard theorem; the book cites Barzdin (1963), Yao (1971) and Schroeppel (1972). Two counters are universal only for suitably encoded inputs.

8.4 FRACTRAN

Definition — FRACTRAN (Conway, 1987)

A FRACTRAN program is a finite list of positive fractions f1​,…,fk​. Its state is one positive integer N. In each step, find the first fi​ for which Nfi​ is an integer and replace N by Nfi​; if there is none, halt.

The exponents in the prime factorization of N are counters in disguise: multiplying by 23​ subtracts 1 from the exponent of 2 and adds 1 to the exponent of 3, and it applies only when the exponent of 2 is positive — a built-in zero test. Extra primes can play the role of a counter machine’s states, so FRACTRAN is universal.

Two tiny programs

  • [23​] turns 2a3b into 3a+b, in a steps: it adds two counters.
  • [33455​,1311​,111​,73​,211​,31​] turns 2a3b into 5ab: it multiplies, with the primes 7, 11 and 13 doing the bookkeeping.

For every computable function f there is a FRACTRAN program that turns 2n+1 into 3f(n)+1. Again the encoding is unavoidable. Started at N=1, a program either halts at once, with output 1 (if none of its fractions is an integer, none applies to 1), or runs forever (an integer fraction applies to every N, so some fraction always applies). So no FRACTRAN program turns every n directly into n+1.

8.5 Post’s correspondence problem

Definition — Post's correspondence problem (PCP)

Given a finite list of dominoes (x1​/y1​),…,(xn​/yn​), each a pair of strings (top/bottom), is there a sequence of indices i1​,i2​,…,ik​ with k≥1, repetitions allowed, such that

xi1​​xi2​​⋯xik​​=yi1​​yi2​​⋯yik​​?

An instance and its shortest solution

With a=(0/100), b=(01/00) and c=(110/11), the sequence c,b,c,a is a solution: the tops give 110⋅01⋅110⋅0 and the bottoms 11⋅00⋅11⋅100, and both spell 110011100 (the book prints 110110100 here, a typo). No solution is shorter: every solution must start with c, because the top and bottom of a and of b already disagree, and no sequence of one, two or three dominoes works. Repeating a solution gives another one (cbcacbca), so a solvable instance has infinitely many solutions.

  • PCP is undecidable. Dominoes can be designed so that every solution spells out a halting computation of a given machine, one configuration after another, with the bottom row always one configuration ahead of the top; the book notes that the simplest proof simulates a tag machine, another universal model.
  • PCP is acceptable: try all sequences in order of length, and accept when one works. Since PCP is acceptable but undecidable, its complement is not even acceptable (§7.3).
  • Shortest solutions can be enormous. The book lists the three-domino instance (0/001), (001/1), (1/0), whose shortest solution uses 75 dominoes, and others whose shortest solutions use hundreds. No computable function of the instance bounds the length of its shortest solution: with such a bound, searching up to it would decide PCP.

8.6 Matrix mortality

Definition — matrix mortality

Given square integer matrices A1​,…,Ak​, all of the same size, is some product Ai1​​Ai2​​⋯Aim​​ of them, with repetitions allowed, equal to the zero matrix?

Strings can be encoded as integer matrices so that concatenation becomes matrix multiplication, and a careful construction turns any PCP instance into a set of matrices that has a zero product if and only if the instance has a solution. So mortality is undecidable — even for two 15×15 matrices, or for six 3×3 matrices (Cassaigne, Halava, Harju and Nicolas, 2014). With a single matrix the question is easy: some power of an n×n matrix is zero if and only if its nth power is. The order of the factors matters:

A=[10​00​],B=[01​01​]:AB=[00​00​],BA=[01​00​],A2=A,B2=B.

8.7 Dynamical systems

Continuous physical systems can be universal too. Reif, Tygar and Yoshida (1994) encode a Turing machine’s configuration as the coordinates of the point where a light ray crosses a unit square — one coordinate encodes the tape left of the head, the other the tape right of the head, just like the two stacks of §8.2 — and build a system of mirrors with quadratic surfaces (or of lenses) that carries the ray from one configuration’s point to the next one’s. So “does a ray starting here ever reach that region?” is undecidable: ray tracing, in general, is undecidable.

8.8 Wang tiles

A Wang tile is a unit square with a color on each edge. Given a finite set of tile types, with unlimited copies of each, can the plane be covered without rotating any tile, so that tiles that share an edge give it the same color?

A Turing machine’s run can be drawn as a tiling: row t spells out the configuration after t steps, and the colors on the horizontal edges carry each cell’s symbol (and, at the head, the state) up to the next row, so that the only way to complete a row is to compute the next configuration. If a special starting tile must sit in the corner and write the initial configuration, then a quarter of the plane can be tiled if and only if the machine never halts — so this version of the tiling problem is undecidable. Wang conjectured that every tile set that tiles the plane also tiles it periodically, which would make the unrestricted problem (no starting tile) decidable; Berger (1966) refuted the conjecture and proved the unrestricted problem undecidable, using tile sets that tile the plane only aperiodically.

8.9 Combinator calculus

Definition — combinator terms and evaluation

A term is one of the combinators S, K, I (or a variable x,y,…), or a pair (X,Y) of terms, meaning ”X applied to Y”. Application associates to the left, and the parentheses that this makes redundant are dropped: SKK(IS) abbreviates (((S,K),K),(I,S)). Evaluation rewrites any subterm with one of the three rules

Ix → x,Kxy → x,Sxyz → xz(yz).

A subterm that matches a left-hand side is a redex; a term with no redex is in normal form.

(Schönfinkel introduced combinators in the 1920s.) Several redexes may be available at once, so a reduction sequence depends on the order in which they are chosen.

Reversing two arguments

R:=S(K(SI))K swaps its two arguments. Rewriting the leftmost outermost redex at each step:

S(K(SI))Kxy→K(SI)x(Kx)y→SI(Kx)y→Iy(Kxy)→y(Kxy)→yx.

Similarly SKKx→Kx(Kx)→x, so SKK does the job of I: the two combinators S and K suffice.

A term that runs forever

Let T:=S(KI)(SII). Rewriting at each step the leftmost I- or K-redex if there is one, and otherwise the leftmost S-redex:

SIIT​→IT(IT)→T(IT)→TT=S(KI)(SII)T→KIT(SIIT)→I(SIIT)→SIIT,​

back where it started after six steps. Rewriting the leftmost outermost redex instead, the term never returns to itself but never stops either: it passes through SII(IT), SII(I(IT)), … forever.

Combinator calculus is universal: it is equivalent to Church’s λ-calculus, and so to Turing machines. In particular, it is undecidable whether a given term has a normal form — whether evaluation can ever stop.

Summary

  • Universal means “can simulate every Turing machine”, and universality brings undecidability with it, by a reduction from the halting problem.
  • A tape is two stacks cut at the head, so two stacks are universal; one stack with a single pass over the input gives only the context-free languages.
  • Three counters simulate a tape (its halves as numbers); two counters simulate three via 2a3b5c. But two counters cannot even compute n↦2n: universality needs suitably encoded inputs.
  • FRACTRAN is a counter machine in disguise: prime exponents are the counters. [23​] adds.
  • PCP is undecidable but acceptable. Example: c,b,c,a spells 110011100 on both rows, and no shorter sequence works.
  • Matrix mortality (even two 15×15 or six 3×3 matrices), ray tracing with mirrors and tiling the plane with Wang tiles are undecidable for the same reason.
  • Three rewriting rules, Ix→x, Kxy→x and Sxyz→xz(yz), are universal; SII(S(KI)(SII)) can rewrite forever.

On the exams

The final exam (Dec 11) covers everything, Chapters 6–9 included. The book presents this chapter as a sketch, so treat it as background: it explains why undecidability shows up everywhere, and it supplies intuition for true/false items such as “a finite-state machine with two stacks is as powerful as a Turing machine” (true), “a finite-state machine that reads its input once with one stack can recognize {0n1n0n}” (false), or “Post’s correspondence problem is acceptable” (true).
