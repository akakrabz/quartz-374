In one breath

A Turing machine is a finite-state control attached to an unbounded tape that it can read, overwrite and walk along in both directions. On a given input it accepts, rejects, crashes off the left end of the tape, or runs forever, and the difference between accepting a language and deciding it (also halting on every input) organizes all of Chapter 7. Designing machines is tedious but mechanical — scan, mark, walk back — and every reasonable variation (stay-put moves, more tracks, heads or tapes, a tape infinite in both directions) accepts and decides exactly the same languages, at most quadratically slower. Turing machines can simulate a real computer and, through a universal machine, each other. That generality is the point: they are a terrible model for fast algorithms and the standard model for proving what cannot be computed.

In 1936, at the age of 23, Alan Turing defined these machines, described a single machine that can simulate all the others, and proved that no machine solves the halting problem — and therefore that Hilbert’s Entscheidungsproblem (decide whether a given statement of first-order logic is provable) has no algorithmic solution. Alonzo Church had reached the same conclusion a few months earlier with his λ-calculus; Turing then proved that the two models compute exactly the same functions.

The Church–Turing thesis

Every function that can be computed “by finite means” — by any algorithm whatsoever — can be computed by a Turing machine.

This is a claim about the world, not a theorem: “algorithm” has no formal definition to prove it against, and Turing himself called his arguments for it appeals to intuition. The evidence is that every reasonable model proposed since 1936 — the λ-calculus, recursive functions, register machines, programming languages, and the strange systems of Chapter 8 — computes exactly the same functions.

6.1 Why bother?

Turing machines are a poor model of speed. Small changes to the model change running times: reversing an n-bit string takes O(n) time on a machine with two tapes but provably Ω(n2) time with one. Nobody designs algorithms on them; algorithms are analyzed on random-access models instead.

They are an excellent model of impossibility. To prove that no algorithm solves a problem, we need a definition of “algorithm” that is

  • simple enough that one proof can reason about every possible machine at once — a handful of components and a single step rule; and
  • powerful enough to simulate every other reasonable model, including Turing machines themselves. Self-simulation is what makes the self-referential undecidability proofs of Chapter 7 possible.

A DFA with a notebook

A DFA reads its input once, left to right, and its only memory is its current state. A Turing machine has the same kind of finite control, but its input sits on a tape that it may reread, overwrite and extend without limit, moving in either direction. Finite control plus unbounded rewritable memory is general computation.

6.2 Formal definitions

Definition — Turing machine

A Turing machine M consists of

  • a tape alphabet Γ: a finite set with at least two symbols, one of which is the blank □;
  • an input alphabet Σ⊆Γ∖{□}, non-empty;
  • a finite set Q of states containing three distinct special states start, accept and reject;
  • a transition function δ:(Q∖{accept,reject})×Γ→Q×Γ×{−1,+1}.

δ(p,a)=(q,b,Δ) means: in state p, reading a, overwrite it with b, move the head one cell — to the left if Δ=−1, to the right if Δ=+1 — and enter state q. Nothing happens after accept or reject.

The tape has a left end, cell 0, and extends forever to the right; at every moment all but finitely many cells are blank.

Definition — configuration, step, crash

A configuration is a triple (q,x,i): the current state q, the tape contents x∈Γ∗ (followed by infinitely many blanks; trailing blanks may be written or left out, so (q,x,i) and (q,x□,i) are the same configuration), and the head position i≥0. If δ(p,a)=(q,b,Δ) then

(p, xay, i) ⇒ (q, xby, i+Δ)whenever ∣x∣=i,

that is, when the head is on cell i, which holds a. Every configuration has at most one successor, and ⇒∗ means zero or more steps. On input w∈Σ∗ the machine starts in the initial configuration (start,w,0). If a step would move the head to position −1, there is no next configuration: the machine crashes.

Definition — the four outcomes

On each input w, exactly one of these happens:

  • M accepts w: (start,w,0)⇒∗(accept,x,i) for some x and i;
  • M rejects w: (start,w,0)⇒∗(reject,x,i) for some x and i;
  • M crashes on w: the run reaches a configuration that tries to move left from cell 0;
  • M runs forever on w: none of the above, ever.

M halts on w if it accepts or rejects w; otherwise — if it crashes or runs forever — M diverges on w. (Chapter 7’s set Diverge(M) therefore contains the inputs on which M crashes.)

"Rejects" and "does not accept" are different

A machine that does not accept w may reject it, crash, or run forever. Accepting and rejecting are definite answers that an observer eventually sees, but “does not accept” may never become visible: a machine that has run for a million steps may still accept at step 106+1. Chapter 7 is built on this distinction — Reject(M) and Σ∗∖Accept(M) are different sets in general (§7.1).

Definition — accepting versus deciding a language

Let L⊆Σ∗, and let Accept(M) be the set of strings that M accepts.

  • M accepts (or recognizes) L if Accept(M)=L: M accepts every string in L and nothing else. On strings outside L it may reject, crash or run forever. L is acceptable if some Turing machine accepts it.
  • M decides L if M accepts every string in L and rejects every string in Σ∗∖L — equivalently, M accepts L and halts on every input. L is decidable if some Turing machine decides it.

Every decidable language is acceptable, since a machine that decides L also accepts it. The converse fails: the halting problem is acceptable but undecidable (§7.9), and some languages are not even acceptable.

Missing transitions

The definition makes δ total on the non-halting states, but tables and diagrams usually leave many transitions out. The convention, in the book and on this site, is that every missing transition goes to reject. Say so explicitly on an exam, exactly as you would mention the omitted dump state of a DFA.

6.3 A first example

The language L={0n1n0n∣n≥0} is not regular — 0∗ is a fooling set, with suffix 1i0i for 0i, as in §3.8 — and it is the standard example of a language that is not even context-free (the proof is beyond this course). It is decidable. The machine below follows the book’s idea of marking one symbol of each block per round, with one addition: it checks the format of the input first.

The algorithm in English

Phase 1: check the format. If the input is empty, accept. Otherwise its first symbol must be 0; overwrite it with #, which marks the left end of the tape and counts as the first matched 0. Scan right, checking that the input has the form 0+1+0+, then walk back to the #.

Phase 2: match in rounds. Each round marks the first unmarked 1 with x, marks the first unmarked 0 after the 1s with x, walks back to the last #, and marks the next 0 of the first block with #. Once the first block is used up, accept if and only if every remaining symbol is marked.

Whenever a step cannot find the symbol it needs, reject.

The book's machine skips the format check

The machine printed in the book’s §6.3 (states start, seek1, seek0, reset, verify) starts matching immediately. Read with a move to the left after it marks a 0 — which is what the text and its traces do; the printed table says +1 there, a typo — it also accepts some strings outside L, such as 001010 (18 strings of length at most 12 in all), and because its start state has no transition on □, it rejects ε, which is in L. Its matching idea is sound; it needs a format check like Phase 1. The general lesson: test a design on ε and on near-misses such as 001010, 0110 and 00, not only on members of the language.

Recipe — designing a Turing machine

  1. Write the algorithm in English as a few passes over the tape: scan for something, mark it, walk back.
  2. Mark, don’t count. The state is finite; unbounded counts live on the tape as marked symbols.
  3. Mark the left end before the machine ever walks left, so that it knows where to stop instead of crashing.
  4. Each pass becomes one or two states, and “keep scanning” becomes a self-loop.
  5. Write the transition table with a one-line meaning for every state, and say that missing transitions reject.
  6. Trace the machine on ε, on a short member of the language, and on several near-misses.

Writing a Turing machine on an exam

Turing machines were not on Midterm 1. If the final asks you to design one, give the transition table (or a state diagram) together with an English description of what each state does, use mnemonic state names, and say that missing transitions reject — the standards for DFAs, scaled up. Begin with the phase-by-phase description in English; the table should implement exactly that description.

6.4 Variations

The definition above is one choice among many. Books, courses and research papers vary it in harmless ways, and all of these variants accept and decide exactly the same languages:

  • halting: several accepting and rejecting states; halting whenever no transition applies; only accepting states (a crash then counts as rejection); halting by moving off the left end;
  • moves: stay-put moves (Δ=0); moves of several cells at once; steps that either write or move, but not both;
  • transition function: partial instead of total, with missing transitions rejecting (as in our tables);
  • left end: an end marker that cannot be overwritten, or a move left at cell 0 that leaves the head where it is instead of crashing.

Two machines are equivalent if they accept the same strings and reject the same strings (so they also diverge on the same strings, although one may crash where the other runs forever). To show that a variant adds no power, show that a standard machine can simulate it. The cost of the simulation matters for running time, never for decidability.

Construction — removing stay-put moves

Let M have moves Δ∈{−1,0,+1}. Build M′ with states Q′=Q×{0,1}, start state (start,0), accepting state (accept,0), rejecting state (reject,0), and

δ′((p,0),a):={((q,1),b,+1)((q,0),b,Δ)​if δ(p,a)=(q,b,0),if δ(p,a)=(q,b,Δ) with Δ=0,​ δ′((p,1),a):=((p,0),a,−1)for every state p and symbol a.

State (q,1) means “I moved right only because M wanted to stay put; step back”. On every input, M′ accepts, rejects, crashes or runs forever exactly when M does, with the same final tape, and t steps of M take at most 2t steps of M′.

For example, some definitions let the final transition into accept stay put, and the machine of §6.3 could hand the cell from mark0 to verify without moving. With those three stay-put moves, the construction produces a 24-state machine without them that behaves identically, one extra step per stay-put move.

6.5 Computing functions

Definition — computing a function

Replace accept and reject by a single halting state halt. If M halts on input w, its output M(w) is the tape contents at that moment, without the trailing blanks: M(w)=x if and only if (start,w,0)⇒∗(halt,x,i) for some i, where x does not end with □. If M never halts on w, then M diverges on w, written M(w)↑, and M(w) is undefined. M computes a function f:Σ∗→Σ∗ if M(w)=f(w) for every w∈Σ∗.

Shifting. The book’s machine for w↦0w keeps in its state the symbol it still has to write. In each step it writes that symbol and remembers the one it overwrote. (The book names the states 0 and 1; here they are hold0 and hold1, and hold0 is the start state.)

Binary increment = shift, then carry

Adding 1 to a binary number can carry into a new leading digit (111 + 1 = 1000), and a machine that walks left looking for room for the carry would crash at cell 0. Shifting first makes the room: the machine below shifts w one cell to the right with a 0 in front, exactly like the shift machine, and then adds 1 at the right end; the carry stops at that leading 0 at the latest.

If w is the binary representation of n (leading zeros allowed), the output is n+1 in binary with ∣w∣+1 digits: 1011 ↦ 01100, 111 ↦ 1000, and ε ↦ 1. Removing the leading 0 would take one more pass. The book’s binary adder (its §6.5.2) works in the same style: phases for scanning and adding, with the carry kept in the state.

The quadratic slowdown is unavoidable

After t steps the simulated heads can be up to t cells apart, so one sweep costs O(t) steps and t simulated steps cost O(t2). No cleverer one-head simulation exists in general: the marked palindromes {w#wR∣w∈{0,1}∗} can be decided in O(n) time with two heads — send one head to the far end, then walk the two heads toward each other, comparing — but need Ω(n2) time on a standard machine with one head.

Combining the simulations, any fixed number of tapes, heads and tracks, on tapes infinite in one or both directions, costs at most a quadratic slowdown. So decidability never depends on these details, and neither does running in polynomial time, which is what the classes P and NP of Chapter 9 measure.

6.7 Simulating a real computer

Two features of real programs remain, and Turing machines can simulate both.

  • Subroutines and recursion. Keep a call stack on an extra tape. To call a subroutine, push a record naming the state to return to and enter the subroutine’s states; to return, pop the top record and continue in the state it names. With the stack on its own tape, t steps of a machine with recursive calls take O(t) steps on a multi-tape machine, and so O(t2) steps on a standard one.
  • Random-access memory. Keep the memory on a tape as a list of pairs [address∙data]. A read or write scans the list for the address, and appends a new pair if the address is not there yet. If every address and value has at most ℓ bits, the kth access costs O(kℓ) steps on a multi-tape machine, so t accesses cost O(t2ℓ) — and O(t3ℓ2) on a standard one-tape machine.

Every overhead is polynomial. So a Turing machine can run any program a real computer can run, at most polynomially slower, and “computable by a program in your favorite language” means the same thing as “computable by a Turing machine” — evidence for the Church–Turing thesis from the one model we actually build.

6.8 Universal Turing machines

A universal Turing machine U is an interpreter for Turing machines, written as a Turing machine. Its input is an encoding ⟨M,w⟩ of a machine M together with an input w for M.

The universal machine

U accepts ⟨M,w⟩ if and only if M accepts w, and U rejects ⟨M,w⟩ if and only if M rejects w: on every input, U gives the answer that M would give.

U has one fixed, finite alphabet, but the machines it simulates have arbitrarily large alphabets and state sets, so everything about M is written in binary, with a few punctuation symbols.

The encodings

  • Symbols: each a∈Γ gets a distinct string ⟨a⟩ of ⌈lg∣Γ∣⌉ bits. A string is written symbol by symbol between brackets: ⟨w⟩=[⟨w1​⟩∙⟨w2​⟩∙⋯∙⟨wn​⟩].
  • States: each q∈Q gets a distinct string ⟨q⟩ of ⌈lg∣Q∣⌉ bits, with ⟨start⟩=1⋯1 and ⟨reject⟩=0⋯0. The book fixes no code for accept, but U has to recognize it, so fix one as well; this site uses ⟨accept⟩=0⋯01.
  • Moves: ⟨−1⟩=0 and ⟨+1⟩=1.
  • Transitions: each δ(p,a)=(q,b,Δ) with q=reject becomes a block [⟨p⟩∙⟨a⟩∣⟨q⟩∙⟨b⟩∙⟨Δ⟩]. Transitions into reject are left out — they become missing transitions.
  • The machine: ⟨M⟩=[⟨reject⟩∙⟨□⟩]⟨δ⟩, where ⟨δ⟩ is the list of all blocks inside one more pair of brackets. The first block tells U how long the codes are.
  • Configurations: a list of cells [⟨q⟩∙⟨a⟩], one per tape cell, inside one more pair of brackets. Here a is the cell’s symbol, and q=reject in every cell except the one under the head, which carries the current state.

Encoding the machine of §6.3

It has ∣Γ∣=5 symbols and ∣Q∣=12 states, so symbols take 3 bits and states take 4. Choose ⟨□⟩=000, ⟨0⟩=001, ⟨1⟩=010, ⟨#⟩=011, ⟨x⟩=100, and ⟨start⟩=1111, ⟨reject⟩=0000, ⟨accept⟩=0001, ⟨seek1⟩=0110, ⟨seek0⟩=0111, ⟨reset⟩=1000, with other distinct codes for the other states. Then

  • δ(seek1,1)=(seek0,x,+1) becomes the block [0110•010|0111•100•1];
  • ⟨M⟩ is [0000•000] followed by a bracketed list of 25 such blocks, one for each transition in the table;
  • the input 010 is [001•010•001];
  • the configuration (reset,#0x1x0,3) drawn in §6.2 is [[0000•011][0000•001][0000•100][1000•010][0000•100][0000•001]].

The book’s own example, for its seven-state machine with 3-bit codes, lists ⟨start⟩=111 and uses it in the initial configuration, but writes start as 001 inside its encoded transitions — a typo; by the rule above the code is 111 there too.

How U simulates one step of M

U keeps ⟨δ⟩ in one place and the encoded configuration in another (on separate tapes, or tracks of one tape).

  1. Find the head: scan the configuration for the one cell whose state code is not ⟨reject⟩.
  2. Look up the transition: scan ⟨δ⟩ for the block whose left half matches that cell. If there is none, reject.
  3. Apply it: copy the block’s ⟨q⟩∙⟨b⟩ into the cell. If q=accept, accept.
  4. Move: reset this cell’s state code to ⟨reject⟩ and write ⟨q⟩ into the neighboring cell in direction Δ; at the right end, first append a fresh cell [⟨reject⟩∙⟨□⟩], so the encoded tape behaves as if it were infinite. Then repeat. (If the head would move left from the first cell, M crashes; then U must not answer either — it can simply loop forever.)

Initialization copies ⟨w⟩ into this format, with ⟨start⟩ in the first cell.

So one fixed machine runs every program: a stored-program computer, described years before one was built. In Chapter 7, U does two jobs. It shows that Accept={⟨M,w⟩∣M accepts w} is acceptable — U accepts it — and its ability to run a machine on any string, including the machine’s own encoding, powers the self-referential arguments that make Accept undecidable (§7.4). Chapter 8 replaces U by much smaller universal systems.

Summary

  • A Turing machine is a finite control plus an unbounded tape: δ:(Q∖{accept,reject})×Γ→Q×Γ×{−1,+1}, configurations (q,x,i), start (start,w,0); a move left from cell 0 crashes.
  • On each input a machine accepts, rejects, crashes or runs forever. “Rejects” is not the same as “does not accept”.
  • M accepts L if Accept(M)=L; M decides L if it also halts on every input. Acceptable = recognizable = r.e.; decidable = computable = recursive; every decidable language is acceptable, not conversely.
  • Design machines in passes — scan, mark, walk back — with the left end marked; give a table plus an English meaning for every state; missing transitions reject. {0n1n0n} is decidable in O(n2) time.
  • All reasonable variants are equivalent: stay-put moves (states Q×{0,1}), several halting states, two-way infinite tapes, tracks, heads, tapes. One head costs a Θ(t2) slowdown, and that is unavoidable; two tapes cost only O(tlogt).
  • For functions: one halting state, the output is the final tape contents, and M(w)↑ when M diverges. The shift machine needs two states besides halt, the increment machine three.
  • Recursion and random-access memory cost only a polynomial slowdown, so Turing machines compute everything real programs compute.
  • A universal machine U accepts ⟨M,w⟩ iff M accepts w and rejects it iff M rejects w, by stepping through an encoded configuration.

On the exams

Turing machines were not on Midterm 1. The final exam (Dec 11) covers everything, Chapters 6–9 included, and Turing machines appear there mostly through undecidability (Chapter 7) and through true/false items such as “every decidable language is acceptable” (true), “if M does not accept w, then M rejects w” (false: it may run forever or crash), “some language decided by a two-tape machine is decided by no one-tape machine” (false: the extra tape only saves time), or ”{0n1n0n∣n≥0} is decidable” (true). If you are asked to design a machine, give a transition table or diagram plus an English description of every state, and say that missing transitions reject.
