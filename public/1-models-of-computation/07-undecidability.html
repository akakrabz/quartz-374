In one breath

A Turing machine accepts a language if it accepts exactly the strings in it, and decides it if it also halts — rejecting — on every other input; a language is decidable exactly when both it and its complement are acceptable. Running a machine built from a supposed decider on its own encoding — diagonalization — proves that SelfReject is undecidable, and the same idea (Cantor’s theorem) shows that most languages are not even acceptable. Reductions spread undecidability: assume a decider for L, use it as a black box to decide a language already known to be undecidable, and conclude that the decider cannot exist. Rice’s theorem packages the most common reduction: every non-trivial property of the language Accept(M) is undecidable. Questions about a machine’s behavior, rather than its language, can go either way.

7.1 Acceptable versus decidable

A Turing machine (§6.2) can do three things with an input: accept it, reject it, or run forever — diverge. Sorting the inputs by outcome gives four languages.

Definition — the four languages of a machine; accepting and deciding

For a Turing machine M with input alphabet Σ:

Accept(M)Reject(M)​:={w∈Σ∗∣M accepts w},:={w∈Σ∗∣M rejects w},​Halt(M)Diverge(M)​:=Accept(M)∪Reject(M),:=Σ∗∖Halt(M).​

M accepts a language L if Accept(M)=L. M decides L if moreover Diverge(M)=∅ — equivalently, Accept(M)=L and Reject(M)=Σ∗∖L.

A language is acceptable (also called semi-computable, semi-decidable, recognizable, listable, or recursively enumerable) if some Turing machine accepts it, and decidable (computable, recursive) if some Turing machine decides it.

Every decidable language is acceptable; this chapter shows that the converse fails. Acceptable and decidable are properties of a language, while accepts and decides relate a machine to a language: a machine that accepts the strings starting with 1 and loops on all others does not decide 1(0+1)∗, but another machine does, so the language is decidable.

"Does not accept" is not "rejects"

  • w∈/Accept(M) means that M rejects w or diverges on w. Every proof in this chapter has to handle both.
  • A decider must halt on every string, including strings that do not encode anything; a decider for a language of encodings rejects such garbage.
  • A machine that crashes (moves left off the end of the tape) neither accepts nor rejects, so by the definition the input lands in Diverge(M).

Concept page: acceptable-and-decidable.

7.2 Decidable without knowing the algorithm

Decidability asks whether an algorithm exists, not whether anyone can write it down. The book’s example: let

Π:={w∣the binary expansion of π contains the string 1∣w∣}.

Membership depends only on the length of w: w∈Π if and only if π has a run of at least ∣w∣ consecutive 1s.

Π is decidable — by one of infinitely many machines

Either the runs of 1s in π have bounded length, or they do not.

  • If 1N appears in π but 1N+1 does not, then Π={w∣∣w∣≤N}. A machine with N+3 states — counting states 0,1,…,N, accept, reject — decides it: it moves right, counting symbols, accepts when it reaches the blank, and rejects if it reads a symbol in state N (the input is too long).
  • Otherwise Π=Σ∗, which the machine that accepts immediately decides.

One of these machines decides Π, so Π is decidable. We just do not know which one. Since π=11.0010010000111111011…2​ shows 16 within 16 bits after the point, every string of length at most 6 is in Π; the first 4000 bits after the point contain a run of ten 1s, and none longer. Whether the runs are unbounded is an open question.

"Unknown" is not "undecidable"

Undecidability says that no single algorithm answers all of infinitely many questions correctly. Every finite language is decidable, whatever its strings are — even if nobody knows them.

7.3 Useful properties

Lemma 1

For every Turing machine M there are Turing machines MR, MA and MH such that

  • (a) Accept(MR)=Reject(M) and Reject(MR)=Accept(M) — swap the accept and reject states;
  • (b) Accept(MA)=Accept(M) and Reject(MA)=∅ — redirect every transition into the reject state to a new state hang that moves right forever;
  • (c) Accept(MH)=Halt(M) and Reject(MH)=∅ — redirect every transition into the reject state to the accept state.

(First make the “missing transitions reject” convention explicit, so that every rejection is a transition into the reject state.)

So “rejectable” and “haltable” languages are just the acceptable ones: Reject(M)=Accept(MR), Halt(M)=Accept(MH), and Accept(M)=Reject(MR)=Halt(MA).

Lemma 2

If L and L′ are decidable, then so are L∪L′, L∩L′, L∖L′ and L′∖L.

Run the two deciders one after the other on two copies of the input — each halts — and combine the answers. With Lemma 1(a), the complement Σ∗∖L of a decidable language is decidable too. The contrapositive is a tool for later:

Corollary 3

Let L′ be decidable. If L∩L′, L∪L′, L∖L′ or L′∖L is undecidable, then L is undecidable.

Lemma 4

If L and L′ are acceptable, then so are L∪L′ and L∩L′.

For L∩L′, run an acceptor M for L and then, if it accepts, an acceptor M′ for L′; if M never halts, the input is not in L anyway. For L∪L′ this serial plan fails: if M accepts the strings starting with 1 and runs forever on all others, and M′ decides the strings ending in 0, then “run M, then M′” never answers on 00. Instead run the two machines in parallel, one step of each in turn (on two tapes, or on the product of their state sets, as in the product construction), and accept as soon as either accepts.

Lemma 5

An acceptable language L is decidable if and only if Σ∗∖L is also acceptable.

Proof (click to expand)

(⇒) If M decides L, then MR (Lemma 1) decides, and in particular accepts, Σ∗∖L.

(⇐) Let M accept L and M accept Σ∗∖L. The machine D copies its input w to a second tape and runs M and M in parallel, one step each in turn; it accepts as soon as M accepts and rejects as soon as M accepts. Every string w lies in exactly one of L and Σ∗∖L, so exactly one of the two machines eventually accepts w (the other may reject or run forever; D ignores that). So D halts on every input with the right answer: it decides L. ■

Call L co-acceptable if Σ∗∖L is acceptable. Lemma 5 says: decidable = acceptable and co-acceptable. Read backwards, it gives the chapter’s first way to prove a language unacceptable:

Consequence of Lemma 5

If L is acceptable but undecidable, then Σ∗∖L is not acceptable.

7.4 Code is data; data is code

A Turing machine is a finite object, so it can be written as a string ⟨M⟩, and a machine with an input as a string ⟨M,w⟩ (§6.8). Every argument in this chapter treats machines as inputs to other machines, and relies on three properties of the encoding:

  • Unique. Different machines get different encodings, and an algorithm can tell whether a string encodes a machine.
  • Modifiable. An algorithm can turn ⟨M⟩ into the encoding ⟨M′⟩ of a related machine: swap accept and reject, redirect transitions, first erase the input and write a fixed string w, run M as a subroutine or in parallel with other machines.
  • Executable. The universal machine U accepts, rejects or diverges on ⟨M,w⟩ exactly as M does on w.

The fact every reduction uses

Computing ⟨M′⟩ from ⟨M⟩ (and a string w) is a simple algorithm that always halts — even if M′ itself would run forever on every input. Writing a program down is not running it.

7.5 Self-haters gonna self-hate

Feed machines their own encodings. Let

SelfReject:={⟨M⟩∣M rejects ⟨M⟩}.

Theorem 6

SelfReject is undecidable.

Proof of Theorem 6 — the model diagonal argument

Suppose for the sake of argument that some Turing machine SR decides SelfReject. Then SR halts on every input, and for every Turing machine M,

SR accepts ⟨M⟩⟺⟨M⟩∈SelfReject⟺M rejects ⟨M⟩.

In particular this holds for M=SR. Run SR on its own encoding. Because SR halts on every input, there are two cases.

  • If SR accepts ⟨SR⟩, the equivalence with M=SR says that SR rejects ⟨SR⟩ — a contradiction.
  • If SR rejects ⟨SR⟩, the equivalence says that SR accepts ⟨SR⟩ — a contradiction.

Both cases are impossible, so SR does not exist. ■

The decider’s row would have to be the flipped diagonal, which is no row of the table — but every machine is a row.

Where diagonal arguments go wrong

  • The contradiction comes from running the machine built from the hypothetical decider on its own encoding. Plugging in some other machine proves nothing.
  • Say why the self-run halts (the decider halts on every input); otherwise there is a third case. And name every machine — “it accepts its encoding” is ambiguous when three machines are around.

Concept page: diagonalization.

7.6 Aside: uncountable barbers

Cantor's theorem

For every set X, no function f:X→2X is onto.

Proof (click to expand)

Call x sad if x∈/f(x), and let Y:={x∈X∣x∈/f(x)} be the set of sad elements. If Y=f(y) for some y∈X, then y∈Y⟺y∈/f(y)⟺y∈/Y, which is impossible. So Y is not in the image of f. ■

Apply it with X=Σ∗ and f(w):=Accept(M) if w=⟨M⟩, f(w):=∅ otherwise. Every acceptable language is in the image of f, so not every language is acceptable. The proof even names one: Y=Σ∗∖SelfAccept (every non-encoding, and every ⟨M⟩ that M does not accept). In counting terms (§2.8, counting-arguments): countably many machines, uncountably many languages. Russell’s barber — who cuts the hair of exactly those who do not cut their own — is the same argument, with “cuts the hair of” for “accepts the encoding of”.

7.7 More self-referential languages

SelfAcceptSelfHaltSelfDiverge​:={⟨M⟩∣M accepts ⟨M⟩},:={⟨M⟩∣M halts on ⟨M⟩},:={⟨M⟩∣M diverges on ⟨M⟩}.​

Each proof builds a wrapper machine from the hypothetical one with Lemma 1 and runs it on its own encoding.

Theorem 7

SelfAccept is undecidable.

Proof (click to expand)

Suppose SA decides SelfAccept, and let SAR be SA with its accept and reject states swapped. Then SAR halts on every input, and for every machine M, SAR rejects ⟨M⟩ if and only if M accepts ⟨M⟩. Take M=SAR. If SAR accepts ⟨SAR⟩, the equivalence says that SAR rejects ⟨SAR⟩; if SAR rejects ⟨SAR⟩, the equivalence says that SAR accepts ⟨SAR⟩. Both are contradictions, so SA does not exist. ■

Theorem 8

SelfHalt is undecidable.

Proof (click to expand)

Suppose SH decides SelfHalt. Build SHX from SH by redirecting every transition into the accept state to a looping state hang, and every transition into the reject state to the accept state. On input ⟨M⟩, SH halts; so SHX runs forever if M halts on ⟨M⟩, and accepts if M diverges on ⟨M⟩. For M=SHX: SHX halts on ⟨SHX⟩ if and only if SHX diverges on ⟨SHX⟩ — a contradiction. ■

Theorem 9

SelfDiverge is not acceptable (and therefore not decidable).

Proof (click to expand)

Suppose SD accepts SelfDiverge — it need not halt on other inputs. Let SDA:=SDA (Lemma 1(b): rejections become endless loops). Then SDA accepts exactly SelfDiverge and rejects nothing, so SDA halts on an input exactly when it accepts it. For the input ⟨SDA⟩:

SDA halts on ⟨SDA⟩⟺⟨SDA⟩∈SelfDiverge⟺SDA diverges on ⟨SDA⟩,

a contradiction. The proof never needed SD to halt, which is why it rules out an acceptor, not just a decider. ■

Template — undecidability by diagonalization

Suppose for the sake of argument that some Turing machine Dec decides L.
Build a new machine Wrap from Dec: [swap Dec‘s accept and reject states / redirect its accepting transitions to a looping state / …].
Then for every Turing machine M: Wrap [accepts, or halts on] ⟨M⟩ if and only if M [does not …] ⟨M⟩.
In particular, take M=Wrap.
If Wrap [accepts] ⟨Wrap⟩, then by the line above Wrap does not [accept] ⟨Wrap⟩ — a contradiction.
If Wrap does not [accept] ⟨Wrap⟩, then by the line above Wrap [accepts] ⟨Wrap⟩ — a contradiction.
So Dec does not exist, and L is undecidable. ■

How a diagonalization proof is graded

Out of 10: 4 for the wrapper machine — built from the hypothetical decider, with its behavior on ⟨M⟩ stated — and 6 for the contradiction, 3 for each of the two cases.

7.9 The halting problem via reduction

Now let the input carry the machine and the string separately:

AcceptReject​:={⟨M,w⟩∣M accepts w},:={⟨M,w⟩∣M rejects w},​HaltDiverge​:={⟨M,w⟩∣M halts on w},:={⟨M,w⟩∣M diverges on w}.​

The universal machine shows that Accept, Reject and Halt are acceptable (run U, UR, UH).

Theorem 12

Halt is undecidable.

Proof (click to expand)

Suppose some machine H decides Halt. Build SH: on input w, reject if w is not the encoding of a machine; otherwise w=⟨M⟩, so write ⟨M,⟨M⟩⟩ on the tape and run H on it, returning its answer. SH halts on every input, and it accepts ⟨M⟩ exactly when M halts on ⟨M⟩. So SH decides SelfHalt, contradicting Theorem 8. ■

The same argument with SelfAccept, SelfReject or SelfDiverge shows that Accept, Reject and Diverge are undecidable; Diverge is not even acceptable, since its complement is (Lemma 5). The proof reduces SelfHalt to Halt: it solves SelfHalt with a solver for Halt as a subroutine. That is the general method.

The direction of a reduction

To prove that L is undecidable, reduce a known undecidable language to L: assume that some machine decides L, and use it as a black-box subroutine in a machine that decides a language already known to be undecidable. Then the assumed machine cannot exist.

Reducing L to a known undecidable language — deciding L with the help of a decider for Halt — proves nothing: every decidable language reduces to Halt too.

Template — undecidability by reduction from Accept

Suppose for the sake of argument that some Turing machine DecideL decides L.
Consider the following machine DecideAccept. Given ⟨M,w⟩, it writes the encoding ⟨M′⟩ of the machine
M′(x): [for example: ignore x; run M on w; then …]
and then runs DecideL on ⟨M′⟩ and returns its answer.
⇒ Suppose M accepts w. Then M′ […], so ⟨M′⟩∈L. So DecideL accepts ⟨M′⟩, and DecideAccept accepts ⟨M,w⟩.
⇐ Suppose M does not accept w — it rejects or diverges. Then M′ […], so ⟨M′⟩∈/L. So DecideL rejects ⟨M′⟩, and DecideAccept rejects ⟨M,w⟩.
In both cases DecideAccept is correct, and it always halts. So DecideAccept decides Accept, which is impossible.
We conclude that DecideL does not exist: L is undecidable. ■

Reductions juggle four machines

  • Name every machine and never write “it” or “the machine”: the hypothetical decider (DecideL), the decider you build (DecideAccept), its input machine (M), and the machine whose encoding you write down (M′).
  • DecideAccept never runs M′; it only writes ⟨M′⟩. M′ may run forever — that is usually the point — but DecideAccept must always halt.
  • “Does not accept” means rejects or diverges, and the second direction must cover both. If M′ runs M on w and M diverges, M′ is stuck forever.
  • Wrong direction: building a decider for L out of a decider for Accept proves nothing.

How a reduction proof is graded

Out of 10: 4 for the reduction itself — a correct description of the new decider and of M′, in the right direction — 3 for showing that a yes-instance (M accepts w) leads to acceptance, and 3 for showing that a no-instance (M rejects or diverges) leads to rejection.

Concept pages: halting-problem, undecidability-reductions.

7.10 More undecidable languages

NeverAccept:={⟨M⟩∣Accept(M)=∅}.

Theorem 13

NeverAccept is undecidable.

Proof of Theorem 13 — the model reduction

Suppose for the sake of argument that some Turing machine NA decides NeverAccept. Consider the following machine DecideAccept. Given ⟨M,w⟩, it writes the encoding ⟨Mw​⟩ of the machine

Mw​(x): erase x; write w on the tape; run M (on w).

Then DecideAccept runs NA on ⟨Mw​⟩ and returns the opposite answer (equivalently, it runs NAR). DecideAccept always halts: writing ⟨Mw​⟩ is an algorithm, and NA halts on every input.

  • Suppose M accepts w. Then Mw​ accepts every input x, so Accept(Mw​)=Σ∗=∅, so ⟨Mw​⟩∈/NeverAccept. So NA rejects ⟨Mw​⟩, and DecideAccept accepts ⟨M,w⟩.
  • Suppose M does not accept w. Then on every input x, Mw​ either rejects (if M rejects w) or runs forever (if M diverges on w); either way Accept(Mw​)=∅, so ⟨Mw​⟩∈NeverAccept. So NA accepts ⟨Mw​⟩, and DecideAccept rejects ⟨M,w⟩.

In both cases DecideAccept answers correctly, so it decides Accept — which is impossible. Hence NA does not exist. ■

Mw​ is the workhorse of reductions: Accept(Mw​) is Σ∗ or ∅, depending on what M does with w. NeverAccept is not even acceptable, by Lemma 5: its complement (Accept(M)=∅, plus garbage) is acceptable — in round t=1,2,… run M for t steps on each of the first t strings of Σ∗.

The same reduction with Reject(Mw​), Halt(Mw​) or Diverge(Mw​) in place of Accept(Mw​) shows that

NeverRejectNeverHaltNeverDiverge​:={⟨M⟩∣Reject(M)=∅},:={⟨M⟩∣Halt(M)=∅},:={⟨M⟩∣Diverge(M)=∅}​

are undecidable too (reduce from Reject, from Halt, and from Halt again: Diverge(Mw​)=∅ exactly when M halts on w). Each new undecidable language becomes a starting point for further reductions:

Theorem 14

DivergeSame:={⟨M1​⟩⟨M2​⟩∣Diverge(M1​)=Diverge(M2​)} is undecidable.

Proof (click to expand)

Suppose DS decides DivergeSame. Fix a machine Y that accepts every input at once, so Diverge(Y)=∅. The machine ND that, given ⟨M⟩, runs DS on ⟨M⟩⟨Y⟩ accepts exactly when Diverge(M)=∅. So ND decides NeverDiverge — impossible. ■

7.11 Rice’s theorem

Most of these reductions follow one pattern, and Rice’s theorem does it once and for all. A property of languages is a set L of languages; define

AcceptIn(L):={⟨M⟩∣Accept(M)∈L}.

For example, NeverAccept=AcceptIn({∅}).

Rice's theorem

Let L be a set of languages such that Accept(Y)∈L for some Turing machine Y, and Accept(N)∈/L for some Turing machine N. Then AcceptIn(L) is undecidable.

Form closer to the proof: if ∅∈/L and Accept(Y)∈L for some Turing machine Y, then AcceptIn(L) is undecidable.

Proof sketch (click to expand)

The form with ∅∈/L. Suppose AL decides AcceptIn(L). Build DecideHalt: given ⟨M,w⟩, write the encoding of

WTF(x): run M on w and ignore the result; then run Y on x and return its answer,

run AL on ⟨WTF⟩, and return its answer. If M halts on w, then WTF behaves exactly like Y, so Accept(WTF)=Accept(Y)∈L, and AL accepts. If M diverges on w, then WTF diverges on every input, so Accept(WTF)=∅∈/L, and AL rejects. So DecideHalt decides Halt, which is impossible.

The general form. If ∅∈/L, use the first form with Y. If ∅∈L, apply the first form to the complementary property L′ (all languages not in L), which does not contain ∅ and does contain Accept(N). Then AcceptIn(L′) is undecidable; it is the set of encodings minus AcceptIn(L), so AcceptIn(L) is undecidable by Corollary 3. ■

Using Rice's theorem

  1. Name the property. Write the language as AcceptIn(L) with an explicit set of languages L, and check that membership of ⟨M⟩ depends only on Accept(M): two machines with the same language must be both in or both out.
  2. Give a machine Y with Accept(Y)∈L, concretely.
  3. Give a machine N with Accept(N)∈/L, concretely.
  4. Conclude: by Rice’s theorem, AcceptIn(L) is undecidable.

Handy witnesses: MAccept​ accepts every input at once (Accept=Σ∗); MReject​ rejects every input at once (Accept=∅, Reject=Σ∗); MDiverge​ moves right forever (Accept=∅, Diverge=Σ∗).

Theorem 16

{⟨M,w⟩∣M accepts wk for every integer k≥0} is undecidable.

For a fixed string w, the property Lw​:={L∣wk∈L for every k≥0} contains Accept(MAccept​)=Σ∗ but not Accept(MReject​)=∅, which does not even contain w0=ε. So AcceptIn(Lw​) is undecidable; a decider for the language of pairs would decide it by appending the fixed w to its input.

Rice's rejection, halting, divergence and decision theorems

The same proof works for the other languages of a machine. If Reject(Y)∈L and Reject(N)∈/L for some machines Y and N, then RejectIn(L):={⟨M⟩∣Reject(M)∈L} is undecidable. Likewise HaltIn(L) (with Halt) and DivergeIn(L) (with Diverge); and if some machine Y decides a language in L and some machine N decides a language not in L, then DecideIn(L):={⟨M⟩∣M decides a language in L} is undecidable.

Choose the variant that matches the definition, and describe the witnesses by that language: NeverDiverge=DivergeIn({∅}) with Y=MAccept​ (Diverge=∅) and N=MDiverge​ (Diverge=Σ∗); NeverHalt=HaltIn({∅}) with Y=MDiverge​ and N=MAccept​.

When Rice's theorem does not apply

  • Behavior is not language. ThisIsSparta:={⟨M⟩∣M accepts SPARTA after exactly 300 steps} is decidable — simulate 300 steps. Machines that accept every input after exactly 300 and after 301 steps have the same language, but only the first is in it, so it is not a property of Accept(M).
  • Self-reference. RevAccept:={⟨M⟩∣M accepts ⟨M⟩R} depends on M‘s own encoding, so Rice does not apply; it is undecidable by a reduction. Given ⟨M,w⟩, write ⟨M′⟩ for “ignore the input; run M on w”: M′ accepts ⟨M′⟩R (and everything else) if M accepts w, and nothing otherwise.
  • Trivial properties. If every acceptable language has the property, or none does, there is no Y or no N, and the language is decidable: {⟨M⟩∣Accept(M) is acceptable} is just the set of all encodings.
  • Rice proves undecidability only, not unacceptability — for that, see §7.12.

How a proof by Rice's theorem is graded

Out of 10: 4 for a machine whose language has the property, 4 for a machine whose language does not, and 2 for the details — including stating the property as a set of languages and using the right variant of the theorem.

Concept page: rices-theorem.

7.12 The Rice–McNaughton–Myhill–Shapiro theorem

This section is optional in the book. Rice’s theorem says when AcceptIn(L) is undecidable; this theorem says exactly when it is acceptable.

Definition — monotone, compact, finitely acceptable

A set L of acceptable languages is

  • monotone if every acceptable superset of a language in L is also in L;
  • compact if every language in L has a finite subset that is also in L;
  • finitely acceptable if the language {⟨L⟩∣L∈L and L is finite} is acceptable, where ⟨L⟩ lists the strings of L.

The Rice–McNaughton–Myhill–Shapiro theorem

For every set L of acceptable languages, AcceptIn(L) is acceptable if and only if L is monotone, compact and finitely acceptable.

Lemma 17

If L is not monotone, then AcceptIn(L) is not acceptable.

Proof sketch (click to expand)

Pick machines Y and N with Accept(Y)∈L, Accept(N)∈/L and Accept(Y)⊆Accept(N) (that is what “not monotone” provides). Given ⟨M⟩, write the encoding of the machine WTF that, on input x, runs Y on x, N on x and M on ⟨M⟩ in parallel, and accepts if Y accepts x, or if N accepts x and M halts on ⟨M⟩. If M halts on ⟨M⟩, then Accept(WTF)=Accept(Y)∪Accept(N)=Accept(N)∈/L; otherwise Accept(WTF)=Accept(Y)∈L. So ⟨WTF⟩∈AcceptIn(L) exactly when ⟨M⟩∈SelfDiverge, and an acceptor for AcceptIn(L) would give an acceptor for SelfDiverge, contradicting Theorem 9. ■

Each of the following languages is not acceptable:

7.13 Turing machine behavior: it’s complicated

Rice’s theorem covers properties of the language. Properties of a machine’s behavior have no such rule, and examples go both ways.

NeverLeft:={⟨M,w⟩∣M never moves left when run on input w}.

Theorem 19

NeverLeft is decidable.

Proof (click to expand)

Simulate M on w, one step at a time. Reject as soon as M moves left. Accept if M halts. Accept once M has read more than ∣Q∣ blanks, where Q is M‘s set of states.

The last rule is the heart of the proof. While M moves only right, it reads each cell exactly once; after the input it reads only blanks that it has never written on, so each of its moves there depends on its current state alone. Among more than ∣Q∣ blank reads, two happen in the same state q. Everything M did between those two moments — all right moves — therefore repeats forever: M never halts and never moves left, and accepting is correct. The simulation stops after at most ∣w∣+∣Q∣ steps, so this is a decider. ■

LeftThree:={⟨M,w⟩∣M eventually moves left three times in a row when run on input w}.

Theorem 20

LeftThree is undecidable.

Proof sketch (click to expand)

Reduce from Accept. From ⟨M⟩, build M′ that simulates M step by step with two changes. After each simulated step, M′ moves right once and then left once, so it never makes three left moves in a row while simulating. And instead of entering the accept state, M′ moves right three times and then left three times (changing nothing), and only then accepts; the right moves first keep it from falling off the left end. So M′ moves left three times in a row on w exactly when M accepts w, and a decider for LeftThree would decide Accept. ■

LeftThree is acceptable (simulate and wait), so it sits with Halt in the left lune of the figure in §7.8; NeverLeft is decidable.

Rules of thumb for behaviors (heuristics, not theorems)

  • Probably undecidable if a machine could simulate an arbitrary Turing machine while avoiding the behavior, and show it only when the simulation accepts: reentering the start state, revisiting the left end of the tape, writing a blank, moving left three times in a row.
  • Probably decidable if the behavior confines the machine to finitely many configurations, or forces it into an endless loop after finitely many steps: ever leaving the start state, reading the whole input, writing a non-blank symbol over a blank, never moving left.

Summary

  • Accept(M), Reject(M), Diverge(M) partition Σ∗; deciding means also Diverge(M)=∅. “Does not accept” means rejects or diverges.
  • Decidable languages are closed under boolean operations, acceptable ones under ∪ (in parallel) and ∩. Decidable = acceptable and co-acceptable (Lemma 5).
  • Diagonalization: run the machine built from a hypothetical decider on its own encoding. SelfReject, SelfAccept, SelfHalt are undecidable but acceptable; SelfDiverge is unacceptable; by Cantor, most languages are.
  • Reduction: decide a known undecidable language with a hypothetical decider for L — never the other way round. Writing ⟨M′⟩ always halts; running M′ need not.
  • Halt, Accept, NeverAccept, DivergeSame, … are undecidable; Mw​ (“ignore x, run M on w”) has language Σ∗ or ∅.
  • Rice: a property of Accept(M) with a yes-machine and a no-machine is undecidable; use the variant that matches the definition. Not for behavior or self-reference. RMMS: non-monotone properties are not even acceptable.
  • Behaviors go either way: NeverLeft is decidable (∣Q∣ blanks), LeftThree is not.

On the exams

Chapters 6–9 are tested on the final exam (Dec 11) only. An undecidability proof is graded out of 10 with one of three rubrics: diagonalization (4 wrapper machine + 6 contradiction, 3 per case), reduction (4 reduction + 3 + 3 for the two directions), or Rice’s theorem (4 yes-machine + 4 no-machine + 2 details, including the right variant). Pick the tool first: a property of Accept(M) calls for Rice; self-reference or behavior calls for a reduction (usually with Mw​) or a diagonal argument. True/false practice: “every acceptable language is decidable” (false: SelfReject); “the complement of an acceptable language is acceptable” (false: SelfDiverge); ”’M has 374 states’ is undecidable by Rice’s theorem” (false: decidable — a property of the machine, not its language).
