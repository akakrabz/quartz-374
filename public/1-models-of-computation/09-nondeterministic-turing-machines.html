In one breath

A nondeterministic Turing machine may have several transitions to choose from, and its possible runs form a computation tree. It accepts an input if some branch accepts, but rejects it only if every branch rejects — an asymmetry that deterministic machines do not have. Nondeterminism adds no computing power: a deterministic machine can search the tree breadth-first (depth-first search could follow an infinite branch forever), or try every sequence of choices — every advice string — in order of length. Both simulations take exponential time, and whether that blow-up is avoidable for polynomial-time machines is the P versus NP question. The Cook–Levin theorem reduces it to a single problem: if the satisfiability of boolean formulas can be decided in polynomial time, then P = NP.

9.1 Definitions

A nondeterministic Turing machine relates to a deterministic one (§6.2) the way an NFA relates to a DFA (§4.1): the transition function returns a set of options.

Definition — nondeterministic Turing machine

A nondeterministic Turing machine N has the same components as a deterministic one — a tape alphabet Γ with a blank □, an input alphabet Σ⊆Γ∖{□}, and a finite set of states Q containing start, accept and reject — but its transition function returns a set of triples:

δ:(Q∖{accept,reject})×Γ→2Q×Γ×{−1,+1}.

In state p reading a, the machine may perform any transition (q,b,Δ)∈δ(p,a): change to state q, write b, and move by Δ. If δ(p,a)=∅, it moves to the reject state and halts.

Definition — computation tree

The computation tree of N on input w has the initial configuration (start,w,0) as its root. The children of a configuration are the configurations reachable from it by one transition, and accepting and rejecting configurations are leaves. A branch is a path from the root: either finite, ending in a leaf, or infinite. A deterministic machine’s tree is a single branch.

A running example. The machine N below accepts the strings that contain 11 by guessing where the 11 starts. Every transition moves right and rewrites the symbol it reads; when there is a choice, choice 1 is listed first.

optionschoice 1choice 2
δ(start,0)(start,0,+1)—
δ(start,1)(start,1,+1): keep scanning(got1,1,+1): guess that 11 starts here
δ(start,□)(reject,□,+1): give up(loop,□,+1): loop forever
δ(got1,0)(reject,0,+1)—
δ(got1,1)(accept,1,+1)—
δ(got1,□)(reject,□,+1)—
δ(loop,a), every a(loop,a,+1)—

On each 1, N either keeps scanning or guesses that this 1 begins 11 and checks the next symbol. At the end of the input it may give up (reject) or — a deliberately bad option — loop forever. Let N′ be the same machine without the looping option.

9.2 Acceptance and rejection

Definition — accepting, rejecting, deciding

  • N accepts w if some branch of its computation tree on w ends in an accepting configuration. Other branches may reject or run forever.
  • N rejects w if every branch ends in a rejecting configuration. Then every branch is finite, so the whole tree is finite (each configuration has finitely many children — König’s lemma): N halts within some number of steps, whatever it chooses.
  • Otherwise N neither accepts nor rejects w.

N accepts a language L if it accepts exactly the strings in L, and decides L if it accepts every string in L and rejects every string not in L.

In the example, N accepts 011 through the accepting leaf, although one of its branches never halts. On 010 no branch accepts and the looping branch never halts, so N neither accepts nor rejects 010: N accepts the strings containing 11 but does not decide that language. N′ has no looping option; on 010 every branch of N′ rejects, and N′ decides the language.

The asymmetry

  • Accepting needs one good branch; rejecting needs all branches to reject — so all of them must halt. As for deterministic machines, ”N does not accept w” is weaker than ”N rejects w”.
  • Swapping accept and reject does not complement a nondeterministic machine. With its accept and reject states swapped, N′ accepts w whenever some branch of N′ rejects w — and the branch that never guesses always does. So the swapped machine accepts every string, not the strings without 11. (For deterministic machines the swap works: Lemma 1(a) of Chapter 7.)

Theorem 1 below shows that for computability the asymmetry is harmless: nondeterministic machines accept exactly the acceptable languages and decide exactly the decidable ones, so the complement of a language decided by a nondeterministic machine is decidable — first remove the nondeterminism, then swap. With a time bound it is a real issue: whether the complement of every language in NP is in NP is a famous open question.

9.3 Time and space complexity

Definition — complexity classes

  • TIME(f(n)): the languages decided by some deterministic multi-tape Turing machine in O(f(n)) time.
  • NTIME(f(n)): the languages decided by some nondeterministic multi-tape Turing machine in O(f(n)) time — on every input of length n, every branch halts within O(f(n)) steps.
  • SPACE(f(n)) and NSPACE(f(n)): the same with O(f(n)) tape cells instead of steps.
  • P:=⋃k​TIME(nk) and NP:=⋃k​NTIME(nk).

Why multi-tape machines? The number of tapes changes running times, but only a little: t steps of a k-tape machine can be simulated in O(tlogt) steps with two tapes and in O(t2) steps with one tape, and the quadratic loss is sometimes unavoidable — marked palindromes take O(n) time with two heads but Ω(n2) with one (§6.6). Polynomial bounds survive these slowdowns, so P and NP are the same for every fixed number of tapes.

Some inclusions are free: a deterministic machine is a nondeterministic one with a single option each time, so TIME(f(n))⊆NTIME(f(n)), SPACE(f(n))⊆NSPACE(f(n)), and P⊆NP. Theorem 1, whose simulation works the same way for multi-tape machines, gives one in the other direction: NTIME(f(n))⊆⋃c​TIME(cf(n)) for f(n)≥n, so every problem in NP can be solved in exponential time. Whether P=NP is open.

9.4 Deterministic simulation via dovetailing

Theorem 1

For every nondeterministic Turing machine N there is a deterministic Turing machine M that accepts exactly the strings N accepts and rejects exactly the strings N rejects. If every branch of N on input x halts within t steps, then M halts on x within O(t2r2t) steps, where r is the largest number of options in any set δ(p,a).

The breadth-first simulation behind Theorem 1

M keeps a queue of encoded configurations on its tape, separated by markers; initially it holds only (start,x,0). Then M repeats:

  1. If the queue is empty, reject.
  2. Remove the first configuration c. If c is accepting, accept. If c is rejecting, discard it.
  3. Otherwise append the (at most r) configurations reachable from c in one transition to the end of the queue.

Correctness. The queue processes the tree level by level, and each level is finite, so every configuration at depth d is reached after finitely many rounds. If N accepts x, an accepting configuration is eventually removed, and M accepts. If N rejects x, the tree is finite and has no accepting leaf, so the queue runs empty and M rejects. In the remaining case — no accepting leaf, but an infinite branch — M runs forever, which is right, because N neither accepts nor rejects.

Why not depth-first? Backtracking — try choice 1, and only if that subtree fails, choice 2 — is the natural recursive search, but it explores the subtree of choice 1 completely before anything else. If that subtree contains an infinite branch, the search never returns, even when another choice accepts within three steps, as in the figure. Breadth-first search cannot get stuck, because it never goes deeper than level d+1 before finishing level d.

Running time. There are at most rt configurations at depth t, so the tree has O(rt) nodes (for r≥2); each configuration fits in O(t) cells (assuming t≥∣x∣), so the queue holds O(trt) symbols. With one head, copying a configuration of length O(t) to the far end of the queue takes O(t) trips of length O(trt): O(t2rt) steps per configuration, O(t2r2t) in all. With two tapes or two heads, one at each end of the queue, the copying costs O(t) per configuration and the whole simulation O(trt).

Compare the subset construction (§4.5): an NFA’s configuration is just a state, so a DFA can track the set of current states. A Turing machine’s configuration includes the whole tape, so the deterministic simulation tracks a list of whole configurations, which can grow exponentially with the running time.

9.5 Nondeterminism as advice

The choices can be supplied in advance. Number the options of every set δN​(p,a) as 1,2,… in some fixed order, and let Ω:={1,…,r}. A deterministic machine M reads its input w and also an advice string x∈Ω∗ on a separate read-only tape: at each step it reads the next advice symbol ω and performs option ω of δN​(q,a) (the last option, if there are fewer than ω). So δN​(q,a)={δM​(q,a,ω)∣ω∈Ω}, so each advice string of length t follows one branch of N‘s computation tree for up to t steps, and every branch is followed by some advice string.

The advice view of nondeterminism

  • N accepts w if and only if M accepts (w,x) for some advice string x.
  • N rejects w if and only if there is a length t such that M rejects (w,x) within t steps for every advice string x of length t.

Example. For N on 011 (with Ω={1,2}), the advice strings of length 3 that make M accept are exactly 121, 122, 221 and 222: the second step is the only real choice on the way to the accepting leaf (choice 2, “this 1 begins 11”), and the other two steps have a single option, so their advice symbols are ignored.

Trying the advice strings in order of length, and running each for as many steps as its length, is dovetailing:

Dovetail(w):
    for t ← 1, 2, 3, …
        done ← True
        for every advice string x of length t
            if M accepts (w, x) within t steps: accept
            if M has not halted on (w, x) after t steps: done ← False
        if done: reject

Correctness — a second proof of Theorem 1. If N accepts w through an accepting leaf at depth ℓ, then in every round t<ℓ the first t choices of that branch give a run that has not halted, so Dovetail does not reject; in round ℓ the branch’s own advice makes M accept. If N rejects w, its tree has some finite depth D, and in round D every run halts and none accepts, so Dovetail rejects. Otherwise it runs forever.

Running time. If every branch halts within t steps, Dovetail stops by round t, after simulating ∑s≤t​srs≤2trt steps of M (for r≥2): O(trt) time with three tapes (input, advice, work) and O(t2rt) with one tape, where each simulated step shuttles between the work area and the advice. That beats the queue simulation’s O(t2r2t): recomputing configurations from scratch is cheaper than storing them and scanning past them.

9.6 The Cook–Levin theorem

The advice view describes NP without nondeterministic machines; the advice is a certificate that w∈L — a satisfying assignment, a tour, a coloring — that a deterministic verifier can check quickly.

Definition — NP, in the form the proof uses

L∈NP if there are an integer k and a deterministic Turing machine M, the verifier, such that for every string w:

  • if w∈L, then M accepts (w,x) for some advice string x;
  • if w∈/L, then M rejects (w,x) for every advice string x;
  • M always halts within max{1,∣w∣k} steps.

SAT is the language of satisfiable boolean formulas: formulas built from variables with ∧, ∨ and ¬ for which some assignment of True/False to the variables makes the formula true.

The Cook–Levin theorem

If SAT∈P, then P=NP.

The plan. Fix L∈NP with verifier M and exponent k. Given w of length n, let N:=max{1,nk} and build a formula Φw​ that is satisfiable if and only if some advice string makes M accept (w,x) — that is, if and only if w∈L. A fast algorithm for SAT run on Φw​ then decides L.

The variables describe a run of M on w followed by an unknown advice string, for every time 0≤t≤N, state q and symbol a:

  • Qt,i,q​ — “after t steps, M is in state q with its head on cell i”;
  • Tt,i,a​ — “after t steps, cell i holds the symbol a”.

The head starts on cell 1 and moves at most N times, so cells 1,…,N+1 suffice, plus an empty sentinel cell on each side, cells 0 and N+2. At time 0, cells 1,…,n hold w, cell n+1 holds a blank, and cells n+2,…,N+1 hold the advice.

The constraints come in five kinds:

  1. Boundaries. The sentinel cells never hold the head or a symbol: all Qt,0,q​, Qt,N+2,q​, Tt,0,a​ and Tt,N+2,a​ are false.
  2. Initialization. At time 0 the head is on cell 1 in state start (and no other Q0,i,q​ is true), cells 1,…,n hold the symbols of w, and cell n+1 holds a blank.
  3. Advice. Each cell n+2,…,N+1 holds exactly one symbol at time 0 — which one is left to the satisfying assignment: this is where the formula guesses the advice.
  4. Transitions. For 1≤t≤N and 1≤i≤N+1, each variable Qt,i,q​ and Tt,i,b​ is equivalent to a formula of constant size in the time-(t−1) variables of cells i−1, i, i+1, following δ.
  5. Acceptance. Qt,i,accept​ is true for some t and i.

The transition constraints in full (click to expand)

Qt,i,q​⟺δ(p,a)=(q,⋅,+1)⋁​(Qt−1,i−1,p​∧Tt−1,i−1,a​) ∨δ(p,a)=(q,⋅,−1)⋁​(Qt−1,i+1,p​∧Tt−1,i+1,a​) Tt,i,b​⟺δ(p,a)=(⋅,b,⋅)⋁​(Qt−1,i,p​∧Tt−1,i,a​) ∨ (Tt−1,i,b​∧q∈Q⋀​¬Qt−1,i,q​)

The head is on cell i in state q exactly when it just arrived from a neighboring cell by a transition into q. Cell i holds b exactly when the head just wrote b there, or b was there before and the head was elsewhere. Once the advice cells are fixed, these equivalences force the value of every later variable, so a satisfying assignment is the run of M on w with that advice — and the acceptance constraint holds exactly when that run accepts.

Size. M is fixed, so ∣Q∣, ∣Γ∣ and δ are constants. There are (N+1)(N+3)(∣Q∣+∣Γ∣)=O(N2) variables and O(N2) constraints of constant size, plus one acceptance constraint with O(N2) literals. So Φw​ has size O(N2)=O(n2k), and an algorithm can write it down in O(n2k) time.

Conclusion. If some algorithm decides SAT in O(mc) time for formulas of size m, then building Φw​ and testing it decides w∈L in O(n2k)+O(n2kc) time, so L∈P. Since L was an arbitrary language in NP, NP⊆P; and P⊆NP always, so P=NP. ■

What the proof really shows

The construction is a polynomial-time reduction from every language in NP to SAT: w∈L if and only if Φw​∈SAT. So SAT is NP-hard — at least as hard as every problem in NP. And SAT is itself in NP (a satisfying assignment is a certificate that a verifier checks in polynomial time), so it is NP-complete. The algorithms half of the course starts from here: to prove that another problem X is NP-hard, reduce SAT (or another known NP-hard problem) to X in polynomial time — the same direction rule as for undecidability (§7.9). See Algorithms.

Reading "NP" correctly

  • NP stands for nondeterministic polynomial time, not “not polynomial”: every problem in P is in NP.
  • The definition is asymmetric, like acceptance in §9.2: yes-instances have short certificates; nothing promises short certificates for no-instances.
  • Cook–Levin is a statement about SAT; the reduction goes from an arbitrary L∈NP to SAT, never the other way.

Summary

  • A nondeterministic TM has δ(p,a)⊆Q×Γ×{−1,+1}; its runs form a computation tree rooted at (start,w,0).
  • Accept: some branch accepts (others may diverge). Reject: every branch rejects, so the tree is finite. Swapping accept and reject does not complement a nondeterministic machine.
  • TIME, NTIME, SPACE, NSPACE use multi-tape machines; the tape count costs at most a quadratic factor, so P and NP do not depend on it. P⊆NP⊆ exponential time.
  • Theorem 1: a deterministic machine accepts and rejects the same strings, by breadth-first search of the tree — O(t2r2t) on one tape, O(trt) with two. Depth-first search can get stuck on an infinite branch.
  • Advice strings x∈{1,…,r}∗ make the choices explicit; dovetailing tries all of length t for t steps, in O(trt) time with three tapes.
  • NP = languages with polynomial-time verifiers and certificates. Cook–Levin: Φw​ with variables Qt,i,q​, Tt,i,a​ and five kinds of constraints has size O(N2) and is satisfiable iff w∈L; so SAT∈P implies P=NP.

On the exams

Chapters 6–9 are tested on the final exam (Dec 11) only, and the final also covers the NP-hardness material of the algorithms half, which rests on the Cook–Levin theorem. From this chapter, know the definitions cold — they make good true/false items: “a nondeterministic machine rejects w if some branch rejects w” (false: every branch must); “swapping accept and reject in a nondeterministic decider for L gives a decider for Σ∗∖L” (false: see §9.2); “every language accepted by a nondeterministic Turing machine is acceptable” (true: Theorem 1); “depth-first search would work just as well in Theorem 1” (false); “if P=NP, then SAT∈P” (true, because SAT∈NP).
