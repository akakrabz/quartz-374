In one breath

A language is any set of strings. The regular languages are the ones built from the empty language and single strings by finitely many unions, concatenations and Kleene stars, and regular expressions are the notation for them: 0+1(0+1)∗00 describes the binary numerals (without leading 0s) of the multiples of 4. Because the definition is recursive, a proof about regular expressions is an induction with five cases — ∅, a string, S+T, ST, S∗ — and a proof about regular languages picks an expression and inducts on it. A handful of identities, including Arden’s rule for equations L=AL∪B, let you calculate with languages without any induction. And a counting argument shows that almost all languages are not regular.

2.1 Languages

Definition — language

A (formal) language over an alphabet Σ is any set of strings over Σ: any subset L⊆Σ∗. It may be finite or infinite.

Examples over {0,1}: the empty language ∅; {ε}; {0,1,10}; all of Σ∗; the palindromes; the binary numerals of prime numbers. A language is the same thing as a yes/no problem — given a string w, decide whether w∈L — and the rest of the course asks which machines can solve such problems.

Three different "empty" things

  • ∅ is the empty language: it contains no strings at all.
  • {ε} is a language with exactly one string, the empty string. It is not empty.
  • ε is a string of length 0, not a language.

They behave differently: ∅∙L=∅ but {ε}∙L=L (§2.2), and ∅∗={ε}. In a regular expression, ∅ denotes ∅ and ε denotes {ε}; a missing or extra ε is the typical “one mistake” deduction on a graded regular expression.

Concept page: languages.

2.2 Building languages

Languages are sets, so A∪B, A∩B, A∖B and A⊕B are languages, and so is the complement A:=Σ∗∖A. Two more operations use the fact that the elements are strings.

Definition — concatenation, Kleene star, Kleene plus

  • Concatenation: A∙B:={xy∣x∈A and y∈B}, usually written AB.
  • Kleene star: L∗ is the set of strings w such that either w=ε, or w=xy for some x∈L and y∈L∗. Equivalently, L∗ is the smallest superset of L that contains ε and is closed under concatenation: all concatenations of zero or more strings from L.
  • Kleene plus: L+:=L∙L∗, all concatenations of one or more strings from L.

For example, {HOCUS,ABRACA}∙{POCUS,DABRA} contains four strings: HOCUSPOCUS, ABRACAPOCUS, HOCUSDABRA and ABRACADABRA. A concatenation can have fewer than ∣A∣⋅∣B∣ strings, because different pairs can glue to the same string: {0,00}∙{0,00}={00,000,0000}. The star {0,11}∗ begins ε,0,00,11,000,011,110,… The two exceptions are ∅∗={ε}∗={ε}; for every other language, L∗ is infinite. And Σ∗ really is the star of the language Σ of one-symbol strings, so the notation of Chapter 1 is consistent.

Lemma 2.1

For all languages A, B and C:

  • (a) A∪B=B∪A;
  • (b) (A∪B)∪C=A∪(B∪C);
  • (c) ∅∙A=A∙∅=∅;
  • (d) {ε}∙A=A∙{ε}=A;
  • (e) (A∙B)∙C=A∙(B∙C);
  • (f) A∙(B∪C)=(A∙B)∪(A∙C);
  • (g) (A∪B)∙C=(A∙C)∪(B∙C).

Lemma 2.2

For every language L:

  • (a) L∗={ε}∪L+=L∗∙L∗=(L∪{ε})∗=(L∖{ε})∗={ε}∪L∪(L+∙L+);
  • (b) L+=L∙L∗=L∗∙L=L+∙L∗=L∗∙L+=L∪(L+∙L+);
  • (c) L+=L∗ if and only if ε∈L.

These identities are the algebra of regular expressions: for instance, (0+1)∗(0+1)∗ simplifies to (0+1)∗ by Lemma 2.2(a).

Identities that look true but are not

  • Concatenation is not commutative: {0}∙{1}={01}={10}={1}∙{0}.
  • Concatenation does not distribute over ∩. With A={ε,0}, B={0}, C={00}: A(B∩C)=A∙∅=∅, but AB∩AC={0,00}∩{00,000}={00}. Only A(B∩C)⊆AB∩AC holds.
  • L+=L∗ only when ε∈L: for L={0}, L+ is 00∗ and L∗ is 0∗.

Lemma 2.3 (Arden's rule)

Let A, B and L be languages with L=A∙L∪B. Then A∗∙B⊆L. Moreover, if ε∈/A, then L=A∙L∪B holds if and only if L=A∗∙B.

Proof (click to expand)

A∗B⊆L. Write A0:={ε} and An:=A∙An−1, so that A∗=⋃n≥0​An and therefore A∗B=⋃n≥0​AnB. So it suffices to show AnB⊆L for every n≥0, by induction on n. For n=0: B⊆AL∪B=L. For n≥1, assuming An−1B⊆L, we get AnB=A(An−1B)⊆AL⊆L, because L=AL∪B.

A∗B is a solution (for every A): A(A∗B)∪B=(A+∪{ε})B=A∗B by Lemma 2.1(a, d, e, g) and Lemma 2.2(a, b).

If ε∈/A, there is no other solution. Suppose L=AL∪B but L⊆A∗B, and let w be a shortest string in L∖A∗B. Since B⊆A∗B, w∈/B, so w∈AL: w=xy with x∈A and y∈L. Because ε∈/A, the string x is non-empty, so ∣y∣<∣w∣, and y∈A∗B by the choice of w. Then w=xy∈A(A∗B)⊆A∗B, a contradiction. So L⊆A∗B, and with the first part, L=A∗B. ■

Arden's rule on a single equation

As in regular expressions, a string here stands for the language that contains just that string. If L=0L∪1, then A={0} does not contain ε, so the only solution is L=0∗1. Check: 00∗1∪1=0+1∪1=0∗1.

The condition ε∈/A matters. The equation L={ε,0}∙L∪1 is solved by 0∗1 but also by Σ∗; Arden’s rule only says that {ε,0}∗1=0∗1 is the smallest solution.

Solving a DFA. Language equations turn a DFA into a regular expression. For each state q, let Lq​ be the set of strings that lead from q to an accepting state. For the odd-number-of-1s machine of §3.3:

Arden’s rule on the second equation (A=0) gives Lt​=0∗(1Ls​∪{ε})=0∗1Ls​∪0∗. Substituting into the first equation and distributing gives Ls​=(0+10∗1)Ls​∪10∗, and Arden’s rule again (ε∈/0+10∗1) gives

Ls​=(0+10∗1)∗10∗,

an expression for the strings with an odd number of 1s. Chapter 4 does the same job graphically, by state elimination.

2.3 Regular languages and regular expressions

Definition — regular language

A language L is regular if and only if it satisfies one of these conditions:

  • L is empty;
  • L contains exactly one string (which may be ε);
  • L is the union of two regular languages;
  • L is the concatenation of two regular languages; or
  • L is the Kleene star of a regular language.

So every finite language is regular (it is empty, or a union of finitely many one-string languages), and so is Σ∗. Regular expressions are the compact notation for this definition: omit the braces around one-string sets, write + for union, and write concatenation by juxtaposition.

Definition — regular expression, L(R), matching, equivalence

A regular expression is ∅, a string w (possibly ε), or S+T, ST or S∗ for regular expressions S and T, with parentheses for grouping. Its language L(R) is defined by

  • L(∅):=∅ and L(w):={w};
  • L(S+T):=L(S)∪L(T), L(ST):=L(S)∙L(T) and L(S∗):=L(S)∗.

A string w matches R if w∈L(R). Two regular expressions are equivalent if they have the same language. Precedence: ∗ binds tightest, then concatenation, then +.

Precedence

  • 10∗ means 1(0∗), the language {1,10,100,…} — not (10)∗={ε,10,1010,…}.
  • 0+1∗ means 0+(1∗), not (0+1)∗.
  • 0+1(0+1)∗00 means 0+(1(0+1)∗00): the union is applied last.

When in doubt, add parentheses; redundant ones are never wrong.

The book’s examples, all over {0,1}:

regular expressionits language: the binary strings …
0∗made of 0s only (including ε)
00000∗made of at least four 0s
(00000)∗made of 0s, a multiple of 5 of them
(0+1)∗— all of them
(ε+1)(01)∗(ε+0)that alternate: no 00 and no 11
(0+1)∗0000(0+1)∗that contain the substring 0000
((ε+0+00+000)1)∗(ε+0+00+000)without 0000: at most three 0s before each 1 and at the end
((0+1)(0+1))∗of even length
1∗(01∗01∗)∗with an even number of 0s: after the leading 1s, the 0s come in pairs
0+1(0+1)∗00that are binary numerals of multiples of 4, without leading 0s
0∗0+0∗1(10∗1+01∗0)∗10∗that are non-empty binary numerals of multiples of 3 (leading 0s allowed)

The last expression is hard to invent directly; Chapter 4 derives it by state elimination from a DFA that tracks the remainder mod 3, with a separate non-accepting start state (the three remainder states alone would also accept ε, which the expression does not match). Different expressions can describe the same language: (0+1)∗, (1+0)∗, (0∗1∗)∗ and (00+01+10+11)∗(0+1+ε) are all equivalent — union is commutative; every single symbol is in 0∗1∗; and every string splits into pairs of symbols plus at most one leftover symbol. Without the last factor, (00+01+10+11)∗ describes only the even-length strings.

By Kleene’s theorem (§3.7), the regular languages are exactly the languages that DFAs accept. Regular expressions have no symbol for ∩ or complement, but regular languages are closed under both anyway — the DFA view proves it (Corollary 3.4).

Designing a regular expression

Recipe — from a description to a regular expression

  1. List short examples, in and out of the language, including ε and every string of length 1 and 2.
  2. Find blocks. Cut a typical string into pieces that a star can repeat — runs, or chunks that end at each 1 — and handle the beginning and the end separately.
  3. Write the expression piece by piece, and explain each piece in English. Homework requires the explanation, and it is how you catch your own mistakes.
  4. Test both directions: every string the expression generates is in the language (nothing extra), and every string in the language is generated (nothing missing). Check ε explicitly.
  5. “And” is hard. Expressions have no ∩. Refine the blocks until both conditions can be read off them (Example 2), or build a product DFA and convert it (Chapter 4).

Example 1 — every 1 is immediately followed by 00

Idea. Each 1 must be followed by 00, so each 1 starts a block 100; these blocks cannot overlap, because a block’s second and third symbols are 0s. Every other symbol is a 0 standing alone.

Answer: (0+100)∗.

In English: 100 is a 1 together with the two 0s it requires; 0 is a 0 that belongs to no 1; the star allows any sequence of these blocks, in any order. The empty sequence gives ε, which is in the language because it has no 1 that could violate the condition.

Test: ε, 0, 100, 1000 and 0100100 match; 1, 10, 11 and 1001 do not, and none of them is in the language.

A wrong answer: (0∗100)∗ forces every non-empty string to end with the block 100, so it misses 0, 00, 1000 and infinitely many other strings of the language.

Example 2 — an even number of 0s and no substring 11

Idea. In a string without 11, every 1 except possibly the last symbol is immediately followed by a 0. So the string splits into blocks 0 and 10, possibly followed by one final 1: the strings without 11 are exactly (0+10)∗(ε+1). Each block contains exactly one 0 and the final 1 contains none, so the number of 0s equals the number of blocks — and it is even exactly when the blocks come in pairs.

Answer: ((0+10)(0+10))∗(ε+1).

In English: (0+10)(0+10) is two consecutive blocks, each a single 0 possibly preceded by one 1, and so contains two 0s and no 11; the star repeats such pairs; (ε+1) allows one final 1, which cannot create 11 because every block ends with 0.

Test: ε, 1, 00, 010 and 1001 match; 0, 11, 101 and 0110 do not, and none of them is in the language.

Two wrong answers: dropping (ε+1) misses 1, 001, 00001, …; and (0+10)∗(ε+1) ignores the parity, so it also matches 0, 000, 00000, …. Both are wrong on infinitely many strings.

How a regular expression is graded

Midterm-1-style exams ask for a regular expression (together with a DFA, Chapter 3) for a described language, with no proof required. The standard rubric, out of 10 points: 2 for syntax and 8 for correctness, with exam deductions twice the homework ones — 2 for one mistake (typically a missing or extra ε), 4 for a few wrong strings, and all 8 if infinitely many strings are wrong, as in each of the wrong answers above. An answer of ∅ or Σ∗ earns no credit. Homework answers must also explain each piece in English, as the examples do.

2.4 Things that aren’t regular expressions

Programming languages and editors provide regexen: patterns with many conveniences. In most of them + means “one or more”, union is written |, ? means “optional”, {2,3} means “two or three times”, [01] is a character class, and \1 refers back to an earlier group. Most of these are abbreviations — 0+ is 00∗, 0? is ε+0, 0{2,3} is 00(0+ε) — but back-references are not. The regex (.*)\1 matches exactly the strings of the form ww, and {ww∣w∈Σ∗} is not regular: 0∗1 is an infinite fooling set for it, because the suffix 0i1 completes 0i1 to a square but not 0j1 for j=i (§3.8). So a regex is not necessarily a regular expression. Shell globs (*.md, file?.txt) go the other way: they are much weaker than regular expressions.

Use only the real syntax

A regular expression in this course is built from ∅, strings (including ε), + for union, concatenation, ∗ and parentheses — nothing else. Write RR∗ for “one or more copies of R” (the regex 0+1 means 00∗1, but the regular expression 0+1 means “0 or 1”). There is no ∩, no complement, and no counter: 0n1n is not a regular expression, and {0n1n∣n≥0} is not even regular (Lemma 3.6).

2.5 Regular expression trees

Definition — expression tree, size, subexpression

A regular expression tree is a leaf labeled ∅; a leaf labeled with a string; a node labeled + or ∙ with two subtrees; or a node labeled ∗ with one subtree. (The cases mirror the definition of regular languages exactly.) The size of an expression is the number of nodes in its tree. A subexpression of R is an expression whose tree is a subtree of some tree for R; a proper subexpression is any subexpression other than R itself.

“Some tree” because concatenation and union are associative: 1(0+1)∗00 can be grouped as 1∙((0+1)∗00) or as (1(0+1)∗)∙00, and both trees are fine.

The size counts operators, including the invisible concatenations, but not parentheses: 0+1(0+1)∗00 has 11 characters but size 10, and the book’s tree for the multiples-of-3 expression 0∗0+0∗1(10∗1+01∗0)∗10∗ has 29 nodes for 22 characters.

Subexpression vs. substring. Every subexpression is a substring of R, but a substring that happens to be a well-formed expression need not be a subexpression. In the book’s example, 10∗1 is a subexpression, but 0∗0+0∗1 and 0∗1+01∗0 are not. Any expression can be parsed into its tree in linear time, so algorithms (and proofs) may assume they are handed the tree.

2.6 Proofs about regular expressions

To prove something about every regular expression, induct on its structure: the tree, not the characters. There are five cases, one for each kind of root, and the induction hypothesis covers the subtrees.

Template — induction on regular expressions

Let R be an arbitrary regular expression.
Assume that every proper subexpression of R [has the property].
There are five cases to consider.
Case R=∅. … Therefore R [has the property].
Case R is a single string w (possibly ε). … Therefore R [has the property].
Case R=S+T for some regular expressions S and T. The induction hypothesis implies that S and T [have the property]. …
Case R=ST for some regular expressions S and T. The induction hypothesis implies that S and T [have the property]. …
Case R=S∗ for some regular expression S. The induction hypothesis implies that S [has the property]. …
In all five cases, R [has the property]. ■

If structural induction feels unfamiliar, induct on the size instead: “assume every regular expression smaller than R has the property”. The cases are identical, because S and T are smaller than S+T, ST and S∗.

Lemma 2.4

If a regular expression does not use the symbol ∅, then its language is not empty.

Proof of Lemma 2.4 — the model to copy

Let R be an arbitrary regular expression that does not use ∅. Assume that every proper subexpression of R that does not use ∅ represents a non-empty language. There are five cases.

  • R=∅. This case is impossible, because R does not use ∅.
  • R is a single string w. Then w∈L(R)={w}, so L(R) is non-empty.
  • R=S+T. S is a proper subexpression of R, and it does not use ∅ because R does not. So the induction hypothesis gives a string x∈L(S), and x∈L(S)∪L(T)=L(R).
  • R=ST. Neither S nor T uses ∅, so the induction hypothesis gives strings x∈L(S) and y∈L(T). Then xy∈L(S)∙L(T)=L(R).
  • R=S∗. ε∈L(S)∗=L(R) by the definition of Kleene star. (The induction hypothesis is not needed.)

In all five cases, L(R) is non-empty. ■

The converse is false: ∅∗ and 0+∅ use ∅, yet L(∅∗)={ε} and L(0+∅)={0}.

The star case: the hypothesis covers S, not S∗

In the case R=S∗, the expression S∗ is R, so the hypothesis says nothing about it. Unrolling L(S∗)={ε}∪L(S)∙L(S∗) and then “applying the hypothesis to S∗” is circular. When the star case needs real work, use what the hypothesis gives about S, plus a second induction on the number of pieces: every string in L(S)∗ is x1​x2​⋯xk​ with each xi​∈L(S).

2.7 Proofs about regular languages

A language is just a set: it has no recursive structure to induct on, and “smaller” means nothing useful — a subset of a regular language need not even be regular ({0n1n∣n≥0}⊆(0+1)∗). So to prove that every regular language has a property, let L be regular, choose a regular expression R with L(R)=L (one exists by definition), and prove the property by induction on R.

Lemma 2.5

Every regular language other than ∅ is the language of some regular expression that does not use the symbol ∅.

Proof (click to expand)

A structural induction proves a claim about every regular expression, and the subexpressions of an expression with a non-empty language can have empty languages (the ∅ in 0+∅). So state the claim in a form that holds for all of them: for every regular expression R, either L(R)=∅, or L(R)=L(R′) for some regular expression R′ that does not use ∅. Assume the claim for every proper subexpression of R.

  • R=∅: L(R)=∅.
  • R is a string: R′=R itself.
  • R=S+T: if L(S) and L(T) are both empty, so is L(R). If only L(T) is empty, then L(R)=L(S)=L(S′) for the ∅-free S′ given by the hypothesis; symmetrically if only L(S) is empty. If neither is empty, R′=S′+T′.
  • R=ST: if L(S) or L(T) is empty, then L(R)=∅ by Lemma 2.1(c). Otherwise R′=S′T′.
  • R=S∗: if L(S)=∅, then L(R)=∅∗={ε}, so R′=ε. Otherwise R′=(S′)∗.

For a non-empty regular language L=L(R), the first alternative is impossible, so R′ is the expression the lemma asks for. For example, ∅∗ becomes ε, (0+∅)1 becomes 01, and 0∅+1∗ becomes 1∗. ■

Stating the claim so that it covers every object the hypothesis will be applied to — here every subexpression, even one with an empty language — is the same move as quantifying over all arguments in §1.4, or proving a claim for every state of a DFA in §3.3.

Structural recursion builds new expressions — reversal

Define rev(R) by recursion on R: rev(∅):=∅, rev(w):=wR, rev(S+T):=rev(S)+rev(T), rev(ST):=rev(T)rev(S) (order swapped), and rev(S∗):=rev(S)∗. A structural induction, using (xy)R=yRxR from Chapter 1, proves L(rev(R))={wR∣w∈L(R)}. So the reversal of every regular language is regular. For example, rev(0+1(0+1)∗00)=0+00(0+1)∗1.

This is one of two standard ways to prove that a transformed language is regular; the other modifies a DFA (§4.9, language-transformations).

2.8 Not every language is regular

A counting argument shows that regular languages are rare, without exhibiting a single non-regular one. Work over the one-symbol alphabet {1}.

  • Countably many regular languages. A regular expression over {1} is a string over the seven symbols 1, +, (, ), ∗, ε, ∅. Read these symbols as the digits 1 to 7 and the expression as a base-8 numeral: different expressions get different positive integers. So the regular expressions, and therefore the regular languages, can be listed in a sequence.
  • Uncountably many languages. Write each real number 0≤α<1 in binary as α=0.b1​b2​b3​… (never ending in infinitely many 1s), and let Lα​:={1n∣bn+1​=1}. Different reals have different expansions, so different α give different languages — and there are uncountably many reals in [0,1).

So all but countably many languages over {1} are not regular. The same argument works for context-free grammars (§5.6) and for Turing machines (Chapter 7). A specific non-regular language needs a specific proof: the fooling sets of §3.8. One curious example: the set of all regular expressions over {0,1} is itself a non-regular language, because its parentheses must balance — the prefixes (i and (j are distinguished by the suffix 0)i.

Summary

  • A language is any set of strings; ∅ (no strings), {ε} (one string) and ε (a string) are three different things.
  • AB, L∗ and L+ build new languages. Lemmas 2.1–2.2 are their algebra; concatenation is not commutative and does not distribute over ∩.
  • Arden’s rule: if ε∈/A, then L=AL∪B if and only if L=A∗B — enough to turn a small DFA into an expression.
  • Regular languages are built from ∅ and single strings by ∪, ∙ and ∗; regular expressions write them down, with precedence ∗, then concatenation, then +.
  • Design expressions by cutting strings into blocks; explain every piece in English; test ε and short strings in both directions.
  • An expression is really a tree; subexpressions are subtrees, not arbitrary well-formed substrings.
  • Structural induction has five cases (∅, string, S+T, ST, S∗); the claim must hold for every subexpression, even one with an empty language (Lemma 2.5). Prove facts about regular languages through an expression that represents them.
  • There are countably many regular languages but uncountably many languages.
