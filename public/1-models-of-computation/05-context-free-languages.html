In one breath

A context-free grammar is a finite set of recursive rules such as C→ε∣0C1: each nonterminal names a language, and each rule is one way to build a string of that language from strings of others. Grammars generate every regular language and more — C generates {0n1n∣n≥0}, which is not regular — and recursive automata, NFAs that call each other like subroutines, accept exactly the same languages. Every generated string has a parse tree; a grammar in which some string has two is ambiguous. Proving L(G)=L takes two inductions — everything in L is generated, everything generated is in L — with extra care for ε-rules and for nonterminals that refer to each other. Every grammar can be put in Chomsky normal form, and a counting argument shows that most languages are still not context-free.

5.1 Definitions

Regular languages are built from single strings by union, concatenation and Kleene star. Context-free languages replace the star by arbitrary recursion: a language may be defined in terms of itself, anywhere inside a rule.

Definition — context-free grammar

A context-free grammar (CFG) G=(Σ,Γ,R,S) consists of

  • Σ — a finite set of terminals: the alphabet of the strings being generated;
  • Γ — a finite set of nonterminals (variables), disjoint from Σ;
  • R — a finite set of production rules A→ω, where A∈Γ and ω∈(Σ∪Γ)∗;
  • S∈Γ — the start symbol.

Rules with the same left side are combined with a bar: C→ε∣0C1 is two rules. Conventions: a,b,c are terminals, upper-case letters are nonterminals, and w,x,y,z are strings over Σ∪Γ.

Definition — derivation, L(w), L(G), context-free language

  • If A→y is a rule, then xAz⇝xyz: one derivation step replaces one occurrence of a nonterminal by the right side of one of its rules. The surrounding x and z play no role — that is what context-free means.
  • x⇝∗z (”z derives from x”) if x=z, or x⇝y and y⇝∗z for some string y: a derivation is a sequence of zero or more steps.
  • L(w):={x∈Σ∗∣w⇝∗x} for any string w∈(Σ∪Γ)∗, and the language of the grammar is L(G):=L(S).
  • A language is context-free if it is L(G) for some context-free grammar G.

Because steps ignore their surroundings, a derivation can be carried out inside any context: if x⇝∗y, then wxz⇝∗wyz. The book’s running example is

S→A∣BA→0A∣0CB→B1∣C1C→ε∣0C1

with terminals 0,1, nonterminals S,A,B,C and start symbol S. Every nonterminal generates its own language:

nonterminalits languagewhy
C{0n1n∣n≥0}C→0C1 wraps a C-string in one more 0…1 pair
A{0m1n∣m>n}one or more extra 0s in front of a C-string
B{0m1n∣m<n}a C-string followed by one or more extra 1s

For example, 00011∈L(S):

S⇝A⇝0C⇝00C1⇝000C11⇝00011.

A grammar is a recursive definition

Read each nonterminal as the name of a language and each rule as one way to build its strings. C→ε∣0C1 says “a string of C is empty, or a string of C with a 0 in front and a 1 behind”: L(C)={ε}∪0L(C)1. A regular expression can recurse only through the star, which repeats pieces side by side; a grammar can put the recursive call between two symbols, and that nesting is exactly what lets C match every 0 with a 1.

5.2 Parse trees and ambiguity

Definition — parse tree

A parse tree for a string w∈Σ∗ (from the nonterminal A) is an ordered rooted tree in which

  • the root is labeled A — the start symbol S for a parse tree of L(G) — and every internal node is labeled with a nonterminal;
  • the children of a node labeled B spell, from left to right, the right side of some rule B→ω (a single leaf ε when the rule is B→ε);
  • the leaves are labeled with terminals or ε, and read from left to right they spell w.

A parse tree records which rules were used where, but not in which order. A derivation fixes an order, so one tree usually corresponds to many derivations — but to exactly one leftmost derivation, the one that always expands the leftmost nonterminal. The derivation of 00011 in §5.1 is the leftmost derivation of the right-hand tree above.

Definition — ambiguity

A string w is ambiguous (with respect to G) if it has more than one parse tree — equivalently, more than one leftmost derivation. A grammar is ambiguous if some string is ambiguous. A context-free language is inherently ambiguous if every grammar that generates it is ambiguous.

The grammar S→1∣S+S generates the sums 1+1+⋯+1, and it is ambiguous: 1+1+1 has two parse trees, with leftmost derivations

​S⇝S+S⇝S+S+S⇝1+S+S⇝1+1+S⇝1+1+1S⇝S+S⇝1+S⇝1+S+S⇝1+1+S⇝1+1+1​​(left tree)(right tree)​

A sum of k ones has one parse tree for each way to fully parenthesize it: 1,1,2,5,14,42,… trees for k=1,2,3,… (the Catalan numbers) — so 1+1+1+1 has five. The grammar S→1∣1+S generates the same language, (1+)∗1, with exactly one parse tree per string: it groups every sum from the right, as 1+(1+(1+1)). So ambiguity is a property of a grammar; this language is not inherently ambiguous. Inherently ambiguous languages do exist; the standard example is {aibjck∣i=j or j=k}. Its natural grammar S→XC∣AY, with L(X)={aibi}, L(Y)={bjcj}, L(A)=a∗ and L(C)=c∗, gives every anbncn two parse trees, and every other grammar for this language also has some ambiguous string (a proof beyond this course).

Two derivations are not two parse trees

To show that a grammar is ambiguous, exhibit one string with two different parse trees (or two different leftmost derivations). Derivations that merely expand nonterminals in another order build the same tree: S⇝S+S⇝1+S⇝1+1 and S⇝S+S⇝S+1⇝1+1 are two derivations of 1+1, which has only one parse tree.

5.3 From grammar to language

To prove that a grammar generates a language L, prove two inclusions, each by induction:

  • L⊆L(G): everything in L is generated — build a derivation;
  • L(G)⊆L: everything generated is in L — take a derivation apart.

For L(C)={0n1n∣n≥0} these are Lemmas 5.1 and 5.2.

Lemma 5.1

C⇝∗0n1n for every integer n≥0.

Proof of Lemma 5.1 — the model to copy

Let n be an arbitrary non-negative integer, and assume that C⇝∗0k1k for every integer k with 0≤k<n. There are two cases.

Case n=0. The rule C→ε gives C⇝ε=0010.

Case n≥1. Then 0≤n−1<n, so the induction hypothesis gives C⇝∗0n−11n−1, and

C​⇝0C1⇝∗0∙0n−11n−1∙1=0n1n.​​by the rule C→0C1by the induction hypothesis, inside the context 0  ​1​

In both cases, C⇝∗0n1n. ■

Lemma 5.2

Every string in L(C) is equal to 0n1n for some integer n≥0.

Proof of Lemma 5.2 — the model to copy

Let w be an arbitrary string in L(C), and fix a derivation C⇝∗w. Assume that every string x∈L(C) with ∣x∣<∣w∣ is equal to 0k1k for some k≥0. The derivation starts with one of the two rules for C.

Case C→ε. Then the derivation is C⇝ε, so w=ε=0010.

Case C→0C1. Then the derivation is C⇝0C1⇝∗w. The 0 and the 1 are terminals, so every later step rewrites something derived from the middle C: w=0x1 for some string x with C⇝∗x. So x∈L(C) and ∣x∣=∣w∣−2<∣w∣, and the induction hypothesis gives x=0k1k for some k≥0. Therefore w=0∙0k1k∙1=0k+11k+1.

In both cases, w=0n1n for some n≥0. ■

Together the two lemmas say L(C)={0n1n∣n≥0}. Note the asymmetry: Lemma 5.1 inducts on the parameter n and builds a derivation; Lemma 5.2 inducts on the string and has one case per rule.

Template — proving L(G)=L

  1. State the language of every nonterminal. If nonterminals use each other, the claims must be proved together, in one induction (mutual induction, below).
  2. L⊆L(G). Let w∈L be arbitrary; assume every shorter string of L is generated (or induct on a parameter, like n above). Split w into pieces that match the right side of one rule, apply the hypothesis to the pieces, and assemble a derivation S⇝ω⇝∗w.
  3. L(G)⊆L. Let w∈L(G) be arbitrary and fix a derivation of w; assume every shorter generated string is in L. Write one case per rule the derivation can start with; in each case w splits into pieces derived from the symbols of the right side, the hypothesis applies to each piece, and the pieces together satisfy the definition of L.
  4. If the grammar has ε-rules, fix a shortest derivation of w (next subsection), or induct on the length of the derivation instead of the string.

Careful with those epsilons

The grammar S→ε∣SS∣0S1∣1S0 generates exactly the strings with equally many 0s and 1s. In the case S→SS, the naive proof writes w=xy with S⇝∗x and S⇝∗y — but nothing forces x and y to be shorter than w: one of them may be ε and the other w itself. Derivations can be arbitrarily long without making the string longer, as in S⇝SS⇝S⇝SS⇝S⇝⋯⇝0S1⇝01, and even ε has infinitely many parse trees. The fix is to pick the derivation carefully.

Lemma 5.3

For the grammar S→ε∣SS∣0S1∣1S0, every string w∈L(S) satisfies #(0,w)=#(1,w).

Proof (click to expand) — induction with a shortest derivation

Let w be an arbitrary string in L(S), and fix a derivation S⇝∗w with the fewest possible steps. Assume that #(0,x)=#(1,x) for every string x∈L(S) with ∣x∣<∣w∣. There are four cases, by the first rule of the derivation.

  • S→ε. Then w=ε, and #(0,ε)=0=#(1,ε).
  • S→0S1. Then w=0x1 with S⇝∗x and ∣x∣<∣w∣, so the hypothesis gives #(0,x)=#(1,x), and #(0,w)=#(0,x)+1=#(1,x)+1=#(1,w).
  • S→1S0. Symmetric.
  • S→SS. Every later step rewrites a symbol derived from the left S or one derived from the right S, so the remaining steps split into a derivation S⇝∗x and a derivation S⇝∗y with w=xy. If x were ε, the derivation S⇝∗y=w alone would be a derivation of w with fewer steps (it skips at least the first step), contradicting our choice. So x=ε, and likewise y=ε. Hence ∣x∣<∣w∣ and ∣y∣<∣w∣, the hypothesis applies to both, and #(0,w)=#(0,x)+#(0,y)=#(1,x)+#(1,y)=#(1,w).

In every case, #(0,w)=#(1,w). ■

The difficulty comes only from nullable nonterminals (A⇝∗ε) and cycles of unit rules (A⇝∗B⇝∗A): they are what let a derivation grow longer without the string growing. Inducting on the length of the derivation instead of the length of the string sidesteps the issue in every grammar. The other inclusion — every balanced string is generated — uses the decomposition in §5.4.

Mutual induction

When nonterminals refer to each other, no claim about one of them can be proved alone.

Lemma 5.4

For the grammar S→0A1∣ε, A→1S0∣ε: L(S)=(01)∗ and L(A)=(10)∗.

Proof (click to expand) — both claims in one induction

Let w be an arbitrary string, and assume both claims for every shorter string: for every x with ∣x∣<∣w∣, x∈L(S)⟺x∈(01)∗ and x∈L(A)⟺x∈(10)∗. We use (01)n=0(10)n−11 and (10)n=1(01)n−10 for n≥1.

  • w∈L(S)⇒w∈(01)∗. A derivation of w from S starts with S→ε (then w=ε) or with S→0A1 (then w=0x1 with x∈L(A); by the hypothesis about A, x=(10)k, so w=0(10)k1=(01)k+1).
  • w∈(01)∗⇒w∈L(S). If w=ε, use S→ε. Otherwise w=(01)n=0(10)n−11 with n≥1; the hypothesis about A gives A⇝∗(10)n−1, so S⇝0A1⇝∗w.
  • The two claims about A are the same arguments with 0 and 1 exchanged, using the hypothesis about S.

So both claims hold for w. ■

Each grammar comes from decomposing a typical string of the language:

  • Non-palindromes. Compare w with wR from the outside in; at the first (outermost) mismatch, w=xazbxR with a=b. The rules S→0S0∣1S1 build the matching outside x⋯xR, 0Z1 and 1Z0 place the mismatch, and Z fills in an arbitrary middle z.
  • Equally many 0s and 1s. A non-empty such string splits after its shortest non-empty prefix with equal counts. That prefix starts and ends with different symbols, and its middle and the rest of w are again balanced — for example 00111001=0⋅01⋅1⋅1001. That is the rule S→0S1S∣1S0S, and it proves the missing inclusion of Lemma 5.3. (The rules do not force the shortest prefix, so this grammar is still ambiguous: 0101 splits as 0⋅ε⋅1⋅01 or 0⋅10⋅1⋅ε.)
  • More 0s than 1s. Cut w after the first prefix with exactly one more 0 than 1s: w=x0y with x balanced and #(0,y)≥#(1,y). That is O→E0O∣E0E.
  • Expressions. Sums of terms, products of factors: the grammar is unambiguous, and its parse trees respect precedence and grouping — X+Y×X parses as X+(Y×X), X×Y+X as (X×Y)+X, and X+Y+X as (X+Y)+X.

Designing a grammar

Recipe — from a description to a grammar

  1. List short strings in and out of the language, including ε.
  2. Decompose a typical string: by an outer pair of matching symbols (nesting), at the first point where some count balances, or by cases — a union gets one nonterminal per case.
  3. Give each piece a nonterminal and describe its language in English, in a sentence that makes sense on its own.
  4. Write the rules and check each one against the descriptions: the strings a rule builds must be in the left side’s language (nothing extra), and every string of that language must be buildable by some rule (nothing missing).
  5. Test: derive a few strings, and check ε and the short strings that should be rejected.

Example 1 — {0i1j∣i≤j≤2i}: every 0 is matched by one or two 1s

Idea. Match the outer 0s with one 1 each and the inner 0s with two 1s each: 0i1j=0a(0b12b)1a with a=2i−j and b=j−i, and both are non-negative exactly when i≤j≤2i.

Answer: S→0S1∣T, T→0T11∣ε.

In English: T generates {0b12b∣b≥0}, the strings in which every 0 is matched by exactly two 1s. S generates the strings 0ax1a with x∈L(T), that is, 0a+b1a+2b for a,b≥0 — exactly the language.

Test: ε, 01, 011, 0011, 00111, 001111 are generated; 0, 1, 001, 0111, 0101 are not, and none of them is in the language.

Variants. S→0S1∣0S11∣ε is also correct, but ambiguous (00111 has two parse trees) — which costs nothing. S→0S1∣0S11∣01∣011 misses only ε: one mistake. S→0S1∣S1∣ε generates all of {0i1j∣j≥i}, including 0111, 01111, …: infinitely many wrong strings.

Example 2 — binary strings that are not of the form 0n1n

Idea. By cases: a string that is not 0n1n is either 0m1n with m=n — the running example — or not of the form 0∗1∗ at all, which means it contains the substring 10 somewhere.

Answer: S→A∣B∣N, with A, B, C as in §5.1, N→X10X, X→ε∣0X∣1X.

In English: X generates every binary string; N the strings containing 10, which are exactly the strings not in 0∗1∗; C, A, B the strings 0m1n with m=n, m>n, m<n; and S the union of L(A), L(B), L(N) — every string except 0n1n.

Test: 0, 1, 10, 001, 0110 are generated; ε, 01, 0011 are not. Forgetting N is the classic error: S→A∣B alone misses 10, 110, 0110 and every other string containing 10.

So the complement of {0n1n} is context-free too — but complements do not always behave this well (§5.6).

Describe every nonterminal — and mind the tree, not just the strings

  • On homework, every nonterminal needs a self-contained description of its language (”E generates the strings with equally many 0s and 1s”), not of its role (”E is the middle part”). Writing the descriptions is also how you find your own bugs.
  • A grammar can generate exactly the right strings and still be wrong for an application, because its parse trees have the wrong structure. The simple grammar S→0∣1∣S+S∣SS∣S∗∣(S) generates exactly the regular expressions over {0,1} that do not use ∅ or ε — yet it also parses 0∗+1∗ as if it were (0∗+1)∗.

The fix builds precedence into the grammar, exactly like the expression grammar: a regular expression is a sum of terms, a term is a concatenation of factors, and a factor is a starred atom.

S→S+T∣TT→TF∣FF→F∗∣(S)∣0∣1

generates the same strings, has one parse tree per string, and parses 0∗+1∗ as (0∗)+(1∗). Here S generates all the expressions, T the expressions with no + outside parentheses, and F the single atoms — 0, 1 or a parenthesized expression — followed by zero or more stars.

How a grammar is graded

Grammars are graded like regular expressions: out of 10 points, 2 for syntax and 8 for correctness, with exam deductions twice the homework ones — 2 for one mistake (typically a missing or extra ε), 4 for a few wrong strings, all 8 if infinitely many strings are wrong, as in the last variant of Example 1. A grammar for ∅ or Σ∗ earns nothing. Homework also requires the English description of every nonterminal’s language. Ambiguity is not penalized: an ambiguous grammar that generates the right language gets full credit.

5.5 Regular languages are context-free

Every regular language is context-free

Induct on a regular expression R for the language (structural induction). Build grammars for the subexpressions first, with disjoint sets of nonterminals and start symbols S1​, S2​, and add a new start symbol S:

a correct but wordy grammar; by hand, S→0∣1X00, X→ε∣0X∣1X says the same thing.

The inclusion is strict: {0n1n∣n≥0} is context-free (it is L(C)) but not regular — 0∗ is an infinite fooling set for it (Lemma 3.6, §3.8).

The same three constructions work for any two grammars with disjoint nonterminals, so context-free languages are closed under union, concatenation and Kleene star. Reversing the right side of every rule reverses the language — the running example becomes a grammar for {1n0m∣m=n} — so they are closed under reversal as well.

5.6 Not every language is context-free

The counting argument of §2.8 works for grammars too. Write a grammar as a string — terminals, nonterminals numbered in binary, arrows, bars and separators — and encode each character in binary: different grammars become different binary strings and hence, with a leading 1, different positive integers. So there are only countably many context-free languages over a fixed alphabet, but uncountably many languages: almost every language is not context-free.

A specific non-context-free language needs a specific proof, and those proofs are beyond this course. The canonical example is

{0n1n0n∣n≥0}.

Why 0n1n0n is out of reach

Grammars match symbols by nesting (C→0C1 pairs each 0 with a 1), and recursive automata (§5.7) do the same with a stack. Once the 1s have been matched against the first block of 0s, the count is used up — nothing is left to compare with the last block. (A Turing machine can go back and check; Chapter 6 opens with one for exactly this language.)

Closure: intersection and complement fail

{0i1i0j∣i≥1,j≥0} (S→CR, C→0C1∣01, R→0R∣ε) and {0i1j0j∣i≥0,j≥1} (S→PD, P→0P∣ε, D→1D0∣10) are context-free. A string in both contains a 1, so it is 0a1b0c with b≥1, a=b and b=c: the intersection is {0n1n0n∣n≥1}, which is not context-free (a grammar for it plus S′→S∣ε would generate the canonical example). So context-free languages are not closed under intersection — and therefore not under complement either, since they are closed under union and L1​∩L2​=L1​​∪L2​​​.

The forced 1s matter: without them, both languages contain every string 0k, and so does their intersection.

5.7 Recursive automata

Grammars have a machine model too. Think of each nonterminal as a subroutine: an NFA that may, in the middle of its run, call another NFA (or itself) and continue when the call returns.

Definition — recursive automaton

A recursive automaton has an input alphabet Σ, a finite set N of module names with a main name S∈N, and for each A∈N a module MA​: an NFA whose edges are labeled with symbols of Σ, with ε, or with module names, with a start state sA​ and a single accepting state tA​. Different modules have disjoint sets of states.

A configuration is a triple (x,q,σ): the unread input x, the current state q, and a stack σ of states to return to, written as a string with its top first. Writing qℓ​p for an edge from q to p labeled ℓ, one move from (x,q,σ) is

  • read: if x=ax′ and qa​p, go to (x′,p,σ);
  • ε-move: if qε​p, go to (x,p,σ);
  • call: if qA​p for a module name A, push p and jump to A‘s start state: (x,sA​,pσ);
  • return: if q=tA​ for some module A and σ=pσ′, pop: (x,p,σ′).

It accepts w if some sequence of moves leads from (w,sS​,ε) to (ε,tS​,ε).

An accepting run on 001 (stacks written top first):

configuration (x,q,σ)move
(001, sS​, ε)start
(01, a, ε)read 0
(01, sE​, tS​)call E on the edge a→tS​: push tS​
(1, c, tS​)read 0
(1, sE​, d tS​)call E on the edge c→d: push d
(1, tE​, d tS​)ε-move
(1, d, tS​)return: pop d
(ε, tE​, tS​)read 1
(ε, tS​, ε)return: pop tS​ — accept

The stack of return states is what lets the machine count, and why recursive automata are more powerful than NFAs. (Most other textbooks use pushdown automata, NFAs with an explicit stack; they accept the same languages.)

Lemma 5.5

Every context-free language is accepted by a recursive automaton.

Construction. One module per nonterminal A. For each rule A→X1​X2​⋯Xk​, add a path of k edges from sA​ to tA​ labeled X1​,…,Xk​ — an edge labeled with a terminal reads it, an edge labeled with a nonterminal calls that module — and for each rule A→ε an ε-edge from sA​ to tA​. Module E in the figure is exactly this construction for E→0E1∣ε. An accepting run then traces a parse tree: each call is a node, and its module’s path spells the node’s children.

Together, Lemmas 5.5 and 5.6 say: a language is context-free if and only if some recursive automaton accepts it.

5.8 Chomsky normal form

Definition — Chomsky normal form (CNF)

A grammar is in Chomsky normal form if the start symbol S appears on the right side of no rule, the rule S→ε is allowed, and every other rule has one of two forms:

A→BC(two nonterminals)orA→a(one terminal).

Parse trees in CNF are binary. In a parse tree of a string of length n≥1, each of the n leaves hangs below its own node A→a, and the nodes A→BC form a full binary tree whose leaves are those n nodes — so there are n−1 of them, and 2n−1 nonterminal nodes in all. Each derivation step expands one nonterminal node, so every derivation of a string of length n≥1 has exactly 2n−1 steps.

So membership is decidable by brute force: try every derivation with 2n−1 steps. Much better is dynamic programming. For every substring w[i..j], shortest first, compute the set of nonterminals that derive it: A derives the single symbol wi​ if A→wi​ is a rule, and A derives w[i..j] with i<j if some rule A→BC and some split i≤k<j have B⇝∗w[i..k] and C⇝∗w[k+1..j]. Then w∈L(G) if and only if S derives w[1..n] (or w=ε and S→ε is a rule). There are O(n2) substrings with O(n) splits each, so this CYK algorithm (Cocke–Younger–Kasami) takes O(n3) time for a fixed grammar — dynamic programming, as in the algorithms half of the course.

5.9 The CNF conversion algorithm

Theorem 5.7

Every context-free grammar of total length L can be converted, in O(L2) time, into an equivalent grammar in Chomsky normal form of total length O(L2).

The conversion, step by step

  1. New start symbol. Add S′→S, so that the start symbol appears on no right side. (Needed only if S appears on a right side or derives ε; otherwise S′→S is dropped again after step 2, as in the example below. The book drops S′ after step 2 whenever S′ is not nullable, but if S is on a right side, as in S→0S∣1, that leaves the start symbol on a right side, which CNF forbids.)
  2. Split long rules. Replace A→Xα, where X is one symbol and ∣α∣≥2, by A→XB and B→α for a new nonterminal B; repeat until every right side has length at most 2.
  3. Find the nullable nonterminals (A⇝∗ε): A is nullable if some rule A→ω has only nullable symbols on the right (in particular if A→ε); repeat until nothing changes.
  4. Remove ε-rules. For each rule, add every non-empty variant obtained by deleting some occurrences of nullable nonterminals; then delete every rule A→ε, and add S′→ε if S′ is nullable (the only ε-rule of the result).
  5. Merge equivalent nonterminals: those that derive each other by unit rules (A⇝∗B⇝∗A) — the strong components of the graph of unit rules A→B — and delete every rule A→A (merging creates them, and so does step 3, e.g. S→S from S→SS).
  6. Remove unit rules. The unit-rule graph is now acyclic. Process the nonterminals so that B comes before A whenever A→B (reverse topological order), replacing each A→B by copies of all of B‘s rules. Copying can cost Θ(nL) time for n nonterminals, and this step dominates the O(L2) of Theorem 5.7.
  7. Protect terminals. For each terminal a, add a new nonterminal Ta​→a and replace a by Ta​ in every right side of length 2.

Steps 3 and 5 are where conversions go wrong

  • Step 3 adds a variant for every subset of nullable occurrences: from A→BC with both nullable, add A→B and A→C (never A→ε).
  • Step 5 copies the rules of B as they are after B has been processed; in the wrong order, a unit rule can be copied into A and survive.

Summary

  • A grammar (Σ,Γ,R,S) is a recursive definition; L(G) is the set of terminal strings derivable from S.
  • Each parse tree corresponds to one leftmost derivation. A grammar is ambiguous if some string has two parse trees; a language is inherently ambiguous if every grammar for it is.
  • L(G)=L takes two inductions: build derivations (L⊆L(G)) and take them apart, one case per rule (L(G)⊆L). With ε-rules use a shortest derivation; with mutually recursive nonterminals prove all claims together.
  • Design by decomposing a typical string — nesting, first balance point, or cases — and describe the language of every nonterminal in English.
  • Regular ⊊ context-free; context-free languages are closed under union, concatenation, star and reversal, but not under intersection or complement.
  • Counting: only countably many context-free languages. {0n1n0n} is the canonical language that is not context-free.
  • Recursive automata (NFAs that call each other) accept exactly the context-free languages.
  • Every grammar converts to Chomsky normal form (A→BC, A→a), where every parse tree of a length-n string has 2n−1 nonterminal nodes and membership takes O(n3) time by dynamic programming.

On the exams

Midterm 1 (Sep 28) covered context-free languages and grammars. On Midterm-1-style exams a grammar is usually asked together with a fooling-set proof that the same language is not regular (§3.8): the language is context-free but not regular, like {0n1n} or Example 1 above (for which F=0∗ works: name two of its strings 0i and 0j with i<j; then 1i distinguishes them). The grammar is graded with the rubric in §5.4 — syntax, correctness, and on homework an English description of every nonterminal; ambiguity is not penalized. True/false items test the big picture: “every regular language is context-free” (true), “the intersection of two context-free languages is context-free” (false, §5.6), “if a grammar is ambiguous, its language is inherently ambiguous” (false — S→1∣S+S).
