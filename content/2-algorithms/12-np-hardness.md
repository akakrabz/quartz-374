> [!abstract] In one breath
> A decision problem is in **P** if it can be solved in polynomial time, in **NP** if every YES answer has a short proof — a **certificate** — that can be checked in polynomial time, and in **co-NP** if every NO answer has one; $\textsf{P}\subseteq\textsf{NP}\cap\textsf{co-NP}$, and whether $\textsf{P} = \textsf{NP}$ is open. A problem is **NP-hard** if a polynomial-time algorithm for it would give one for every problem in NP, and **NP-complete** if it is NP-hard and in NP. The **Cook–Levin theorem** supplies the first NP-hard problem, circuit satisfiability; every other one is proved NP-hard by a **reduction**: an algorithm that transforms an *arbitrary* instance of a problem $X$ already known to be NP-hard into an instance of the new problem $Y$, in polynomial time, so that YES maps to YES and NO maps to NO — always **from** the known problem **to** the new one. The chapter builds a web of such reductions — CircuitSat → Sat, CircuitSat → 3Sat → independent set → clique and vertex cover → Hamiltonian cycle and subset sum, and 3Sat → 3-coloring and Hamiltonian cycle — each from **gadgets** that encode pieces of the input, each proved correct in both directions, and closes with a catalog of NP-hard problems, rules of thumb for choosing one to reduce from, and the classes beyond NP.

## 12.1 A game you can't win

> [!definition] Definition — boolean circuit, CircuitSat
> A **boolean circuit** is a directed acyclic network of **And**, **Or** and **Not** gates, joined by wires, with $n$ input wires and one output wire. **CircuitSat** (circuit satisfiability): given a boolean circuit, is there an assignment of True/False to its inputs that makes the output True? Equivalently: does the circuit *not* always output False?

For any one input, the output is computed in linear time — evaluate the gates in topological order (depth-first search, [[2-algorithms/06-depth-first-search#63-topological-sort|§6.3]]). So the obvious algorithm tries all $2^n$ inputs, in $O(2^n\cdot\text{size})$ time. Nobody knows anything substantially faster, and nobody has proved that nothing faster exists. The book's story is a salesman who offers a fortune for the right answer about a sealed box of switches and a light bulb: with the box sealed, only testing all $2^n$ settings is safe against an adversary, and even with the full wiring diagram in hand, no one knows how to answer faster.

## 12.2 P versus NP

An algorithm is called **efficient** if its running time is $O(n^c)$ for a constant $c$, where $n$ is the **size of the input** — the number of bits needed to write it down (this matters as soon as the input contains numbers, §12.12). A **decision problem** is one whose answer is a single bit, YES or NO.

> [!definition] Definition — P, NP, co-NP
> - **P** is the set of decision problems that can be solved in polynomial time.
> - **NP** is the set of decision problems such that whenever the answer is YES, there is a proof of that fact — a **certificate** — that can be checked in polynomial time.
> - **co-NP** is the set of decision problems such that whenever the answer is NO, there is a certificate of that fact that can be checked in polynomial time.

**CircuitSat is in NP**: a satisfying input is a certificate, and checking it means evaluating the circuit. No short certificate is known for "this circuit is *not* satisfiable", so CircuitSat is not known to be in co-NP — nor in P. **Every problem in P is in NP and in co-NP**: the checker can ignore the certificate and solve the problem from scratch. The formal definitions, with Turing machines and advice strings, are in Part 1 ([[1-models-of-computation/09-nondeterministic-turing-machines#93-time-and-space-complexity|§9.3]], [[1-models-of-computation/09-nondeterministic-turing-machines#96-the-cooklevin-theorem|§9.6]]); §12.4 sketches them.

| class | short certificate for | example |
|---|---|---|
| P | (none needed: solve it) | is there an $s$–$t$ path? |
| NP | every YES instance | is this circuit satisfiable? (the satisfying input) |
| co-NP | every NO instance | is this circuit unsatisfiable? (the satisfying input proves NO) |

Two questions are open. **Is $\textsf{P} = \textsf{NP}$?** — the first of the Clay Institute's Millennium Prize Problems; almost everyone believes $\textsf{P}\neq\textsf{NP}$, but there has been essentially no progress toward a proof, and known *barrier results* show that whole families of proof techniques cannot work. **Is $\textsf{NP} = \textsf{co-NP}$?** — believed false as well: being able to check YES answers quickly gives no obvious way to check NO answers. The book's picture of "what we think the world looks like": P inside both NP and co-NP, which overlap but differ.

> [!trap] Reading the definitions
> - **NP is not "not polynomial"**: it stands for *nondeterministic polynomial time*, and $\textsf{P}\subseteq\textsf{NP}$. Calling a problem "in NP" is an *upper* bound on its difficulty, not a claim that it is hard.
> - **The definitions are about decision problems.** "Find the largest independent set" is not in NP; "is there an independent set of size $k$?" is.
> - **co-NP is not the complement of NP.** P lies in both.

## 12.3 NP-hard, NP-easy and NP-complete

> [!definition] Definition — NP-hard, NP-easy, NP-complete
> A problem $\Pi$ is **NP-hard** if a polynomial-time algorithm for $\Pi$ would imply a polynomial-time algorithm for every problem in NP:
> $$
> \Pi \text{ is NP-hard} \iff \bigl(\Pi \text{ can be solved in polynomial time} \implies \textsf{P} = \textsf{NP}\bigr).
> $$
> A problem is **NP-complete** if it is NP-hard **and** in NP — the book also calls membership in NP being **NP-easy**. (More generally, NP-easy means solvable in polynomial time with a subroutine for some problem in NP; that is how optimization problems such as "find the largest independent set" get the label. In that broader sense, NP-hard and NP-easy together do not make a problem NP-complete: UnSat (§12.4) is both, but it is in NP only if $\textsf{NP} = \textsf{co-NP}$.)

NP-hard problems are *at least as hard* as everything in NP; NP-complete problems are the hardest problems *in* NP. A polynomial-time algorithm for any one NP-complete problem would give one for all of them — and thousands are known — which is why nobody expects one. Calling a problem NP-hard is, in the book's comparison, like saying "if I own a dog, it speaks fluent English": nobody can prove the conclusion false, but nobody believes it, and so nobody should believe the hypothesis either.

NP-hard problems need not be in NP: optimization problems, problems in co-NP such as "is this circuit unsatisfiable?" (NP-hard under the book's definition: a polynomial-time algorithm for it, with the answer flipped, decides CircuitSat), and even undecidable problems such as the halting problem are NP-hard.

That any problem at all is NP-hard is a theorem, proved by Stephen Cook (1971) and independently by Leonid Levin (1973):

> [!key] The Cook–Levin theorem
> Circuit satisfiability is NP-hard.

The book states it without proof. Part 1 proves the same theorem for formulas — if $\textsf{SAT}\in\textsf{P}$ then $\textsf{P} = \textsf{NP}$ — by building, from any polynomial-time verifier and input $w$, a formula $\Phi_w$ that is satisfiable exactly when some certificate makes the verifier accept ([[1-models-of-computation/09-nondeterministic-turing-machines#96-the-cooklevin-theorem|§9.6]], [[concepts/cook-levin-theorem]]). A formula is a circuit in which every gate feeds just one other, so a fast algorithm for CircuitSat would decide Sat too: the two versions are equivalent. Since CircuitSat is also in NP, it is NP-complete.

## 12.4 Formal definitions

This section is ♥ in the book (and headed "here be dragons"); it fixes what the informal definitions leave vague.

- **Problems are languages.** A decision problem is a language $L\subseteq\{\mathtt{0},\mathtt{1}\}^*$, the set of encodings of its YES instances. **P** is the set of languages decided in polynomial time by a deterministic single-tape Turing machine; **NP** is the set decided in polynomial time by a *nondeterministic* one ([[1-models-of-computation/09-nondeterministic-turing-machines|Part 1, Chapter 9]]). The exact machine model does not matter: an algorithm that runs in $T(n)$ time on a random-access machine can be simulated on a single-tape Turing machine in $O(T(n)^4)$ time, so polynomial stays polynomial and we may argue with arrays, loops and recursion.
- **Cook reductions.** Formally, $\Pi$ is NP-hard if every language in NP has a **polynomial-time Turing reduction** to $\Pi$: a polynomial-time algorithm for it that may call a black-box subroutine for $\Pi$ (an *oracle*), any number of times, and use the answers in any way. These are also called **oracle** or **Cook reductions**.
- **Karp reductions.** Complexity theorists prefer **polynomial-time many-one** (**Karp**) **reductions**: a function $f$, computable in polynomial time, with $x\in L'\iff f(x)\in L$. That is a Cook reduction that calls the oracle exactly once, on $f(x)$, and returns its answer unchanged. Every Karp reduction is a Cook reduction, but not, as far as anyone knows, the reverse.

Why the preference: NP is closed under Karp reductions (if $L'$ reduces to $L\in\textsf{NP}$, then $L'\in\textsf{NP}$), but not under Cook reductions unless $\textsf{NP} = \textsf{co-NP}$. The standard example is **UnSat** — is this formula always false? — which is NP-hard under Cook reductions (flip the answer of an UnSat oracle) but NP-hard under Karp reductions only if $\textsf{NP} = \textsf{co-NP}$ (UnSat is in co-NP). On the other hand, many-one reductions apply only to decision problems, so strictly no optimization problem is Karp-NP-hard. Cook and Karp originally used even weaker *logarithmic-space* reductions; every reduction in the chapter is of that kind, and **all of them are Karp reductions**, which is the form the course asks for.

## 12.5 Reductions and SAT

**Reducing** problem $A$ to problem $B$ means solving $A$ with an algorithm for $B$ as a subroutine — you have done that since your first program. NP-hardness proofs use reductions in the direction most people do not expect:

> [!key] The direction rule
> **To prove that problem $A$ is NP-hard, reduce a known NP-hard problem to $A$.**
>
> That is: describe an efficient algorithm for the known hard problem that uses a hypothetical efficient algorithm for $A$ as a black box. If $A$ were easy, the known problem would be easy, which it is not (unless $\textsf{P} = \textsf{NP}$).

> [!trap] The direction trap
> - **Reducing $A$ to a known NP-hard problem proves nothing about $A$**: every problem in NP — including every problem in P — reduces to Sat. On exams a reduction in the wrong direction is worth at most 1 point of 10.
> - It is the same rule as for undecidability, where a decider for the new language is used to decide $\textsf{Accept}$ or $\textsf{Halt}$ ([[1-models-of-computation/07-undecidability#79-the-halting-problem-via-reduction|§7.9]], [[concepts/undecidability-reductions]]). Two differences: an NP-hardness reduction must run in **polynomial time**, and (as a Karp reduction) it calls the black box once and returns its answer **unchanged**.

The canonical second NP-hard problem is formula satisfiability.

> [!definition] Definition — Sat
> **Sat**: given a boolean formula — variables combined with $\land$, $\lor$, $\lnot$ and other connectives such as $\Rightarrow$, $\Leftrightarrow$, $\neq$ — is there an assignment of True/False to the variables that makes the formula True? The book's example input:
> $$
> (a\lor b\lor c\lor \bar d)\Leftrightarrow\bigl((b\land\bar c)\lor(\bar a\Rightarrow d)\lor(c\neq a\land b)\bigr).
> $$

> [!key] Theorem — Sat is NP-hard (reduction from CircuitSat)
> **Reduction.** Given an arbitrary boolean circuit $K$, label each interior wire with a new variable $y_j$ and the output wire with a new variable $z$, and output the formula $\Phi$ that is the conjunction of one equation per gate, "(output of the gate) = (the gate applied to its inputs)", followed by $\land\, z$.
>
> **⇒ (YES maps to YES).** Given an input that satisfies $K$, compute the value of every wire; with those values for the $y_j$ and $z$, every equation and $z$ hold, so $\Phi$ is satisfied.
>
> **⇐ (only YES comes from YES).** Given a satisfying assignment of $\Phi$, the equations force each $y_j$ and $z$ to be the value of its wire on the input part of the assignment, and $z$ is True; so that input satisfies $K$ — just ignore the $y_j$ and $z$.
>
> **Polynomial time.** One equation of constant size per gate: linear time, and $\Phi$ is a constant factor larger than $K$. So $T_{\textsf{CircuitSat}}(n)\le O(n) + T_{\textsf{Sat}}(O(n))$, and a polynomial-time algorithm for Sat would decide CircuitSat in polynomial time.

For the circuit of the figure above, with interior wires $y_1, \dots, y_7$ and output $z$ (the book's Figure 12.5):
$$
\begin{aligned}
&(y_1 = x_1\land x_4)\land(y_2 = \bar x_4)\land(y_3 = x_3\land y_2)\land(y_4 = y_1\lor x_2)\\
&\quad\land(y_5 = \bar x_2)\land(y_6 = \bar x_5)\land(y_7 = y_3\lor y_5)\land(z = y_4\land y_7\land y_6)\land z.
\end{aligned}
$$
The input $x = \mathtt{01100}$ gives $y_1, \dots, y_7, z = 0, 1, 1, 1, 0, 1, 1, 1$, a satisfying assignment of $\Phi$.

## 12.6 3SAT (from CircuitSat)

> [!definition] Definition — CNF, 3CNF, 3Sat
> A **literal** is a variable or its negation. A **clause** is a disjunction (Or) of literals, and a formula in **conjunctive normal form (CNF)** is a conjunction (And) of clauses, such as $(a\lor b\lor c\lor d)\land(b\lor\bar c\lor\bar d)\land(\bar a\lor c\lor d)\land(a\lor\bar b)$. A **3CNF** formula has **exactly three literals in every clause** (the example is not one: its clauses have 4, 3, 3 and 2). **3Sat**: given a 3CNF formula, is it satisfiable?

3Sat is the most useful starting point for NP-hardness proofs: its instances are uniform, and each clause is a small constraint that a gadget can imitate. One could reduce from Sat, but it is simpler to start again from CircuitSat. The reduction transforms an arbitrary circuit $K$ in four stages; except for the last, it is due to Grigorii Tseitin (1966).

> [!key] Theorem — 3Sat is NP-hard (reduction from CircuitSat)
> 1. **Binary gates.** Replace every And or Or gate with $k > 2$ inputs by a binary tree of $k-1$ two-input gates. The new circuit $K'$ computes the same function, so it has the same satisfying inputs.
> 2. **Transcribe** $K'$ into a formula $\Phi_1$ with one equation per gate and the output variable, as in §12.5.
> 3. **One CNF per gate.** Replace each equation by an equivalent CNF formula, giving $\Phi_2$:
> $$
> \begin{aligned}
> a = b\land c &\ \longmapsto\ (a\lor\bar b\lor\bar c)\land(\bar a\lor b)\land(\bar a\lor c)\\
> a = b\lor c &\ \longmapsto\ (\bar a\lor b\lor c)\land(a\lor\bar b)\land(a\lor\bar c)\\
> a = \bar b &\ \longmapsto\ (a\lor b)\land(\bar a\lor\bar b)
> \end{aligned}
> $$
> $\Phi_1$ and $\Phi_2$ are logically equivalent: same satisfying assignments.
>
> 4. **Exactly three literals.** Pad each two-literal clause with one new variable $x$, and the final one-literal clause $z$ with two new variables $x, y$:
> $$
> \begin{aligned}
> a\lor b &\ \longmapsto\ (a\lor b\lor x)\land(a\lor b\lor\bar x)\\
> z &\ \longmapsto\ (z\lor x\lor y)\land(z\lor\bar x\lor y)\land(z\lor x\lor\bar y)\land(z\lor\bar x\lor\bar y)
> \end{aligned}
> $$
> Whatever values the new variables get, the padded clauses hold exactly when the original clause holds; so a satisfying assignment of $\Phi_2$ extends to $\Phi_3$ with arbitrary values for the new variables, and a satisfying assignment of $\Phi_3$ restricts to one of $\Phi_2$.
>
> Chaining the four stages, $K$ is satisfiable **if and only if** the 3CNF formula $\Phi_3$ is. **Polynomial (in fact linear) time:** $K'$ has at most twice as many wires as $K$, and each binary gate becomes at most 5 clauses of $\Phi_3$, each Not gate 4, plus 4 for the output.

On the book's circuit, $K'$ splits the three-input And gate into $y_8 = y_4\land y_7$ and $y_9 = y_8\land y_6$, so it has six binary gates and three Not gates, and $\Phi_3$ has $6\cdot 5 + 3\cdot 4 + 4 = 46$ clauses over 34 variables: 5 inputs, 9 wires and 20 padding variables (the book prints them all, p. 390). It is only a constant factor larger than the circuit — and even a large polynomial blow-up, $n^{374}$ say, would still be a valid reduction.

## 12.7 Maximum independent set (from 3SAT)

For the next problems the input is a simple undirected graph, and the question is the size of the largest or smallest subgraph with some property.

> [!definition] Definition — independent set, MaxIndSet
> An **independent set** in a graph $G$ is a set of vertices with no edge between any two of them. **MaxIndSet** asks for the size of the largest independent set of $G$; its decision version asks, for given $G$ and $k$, whether $G$ has an independent set of size $k$.

> [!key] Theorem — MaxIndSet is NP-hard (reduction from 3Sat)
> **Reduction.** Given an arbitrary 3CNF formula $\Phi$ with $k$ clauses, build the graph $G$ with $3k$ vertices, **one per literal occurrence**, and an edge between two vertices exactly when (1) they belong to the same clause — so each clause becomes a **triangle** — or (2) they are a variable and its negation. Output $G$ and the number $k$.
>
> No independent set contains two vertices of one triangle, so every independent set of $G$ has size at most $k$. **Claim:** $G$ has an independent set of size $k$ if and only if $\Phi$ is satisfiable.
>
> **⇒.** Fix a satisfying assignment. Every clause has a true literal; choose one vertex for a true literal in each triangle. The $k$ chosen vertices are independent: no two share a triangle, and no two are a variable and its negation, because both are true.
>
> **⇐.** Let $S$ be an independent set of size $k$. It has exactly one vertex in each triangle. Make the literal of every vertex of $S$ true; this is consistent, because contradictory literals are joined by edges and cannot both be in $S$. Give every remaining variable any value. Each clause then contains a true literal, so $\Phi$ is satisfied.
>
> **Polynomial time.** $3k$ vertices and at most $\binom{3k}{2}$ edges, built by brute force in $O(k^2)$ time. A polynomial-time algorithm for MaxIndSet would decide 3Sat — compare the size of the largest independent set of $G$ with $k$ — so MaxIndSet is NP-hard.

## 12.8 The general pattern

Every NP-hardness proof — every polynomial-time reduction from $X$ to $Y$ — has three parts:

1. a **polynomial-time algorithm** that transforms an **arbitrary** instance $x$ of $X$ into a **special** instance $y$ of $Y$;
2. a proof that if $x$ is a "good" (YES) instance of $X$, then $y$ is a good instance of $Y$;
3. a proof that if $y$ is a good instance of $Y$, then $x$ is a good instance of $X$ — usually the part that causes the most trouble.

The reduction runs one way, from $X$ to $Y$, but the proof goes both ways — and the two halves are **not symmetric**. Part 2 must handle every instance of $X$; part 3 only the *special* instances of $Y$ that the reduction builds. Exploiting that asymmetry is the key to designing reductions: the built instance is highly structured, and its structure forces every solution to "come from" a solution of $x$. Arbitrary instances of $Y$ never need to be considered, and nothing ever transforms an instance of $Y$ back into one of $X$.

It helps to think of **certificates** — proofs that an instance is good: an input that lights the bulb for CircuitSat, a satisfying assignment for Sat and 3Sat, a large independent set for MaxIndSet. A reduction is then three algorithms:

| | CircuitSat → 3Sat | 3Sat → MaxIndSet |
|---|---|---|
| instance $x\mapsto y$ (polynomial time) | each wire a variable, each gate a CNF, padded to 3CNF | a triangle per clause, edges between contradictory literals, and $k$ = #clauses |
| certificate for $x\ \mapsto$ certificate for $y$ | trace the input through the circuit; new variables arbitrary | one true literal per clause |
| certificate for $y\ \mapsto$ certificate for $x$ | keep the values of the input variables | make the chosen literals true |

Only the first algorithm must run in polynomial time (the other two usually do anyway). Designing all three together, rather than writing down a construction and hoping to prove it afterwards, is what works — especially on an exam. In Ricky Jay's words, quoted by the book: this is an acquired skill.

> [!template] Template — proving that $Y$ is NP-hard (rubric: 1 + 2 + 2 + 2 + 2 + 1)
> We prove that $Y$ is NP-hard by a polynomial-time reduction from $X$, which is NP-hard [cite: lecture or book]. \
> **Reduction.** Given an arbitrary instance $x$ of $X$ [name its parts: a formula $\Phi$ with $n$ variables and $k$ clauses; a graph $G = (V,E)$ and an integer $k$], we build the instance $y$ of $Y$ as follows: [every vertex, edge, number or clause of $y$, as an explicit function of $x$ — one gadget per part of $x$]. \
> $y$ has [size, e.g. $3k$ vertices and $O(k^2)$ edges], so the reduction runs in **polynomial time**, [e.g. $O(k^2)$]. \
> **⇒ ("only if").** Suppose $x$ is a YES instance, with certificate [a satisfying assignment …]. Then [build a certificate for $y$ …], so $y$ is a YES instance. \
> **⇐ ("if").** Suppose the instance $y$ built above is a YES instance, with certificate [an independent set $S$ of size $k$ …]. Then [use the structure of $y$ to build a certificate for $x$ …], so $x$ is a YES instance. \
> So $x$ is a YES instance of $X$ if and only if $y$ is a YES instance of $Y$: a polynomial-time algorithm for $Y$ would solve $X$ in polynomial time. Hence $Y$ is NP-hard. $\blacksquare$
>
> For **NP-completeness**, add: $Y\in\textsf{NP}$, because [the certificate] can be checked in polynomial time [how].

> [!trap] Where reductions lose points
> - **Wrong direction** — an algorithm for the known problem built from the new one is what is required, not the reverse: at most 1 point of 10.
> - **Not an arbitrary instance.** The reduction must accept *every* instance of $X$ — not "a satisfiable formula", not "a graph with an even number of vertices" — and use **nothing but** that instance. It may not look at the answer: it does not know whether $x$ is a YES instance, nor a certificate for it. A reduction that is not structurally sound earns nothing else.
> - **Only one direction proved.** The "⇐" proof — a YES for the *built* $y$ gives a YES for $x$ — is the one usually skipped, and it is where wrong constructions are caught.
> - **No size or time count.** Say how big $y$ is; numbers in $y$ count by their number of bits (§12.12). And write the words "polynomial time".
> - **Degenerate inputs:** every gadget must be defined for every possible part of $x$ (a clause with a repeated variable, an isolated vertex, $k$ larger than $n$) — or the reduction must handle those cases first.

## 12.9 Clique and vertex cover (from independent set)

> [!definition] Definition — clique, vertex cover, complement graph
> A **clique** in $G$ is a set of vertices that are pairwise adjacent (they induce a complete graph); **MaxClique** asks for the size of the largest. A **vertex cover** is a set of vertices that touches every edge; **MinVertexCover** asks for the size of the smallest, and the decision version **VertexCover** asks whether $G$ has a vertex cover of size at most $k$. The **edge-complement** $\overline G$ of $G = (V,E)$ has the same vertices and exactly the edges $uv$ that are *not* in $E$.

> [!key] The three complement relations
> For every graph $G = (V, E)$ with $n$ vertices and every $S\subseteq V$:
> $$
> S \text{ is independent in } G \iff S \text{ is a clique in } \overline G \iff V\setminus S \text{ is a vertex cover of } G.
> $$
> So the largest independent set of $G$ has the same size as the largest clique of $\overline G$, and $n$ minus the size of the smallest vertex cover of $G$.

**Proof.** The first equivalence is the definition of $\overline G$. For the second: $V\setminus S$ misses an edge $uv$ exactly when both $u$ and $v$ are in $S$, so $V\setminus S$ touches every edge exactly when no edge has both ends in $S$. $\square$

So both problems are NP-hard, by reductions from MaxIndSet whose correctness proofs are the equivalences above (both directions at once):

- **MaxClique.** Given an arbitrary graph $G$ (and $k$), output $\overline G$ (and the same $k$): $G$ has an independent set of size $k$ iff $\overline G$ has a clique of size $k$. Building $\overline G$ takes $O(V^2)$ time.
- **MinVertexCover.** Given $G$ and $k$, output $G$ and $n - k$: $G$ has an independent set of size $k$ iff it has a vertex cover of size $n - k$ (at most $n-k$ is the same, since a superset of a vertex cover is one). Linear time.

On the graph of the figure in §12.7 (12 vertices): the largest independent set has 4 vertices, so the smallest vertex cover has $12 - 4 = 8$ — the eight uncircled vertices form one — and the complement graph has a largest clique of 4 vertices, the circled ones. (In the book's Figure 12.10 the output is labeled "size of largest independent set in $\overline G$"; it should say "in $G$".)

> [!trap] Complement traps
> - **Two different complements:** the clique reduction complements the *edges* (same vertices, $\overline G$); the vertex-cover reduction complements the *vertex set* ($V\setminus S$, same graph).
> - **The numbers change for vertex cover:** $k\mapsto n - k$, not $k\mapsto k$.

## 12.10 Graph coloring (from 3SAT)

> [!definition] Definition — proper coloring, 3Color
> A **proper $k$-coloring** of $G = (V,E)$ is a function $C\colon V\to\{1, \dots, k\}$ with $C(u)\neq C(v)$ for every edge $uv$; the colors are just labels. The **graph coloring** problem asks for the smallest $k$ for which a proper $k$-coloring exists. **3Color**: does $G$ have a proper 3-coloring?

Proving 3Color NP-hard proves graph coloring NP-hard, since 3Color is the special case "is the answer at most 3?". The reduction is from 3Sat ("because it has a 3 in it", says the book — and means it), and it is built from three kinds of **gadgets**, subgraphs that enforce pieces of the formula in the language of colorings.

> [!key] Theorem — 3Color is NP-hard (reduction from 3Sat)
> **Reduction.** Given an arbitrary 3CNF formula $\Phi$ with $n$ variables and $k$ clauses, build $G$ from:
> - **one truth gadget**: a triangle on new vertices $T$, $F$, $X$. In any proper 3-coloring they get three different colors, which we *name* True, False and Other after them;
> - **a variable gadget for each variable $a$**: new vertices $a$ and $\bar a$, forming a triangle with $X$. So $a$ and $\bar a$ are colored True and False, in some order;
> - **a clause gadget for each clause $(\ell_1\lor\ell_2\lor\ell_3)$**: five new vertices $p, q, r, s, t$ and ten edges $\ell_1 p$, $\ell_2 q$, $pq$, $pr$, $qr$, $rs$, $\ell_3 t$, $st$, $sT$, $tT$, where $\ell_i$ is the literal's vertex in its variable gadget.
>
> $G$ has $3 + 2n + 5k$ vertices and $3 + 3n + 10k$ edges, built in linear time. **Claim:** $G$ is 3-colorable if and only if $\Phi$ is satisfiable.

**The clause gadget.** The triangle $pqr$, fed by $\ell_1$ and $\ell_2$, acts as a **majority gate**. Once the two input colors are fixed, only two or three valid colorings remain — five in all, drawn in the book's Figure 12.14: if $\ell_1$ and $\ell_2$ have the same color, then $p$ and $q$ must take the other two colors and $r$ gets the inputs' color (two colorings); if they differ, $r$ can be any of the three colors (three colorings). The triangle $stT$, fed by $r$ and $\ell_3$, works the same way with $T$ fixed to True. So:
- if all three literal vertices are False, then $r$ is False, and $s$ (adjacent to $r$ and $T$) and $t$ (adjacent to $\ell_3$ and $T$) must both be Other — but $s$ and $t$ are adjacent: **no valid coloring**;
- if at least one literal vertex is True, the coloring extends (choose $r$ True when $\ell_1$ or $\ell_2$ is True; otherwise $r$ is False and $\ell_3$ is True, and $s$ = Other, $t$ = False works).

**⇒.** Given a satisfying assignment, color $T, F, X$ True, False, Other, each literal vertex by its truth value, and extend through every clause gadget, which is possible because every clause has a true literal.

**⇐.** Given a proper 3-coloring, call its colors True, False, Other after $T, F, X$. Every literal vertex is colored True or False (it is adjacent to $X$), and $a$, $\bar a$ get opposite colors; set each variable to the color of its vertex. Each clause gadget has a literal vertex colored True, so each clause is satisfied.

For the book's four-clause formula of §12.7, $G$ has $3 + 8 + 20 = 31$ vertices and $3 + 12 + 40 = 55$ edges, and the book's Figure 12.15 shows one of the colorings for the satisfying assignment $a = c = $ True, $b = d = $ False.

> [!trap] Coloring traps
> - **The colors have no meaning until the truth gadget names them.** "Colored True" means "the same color as $T$".
> - **A literal vertex appears in several clause gadgets** — there is one vertex per *literal*, shared, unlike the one vertex per *occurrence* of §12.7.
> - **2Color is easy** (a graph is 2-colorable iff it has no odd cycle, checked by whatever-first search); the hardness starts at 3.

## 12.11 Hamiltonian cycle

> [!definition] Definition — Hamiltonian cycle
> A **Hamiltonian cycle** in a graph is a cycle that visits every vertex exactly once. **DirectedHamCycle**: does a given directed graph have one? (Not to be confused with an **Euler tour**, a closed walk that traverses every *edge* once, which depth-first search finds in linear time.)

The book proves DirectedHamCycle NP-hard twice: from vertex cover, and directly from 3Sat. The course lectures the second.

### From vertex cover

Given an undirected graph $G$ and an integer $k$, build a directed graph $H$ that is Hamiltonian iff $G$ has a vertex cover of size $k$. First a precision the book leaves out: **delete the isolated vertices of $G$** (they never help a cover), and if $k$ is at least the number $n'$ of vertices left, output any fixed Hamiltonian graph (such as a directed triangle), since then all $n'$ vertices form a cover. Otherwise $k < n'$, and a cover of size at most $k$ can be padded to size exactly $k$.

> [!key] Theorem — DirectedHamCycle is NP-hard (reduction from VertexCover)
> **Reduction** ($G$ without isolated vertices, $k < V$):
> - **Edge gadget** for each edge $uv$: four vertices $(u,v,\text{in})$, $(u,v,\text{out})$, $(v,u,\text{in})$, $(v,u,\text{out})$ and six edges $(u,v,\text{in})\to(u,v,\text{out})$, $(v,u,\text{in})\to(v,u,\text{out})$, and both directions between the two "in" vertices and between the two "out" vertices.
> - **Vertex chain** for each vertex $u$ with neighbors $v_1, \dots, v_d$ (in any order): the edges $(u,v_i,\text{out})\to(u,v_{i+1},\text{in})$ for $1\le i < d$, which string the $u$-sides of $u$'s edge gadgets into one path.
> - **Cover vertices** $x_1, \dots, x_k$, each with an edge to the first vertex $(u,v_1,\text{in})$ and from the last vertex $(u,v_d,\text{out})$ of every vertex chain.
>
> $H$ has $4E + k$ vertices and $6E + (2E - V) + 2kV$ edges: $O(V^2)$ time.

Only the "in" vertices have edges entering a gadget from outside, and only the "out" vertices have edges leaving it, so a Hamiltonian cycle crosses each edge gadget in one of the three ways of the figure — straight through on both sides, or along one side with a detour through the other.

**⇒.** Let $C = \{u_1, \dots, u_k\}$ be a vertex cover. For $i = 1, \dots, k$, go from $x_i$ through the whole chain of $u_i$ to $x_{i+1}$ (to $x_1$ after $u_k$). At each gadget $(u_i, v, \text{in})$ on the way: if $v\in C$, take the edge to $(u_i, v, \text{out})$; if $v\notin C$, detour $(u_i,v,\text{in})\to(v,u_i,\text{in})\to(v,u_i,\text{out})\to(u_i,v,\text{out})$. Every gadget of an edge $uv$ is visited completely: on $u$'s chain and on $v$'s if both are in $C$, otherwise by the detour from the one that is.

**⇐.** Let $\mathcal C$ be a Hamiltonian cycle. After each cover vertex it enters a vertex chain at its first vertex; by the case analysis of the gadgets, it must then follow that chain to its end (taking the straight edge or the detour at every gadget) and leave to a cover vertex. A detour $(u,v,\text{in})\to(v,u,\text{in})\to\cdots$ uses up the $v$-side of that gadget, so $v$'s chain is not traversed. So $\mathcal C$ traverses exactly $k$ vertex chains, one after each cover vertex, and every gadget is visited from one of them: the $k$ chain owners form a vertex cover.

On the book's example (Figures 12.17–12.18) — the 4-cycle $u\,v\,x\,w$ plus the diagonal $ux$, with $k = 2$ — $H$ has $4\cdot 5 + 2 = 22$ vertices and $30 + 6 + 16 = 52$ edges; $\{u, x\}$ is the only vertex cover of size 2, and $H$ has exactly two Hamiltonian cycles, one for each way of assigning $x_1, x_2$ to the chains of $u$ and $x$.

### From 3SAT

The idea: a variable becomes a row of vertices that a Hamiltonian cycle crosses either left to right (True) or right to left (False); a clause becomes one extra vertex that can be picked up by a short detour out of a row and back, and the detour points the way that makes the clause's literal true.

> [!warning] Deviation from the book: its construction needs two repairs
> The book's version has, for each variable $x_i$, a doubly linked row of vertices — "$2k$ vertices $(i,0), \dots, (i,2k)$" in the text, which is $2k+1$ of them; the figures draw $2k$ — joins the two ends of each row directly to both ends of the next row by four edges $(i,0)\to(i+1,0)$, $(i,2k)\to(i+1,0)$, $(i,0)\to(i+1,2k)$, $(i,2k)\to(i+1,2k)$ (cyclically), and attaches clause vertex $[j]$ at the adjacent positions $2j-1$, $2j$; for the "⇐" direction it appeals to "exhaustive case analysis". **That claim is false.** Take the eight clauses on $a, b, c$ — every combination of signs, so the formula is unsatisfiable — with $(\bar a\lor b\lor c)$ last. The assignment $a$ = True, $b = c$ = False satisfies the other seven. Its cycle crosses row $a$ left to right and rows $b$, $c$ right to left, picking up clauses 1–7 by ordinary detours; now replace the connecting edge $(1,2k)\to(2,2k)$ by $(1,2k)\to[8]\to(2,2k)$, which exist because $\bar a$ and $b$ are in clause 8. The result is a Hamiltonian cycle (in both readings of the book's indices), although no satisfying assignment exists: a clause vertex at the end of a row can stand in for a connecting edge between rows. The repair below, standard in other textbooks, separates the clause positions by **spacer** vertices and routes the connections between rows through **hub** vertices.

> [!key] Theorem — DirectedHamCycle is NP-hard (reduction from 3Sat, repaired)
> **Reduction.** Given an arbitrary 3CNF formula $\Phi$ with variables $x_1, \dots, x_n$ and clauses $c_1, \dots, c_k$, build the directed graph $H$:
> - **Rows.** For each variable $x_i$, vertices $(i, 0), (i, 1), \dots, (i, 3k)$ with edges both ways between neighbors $(i, m-1)$ and $(i, m)$. Positions $3j-2$ and $3j-1$ belong to clause $c_j$; positions $0, 3, 6, \dots, 3k$ are **spacers**.
> - **Hubs** $h_1, \dots, h_n$, with edges $h_i\to(i,0)$, $h_i\to(i,3k)$, $(i,0)\to h_{i+1}$ and $(i,3k)\to h_{i+1}$, where $h_{n+1}$ means $h_1$.
> - **Clause vertices** $[1], \dots, [k]$. If $x_i$ is in $c_j$: edges $(i,3j-2)\to[j]\to(i,3j-1)$, a detour for left-to-right travel. If $\bar x_i$ is in $c_j$: edges $(i,3j-1)\to[j]\to(i,3j-2)$, a detour for right-to-left travel.
>
> $H$ has $n(3k+2) + k$ vertices and at most $6kn + 4n + 6k$ edges (exactly that many when no clause repeats a literal), built in $O(nk)$ time — at most quadratic in the length of $\Phi$. **Claim:** $H$ is Hamiltonian iff $\Phi$ is satisfiable.

**⇒.** Given a satisfying assignment, go $h_1\to\text{row }1\to h_2\to\text{row }2\to\cdots\to\text{row }n\to h_1$, crossing row $i$ left to right if $x_i$ = True and right to left if $x_i$ = False. Without the clause vertices this visits every vertex once. For each clause $c_j$ choose one true literal: if it is $x_i$, row $i$ is crossed left to right, and the step $(i,3j-2)\to(i,3j-1)$ can be replaced by the detour through $[j]$; if it is $\bar x_i$, row $i$ is crossed right to left and the step $(i,3j-1)\to(i,3j-2)$ can. Each clause vertex is picked up exactly once.

**⇐.** Let $\mathcal C$ be a Hamiltonian cycle.
1. *Every clause vertex is a detour within one row.* Suppose $\mathcal C$ enters $[j]$ from $(i, 3j-2)$ (a positive literal) but does not continue to $(i,3j-1)$. Then $(i,3j-1)$ can only be entered from the spacer $(i,3j)$ and must continue to $(i,3j-2)$ — its other neighbors are used up — so $\mathcal C$ contains $(i,3j)\to(i,3j-1)\to(i,3j-2)\to[j]$. Now the spacer $(i,3j-3)$ has lost its neighbor $(i,3j-2)$. If $j > 1$, its only remaining neighbor is $(i,3j-4)$, which cannot be both its predecessor and its successor: contradiction. If $j = 1$, the spacer $(i,0)$ must sit between the hubs, $h_i\to(i,0)\to h_{i+1}$, and then the other end $(i,3k)$ has only $(i,3k-1)$ left: contradiction. A negative literal is symmetric (the stranded spacer is $(i,3j)$). So $\mathcal C$ leaves $[j]$ to the partner vertex in the same row.
2. *Every row is crossed in one direction.* Replace each detour by the row edge it bypasses. The result is a Hamiltonian cycle of $H$ without clause vertices, where row $i$ touches the rest only through its two ends and the hubs $h_i$, $h_{i+1}$. So it enters row $i$ at one end from $h_i$, runs along the whole row, and leaves from the other end to $h_{i+1}$. Set $x_i$ = True iff row $i$ is crossed left to right.
3. *Every clause is satisfied.* $[j]$ sits on a detour of some row $i$, in the direction of that row's crossing. A left-to-right detour exists only if $x_i\in c_j$, and then $x_i$ = True; a right-to-left detour only if $\bar x_i\in c_j$, and then $x_i$ = False. Either way $c_j$ has a true literal.

The book's own example is its four-clause formula with the satisfying assignment $a = b = d$ = True, $c$ = False; in the repaired graph ($4\cdot 14 + 4 = 60$ vertices) the cycle described in "⇒" is Hamiltonian.

### Variants and extensions

- **Hamiltonian path** (directed): NP-hard by easy modifications of either reduction; DirectedHamCycle and DirectedHamPath also reduce to each other (left as exercises in the book).
- **Undirected graphs**: also NP-hard, by a simple reduction from the directed version (an exercise).
- **TravelingSalesman** — the shortest Hamiltonian cycle (or path) in a graph with edge weights — is NP-hard: with every weight 1, it answers whether a Hamiltonian cycle exists.

> [!trap] Hamiltonian-cycle traps
> - **Hamilton is not Euler**: every *vertex* once (NP-hard) versus every *edge* once (linear time).
> - **Check the "⇐" direction on a cycle that cheats.** A cycle may use a gadget in a way the construction did not intend — here, a clause vertex as a bridge between two rows. That is exactly the case analysis the proof has to rule out.
> - **The isolated-vertex case** of the vertex-cover reduction: an isolated vertex has no chain, so with one edge $uv$, two isolated vertices and $k = 3$, $G$ has a cover of size $1\le 3$ but $H$ has three cover vertices and only two chains — no Hamiltonian cycle. Handle such instances before building $H$.

## 12.12 Subset sum (from vertex cover)

**SubsetSum** ([[2-algorithms/02-backtracking#23-subset-sum|§2.3]], [[2-algorithms/03-dynamic-programming#38-subset-sum|§3.8]]): given positive integers $X[1\,..\,n]$ and a target $T$, does some subset of them sum to $T$? The reduction is again from VertexCover, with only two kinds of gadget, both of them numbers: one per vertex and one per edge. Assume $0\le k\le V$ (a larger $k$ is a trivial YES instance).

> [!key] Theorem — SubsetSum is NP-hard (reduction from VertexCover)
> **Reduction.** Given an arbitrary graph $G = (V, E)$ and integer $k$, number the edges $0, \dots, E-1$ arbitrarily and let $\Delta(v)$ be the set of edges at $v$. Output the numbers
> $$
> \begin{aligned}
> b_i &:= 4^i && \text{for each edge } i,\\
> a_v &:= 4^E + \sum_{i\in\Delta(v)} 4^i && \text{for each vertex } v,\\
> T &:= k\cdot 4^E + \sum_{i=0}^{E-1} 2\cdot 4^i .
> \end{aligned}
> $$
> In base 4, every number has $E+1$ digits: digit $E$ is 1 for a vertex number and 0 for an edge number; digit $i < E$ is 1 for $b_i$ and for the numbers of the two endpoints of edge $i$, and 0 otherwise. $T$ is $k$ followed by $E$ digits 2.
>
> **⇒.** Let $C$ be a vertex cover of size $k$ (pad a smaller one with any other vertices; $k\le V$). Take $a_v$ for $v\in C$, and $b_i$ for every edge $i$ with exactly one endpoint in $C$. The $k$ vertex numbers contribute $k\cdot 4^E$; in digit $i < E$ the sum is 2 — two endpoints, or one endpoint and $b_i$. So the subset sums to $T$.
>
> **⇐.** Suppose $\sum_{v\in V'} a_v + \sum_{i\in E'} b_i = T$. For each $i < E$ exactly three numbers have a 1 in digit $i$ ($b_i$ and two vertex numbers), so the low digits never carry: digit $i$ of the sum is the number of chosen numbers with a 1 there, and it must be 2. Since $b_i$ contributes at most 1, **at least one endpoint of every edge is in $V'$**: $V'$ is a vertex cover. And the low parts (digits $0$ to $E-1$) of the chosen numbers add up to less than $4^E$, so the sum divided by $4^E$, rounded down, is $\lvert V'\rvert = \lfloor T/4^E\rfloor = k$.
>
> **Polynomial time.** $V + E$ numbers of $E+1$ base-4 digits each — $O(E)$ bits — so the output has $O((V+E)E)$ bits and is written in polynomial time.

The book's example: $V = \{u, v, w, x\}$, $E = \{uv, uw, vw, vx, wx\}$ numbered so that $uv$ is the most significant edge digit, and $k = 2$.

| number | vertex digit | $uv$ | $uw$ | $vw$ | $vx$ | $wx$ | value | in $X'$ for $C = \{v, w\}$ |
|---|---|---|---|---|---|---|---|---|
| $a_u$ | 1 | 1 | 1 | 0 | 0 | 0 | 1344 | |
| $a_v$ | 1 | 1 | 0 | 1 | 1 | 0 | 1300 | ✓ |
| $a_w$ | 1 | 0 | 1 | 1 | 0 | 1 | 1105 | ✓ |
| $a_x$ | 1 | 0 | 0 | 0 | 1 | 1 | 1029 | |
| $b_{uv}$ | 0 | 1 | 0 | 0 | 0 | 0 | 256 | ✓ |
| $b_{uw}$ | 0 | 0 | 1 | 0 | 0 | 0 | 64 | ✓ |
| $b_{vw}$ | 0 | 0 | 0 | 1 | 0 | 0 | 16 | |
| $b_{vx}$ | 0 | 0 | 0 | 0 | 1 | 0 | 4 | ✓ |

The cover $\{v, w\}$ — the only vertex cover of size 2 — gives $1300 + 1105 + 256 + 64 + 4 + 1 = 2730$, and no other subset of the nine numbers sums to 2730. With $k = 1$ the target would be $1\cdot 4^5 + 682 = 1706$, and no subset reaches it.

One more precision: two vertices can get the **same** number (the endpoints of an isolated edge $uv$ both get $4^E + 4^i$; isolated vertices all get $4^E$), so the input is a *multiset* — an array $X[1\,..\,n]$, as in Chapter 2 — not a set.

### Caveat reductor

Chapter 3 solves SubsetSum in $O(nT)$ time. Did we just prove $\textsf{P} = \textsf{NP}$? No: $O(nT)$ is polynomial in the *value* $T$, but $T$ takes only $O(\log T)$ bits, so the running time is **exponential in the input size** — and the reduction above produces a $T$ of at least $4^E$ (whenever $k\ge 1$), exponential in the size of $G$. Such algorithms run in **pseudo-polynomial time**, and an NP-hard problem that has one is **weakly NP-hard**: easy when the numbers are written in unary, hard in binary. A problem that stays NP-hard when every number is written in unary is **strongly NP-hard** — for example TravelingSalesman, even on complete graphs with all edge weights 1 or 2.

> [!trap] Subset-sum traps
> - **"Polynomial in $n$ and $T$" is not polynomial time.** Input size counts bits.
> - **No carries is the whole proof** of "⇐": it is why base 4 (and not base 2) is used — a digit receives at most three 1s.
> - **The reduction may not choose the cover.** The numbers depend only on $G$ and $k$; the cover appears only in the proofs.

## 12.13 Other useful NP-hard problems

Thousands of problems are known to be NP-hard; most of the ones above and below were first proved NP-hard in Richard Karp's 1972 paper, and Garey and Johnson's *Computers and Intractability* (1979) collects many more. A short list of good starting points:

| problem | question | NP-hard by reduction from |
|---|---|---|
| PlanarCircuitSat | CircuitSat for a circuit drawn without crossing wires | CircuitSat (replace each crossing by a small group of gates) |
| 1-in-3Sat | a 3CNF assignment with **exactly one** true literal per clause? | 3Sat |
| NotAllEqual3Sat | an assignment with at least one true **and** one false literal per clause? | 3Sat |
| Planar3Sat | 3Sat when the clause–variable incidence graph is planar | PlanarCircuitSat |
| Exact3DimensionalMatching (X3M) | do some disjoint triples from a given collection cover the set $S$ exactly? | 3Sat |
| Partition | can a set of integers be split into two parts of equal sum? (weakly NP-hard) | SubsetSum |
| 3Partition | can $3n$ integers be split into $n$ triples of equal sum? (strongly NP-hard, even with numbers at most $n^3$) | X3M |
| SetCover | the fewest of the sets $S_1, \dots, S_m$ that cover their union (generalizes VertexCover and X3M) | — |
| HittingSet | the fewest elements that meet every set $S_i$ (generalizes VertexCover) | — |
| LongestPath | the longest simple path from $u$ to $v$, weights $\ge 0$, directed or undirected (generalizes Hamiltonian path) | — |
| SteinerTree | the lightest subtree containing every marked vertex | VertexCover |
| Max2Sat | an assignment satisfying as many 2-literal clauses as possible | 3Sat |
| MaxCut | a set $S$ maximizing the number of edges with exactly one endpoint in $S$ | Max2Sat |

Contrasts worth remembering: the *shortest* path is easy ([[2-algorithms/08-shortest-paths|Chapter 8]]), the longest simple path is not; SteinerTree with all vertices marked is the minimum spanning tree, and with two marked vertices a shortest path; **2Sat** (satisfy every 2-literal clause) is solvable in polynomial time, while Max2Sat is NP-hard; PlanarNotAllEqual3Sat is, surprisingly, in P. Most interesting puzzles and solitaire games are NP-hard or have NP-hard generalizations — Minesweeper (from CircuitSat), Sudoku and Klondike, Super Mario Brothers and 2048 (from 3Sat), Tetris (from 3Partition), Pac-Man (from Hamiltonian cycle), the shortest solution of an $n\times n\times n$ Rubik's cube.

## 12.14 Choosing the right problem

Choosing the problem to reduce from is often the hardest step. By Cook–Levin any NP-complete problem *could* be used, but some make the reduction far easier. The book's rules of thumb:

| if the new problem asks to … | try reducing from |
|---|---|
| assign bits to objects, choose a subset, or split objects into two groups | some version of Sat, or Partition |
| assign labels from a small fixed set, or split objects into a few groups | $k$Color, or 3Color |
| arrange objects in an order | DirectedHamCycle, DirectedHamPath, TravelingSalesman |
| find a **small** subset satisfying constraints | MinVertexCover |
| find a **large** subset satisfying constraints | MaxIndSet, MaxClique, Max2Sat |
| split objects into many small groups | 3Partition |
| … and the number 3 appears naturally | 3Sat, 3Color, X3M, 3Partition |
| none of the above | 3Sat, or even CircuitSat |

Choose the *simplest* problem that still captures the feature that makes yours hard — not Tetris or Super Mario Brothers. On the course's exams, any NP-hard problem in the lecture notes may be reduced from — every problem of this chapter qualifies.

## 12.15 A frivolous real-world example

In **international draughts** (the 10×10 variant of checkers played in most of the world) kings fly any distance along a diagonal, captured pieces are removed only at the end of the turn and cannot be jumped twice, and — the crucial rule — **the player must make a move that captures the maximum possible number of pieces**. The real game is a finite lookup table. But on an $n\times n$ board, **just finding a legal move is NP-hard** — the only real game the book knows where merely following the rules is hard. Bob Hearn's reduction (2010) is from Hamiltonian cycle:

- each vertex of the graph $G$ becomes a **vault**: a diamond of $N$ capturable black pieces walled in by uncapturable ones, entered through one "ear" and left through the other;
- each arc $i\to j$ becomes a path of two diagonal segments from vault $i$ to vault $j$, with **corner gadgets** that turn the king and **crossing gadgets** that let it go straight through but not switch paths;
- one white king starts at the bottom of one vault and must alternate between clearing vaults and traversing whole arc paths.

If $G$ has a Hamiltonian cycle the king captures at least $nN$ pieces; otherwise at most $(n - \tfrac12)N + O(n^3)$ (half of the starting vault, plus the corner and crossing gadgets). With $N = n^4$ the board has size $O(n^5)\times O(n^5)$, built in polynomial time, and the maximum capture reveals whether $G$ is Hamiltonian. Whether it is NP-hard to decide if White can capture *all* black pieces in one turn is still open.

## 12.16 On beyond zebra

This section is ♥ in the book: a quick tour of the classes beyond NP.

- **PSPACE**: problems solvable in polynomial *space*. $\textsf{NP}\subseteq\textsf{PSPACE}$; nobody can prove even $\textsf{P}\neq\textsf{PSPACE}$. **PSPACE-hard** is defined with polynomial-time many-one reductions. The canonical PSPACE-hard problem is **QBF** — is a fully quantified boolean formula true? — even with alternating quantifiers in front of a 3CNF formula, which is a two-player game where Alice and Bob alternately set the variables. Generalized games (tic-tac-toe, reversi, checkers, go, chess, mancala) are typically PSPACE-hard, and so are **NFA totality** (does an NFA accept every string?) and NFA equivalence and minimization — whereas the same questions for DFAs take polynomial time ([[concepts/nfa]], [[concepts/dfa-minimization]]).
- **EXP**: problems solvable in $2^{n^c}$ time. $\textsf{PSPACE}\subseteq\textsf{EXP}$, and $\textsf{P}\neq\textsf{EXP}$ is known, so no EXP-hard problem is in P. $n\times n$ chess without a bound on capture-free moves is EXP-hard; with a polynomial bound it is in PSPACE.
- **Beyond:** NEXP (YES answers with exponential-time-checkable proofs), EXPSPACE (deciding equivalence of regular expressions with an intersection operator is EXPSPACE-hard), then doubly and triply exponential classes, and so on.
- **ELEMENTARY**: time or space bounded by a tower $2\uparrow^k n$ of fixed height $k$ ($2\uparrow^0 n = n$, $2\uparrow^k n = 2^{2\uparrow^{k-1} n}$). Some natural decidable problems are not even elementary: Stockmeyer (1974) proved that equivalence of regular expressions with a complement operator needs non-elementary time, even without the Kleene star — each nested complement can blow the automaton up exponentially ([[1-models-of-computation/04-nondeterministic-automata#45-nfa-to-dfa-the-subset-construction|subset construction]]).

All these classes are nested,
$$
\textsf{P}\subseteq\textsf{NP}\subseteq\textsf{PSPACE}\subseteq\textsf{EXP}\subseteq\textsf{NEXP}\subseteq\textsf{EXPSPACE}\subseteq\textsf{EEXP}\subseteq\textsf{NEEXP}\subseteq\cdots,
$$
and every inclusion is believed strict; what is proved is only that each class is strictly contained in the one **three steps later** ($\textsf{P}\neq\textsf{EXP}$, $\textsf{PSPACE}\neq\textsf{EXPSPACE}$), not, for example, $\textsf{P}\neq\textsf{PSPACE}$ or $\textsf{NP}\neq\textsf{EXP}$.

## Summary

- P: solvable in polynomial time (in the number of input bits); NP: YES answers have polynomial-time-checkable certificates; co-NP: NO answers do. $\textsf{P}\subseteq\textsf{NP}\cap\textsf{co-NP}$; P versus NP and NP versus co-NP are open.
- NP-hard: a polynomial-time algorithm would give $\textsf{P} = \textsf{NP}$; NP-complete: NP-hard and in NP. Cook–Levin: CircuitSat (equivalently Sat) is NP-hard. Formally via Cook (oracle) or Karp (many-one) reductions; the chapter's are all Karp reductions.
- Direction rule: reduce **from** a known NP-hard problem **to** the new one, by a polynomial-time algorithm on an **arbitrary** instance; prove YES ⇒ YES and (for the built instances) YES ⇐ YES; transform certificates both ways.
- CircuitSat → Sat (one equation per gate) and CircuitSat → 3Sat (binary gates, CNF per gate, padding): linear size, equisatisfiable.
- 3Sat → MaxIndSet: a triangle per clause, edges between contradictory literals, $k$ = #clauses. Independent in $G$ ⟺ clique in $\overline G$ ⟺ complement is a vertex cover.
- 3Sat → 3Color: truth triangle $T, F, X$, a triangle $a\,\bar a\,X$ per variable, a 5-vertex, 10-edge clause gadget of two majority triangles.
- DirectedHamCycle: from VertexCover (edge gadgets, vertex chains, $k$ cover vertices; remove isolated vertices first) and from 3Sat (rows crossed left or right, clause detours — with spacers and hubs; the book's version without them is wrong). Path, undirected and TSP follow.
- SubsetSum from VertexCover: base-4 digits, no carries, $T = k\,22\cdots2_4$; $O(nT)$ is only pseudo-polynomial (weakly NP-hard).
