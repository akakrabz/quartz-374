> [!abstract] In one breath
> A **greedy algorithm** makes one locally best choice, commits to it, and solves what is left the same way — no backtracking and no table. Greedy algorithms are fast and usually wrong, so every one needs a **proof**, almost always an **inductive exchange argument**: some optimal solution agrees with the greedy choice (swap the greedy choice in; the solution stays feasible and gets no worse), and induction does the rest. The chapter's correct greedy algorithms: store files on a tape in increasing order of **length**, or of **length/frequency** when files are accessed with different frequencies ($O(n\log n)$); choose the most non-overlapping classes by repeatedly taking the class that **finishes first** ($O(n\log n)$); build an optimal prefix-free code by repeatedly **merging the two least frequent characters** (Huffman, $O(n\log n)$); and find a **stable matching** by letting hospitals make offers in preference order while doctors trade up (Gale–Shapley, $O(n^2)$), which gives every hospital its best possible stable partner and every doctor her worst. Other natural greedy rules — earliest start, shortest class, top-down code splitting, fixing unstable pairs one at a time — fail, and a small counterexample shows it.

## 4.1 Storing files on tape

A tape must be read sequentially, so reading a file means scanning past every file stored before it. Let $L[1\,..\,n]$ be the file lengths and let the permutation $\pi$ describe the order on the tape: $\pi(i)$ is the file at position $i$. Reading the file at position $k$ costs $\sum_{i=1}^{k} L[\pi(i)]$.

> [!definition] Problem — tape sorting
> Given $L[1\,..\,n]$, find an order $\pi$ that minimizes the expected cost of reading a file chosen uniformly at random:
> $$
> E[\textsf{cost}(\pi)] \;=\; \frac1n\sum_{k=1}^{n}\sum_{i=1}^{k} L[\pi(i)] \;=\; \frac1n\sum_{i=1}^{n}(n-i+1)\,L[\pi(i)].
> $$

The second form counts, for each position $i$, the $n-i+1$ reads that scan past it: the files near the front are paid for many times, so short files belong there. The greedy algorithm: **sort the files by increasing length** — put the cheapest file first and recurse on the rest. Running time $O(n\log n)$, plus the time to write the files.

> [!key] Lemma 4.1
> $E[\textsf{cost}(\pi)]$ is minimized when $L[\pi(i)]\le L[\pi(i+1)]$ for all $i$.

> [!proof]- Proof (click to expand)
> Suppose two neighbors are out of order: $L[a] > L[b]$ for $a = \pi(i)$ and $b = \pi(i+1)$. Swapping them changes only the costs of reading $a$ and $b$: reading $a$ now costs $L[b]$ more, reading $b$ costs $L[a]$ less. The expected cost changes by $(L[b] - L[a])/n < 0$, so an order with two neighbors out of order is never optimal. There are finitely many orders, so an optimal one exists; it has no neighbors out of order, so it is sorted. All sorted orders write the same sequence of lengths and have the same cost, so all of them are optimal.

For example, files $a, b, c, d$ with lengths $2, 1, 3, 4$: the sorted order $b, a, c, d$ has read costs $1, 3, 6, 10$ and expected cost $20/4 = 5$; the reverse order $d, c, a, b$ has read costs $4, 7, 9, 10$ and expected cost $30/4 = 7.5$.

### Access frequencies

Now file $i$ will be read $F[i] > 0$ times, and we minimize the total cost
$$
\Sigma\textsf{cost}(\pi) \;=\; \sum_{k=1}^{n} F[\pi(k)]\cdot\sum_{i=1}^{k} L[\pi(i)].
$$
Equal frequencies give Lemma 4.1 (sort by length); equal lengths give "sort by decreasing frequency". In general neither key alone is right: sort by the **ratio** $L/F$.

> [!key] Lemma 4.2
> $\Sigma\textsf{cost}(\pi)$ is minimized when $\dfrac{L[\pi(i)]}{F[\pi(i)]}\le\dfrac{L[\pi(i+1)]}{F[\pi(i+1)]}$ for all $i$.

> [!proof]- Proof (click to expand)
> The same exchange. Swap neighbors $a = \pi(i)$ and $b = \pi(i+1)$: each of the $F[a]$ reads of $a$ costs $L[b]$ more, and each of the $F[b]$ reads of $b$ costs $L[a]$ less, so the total changes by
> $$
> L[b]\,F[a] - L[a]\,F[b],\qquad\text{which is negative}\iff \frac{L[a]}{F[a]} > \frac{L[b]}{F[b]}.
> $$
> So an optimal order (one exists) has no neighbors out of ratio order, that is, it is sorted by ratio. Swapping two neighbors with *equal* ratios changes the cost by 0, and any two ratio-sorted orders differ by such swaps, so all ratio-sorted orders have the same cost and are all optimal.

> [!example] Example — length alone and frequency alone both fail
>
> | file | $a$ | $b$ | $c$ | $d$ |
> |---|---|---|---|---|
> | $L$ | 2 | 1 | 3 | 4 |
> | $F$ | 3 | 2 | 1 | 4 |
> | $L/F$ | 0.67 | 0.5 | 3 | 1 |
>
> The ratio order $b, a, d, c$ costs $2\cdot1 + 3\cdot3 + 4\cdot7 + 1\cdot10 = 49$, the minimum over all 24 orders. Sorting by length ($b, a, c, d$) costs 57; sorting by decreasing frequency ($d, a, b, c$) costs 58.

The book remarks that this problem resembles optimal binary search trees ([[2-algorithms/03-dynamic-programming#39-optimal-binary-search-trees|§3.9]]) in spirit, but the data structure and the cost function differ, so the algorithm differs too. Here no dynamic programming is needed: swapping two neighbors changes the cost of no other file, which is what makes the adjacent-swap argument work.

## 4.2 Scheduling classes

> [!definition] Problem — class scheduling
> Given start and finish times $S[1\,..\,n]$ and $F[1\,..\,n]$ with $0\le S[i] < F[i]\le M$, find a largest subset $X\subseteq\{1,\ldots,n\}$ of pairwise **compatible** classes: for all distinct $i, j\in X$, either $S[i] > F[j]$ or $S[j] > F[i]$.

Inequalities are strict, so two classes that share an endpoint conflict. (The book also assumes all start and finish times are distinct; nothing below needs it.) The problem is also known as **interval scheduling**: draw each class as an interval of the time axis and pick as many pairwise disjoint intervals as possible.

**[[concepts/backtracking|Backtracking]] first.** Either class 1 is in the schedule or it is not. If it is, the rest of the schedule consists of an optimal schedule for the classes that end before class 1 starts, $\{i\ge2 \mid F[i] < S[1]\}$, and one for the classes that start after it ends, $\{i\ge 2\mid S[i] > F[1]\}$; if not, we need an optimal schedule for classes $2, \ldots, n$. Trying both and evaluating the recursion bottom up gives a [[concepts/dynamic-programming|dynamic program]]; the book quotes $O(n^3)$ time for it and skips the details. The greedy algorithm is faster and simpler.

**The greedy algorithm.** Scan the classes in order of finish time and take every class that starts after the last class taken finishes.

```text
GreedySchedule(S[1 .. n], F[1 .. n]):
    sort F and permute S to match
    count ← 1
    X[count] ← 1
    for i ← 2 to n
        if S[i] > F[X[count]]
            count ← count + 1
            X[count] ← i
    return X[1 .. count]
```

After the $O(n\log n)$ sort, the loop takes $O(n)$ time: **$O(n\log n)$** in all. (The returned indices refer to the sorted order.)

The greedy schedule is *a* maximum schedule, not *the* maximum schedule — in the figure, $a, d, h, i$ is another. The claim to prove is that some optimal schedule is the greedy one.

> [!key] Lemma 4.3
> Some maximum-size conflict-free schedule contains the class that finishes first.

> [!proof]- Proof (click to expand)
> Let $f$ be the class that finishes first, and let $X$ be a maximum schedule that does not contain $f$. Let $g$ be the class of $X$ that finishes first. Every other class of $X$ starts after $g$ finishes (they are compatible with $g$ and finish later), hence after $f$ finishes, because $F[f]\le F[g]$. So $X' = X\setminus\{g\}\cup\{f\}$ is conflict-free, and it has the same size as $X$, so it is also a maximum schedule. (The book says "maximal" for "maximum size".)

> [!key] Theorem 4.4
> The greedy schedule is an optimal schedule.

> [!proof]- Proof (induction on $n$)
> Let $f$ be the class that finishes first and $A = \{\, j \mid S[j] > F[f] \,\}$ the classes that start after $f$ ends. Every class compatible with $f$ lies in $A$: a class $j$ with $S[f] > F[j]$ would finish before $f$. By Lemma 4.3 some optimal schedule contains $f$; the rest of it is a conflict-free subset of $A$, and conversely $f$ together with any conflict-free subset of $A$ is conflict-free. So the optimum is $1$ plus the optimum for $A$. GreedySchedule takes $f$ first; afterwards it skips every class outside $A$ (each starts at or before $F[f]$, and the last class taken never finishes earlier than $f$) and treats the classes of $A$ exactly as it would if it were run on $A$ alone. Since $\lvert A\rvert < n$, by the induction hypothesis that run takes the optimum for $A$. So the greedy schedule has optimal size.

> [!proof]- Proof (unrolled: the first difference)
> Let $g_1, \ldots, g_k$ be the greedy classes in the order chosen. Among all maximum schedules, sorted by finish time, pick one, $c_1, \ldots, c_m$, that agrees with the greedy schedule on the longest possible prefix, say on $c_1 = g_1, \ldots, c_{j-1} = g_{j-1}$.
> - If $j\le k$ and $j\le m$, then $c_j\ne g_j$. Both start after $g_{j-1}$ finishes, and $g_j$ is the earliest-finishing class with that property, so $F[g_j]\le F[c_j]$. The classes $c_{j+1}, \ldots, c_m$ start after $c_j$ finishes, hence after $g_j$ finishes, and $g_j$ is compatible with $g_1, \ldots, g_{j-1}$ by construction. Replacing $c_j$ by $g_j$ gives a maximum schedule that agrees with the greedy one on a longer prefix — a contradiction.
> - So one sequence is a prefix of the other. If $m > k$, then $c_{k+1}$ starts after $g_k$ finishes, and the greedy algorithm would have taken a $(k+1)$st class — a contradiction. And $k > m$ is impossible because $m$ is the maximum. Hence $k = m$.

> [!trap] Greedy rules that do not work
> The exchange argument needs the greedy choice to *finish first*. Each of these natural rules fails on a small input (classes written as $[S, F]$; take the chosen class, discard everything that conflicts with it, repeat):
>
> | rule | counterexample | greedy | optimum |
> |---|---|---|---|
> | earliest start | $[0,10]$, $[1,2]$, $[3,4]$ | 1 | 2 |
> | shortest duration | $[0,4]$, $[3,6]$, $[5,9]$ | 1 | 2 |
> | fewest conflicts | the 11 classes below | 3 | 4 |
> | earliest finish, but maximizing credit hours | $[0,2]$ worth 1 credit, $[1,10]$ worth 5 | 1 credit | 5 credits |
>
> Fewest conflicts: take $[0,10]$, $[20,30]$, $[40,50]$, $[60,70]$ (the optimum), $[28,42]$, and three mutually overlapping classes over each gap, $[7,23]$, $[8,22]$, $[9,21]$ and $[47,63]$, $[48,62]$, $[49,61]$. The class $[28,42]$ is the only one with just two conflicts, but after taking it at most one class on each side survives. The weighted problem needs dynamic programming. The book's Exercises 4.1–4.2 test more rules; see the [[2-algorithms/04-greedy-algorithms-exercises|solved exercises]].

## 4.3 The general pattern

Both proofs so far have the same shape, and so do almost all greedy correctness proofs.

> [!recipe] Recipe — the inductive exchange argument
> 1. **Assume an optimal solution that differs from the greedy one** (or: take an optimal solution that agrees with the greedy one as long as possible).
> 2. **Find the first difference** between the two.
> 3. **Exchange:** replace the optimal solution's choice there by the greedy choice, and show that the result is still **feasible** and **no worse**. (It need not be better.)
> 4. **Induct:** some optimal solution therefore contains every greedy choice. Sometimes one more step is needed to show that no optimal solution contains *more* than the greedy solution (the case $m > k$ in Theorem 4.4).

> [!template] Template — proving a greedy algorithm correct
> **Greedy choice.** "Let $g$ be [the precise choice: the class that finishes first; the two least frequent characters; …]." \
> **Exchange lemma.** "Let $\mathit{OPT}$ be an optimal solution that does not use $g$, and let $o$ be [the element of $\mathit{OPT}$ playing $g$'s role, e.g. the class of $\mathit{OPT}$ that finishes first]. Then $\mathit{OPT} - o + g$ is feasible because [...] and costs no more because [...]. So some optimal solution uses $g$." \
> **Same problem, smaller.** "Once $g$ is chosen, what remains is an instance of the same problem: [the classes that start after $g$ ends; the alphabet with $x, y$ merged]. An optimal solution that uses $g$ is $g$ plus an optimal solution of that instance, because [...]." \
> **Induction.** "The greedy algorithm chooses $g$ and then, by the induction hypothesis, solves the smaller instance optimally; so its solution is optimal." \
> **Running time.** Usually a sort or a priority queue: $O(n\log n)$.

> [!trap] Where greedy proofs go wrong
> - **Exchanging without checking feasibility.** The swapped-in element must be compatible with everything that stays — in Lemma 4.3 that is why $g$ is the *first-finishing* class of $X$.
> - **Comparing against the greedy solution instead of an arbitrary optimal one.** The argument starts from an optimal solution you know nothing about.
> - **Forgetting the last step.** "Some optimal solution contains all greedy choices" does not yet say that it contains nothing else.
> - **Proving the rule on an example.** One example, or ten, is not a proof; one counterexample *is* a disproof. If the rule fails, fall back on dynamic programming ([[2-algorithms/03-dynamic-programming#35-warning-greed-is-stupid|§3.5]]).

## 4.4 Huffman codes

A **binary code** assigns a string of bits, its **codeword**, to every character of an alphabet. A code is **prefix-free** (also called a *prefix code*) if no codeword is a prefix of another, so an encoded message can be decoded left to right without separators. 7-bit ASCII and UTF-8 are prefix-free; Morse code, read as a code over dot and dash, is not: E (•) is a prefix of I (••), S (•••) and H (••••).

A prefix-free binary code is a binary **code tree** with the characters at the leaves: the codeword of a character spells the path from the root to its leaf (0 = left, 1 = right), so its length is the leaf's **depth**. Unlike a binary search tree, the leaves are in no particular order and only leaves hold characters.

> [!definition] Problem — optimal prefix-free code
> Given frequencies $f[1\,..\,n]$ of the $n$ characters of a message, find a code tree $T$ minimizing the length of the encoded message,
> $$
> \textsf{cost}(T) = \sum_{i=1}^{n} f[i]\cdot\textsf{depth}_T(i).
> $$

The cost function is the one of optimal binary search trees; dropping the order of the leaves makes a greedy algorithm possible. **Huffman's algorithm** (1951): *merge the two least frequent characters into a new character whose frequency is their sum, and recurse;* the merges, read backward, build the tree, each new character becoming an internal node whose children are the two merged ones.

Every internal node of the final tree carries the total frequency of the leaves below it, and each leaf is counted once by each of its proper ancestors, so **the cost of a code tree is the sum of the numbers in its internal nodes** — for a Huffman tree, the sum of the merged frequencies.

> [!example] Example — Sallows' self-describing sentence
> "This sentence contains three a's, three c's, two d's, twenty-six e's, five f's, three g's, eight h's, thirteen i's, two l's, sixteen n's, nine o's, six r's, twenty-seven s's, twenty-two t's, two u's, five v's, eight w's, four x's, five y's, and only one z." Encoding only its 170 letters:
>
> | letter | A | C | D | E | F | G | H | I | L | N |
> |---|---|---|---|---|---|---|---|---|---|---|
> | freq | 3 | 3 | 2 | 26 | 5 | 3 | 8 | 13 | 2 | 16 |
> | depth | 6 | 6 | 7 | 3 | 5 | 6 | 4 | 4 | 6 | 3 |
>
> | letter | O | R | S | T | U | V | W | X | Y | Z |
> |---|---|---|---|---|---|---|---|---|---|---|
> | freq | 9 | 6 | 27 | 22 | 2 | 5 | 8 | 4 | 5 | 1 |
> | depth | 4 | 5 | 3 | 3 | 6 | 5 | 4 | 5 | 5 | 7 |
>
> Huffman first merges Z (1) with one of the three letters of frequency 2 — say D — into a character of frequency 3, then the other two 2s (L and U), then pairs among the four 3s (A, C, G and the merged DZ), and so on; after 19 merges one character of frequency 170 remains. The depths above come from the tree below, in which A = `101000` and S = `111`; the sentence starts `100 0110 1011 111 111 110` (T H I S S E). The encoded sentence has $\sum f[i]\cdot\textsf{depth}(i) = 649$ bits. Ties can be broken differently and give different trees — even different codeword lengths — but every Huffman code has cost 649, and by Theorem 4.6 no prefix-free code does better. (A fixed-length code needs 5 bits per letter for 20 letters: 850 bits.)

> [!key] Lemma 4.5
> Let $x$ and $y$ be the two least frequent characters (ties broken arbitrarily). There is an optimal code tree in which $x$ and $y$ are siblings — in fact siblings of maximum depth.

> [!proof]- Proof (click to expand)
> Let $T$ be an optimal code tree, of depth $d$. We may assume $T$ is **full** — every internal node has two children — since an internal node with one child can be removed, moving its subtree up one level, without increasing the cost. Then a leaf at depth $d$ has a sibling, and the sibling is a leaf too (anything below it would be deeper than $d$). Call these two sibling positions $p$ and $p'$.
>
> Exchanging the characters $u$ and $v$ of two leaves changes the cost by
> $$
> \big(\textsf{depth}(v) - \textsf{depth}(u)\big)\cdot\big(f[u] - f[v]\big),
> $$
> which is at most 0 when $u$ moves to a leaf at least as deep and $f[u]\le f[v]$. Exchange $x$ with the character at $p$, then $y$ with the character at $p'$ (skip an exchange if the character is already in place). Each exchange moves $x$ or $y$ to the maximum depth $d$ and trades it with a character $v$ at least as frequent: every character other than $x$ has frequency at least $f[x]$, and every character other than $x$ and $y$ has frequency at least $f[y]$ (when $y$ moves, $x$ already sits at $p$, so $v\ne x$). Neither exchange increases the cost, so the final tree is still optimal, and in it $x$ and $y$ are sibling leaves at depth $d$.

> [!key] Theorem 4.6
> Every Huffman code is an optimal prefix-free binary code.

> [!proof]- Proof (induction on $n$)
> For $n\le 2$ Huffman's algorithm builds the only full code tree, and an optimal tree can be taken to be full (see the proof of Lemma 4.5). Let $n\ge 3$, let $1$ and $2$ be the two characters Huffman merges first (two least frequent ones), and let $f[n+1] = f[1] + f[2]$ be the merged character. The Huffman tree $T$ is the Huffman tree $T'$ for the $n-1$ frequencies $f[3\,..\,n+1]$ with the leaf $n+1$ replaced by an internal node with children $1$ and $2$.
>
> For **any** code tree $U$ in which $1$ and $2$ are siblings, contracting them into a single leaf $n+1$ gives a tree $U'$ for $f[3\,..\,n+1]$, and since $1$ and $2$ sit one level below the position of $n+1$,
> $$
> \textsf{cost}(U) = \textsf{cost}(U') + f[1] + f[2].
> $$
> By Lemma 4.5 some optimal tree $U$ has $1$ and $2$ as siblings, and by the induction hypothesis $T'$ is optimal for $f[3\,..\,n+1]$. Hence
> $$
> \textsf{cost}(T) = \textsf{cost}(T') + f[1] + f[2] \le \textsf{cost}(U') + f[1] + f[2] = \textsf{cost}(U),
> $$
> so $T$ is optimal too.

**Implementation.** Keep the characters in a priority queue keyed by frequency, and store the tree as three arrays $L$, $R$, $P$ (left child, right child, parent): nodes $1, \ldots, n$ are the leaves, the merged characters get the indices $n+1, \ldots, 2n-1$, and $2n-1$ is the root.

```text
BuildHuffman(f[1 .. n]):
    for i ← 1 to n
        L[i] ← 0; R[i] ← 0
        Insert(i, f[i])
    for i ← n + 1 to 2n − 1             ⟨⟨the book prints n⟩⟩
        x ← ExtractMin()                ⟨⟨find two rarest symbols⟩⟩
        y ← ExtractMin()
        f[i] ← f[x] + f[y]              ⟨⟨merge into a new symbol⟩⟩
        Insert(i, f[i])
        L[i] ← x; P[x] ← i              ⟨⟨update tree pointers⟩⟩
        R[i] ← y; P[y] ← i
    P[2n − 1] ← 0
```

The loop runs $n-1$ times, once per merge. (Starting it at $n$, as printed, would overwrite leaf $n$ and run one ExtractMin too many.) In all there are $2n-1$ Inserts and $2n-2$ ExtractMins, each $O(\log n)$ in a binary heap: **$O(n\log n)$** time.

Encoding and decoding with a fixed code tree take time proportional to the length $m$ of the encoded message. To encode a character, recurse up to the root through $P$ and write the bits on the way back down; to decode, walk down from the root and restart there at every leaf:

```text
HuffmanEncode(A[1 .. k]):
    m ← 1
    for i ← 1 to k
        HuffmanEncodeOne(A[i])

HuffmanEncodeOne(x):
    if x < 2n − 1
        HuffmanEncodeOne(P[x])
        if x = L[P[x]]
            B[m] ← 0
        else
            B[m] ← 1
        m ← m + 1

HuffmanDecode(B[1 .. m]):
    k ← 1
    v ← 2n − 1
    for i ← 1 to m
        if B[i] = 0
            v ← L[v]
        else
            v ← R[v]
        if L[v] = 0
            A[k] ← v
            k ← k + 1
            v ← 2n − 1
```

> [!trap] Huffman traps
> - **Merge the two smallest *current* frequencies** — merged characters included — not the two smallest original ones.
> - **Top-down splitting is not optimal.** Fano and Shannon's earlier greedy rule sorts the frequencies, splits the sorted list into two contiguous parts whose sums are as equal as possible, and recurses on each part. For frequencies $10, 4, 4, 4, 3$ it splits $\{10, 4\}$ / $\{4, 4, 3\}$, then $\{4\}$ / $\{4, 3\}$: cost $57$. Huffman's tree (merge $3+4$, then $4+4$, then $7+8$, then $10+15$) costs $7 + 8 + 15 + 25 = 55$.
> - **Huffman trees are not unique**, nor are their codeword lengths; their cost is.
> - **A code tree is not a search tree**: no order on the leaves, characters only at leaves.

## 4.5 Stable matching

Every year the National Resident Matching Program assigns new doctors to hospital internships from ranked preference lists. The simplified model of the chapter: $n$ doctors and $n$ hospitals, each hospital with one position; every doctor ranks all hospitals and every hospital ranks all doctors, with no ties. Doctors are written $\alpha, \beta, q, r, s, t$; hospitals $A, B, C, D$.

> [!definition] Definition — stable matching
> A **matching** pairs every doctor with exactly one hospital. A doctor $\alpha$ and a hospital $B$ form an **unstable pair** for a matching if
> - $\alpha$ is matched with some hospital $A$ but prefers $B$, and
> - $B$ is matched with some doctor $\beta$ but prefers $\alpha$.
>
> A **stable matching** is a matching with no unstable pair.

### Some bad ideas

Nothing so far guarantees that a stable matching exists at all. Take three doctors and three hospitals with these preferences (best first):
- doctors: $q\colon A\succ C\succ B$, $\ r\colon C\succ A\succ B$, $\ s\colon A\succ B\succ C$;
- hospitals: $A\colon r\succ q\succ s$, $\ B\colon s\succ q\succ r$, $\ C\colon q\succ r\succ s$.

The matching $\{Aq, Br, Cs\}$ is unstable: $A$ prefers $r$ to $q$, and $r$ prefers $A$ to $B$, so $(r, A)$ is an unstable pair.

- **Fix unstable pairs one at a time** — match the pair, and match their two abandoned partners with each other. This can cycle forever (an example of Knuth's): resolving the unstable pairs $Ar$, $Cr$, $Cq$, $Aq$ in turn gives
$$
\{Aq, Br, Cs\}\to\{Ar, Bq, Cs\}\to\{As, Bq, Cr\}\to\{As, Br, Cq\}\to\{Aq, Br, Cs\}.
$$
- **Rounds of offers without second thoughts** — in each round every unmatched hospital offers its position to its favorite *unmatched* doctor, and every unmatched doctor with offers accepts her favorite, for good. Each round matches at least one new pair, so this ends with a matching. On the input above it gives the stable $\{Ar, Bs, Cq\}$ after one round. But take doctors $q\colon C\succ B\succ A$, $\ r\colon A\succ C\succ B$, $\ s\colon A\succ B\succ C$ and hospitals $A\colon q\succ s\succ r$, $\ B\colon q\succ r\succ s$, $\ C\colon s\succ r\succ q$: in round one $q$ accepts $B$ (rejecting $A$), $s$ accepts $C$, and in round two $A$ gets $r$: the result $\{Ar, Bq, Cs\}$ is unstable, because $A$ and $s$ prefer each other to their partners.

### The Boston Pool and Gale–Shapley algorithms

The NRMP adopted the "Boston Pool" algorithm in 1952; in 1962 Gale and Shapley described a generalization and proved that it always produces a stable matching (Shapley shared the 2012 economics Nobel Prize with Roth for this line of work). The difference from the failed protocol: **a doctor may drop a tentative match for a better offer.**

> [!recipe] The Gale–Shapley algorithm (hospitals offer)
> Repeat while some hospital is unmatched:
> 1. An arbitrary unmatched hospital $A$ offers its position to the best doctor $\alpha$ on its list who has not yet rejected it.
> 2. If $\alpha$ is unmatched, she tentatively accepts. If she is matched but prefers $A$, she rejects her current hospital and tentatively accepts $A$. Otherwise she rejects $A$.

Hospitals make offers greedily, and doctors accept greedily: each doctor ends with the best offer she ever receives. The book describes the algorithm in prose; with the array representation it suggests — $\mathit{HPref}[A, r]$ is the $r$th doctor on hospital $A$'s list, $\mathit{DPref}[\alpha, r]$ the $r$th hospital on doctor $\alpha$'s list — it reads:

```text
GaleShapley(HPref[1 .. n, 1 .. n], DPref[1 .. n, 1 .. n]):
    for α ← 1 to n
        for r ← 1 to n
            Rank[α, DPref[α, r]] ← r      ⟨⟨α's rank for each hospital⟩⟩
        Match[α] ← 0                      ⟨⟨α is unmatched⟩⟩
    for A ← 1 to n
        Next[A] ← 1                       ⟨⟨position of A's next offer⟩⟩
    Free ← {1, 2, …, n}                   ⟨⟨unmatched hospitals, e.g. a stack⟩⟩
    while Free ≠ ∅
        remove any hospital A from Free
        α ← HPref[A, Next[A]]
        Next[A] ← Next[A] + 1
        if Match[α] = 0
            Match[α] ← A
        else if Rank[α, A] < Rank[α, Match[α]]
            add Match[α] to Free          ⟨⟨α drops her current hospital⟩⟩
            Match[α] ← A
        else
            add A to Free                 ⟨⟨α rejects A⟩⟩
    return Match[1 .. n]
```

> [!example] Example — the book's four doctors and four hospitals
>
> | rank | $q$ | $r$ | $s$ | $t$ | | $A$ | $B$ | $C$ | $D$ |
> |---|---|---|---|---|---|---|---|---|---|
> | 1st | $A$ | $A$ | $B$ | $D$ | | $t$ | $r$ | $t$ | $s$ |
> | 2nd | $B$ | $D$ | $A$ | $B$ | | $s$ | $t$ | $r$ | $r$ |
> | 3rd | $C$ | $C$ | $C$ | $C$ | | $r$ | $q$ | $s$ | $q$ |
> | 4th | $D$ | $B$ | $D$ | $A$ | | $q$ | $s$ | $q$ | $t$ |
>
> One run: (1) $A\to t$; (2) $B\to r$; (3) $C\to t$, and $t$ drops $A$; (4) $D\to s$; (5) $A\to s$, and $s$ drops $D$; (6) $D\to r$, and $r$ drops $B$; (7) $B\to t$, and $t$ drops $C$; (8) $C\to r$, rejected; (9) $C\to s$, rejected; (10) $C\to q$, accepted. The result is $\{As, Bt, Cq, Dr\}$. No doctor gets her first choice and no hospital its first choice; County ($C$) ends with its last choice. The matching is stable — in fact it is the **only** stable matching for these lists. (The book also calls $\{Ar, Bs, Cq, Dt\}$ stable, but $B$ and $q$ prefer each other to their partners $s$ and $C$.)

### Running time

Each hospital offers its position to each doctor at most once, so there are **at most $n^2$ offers**. With the arrays above (the $\mathit{Rank}$ table built in $O(n^2)$ time, a stack of free hospitals, a pointer $\mathit{Next}[A]$ into each hospital's list), each offer takes $O(1)$ time, so the algorithm runs in **$O(n^2)$ time** — linear in the size of the input, which consists of two $n\times n$ tables. The bound is tight: if all hospitals rank the doctors in the same order $\alpha_1\succ\cdots\succ\alpha_n$ and all doctors rank the hospitals in the same order $A_1\succ\cdots\succ A_n$, then $A_k$ ends with $\alpha_k$ after offering to $\alpha_1, \ldots, \alpha_k$, for exactly $n(n+1)/2$ offers in every run.

### Correctness

> [!key] Theorem — Gale–Shapley computes a stable matching
> For any preference lists and any choice of which free hospital offers next, the algorithm halts after at most $n^2$ offers with a stable matching.

> [!proof]- Proof (click to expand)
> **A perfect matching.** A doctor who has received an offer stays matched forever (she only trades up). If a free hospital $A$ had been rejected by all $n$ doctors, every doctor would have received an offer and be matched — $n$ doctors to the $n-1$ hospitals other than $A$, impossible. So a free hospital always has a doctor left to offer to, and when the algorithm stops, every hospital, hence every doctor, is matched.
>
> **No unstable pair.** Suppose $\alpha$ ends with $A$ but prefers $B$. Doctors only trade up, so $\alpha$ never received an offer from $B$ (she would have ended with $B$ or better). $B$ makes offers in its order of preference and stopped at its final doctor $\beta$ without reaching $\alpha$, so $B$ prefers $\beta$ to $\alpha$. Hence $(\alpha, B)$ is not an unstable pair.

### Optimality

Which hospital makes the next offer does not matter at all: **every run produces the same matching**. Call a doctor $\alpha$ **feasible** for a hospital $A$ if some stable matching pairs them; let $\textsf{best}(A)$ be the highest-ranked feasible doctor on $A$'s list and $\textsf{worst}(\alpha)$ the lowest-ranked feasible hospital on $\alpha$'s list.

> [!key] Lemma 4.7
> During the Gale–Shapley algorithm, each hospital $A$ is rejected only by doctors that are infeasible for $A$.

> [!proof]- Proof (click to expand)
> Induction on the number of rejections, in the order they happen. Suppose $\alpha$ rejects $A$ (at once, or by dropping it) because she holds an offer from $B$, whom she prefers to $A$. $B$ offered to $\alpha$ only after every doctor it prefers to $\alpha$ had rejected it — earlier, so by the induction hypothesis all those doctors are infeasible for $B$. Now take any matching $M$ that pairs $\alpha$ with $A$, and let $\beta$ be $B$'s partner in $M$. If $B$ prefers $\alpha$ to $\beta$, then $(\alpha, B)$ is an unstable pair for $M$. Otherwise $B$ prefers $\beta$ to $\alpha$, so $\beta$ is infeasible for $B$, and $M$, which pairs them, is not stable. Either way $M$ is not stable: $\alpha$ is infeasible for $A$.

> [!key] Corollary 4.8
> The Gale–Shapley algorithm matches $\textsf{best}(A)$ with $A$, for every hospital $A$.

(The final matching is stable, so $A$'s final doctor is feasible; by Lemma 4.7 every doctor $A$ prefers to it is infeasible.) So the hospital-proposing algorithm computes the **best stable matching for every hospital at once** — and the same one in every run. It also follows that hospital $A$ makes offers exactly to the doctors it ranks at or above $\textsf{best}(A)$, so even the number of offers is the same in every run: $2 + 2 + 4 + 2 = 10$ in the example.

> [!key] Corollary 4.9
> The Gale–Shapley algorithm matches $\alpha$ with $\textsf{worst}(\alpha)$, for every doctor $\alpha$.

> [!proof]- Proof (click to expand)
> Let the algorithm pair $\alpha$ with $A$, so $\alpha = \textsf{best}(A)$. Take any stable matching $M$ in which $A$ has another partner $\beta$. $A$ prefers $\alpha$ to $\beta$ (because $\alpha$ is its best feasible doctor), so stability of $M$ forces $\alpha$ to prefer her own partner in $M$ to $A$. Hence $\alpha$ prefers every other feasible hospital to $A$: $A = \textsf{worst}(\alpha)$.

The matching that is best for every hospital is worst for every doctor. A consequence found by Dubins and Freedman (1981): under the hospital-proposing algorithm a doctor can sometimes get a better match by misreporting her preferences, but a single hospital never can (a group of colluding hospitals can make some of its members better off). Partly for this reason the NRMP reversed the roles in 1998: doctors now make the offers, which yields the doctor-optimal, hospital-pessimal stable matching. In the example above the stable matching is unique, so reversing the roles gives the same result (after 9 offers instead of 10).

## The chapter's greedy algorithms at a glance

| problem | greedy choice | time | why it is correct |
|---|---|---|---|
| tape, equal frequencies | shortest file first | $O(n\log n)$ | swapping an out-of-order neighbor pair lowers the cost (Lemma 4.1) |
| tape, frequencies $F$ | smallest $L/F$ first | $O(n\log n)$ | same swap; change $L[b]F[a] - L[a]F[b]$ (Lemma 4.2) |
| class scheduling | class that finishes first | $O(n\log n)$ | exchange with the first-finishing class of an optimum (Lemma 4.3, Theorem 4.4) |
| prefix-free code | merge the two least frequent characters | $O(n\log n)$ | they are deepest siblings in some optimal tree; $\textsf{cost}(T) = \textsf{cost}(T') + f[1] + f[2]$ (Lemma 4.5, Theorem 4.6) |
| stable matching | hospitals offer in preference order, doctors trade up | $O(n^2)$ | a doctor never offered by a hospital she prefers cannot form an unstable pair with it; only infeasible doctors reject (Lemma 4.7) |

## Summary

- A greedy algorithm commits to a locally best choice and recurses on what is left; it is correct only with a proof, and most natural greedy rules are wrong.
- The standard proof is the **inductive exchange argument**: take an optimal solution, swap the greedy choice in at the first difference without losing feasibility or value, and induct; check at the end that the optimum has no extra elements.
- Tape sorting: increasing $L$ for uniform access, increasing $L/F$ with access frequencies — an adjacent swap changes the cost by $L[b]F[a]-L[a]F[b]$. $O(n\log n)$.
- Class scheduling: earliest finish time first, $O(n\log n)$; earliest start, shortest duration and fewest conflicts all fail, and so does earliest finish once classes carry weights.
- Huffman codes: merge the two least frequent characters; optimal by Lemma 4.5 (deepest siblings) and $\textsf{cost}(T) = \textsf{cost}(T') + f[1]+f[2]$; $O(n\log n)$ with a heap; cost = sum of internal-node weights (649 bits for Sallows' sentence).
- Stable matching: Gale–Shapley halts after at most $n^2$ offers, $O(n^2)$ time, with a stable matching that does not depend on the order of offers; it is hospital-optimal ($\textsf{best}(A)$ for every $A$) and doctor-pessimal ($\textsf{worst}(\alpha)$ for every $\alpha$).

> [!exam] On the exams
> Greedy algorithms are **not** on the official Midterm 2 topic list (no greedy lecture this semester). What does appear is part (a) of a dynamic-programming problem — *show that the obvious greedy strategy fails* — answered with one small counterexample and its greedy and optimal values ([[0-toolkit/08-review-algorithms|Midterm 2 review]]). There is no separate rubric for greedy algorithms: a greedy algorithm is an algorithm whose **proof of correctness is part of the answer**; the policy the book states in §3.5 gives no credit without one, even when the algorithm happens to be correct. Inside a dynamic program, an unproved greedy shortcut costs $1\tfrac12$ points of the recurrence ([[0-toolkit/06-how-exams-are-graded#12-dynamic-programming|how dynamic programs are graded]]). So when a problem invites a greedy idea, either write the exchange argument in the template's form — precise greedy choice, exchange lemma, induction, running time — or test the rule on small inputs, and if a counterexample appears, give it concretely (the input, the greedy output, a better solution) and switch to dynamic programming. Words like "clearly", "trivial" and "just" draw extra scrutiny from graders.
