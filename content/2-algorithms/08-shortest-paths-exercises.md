*Solved exercises for [[2-algorithms/08-shortest-paths|Chapter 8]] · book pp. 297–303 · statements paraphrased; see the book for the originals*

These are Exercises 8.0–8.8 and 8.11–8.17. Skipped: 8.4(b), 8.6(c), 8.9 and 8.10, which are marked ♥ (particularly challenging), and 8.18–8.26, beyond the first batch (8.26 is marked ♣, outside material). Every modeling problem is written the way the [[0-toolkit/06-how-exams-are-graded#13-graph-reductions|graph-reduction rubric]] grades it ([[concepts/graph-reductions]]): **the graph**, with vertices, edges and weights as explicit functions of the input, layered when the problem needs state; **the problem** on that graph — shortest path from where to where — and why it answers the question; **the algorithm**, the cheapest standard one as a black box — breadth-first search if unweighted, relaxation in topological order if acyclic, Dijkstra if the weights are nonnegative, Bellman–Ford otherwise; and **the time**, in the input's parameters. Proofs about labels use the chapter's language of tense and tight edges ([[concepts/shortest-paths]]). Three statements need repair: 8.8(a) claims a negative cycle *through* $s$, but the cycle need not pass through $s$; the "only if" half of 8.8(d) is false; and the example walk printed in 8.17 ends with an edge that does not exist. Each is pointed out where it occurs. Write your own answer before opening a solution.

> [!tip] Notation and black boxes from the chapter, used below without re-explanation
> - $\mathit{dist}(v)$ and $\mathit{pred}(v)$ are the labels an algorithm maintains; $\delta(u, v)$ is the true shortest-walk distance (possibly $\pm\infty$), and $\delta(v) = \delta(s, v)$. An edge $u\to v$ is **tense** if $\mathit{dist}(u) + w(u\to v) < \mathit{dist}(v)$ and **tight** if $\mathit{dist}(u) < \infty$ and $\mathit{dist}(u) + w(u\to v) = \mathit{dist}(v)$.
> - **Ford's generic algorithm** ([[2-algorithms/08-shortest-paths#83-the-only-sssp-algorithm|§8.3]]): InitSSSP, then relax tense edges in any order. Labels never increase; every finite $\mathit{dist}(v)$ is the length of some walk from $s$ to $v$; if no edge is tense, the labels are the distances and the predecessor pointers form a shortest-path tree; if a negative cycle is reachable from $s$, the algorithm never halts.
> - **[[concepts/breadth-first-search|Breadth-first search]]** ([[2-algorithms/08-shortest-paths#84-unweighted-graphs-breadth-first-search|§8.4]]), unweighted: $O(V+E)$. **DagSSSP** ([[2-algorithms/08-shortest-paths#85-directed-acyclic-graphs-depth-first-search|§8.5]]), relaxing in topological order, any weights: $O(V+E)$. **[[concepts/dijkstras-algorithm|Dijkstra]]** ([[2-algorithms/08-shortest-paths#86-best-first-dijkstras-algorithm|§8.6]]), nonnegative weights: $O(E\log V)$. **[[concepts/bellman-ford|Bellman–Ford]]** ([[2-algorithms/08-shortest-paths#87-relax-all-the-edges-bellmanford|§8.7]]): $O(VE)$, and after $i$ rounds $\mathit{dist}(v)\le\mathit{dist}_{\le i}(v)$, the length of a shortest walk with at most $i$ edges (Lemma 8.6).
> - **Reachability** by [[concepts/whatever-first-search|whatever-first search]] and **[[concepts/strongly-connected-components|strong components]]** ([[2-algorithms/06-depth-first-search#66-strong-components-in-linear-time|§6.6]]), both $O(V+E)$.
> - **Tight paths.** If the labels are the true distances, a path from $s$ is a shortest path if and only if all its edges are tight: tight edges telescope, and every prefix of a shortest path is a shortest path.

## Exercise 8.0 — Checking distances and predecessors

> [!question] Exercise 8.0 (book p. 297)
> $G$ is a directed graph whose edge weights may be positive, negative or zero, possibly with negative cycles, and $s$ is a vertex of $G$.
>
> (a) Every vertex $v$ stores a number $\mathit{dist}(v)$, but no predecessor pointer. Describe and analyze an algorithm that decides whether $\mathit{dist}(v)$ is the shortest-path distance from $s$ to $v$ for every vertex $v$.
>
> (b) Instead, every vertex $v\ne s$ stores a pointer $\mathit{pred}(v)$ to another vertex, but no distance. Describe and analyze an algorithm that decides whether these pointers define a shortest-path tree rooted at $s$.

### (a) Distance labels

> [!hint]- Hint
> A label can be too high (then some edge is tense) or too low. A label is the length of an actual walk from $s$ only if a path of tight edges leads to it from $s$.

> [!solution]- Solution
> Labels are real numbers or $\infty$, as InitSSSP and Relax produce them. If a negative cycle is reachable from $s$, some vertex has $\delta(v) = -\infty$, no labeling is correct, and the algorithm must answer False.
>
> ```text
> CheckDist(G, s):
>     if dist(s) ≠ 0
>         return False
>     for every edge u→v
>         if dist(u) + w(u→v) < dist(v)            ⟨⟨u→v is tense⟩⟩
>             return False
>     mark the vertices reachable from s along tight edges   ⟨⟨whatever-first search⟩⟩
>     return True if every vertex v with dist(v) < ∞ is marked, else False
> ```
>
> (With $\infty + w = \infty$, an edge out of a vertex labeled $\infty$ is never tense.)
>
> **Correct labels pass.** If $\mathit{dist} = \delta$, then $\mathit{dist}(s) = 0$; no edge $u\to v$ is tense, because a shortest walk to $u$ followed by $u\to v$ is a walk to $v$; and every vertex with a finite distance is the end of a shortest path, all of whose edges are tight, so it is marked.
>
> **Labels that pass are correct.** Suppose all three tests pass.
>
> - *Not too high.* Along any walk $s = v_0\to v_1\to\cdots\to v_\ell$, induction with "no edge is tense" gives $\mathit{dist}(v_j)\le\mathit{dist}(v_{j-1}) + w(v_{j-1}\to v_j)\le$ (length of the walk up to $v_j$), starting from $\mathit{dist}(s) = 0$. So $\mathit{dist}(v)$ is at most the length of every walk from $s$ to $v$; in particular every vertex reachable from $s$ has a finite label.
> - *Not too low.* A vertex with a finite label is marked: some path of tight edges $s = u_0\to\cdots\to u_m = v$ exists, and its equalities telescope to $\mathit{dist}(v) = \mathit{dist}(s) + \sum_j w(u_{j-1}\to u_j)$, the length of that path. So finite labels belong to reachable vertices only, and unreachable vertices are labeled $\infty$.
>
> A finite label is thus the length of a walk from $s$ to $v$ and at most the length of every such walk: it is $\delta(v)$. (So the lengths of walks to $v$ are bounded below, and no negative cycle reachable from $s$ can reach $v$.) Every label is correct.
>
> **Time.** One pass over the edges and one whatever-first search: $O(V + E)$.
>
> **Answer.** Check $\mathit{dist}(s) = 0$, that no edge is tense, and that every vertex with a finite label is reachable from $s$ along tight edges: $O(V+E)$ time.

> [!trap]
> - **"No edge is tense" alone** accepts labels that are too low: a single edge $s\to a$ of weight 1 with $\mathit{dist}(a) = 0$ has no tense edge.
> - **"Every vertex has a tight incoming edge"** is not enough either — see the figure. The tight edges must reach the vertex *from $s$*.
> - If labels may also be $-\infty$ (the convention of Exercise 8.6(b)), the simplest correct check recomputes the distances with that algorithm, in $O(VE)$ time, and compares.

### (b) Predecessor pointers

> [!hint]- Hint
> Turn the pointers into distance labels, then use (a).

> [!solution]- Solution
> Allow $\mathit{pred}(v) = \textsf{Null}$, InitSSSP's value for vertices that $s$ cannot reach; a non-Null pointer must be an edge.
>
> 1. For every edge $u\to v$ with $v\ne s$ and $\mathit{pred}(v) = u$, record $\omega(v)\leftarrow w(u\to v)$. If some non-Null $\mathit{pred}(v)$ has no such edge, return False.
> 2. Make $v$ a child of $\mathit{pred}(v)$ and search from $s$ along child links, setting $d(s) = 0$ and $d(v) = d(\mathit{pred}(v)) + \omega(v)$ when $v$ is reached. If some vertex with a non-Null pointer is not reached, return False: its pointers run into a cycle or into a Null pointer at a vertex other than $s$. Set $d(v) = \infty$ for the vertices with $\mathit{pred}(v) = \textsf{Null}$.
> 3. Return CheckDist with the labels $d$.
>
> **Correctness.** If step 2 succeeds, the pointers form a tree $T$ rooted at $s$, its vertices are exactly those with finite $d$, and $d(v)$ is the length of the tree path from $s$ to $v$. If the pointers define a shortest-path tree, every tree path is a shortest path, so $d = \delta$ and (a) accepts. Conversely, if (a) accepts, then $d = \delta$: every tree path is a shortest path, and $T$ contains exactly the vertices with $\delta(v) < \infty$, the vertices reachable from $s$. So $T$ is a shortest-path tree.
>
> **Time.** $O(V + E)$.
>
> **Answer.** Compute the tree-path lengths that the pointers imply and check them with (a): $O(V+E)$ time.

## Exercise 8.1 — Looped trees

> [!question] Exercise 8.1 (book p. 297)
> A **looped tree** is a binary tree whose edges are directed from parent to child, plus an edge from every leaf back to the root; every edge has a nonnegative weight. (The book's example is redrawn in the figure below.)
>
> (a) How much time does Dijkstra's algorithm need to compute the shortest path between two vertices $u$ and $v$ of a looped tree with $n$ nodes?
>
> (b) Describe and analyze a faster algorithm.

### (a) Dijkstra

> [!solution]- Solution
> A binary tree with $n$ nodes has $n - 1$ edges and at most $(n+1)/2$ leaves (the leaves outnumber the nodes with two children by exactly one). So $V = n$ and $E\le (3n - 1)/2 = O(n)$, and Dijkstra's algorithm from $u$ takes $O(E\log V) = O(n\log n)$ time.
>
> **Answer.** $O(n\log n)$.

### (b) Linear time

> [!hint]- Hint
> Inside the subtree of $u$ every edge goes down. The only way out is a loop edge to the root.

> [!solution]- Solution
> Let $r$ be the root and $T_u$ the subtree of $u$ ($u$ and its descendants). Define
>
> - $D(x)$, the length of the tree path from $r$ down to $x$: $D(r) = 0$, $D(c) = D(x) + w(x\to c)$ for a child $c$ of $x$;
> - $L(x)$, the cheapest way from $x$ back to $r$: $L(x) = w(x\to r)$ if $x$ is a leaf, and otherwise $L(x) = \min_c \{w(x\to c) + L(c)\}$ over the children $c$ of $x$.
>
> **Claim.**
> $$
> \delta(u, v) = \begin{cases} D(v) - D(u) & \text{if } u \text{ is an ancestor of } v \text{ (or } u = v\text{)},\\ L(u) + D(v) & \text{otherwise.}\end{cases}
> $$
>
> *Proof.* Every edge out of a vertex of $T_u$ goes to a child, staying in $T_u$, or is a loop edge into $r$. So a walk from $u$ to $v$ either stays in $T_u$ — then it only moves down, so it is the tree path, which exists only if $v\in T_u$ and costs $D(v) - D(u)$ — or it reaches $r$ through a loop edge. In the second case, the part up to the first visit of $r$ goes down to a leaf of $T_u$ and takes its loop edge, which costs at least $L(u)$; after its last visit of $r$ the walk follows the tree path to $v$, which costs $D(v)$, and the part in between is nonnegative. Both bounds are attained. If $v\in T_u$, the second option costs $L(u) + D(v)\ge D(v)\ge D(v) - D(u)$, because weights are nonnegative, so the tree path wins. (For $u = r$ every vertex is a descendant: $\delta(r, v) = D(v)$.)
>
> **Algorithm.** Compute $D$ by one traversal from $r$; decide whether $u$ is an ancestor of $v$ by walking up the parent pointers from $v$; compute $L(u)$ by a postorder traversal of $T_u$. Each step takes $O(n)$ time. For many queries, compute $D$ and $L$ for all vertices and pre/post numbers once, in $O(n)$ time; then each query takes $O(1)$ time ($u$ is an ancestor of $v$ iff $u.\mathit{pre}\le v.\mathit{pre}$ and $v.\mathit{post}\le u.\mathit{post}$).
>
> On the book's tree (figure): $\delta(a, h) = L(a) + D(h) = 16 + 23 = 39$, $\delta(c, a) = 27 + 5 = 32$, and $\delta(a, e) = D(e) - D(a) = 45 - 5 = 40$.
>
> **Answer.** $\delta(u, v) = D(v) - D(u)$ if $u$ is an ancestor of $v$, and $L(u) + D(v)$ otherwise: $O(n)$ time (and $O(1)$ per query after $O(n)$ preprocessing).

## Exercise 8.2 — A few negative edges

> [!question] Exercise 8.2 (book pp. 297–298)
> $G$ is a directed graph with weighted edges, and $s$ and $t$ are two of its vertices.
>
> (a) Describe and analyze an algorithm that finds the shortest path from $s$ to $t$ when exactly one edge of $G$ has negative weight. *(The book's hint: modify Dijkstra's algorithm. Or don't.)*
>
> (b) Do the same when exactly $k$ edges have negative weight. How does the running time depend on $k$?

### (a) One negative edge

> [!hint]- Hint
> Unless it closes a negative cycle, a shortest walk uses the negative edge at most once. Split the walk there.

> [!solution]- Solution
> Let $x\to y$ be the negative edge and $G^+ = G - (x\to y)$, which has only nonnegative weights. Run Dijkstra's algorithm in $G^+$ from $s$ and from $y$, giving $d_s$ and $d_y$.
>
> **Negative cycles.** Every negative cycle uses $x\to y$ (all other edges are nonnegative), and every cycle through $x\to y$ is that edge plus a path from $y$ to $x$ in $G^+$; so $G$ has a negative cycle iff $d_y(x) + w(x\to y) < 0$. If it does, $d_s(x) < \infty$ and $d_y(t) < \infty$, then $s$ reaches the cycle $y\leadsto x\to y$, which reaches $t$: walks from $s$ to $t$ are arbitrarily short, and there is no shortest path ($\delta(s,t) = -\infty$). (A path from $s$ to $x$ never needs the edge out of $x$, and a path from $y$ never needs the edge into $y$, so reachability in $G$ and in $G^+$ agree here.)
>
> **Otherwise,**
> $$
> \delta(s, t) = \min\bigl\{\, d_s(t),\ \ d_s(x) + w(x\to y) + d_y(t) \,\bigr\}.
> $$
> Both terms are lengths of walks from $s$ to $t$ (or $\infty$). Conversely: if $G$ has no negative cycle, some shortest walk is a simple path, so it uses $x\to y$ at most once; without it the path lies in $G^+$ and costs at least $d_s(t)$; with it, the part before is a walk in $G^+$ from $s$ to $x$ and the part after a walk in $G^+$ from $y$ to $t$. If $G$ has a negative cycle but $s$ cannot reach $x$ or $y$ cannot reach $t$, no walk from $s$ to $t$ uses $x\to y$ at all, $\delta(s, t) = d_s(t)$, and the second term is $\infty$.
>
> **Time.** Two runs of Dijkstra: $O(E\log V)$.
>
> **Answer.** $\min\{d_s(t),\ d_s(x) + w(x\to y) + d_y(t)\}$ from two runs of Dijkstra in $G - (x\to y)$, in $O(E\log V)$ time; there is no shortest path if $d_y(x) + w(x\to y) < 0$, $d_s(x) < \infty$ and $d_y(t) < \infty$.

### (b) k negative edges

> [!hint]- Hint
> Layer the graph by the number of negative edges used so far. Inside a layer Dijkstra works; negative edges only lead to the next layer. One extra layer detects negative cycles.

> [!solution]- Solution
> Let $N$ be the set of $k$ negative edges and $G^+ = G - N$.
>
> **Graph.** A **directed** graph $H$ with vertices $(v, i)$ for $v\in V$ and $0\le i\le k+1$, and edges
>
> - $(u, i)\to(v, i)$ of weight $w(u\to v)$, for every edge $u\to v$ of $G^+$ and every $i$;
> - $(x, i)\to(y, i+1)$ of weight $w(x\to y)$, for every negative edge $x\to y$ and every $i\le k$.
>
> It has $(k+2)V$ vertices and at most $(k+2)E$ edges. Its only negative edges go from a layer to the next, so $H$ has no negative cycle.
>
> **Problem.** Paths in $H$ from $(s, 0)$ to $(v, i)$ are exactly the walks in $G$ from $s$ to $v$ that use negative edges exactly $i$ times (counted with repetition). Let $D_i(v)$ be the shortest-path distance from $(s, 0)$ to $(v, i)$ in $H$, and $D_{\le j}(v) = \min_{i\le j} D_i(v)$.
>
> - If no negative cycle that $s$ reaches can reach $v$, then $\delta(v) = D_{\le k}(v)$: some shortest walk to $v$ is a simple path, and it uses each of the $k$ negative edges at most once.
> - $\delta(v) = -\infty$ exactly for the vertices reachable in $G$ from a vertex $u$ with $D_{k+1}(u) < D_{\le k}(u)$ (proof below).
>
> **Algorithm.** Compute the layers in order, one run of Dijkstra each. $D_0$: Dijkstra from $s$ in $G^+$. Layer $i\ge 1$ is entered through the negative edges: for each head $y$ of a negative edge let $c(y) = \min\{D_{i-1}(x) + w(x\to y) : x\to y\in N\}$ and $c_{\min} = \min_y c(y)$; add to $G^+$ a new vertex $z$ with an edge $z\to y$ of weight $c(y) - c_{\min}\ge 0$ for each such $y$, run Dijkstra from $z$, and set $D_i(v) = \delta(z, v) + c_{\min}$. Finally, whatever-first search in $G$ from all vertices $u$ with $D_{k+1}(u) < D_{\le k}(u)$ marks the vertices with $\delta = -\infty$; every other vertex $v$ gets $\delta(v) = D_{\le k}(v)$. Report $\delta(t)$.
>
> **Why layer $k+1$ finds exactly the negative cycles.**
>
> - Suppose $D_{k+1}(u) < D_{\le k}(u)$, and let $W$ be a shortest path in $H$ to $(u, k+1)$, read as a walk in $G$. It uses $k+1$ negative edges, so some negative edge $x\to y$ twice. If the closed walk between the two visits of $x$ had nonnegative length, cutting it out would leave a walk to $u$ with fewer negative edges and length at most $w(W)$, contradicting $D_{k+1}(u) < D_{\le k}(u)$. So that closed walk is negative and contains a negative cycle (split a closed walk at a repeated vertex: the two lengths add up). The cycle lies on $W$, so $s$ reaches it and it reaches $u$: $\delta(u) = -\infty$, and so for everything $u$ reaches.
> - Conversely, let $C$ be a negative cycle reachable from $s$. Its vertices have finite $D_{\le k}$ (each is the end of a simple path from $s$), and for every edge $u\to v$ of $C$, $D_{\le k+1}(v)\le D_{\le k+1}(u) + w(u\to v)$ if the edge is nonnegative and $D_{\le k+1}(v)\le D_{\le k}(u) + w(u\to v)$ if it is negative. If no vertex of $C$ had $D_{k+1} < D_{\le k}$, then $D_{\le k+1} = D_{\le k}$ on $C$, every edge of $C$ would satisfy the first inequality, and adding them around $C$ would give $0\le w(C)$. So some vertex of $C$ is a starting point of the final search, and everything $C$ reaches is marked.
>
> This is round $V$ of Bellman–Ford in disguise (compare Exercise 8.6(b)).
>
> **Time.** $k+2$ runs of Dijkstra on $G^+$ plus one vertex and at most $k\le E$ edges, and one search: $O((k+1)\,E\log V)$. The time grows linearly with $k$; it beats Bellman–Ford's $O(VE)$ when $k = o(V/\log V)$.
>
> **Answer.** Dijkstra layer by layer in the $(k+2)$-layer graph, $O((k+1)E\log V)$ time; $\delta(s,t) = \min_{i\le k} D_i(t)$, or $-\infty$ if $t$ is reachable from a vertex whose layer-$(k+1)$ distance beats all earlier layers.

## Exercise 8.3 — Vertex weights

> [!question] Exercise 8.3 (book p. 298)
> $G$ is an undirected graph in which every *vertex* has a positive weight.
>
> (a) Describe and analyze an algorithm that finds a spanning tree of minimum total weight, where the weight of a spanning tree is the sum of the weights of its vertices.
>
> (b) Describe and analyze an algorithm that finds a path from a given vertex $s$ to another given vertex $t$ with minimum total weight, where the weight of a path is the sum of the weights of its vertices.
>
> *(The book's hint: one of these problems is trivial.)*

> [!hint]- Hint
> (a) Which vertices does every spanning tree contain? (b) Move each vertex's weight onto the edges that enter it.

> [!solution]- Solution
> **(a)** Every spanning tree contains all $V$ vertices, so every spanning tree weighs $\sum_v w(v)$: any spanning tree is a minimum one. Whatever-first search from any vertex finds one in $O(V + E)$ time; if the search misses a vertex, $G$ is disconnected and has no spanning tree.
>
> **(b) Graph.** A **directed** graph $G'$ on the same vertices with, for every edge $uv$ of $G$, the two edges $u\to v$ of weight $w(v)$ and $v\to u$ of weight $w(u)$. $V$ vertices, $2E$ edges, positive weights.
>
> **Problem.** A path $s = v_0, v_1, \dots, v_\ell = t$ in $G$ weighs $w(s) + \sum_{j\ge 1} w(v_j)$, which is $w(s)$ plus its length in $G'$, and paths correspond one to one. So the answer is $w(s)$ plus the shortest-path distance from $s$ to $t$ in $G'$. (With positive weights, shortest walks are simple paths.)
>
> **Algorithm.** Dijkstra's algorithm from $s$ in $G'$.
>
> **Time.** $O(E\log V)$.
>
> (Equivalently: split every vertex $v$ into $v_{\mathrm{in}}\to v_{\mathrm{out}}$ with weight $w(v)$, and give the edges weight 0.)
>
> **Answer.** (a) Any spanning tree, $O(V+E)$. (b) $w(s) + {}$the distance from $s$ to $t$ in the directed graph with $w(u\to v) = w(v)$, by Dijkstra in $O(E\log V)$ time.

## Exercise 8.4 — Replacement paths

> [!question] Exercise 8.4(a) (book p. 298)
> For an edge $e$ of $G$, let $G\setminus e$ be $G$ with $e$ deleted. The **replacement paths** problem asks for the shortest-path distance from $s$ to $t$ in $G\setminus e$ for *every* edge $e$ — an array of $E$ distances. Edge weights are nonnegative.
>
> (a) $G$ is directed, and the shortest path from $s$ to $t$ passes through *every* vertex of $G$. Describe an algorithm that solves this special case in $O(E\log V)$ time. *(Book's hint: if we delete an edge of the original shortest path, how do the old and new shortest paths overlap?)*
>
> (Part (b), arbitrary undirected graphs, is marked ♥ and skipped.)

> [!hint]- Hint
> Number the vertices along the path. Once a path edge is deleted, a new shortest path is a prefix of the old one, one edge that jumps over the deleted edge, and a suffix of the old one.

> [!solution]- Solution
> Let $P = v_0v_1\cdots v_{n-1}$ be the shortest path, with $n = V$, $s = v_0$, $t = v_{n-1}$ (Dijkstra finds it in $O(E\log V)$ time if it is not given), $e_i = v_i\to v_{i+1}$, and $D(i)$ the length of $P$ up to $v_i$. Prefixes and suffixes of a shortest path are shortest paths, so $\delta(s, v_i) = D(i)$ and $\delta(v_j, t) = D(n-1) - D(j)$.
>
> - **Edges off $P$.** Deleting one leaves $P$ intact: the answer is $D(n-1)$.
> - **Path edges.** Call an edge $a\to b$ that is not on $P$ a **bypass** if $a = v_i$ and $b = v_j$ with $i < j$; it *spans* the path edges $e_i, \dots, e_{j-1}$, and its key is
> $$
> \kappa(a\to b) = D(i) + w(a\to b) + D(n-1) - D(j).
> $$
> **Claim.** $\delta_{G\setminus e_i}(s, t)$ is the smallest key of a bypass spanning $e_i$, or $\infty$ if there is none.
>
> *At most:* the prefix of $P$ to $a$, the bypass, and the suffix of $P$ from $b$ avoid $e_i$ and have total length $\kappa(a\to b)$.
>
> *At least:* let $A = \{v_0, \dots, v_i\}$ and $B$ the other vertices. A walk from $s$ to $t$ in $G\setminus e_i$ starts in $A$ and ends in $B$, so it has a first edge $a\to b$ from $A$ to $B$. That edge is not $e_i$, and not another path edge (only $e_i$ joins $A$ to $B$), so it is a bypass spanning $e_i$. The part of the walk before it is a walk from $s$ to $a$, of length at least $\delta(s, a)$, and the part after it a walk from $b$ to $t$, of length at least $\delta(b, t)$; the total is at least $\kappa(a\to b)$. A backward edge, from $v_j$ to $v_i$ with $i\ge j$, is never the first edge from some $A$ to $B$, so it never matters.
>
> **All minima by a sweep.** For $i = 0, 1, \dots, n-2$: insert into a min-heap, keyed by $\kappa$, the bypasses that start at $v_i$; pop the minimum while it ends at or before $v_i$; the answer for $e_i$ is the key of the minimum ($\infty$ if the heap is empty). Each bypass is inserted and removed once.
>
> **Time.** Dijkstra plus the sweep: $O(E\log V)$.
>
> **Answer.** Each edge off the path gets $D(n-1)$; the path edge $e_i$ gets the smallest key $D(i) + w(v_i\to v_j) + D(n-1) - D(j)$ among the bypasses spanning it, found for all $i$ by one heap sweep: $O(E\log V)$ time.

## Exercise 8.5 — Reinserting one edge

> [!question] Exercise 8.5 (book p. 298)
> $G = (V, E)$ is a connected directed graph with nonnegative edge weights, $s$ and $t$ are vertices, and $H$ is the subgraph of $G$ obtained by deleting some edges. We want to put exactly one edge of $G$ back into $H$ so that the shortest path from $s$ to $t$ in the resulting graph is as short as possible. Describe and analyze an algorithm that chooses the best edge in $O(E\log V)$ time.

> [!hint]- Hint
> A shortest path uses the reinserted edge at most once. What do you need to know about its two ends?

> [!solution]- Solution
> **Distances.** Run Dijkstra in $H$ from $s$, giving $d_s(v) = \delta_H(s, v)$, and in the reversal of $H$ from $t$, giving $d_t(v) = \delta_H(v, t)$.
>
> **The best edge.** For each deleted edge $e = u\to v$ (in $G$ but not in $H$), let $c(e) = d_s(u) + w(u\to v) + d_t(v)$, and reinsert an edge with the smallest $c(e)$.
>
> **Correctness.** Weights are nonnegative, so $H + e$ has a shortest walk from $s$ to $t$ that is a simple path, and it uses $e$ at most once. If it avoids $e$, it costs $\delta_H(s, t) = d_s(t)$; if it uses $e = u\to v$, its part before $e$ lies in $H$ and costs at least $d_s(u)$, its part after $e$ at least $d_t(v)$. Both kinds are attained, so $\delta_{H+e}(s, t) = \min\{d_s(t), c(e)\}$, which is smallest when $c(e)$ is.
>
> **Time.** Two runs of Dijkstra and one scan of the edges: $O(E\log V)$.
>
> **Answer.** Reinsert the deleted edge $u\to v$ minimizing $\delta_H(s, u) + w(u\to v) + \delta_H(v, t)$, from Dijkstra on $H$ and on its reversal: $O(E\log V)$ time.

## Exercise 8.6 — Bellman–Ford with certificates

> [!question] Exercise 8.6 (book pp. 298–299)
> (a) Describe and analyze a modification of Bellman–Ford that returns a negative cycle if one is reachable from $s$, and a shortest-path tree otherwise, still in $O(VE)$ time.
>
> (b) Describe and analyze a modification of Bellman–Ford that ends with $\mathit{dist}(v) = -\infty$ if some walk from $s$ to $v$ contains a negative cycle, and with the length of the shortest path from $s$ to $v$ otherwise, still in $O(VE)$ time.
>
> (Part (c), the same for Ford's generic algorithm, is marked ♥ and skipped.)

### (a) A negative cycle or a shortest-path tree

> [!hint]- Hint
> Run $V-1$ rounds. If an edge is still tense, relax it and walk back along the predecessor pointers from its head.

> [!solution]- Solution
> ```text
> BellmanFordCycle(s):
>     InitSSSP(s)
>     repeat V − 1 times
>         for every edge u→v
>             if u→v is tense
>                 Relax(u→v)
>     for every edge u→v
>         if u→v is tense
>             Relax(u→v)
>             x ← v
>             repeat V times
>                 x ← pred(x)
>             return the cycle x, pred(x), pred(pred(x)), …, back to x (reversed)
>     return the predecessor pointers                 ⟨⟨a shortest-path tree⟩⟩
> ```
>
> Two invariants hold for relaxations in any order (they are used again in Exercise 8.8):
>
> - **(I1)** If $\mathit{pred}(v)\ne\textsf{Null}$, then $\mathit{dist}(v)\ge\mathit{dist}(\mathit{pred}(v)) + w(\mathit{pred}(v)\to v)$. Equality holds right after the relaxation that set $\mathit{pred}(v)$; afterwards $\mathit{dist}(\mathit{pred}(v))$ can only decrease, and $\mathit{dist}(v)$ changes only together with $\mathit{pred}(v)$.
> - **(I2)** Every cycle of predecessor edges has negative length. Look at the relaxation of $u\to v$ that closes the cycle $C$: just before it, $u\to v$ is tense, $\mathit{dist}(v) > \mathit{dist}(u) + w(u\to v)$, and every other edge of $C$ satisfies (I1). Adding the $\lvert C\rvert$ inequalities, the labels cancel: $0 > w(C)$.
>
> **The walk back ends on a cycle.** Suppose the predecessor chain from $v$ reached a Null pointer. Pointers lead only to vertices with finite labels, and the only such vertex without a predecessor is $s$, whose label is then still 0. So the chain is a simple path $Q$ from $s$ to $v$ with at most $V-1$ edges, and (I1) along it gives $\mathit{dist}(v)\ge w(Q)\ge\mathit{dist}_{\le V-1}(v)$. But after $V-1$ rounds $\mathit{dist}(v)\le\mathit{dist}_{\le V-1}(v)$ (Lemma 8.6), and the extra relaxation lowered it further — a contradiction. So the chain never stops; after $V$ steps it is on a cycle of predecessor edges, which is negative by (I2), and reachable from $s$ because its labels are finite.
>
> **Otherwise.** If no edge is tense after $V-1$ rounds, the labels are the distances and the predecessor pointers form a shortest-path tree ([[2-algorithms/08-shortest-paths#83-the-only-sssp-algorithm|§8.3]]); and if a negative cycle is reachable from $s$, some edge is still tense after $V - 1$ rounds ([[2-algorithms/08-shortest-paths#87-relax-all-the-edges-bellmanford|§8.7]]). So the algorithm returns a cycle exactly when a negative cycle is reachable.
>
> **Time.** $O(VE)$ for the rounds, $O(E)$ for the extra pass, $O(V)$ for the walk.
>
> **Answer.** After $V-1$ rounds relax one more tense edge $u\to v$; $V$ predecessor steps from $v$ land on a negative cycle: $O(VE)$ time.

### (b) Minus infinity behind negative cycles

> [!hint]- Hint
> After $V-1$ rounds, where can a tense edge be?

> [!solution]- Solution
> After the $V-1$ rounds, let $T$ be the set of heads of the edges that are still tense. Run whatever-first search in $G$ from all of $T$ at once (from a new vertex with an edge to each vertex of $T$), and set $\mathit{dist}(v)\leftarrow -\infty$ for every marked vertex. The others keep their labels.
>
> **Correctness.** Call $v$ *doomed* if a negative cycle reachable from $s$ reaches $v$ — exactly the vertices with $\delta(v) = -\infty$.
>
> - A vertex $v$ that is not doomed has a shortest walk that is a simple path, so after $V-1$ rounds $\mathit{dist}(v)\le\delta(v)$ (Lemma 8.6), and $\mathit{dist}(v)\ge\delta(v)$ because labels are lengths of walks: $\mathit{dist}(v) = \delta(v)$. If a tense edge $u\to v$ led to such a $v$, then $u$ would not be doomed either (whatever $u$ is reached from, $v$ is too), and $\mathit{dist}(u) + w(u\to v) < \mathit{dist}(v) = \delta(v)\le\delta(u) + w(u\to v)\le\mathit{dist}(u) + w(u\to v)$ — impossible. So every head of a tense edge is doomed, and so is every vertex it reaches.
> - A negative cycle $C$ reachable from $s$ has finite labels, and if none of its edges were tense, adding the inequalities $\mathit{dist}(v)\le\mathit{dist}(u) + w(u\to v)$ around $C$ would give $0\le w(C)$. So some edge of $C$ is tense, its head lies on $C$, and the search marks everything $C$ reaches.
>
> So the marked vertices are exactly the doomed ones; unreachable vertices keep $\infty$.
>
> **Time.** $O(VE) + O(V + E) = O(VE)$.
>
> **Answer.** After $V-1$ rounds, mark everything reachable from the heads of the still-tense edges and set those labels to $-\infty$: $O(VE)$ time.

## Exercise 8.7 — FellmanBored

> [!question] Exercise 8.7 (book p. 299)
> An even looser variant of Ford's algorithm:
>
> ```text
> FellmanBored(s):
>     InitSSSP(s)
>     for i ← 1 to whatever, man, I don't care
>         e_i ← any edge in G
>         if e_i is tense
>             Relax(e_i)
> ```
>
> Prove: if the edges of a walk $v_0\to v_1\to\cdots\to v_\ell$ with $v_0 = s$ occur, in this order, as a subsequence of the examined edges $e_1, e_2, e_3, \dots$, then afterwards $\mathit{dist}(v_\ell)\le\sum_{j=1}^{\ell} w(v_{j-1}\to v_j)$.

> [!hint]- Hint
> Labels never go up. Induct along the walk.

> [!solution]- Solution
> Let $i_1 < i_2 < \cdots < i_\ell$ be the iterations in which the walk's edges are examined, and $P_j = \sum_{m\le j} w(v_{m-1}\to v_m)$ the length of the walk up to $v_j$ ($P_0 = 0$).
>
> **Claim.** From iteration $i_j$ on, $\mathit{dist}(v_j)\le P_j$ (for $j = 0$: at all times).
>
> Labels never increase — Relax only replaces a label by a smaller one — so it suffices to prove the bound right after iteration $i_j$. For $j = 0$, InitSSSP sets $\mathit{dist}(s) = 0 = P_0$. For $j\ge 1$, iteration $i_j$ comes after $i_{j-1}$, so $\mathit{dist}(v_{j-1})\le P_{j-1}$ by induction. If the edge $v_{j-1}\to v_j$ is tense, Relax sets $\mathit{dist}(v_j) = \mathit{dist}(v_{j-1}) + w(v_{j-1}\to v_j)\le P_j$; if it is not tense, $\mathit{dist}(v_j)\le\mathit{dist}(v_{j-1}) + w(v_{j-1}\to v_j)\le P_j$ already. ∎
>
> The case $j = \ell$ is the statement. No assumption about the weights is needed; the claim holds even with negative cycles.
>
> **Answer.** By induction along the walk: once $v_{j-1}\to v_j$ has been examined, $\mathit{dist}(v_j)$ is at most the length of the walk up to $v_j$, and labels never increase.

## Exercise 8.8 — Detecting negative cycles in Ford's algorithm

> [!question] Exercise 8.8 (book p. 299)
> Ford's generic algorithm relaxes tense edges, chosen arbitrarily, for as long as there are any.
>
> (a) Prove that if $\mathit{pred}(s)$ ever changes after InitSSSP, the input graph contains a negative cycle through $s$.
>
> (b) Show that $\mathit{pred}(s)$ might never change, even when the input graph contains a negative cycle through $s$.
>
> (c) Let $P$ be the current set of predecessor edges $\mathit{pred}(v)\to v$ and $X$ the current set of tense edges. Prove that the input graph has no negative cycles if and only if $P\cup X$ is always a dag.
>
> (d) Let $R$ be the set of edges relaxed so far. Prove that the input graph has no negative cycles if and only if $R$ is always a dag.

Two repairs first. A negative cycle that $s$ cannot reach is invisible to the algorithm — its vertices keep the label $\infty$ and their edges are never tense — so in (c) and (d) "negative cycle" must mean one **reachable from $s$**, the chapter's usual reading. With that reading, (a) and the "only if" half of (d) are still false as printed; the figure shows counterexamples. Below we use (I1) and (I2) from Exercise 8.6(a), and the chapter's facts that every finite label is the length of a walk from $s$ and that the algorithm never halts when a negative cycle is reachable.

### (a) When pred(s) changes

> [!hint]- Hint
> When $\mathit{pred}(s)$ changes, an edge $u\to s$ was tense, and $\mathit{dist}(u)$ is the length of a walk from $s$. Is the resulting negative closed walk a cycle?

> [!solution]- Solution
> **What is true.** If $\mathit{pred}(s)$ changes, $G$ has a negative cycle that $s$ can reach and that can reach $s$ — equivalently, $s$ lies on a negative closed walk and $\delta(s) = -\infty$.
>
> *Proof.* At the first change, an edge $u\to s$ is relaxed, so $\mathit{dist}(u) + w(u\to s) < \mathit{dist}(s) = 0$ ($\mathit{dist}(s)$ changes only with $\mathit{pred}(s)$). $\mathit{dist}(u)$ is the length of a walk $W$ from $s$ to $u$, so $W$ followed by $u\to s$ is a closed walk through $s$ of negative length. Splitting a closed walk at a repeated vertex gives two shorter closed walks whose lengths add up, so one of them is negative; repeating, we reach a negative cycle on the walk, which $s$ reaches and which reaches $s$.
>
> **What is false.** The cycle need not pass through $s$. In panel (a) of the figure, the cycles are $a\to b\to a$, of length $-2$, and $s\to a\to s$, of length $+100$. Relax $s\to a$, then $a\to b$ and $b\to a$ alternately; after 51 rounds $\mathit{dist}(a) = -102$, the edge $a\to s$ is tense ($-102 + 100 < 0$), and relaxing it changes $\mathit{pred}(s)$. No negative cycle passes through $s$.
>
> **Answer.** $\mathit{pred}(s)$ changes only if $s$ lies on a negative closed walk; that walk contains a negative cycle, but not necessarily one through $s$.

### (b) When pred(s) never changes

> [!hint]- Hint
> Nothing forces the algorithm to be fair. Give it something else to do forever.

> [!solution]- Solution
> In panel (b), $s\to a\to s$ has length $1 - 2 = -1$, and there is a second negative cycle $b\to c\to b$, of length $-1$, hanging off $s$. Relax $s\to a$ and $s\to b$, then $b\to c$, $c\to b$, $b\to c$, … forever: each of these edges is tense when it is relaxed (the labels of $b$ and $c$ drop by 1 per round), so this is a legal run of Ford's algorithm. The edge $a\to s$ is tense from the first step on, but it is never chosen, and $\mathit{pred}(s)$ stays Null.
>
> (The second cycle is needed: with $s\to a\to s$ alone, after relaxing $s\to a$ the only tense edge is $a\to s$.)
>
> **Answer.** A run that relaxes a different negative cycle forever never touches $s$.

### (c) P ∪ X

> [!hint]- Hint
> One direction: add up (I1) and the tense inequalities around a cycle of $P\cup X$. Other direction: if $P$ stays acyclic, $P$ is a tree rooted at $s$, which bounds every label from below — yet a reachable negative cycle drives some label to $-\infty$.

> [!solution]- Solution
> We prove: some cycle appears in $P\cup X$ at some moment if and only if a negative cycle is reachable from $s$ — in fact, in the "if" direction, a cycle appears in $P$ itself.
>
> **Every cycle of $P\cup X$ is a reachable negative cycle.** Let $C$ be a cycle in $P\cup X$. Tails of predecessor edges and of tense edges have finite labels, so every vertex of $C$ does, and $C$ is reachable from $s$. Predecessor edges satisfy $\mathit{dist}(v) - \mathit{dist}(u)\ge w(u\to v)$ by (I1), tense edges $\mathit{dist}(v) - \mathit{dist}(u) > w(u\to v)$. Adding over $C$, the labels cancel: $0\ge w(C)$, with strict inequality if $C$ contains a tense edge; if it consists of predecessor edges only, $w(C) < 0$ by (I2). So without a reachable negative cycle, $P\cup X$ is always a dag.
>
> **A reachable negative cycle puts a cycle into $P$.** We use a lemma.
>
> *Lemma. In a run that never halts, some label is not bounded below.* Suppose all labels stayed above some bound. Labels never increase, so each converges, to $\lambda(v)$ say. Let $F$ be the set of edges relaxed infinitely often and $U$ the set of their heads; after some moment $T$ only edges of $F$ are relaxed, and every vertex outside $U$ has reached its final label. A relaxation of $u\to v\in F$ sets $\mathit{dist}(v) = \mathit{dist}(u) + w(u\to v)$; passing to the limit along these relaxations, $\lambda(v) = \lambda(u) + w(u\to v)$. Let $\sigma(x) = \mathit{dist}(x) - \lambda(x)\ge 0$. A vertex of $U$ is lowered infinitely often, so $\sigma > 0$ on $U$ at all times, while $\sigma = 0$ outside $U$ after $T$. After $T$, relaxing $u\to v\in F$ sets $\sigma(v) = \sigma(u)$ exactly — so $u\in U$, as $\sigma(v)$ stays positive — and therefore $\sigma$ only takes the finitely many values it had on $U$ at time $T$. Each relaxation strictly lowers $\sigma$ at its head, so after $T$ every vertex is relaxed finitely often — contradicting a run that never halts. ∎ (With integer weights the lemma is immediate: each relaxation lowers a label by at least 1.)
>
> Now let a negative cycle be reachable from $s$. Then Ford's algorithm never halts, and by the lemma some label becomes arbitrarily negative. If $P$ stayed acyclic forever, $\mathit{pred}(s)$ would never change: once it does, every vertex with a finite label has a predecessor with a finite label, and following predecessors from $s$ must repeat a vertex. So $\mathit{dist}(s) = 0$ throughout, $P$ is a tree rooted at $s$, and by (I1) every label is at least the length of its tree path, a simple path, hence at least $-\sum_e\lvert w(e)\rvert$ — bounded below, a contradiction. So at some moment $P$, and with it $P\cup X$, contains a cycle.
>
> **Answer.** Every cycle of $P\cup X$ is a reachable negative cycle; and a reachable negative cycle makes some label unbounded below, which an acyclic $P$ — a tree rooted at $s$ — forbids.

### (d) R — false as printed

> [!hint]- Hint
> An edge stays in $R$ after its head gets a better predecessor. Look for a positive cycle that gets relaxed in both directions.

> [!solution]- Solution
> **The "only if" half is false.** In panel (d), with edges $s\to u$ (10), $s\to v$ (0), $u\to v$ (1) and $v\to u$ (1), relax $s\to u$ ($\mathit{dist}(u) = 10$), $u\to v$ (11), $s\to v$ (0) and $v\to u$ (1), each tense when relaxed; then no edge is tense and the algorithm halts. $R$ contains the cycle $u\to v\to u$, of length 2, although $G$ has no negative cycle at all.
>
> **The "if" half is true.** Every predecessor edge was relaxed when it was set, so $P\subseteq R$ at all times. If a negative cycle is reachable from $s$, then by (c) $P$ — hence $R$ — contains a cycle at some moment.
>
> **Answer.** "No negative cycle $\Rightarrow$ $R$ is always a dag" fails on a positive 2-cycle relaxed in both directions; the converse holds because $P\subseteq R$.

## Exercise 8.11 — Every edge negative

> [!question] Exercise 8.11 (book p. 300)
> In the directed graph $G$ every edge has *negative* weight; $s$ is a source vertex. Describe and analyze an efficient algorithm that computes, for every vertex $t$: $\mathit{dist}(t) = \infty$ if $t$ is not reachable from $s$; $\mathit{dist}(t) = -\infty$ if $G$ has a cycle that is reachable from $s$ and from which $t$ is reachable; and the shortest-path distance from $s$ to $t$ otherwise.

> [!hint]- Hint
> Every cycle is negative, so the question is only which vertices a cycle can reach. Whatever is left is a dag.

> [!solution]- Solution
> 1. Whatever-first search from $s$ finds the set $R$ of reachable vertices; every other vertex gets $\infty$.
> 2. Compute the strong components of $G$. A vertex lies on a cycle if and only if its strong component has at least two vertices or it has a self-loop. Let $Z$ be the set of vertices of $R$ that lie on a cycle. Every cycle is negative.
> 3. Whatever-first search from all of $Z$ at once marks a set $M$; every vertex of $M$ gets $-\infty$. These are exactly the vertices reachable from a cycle reachable from $s$: such a cycle lies inside $R$, so its vertices are in $Z$; and a vertex of $Z$ lies on a cycle that $s$ reaches.
> 4. Let $U = R\setminus M$. The subgraph of $G$ induced by $U$ is a dag, since a cycle in it would put its vertices into $Z\subseteq M$. Every walk from $s$ to a vertex $t\in U$ stays inside $U$: its vertices are reachable from $s$, and none is in $M$, or $t$ would be too. So for $t\in U$ the answer is the shortest-path distance in that dag: run DagSSSP from $s$ (relax the edges in topological order). If $s\in M$, then $U$ is empty.
>
> **Time.** Two searches, strong components, a topological sort and DagSSSP: $O(V + E)$ — better than the $O(VE)$ of Bellman–Ford with Exercise 8.6(b).
>
> **Answer.** Reachability, strong components to find the vertices on cycles, a search from them for $-\infty$, and DagSSSP on the remaining dag: $O(V+E)$ time.

## Exercise 8.12 — Best paths

> [!question] Exercise 8.12 (book p. 300)
> Among the shortest paths from $s$ to $t$, a **best path** is one with the fewest edges. Given a directed graph $G$ with *positive* edge weights and a source vertex $s$, describe and analyze an algorithm that computes best paths from $s$ to every other vertex. The book's Figure 8.18 shows four of the many shortest paths in one graph; the first, a single edge, is the best one.

> [!hint]- Hint
> Keep only the edges that lie on shortest paths. Then count edges.

> [!solution]- Solution
> 1. Dijkstra's algorithm from $s$ computes $\delta(v)$ for every $v$.
> 2. Let $T$ be the subgraph of **tight** edges $u\to v$, those with $\delta(u) < \infty$ and $\delta(u) + w(u\to v) = \delta(v)$. A path from $s$ is a shortest path if and only if all its edges are tight. Because weights are positive, $\delta$ strictly increases along tight edges, so $T$ is a dag.
> 3. Breadth-first search in $T$ from $s$: its tree contains, for every $v$, a path of tight edges with the fewest edges — a best path — and its predecessor pointers form a tree of best paths.
>
> **Time.** $O(E\log V) + O(V + E) = O(E\log V)$.
>
> **Alternative, changing only the weights.** Run Dijkstra with the pairs $(w(e), 1)$ as weights, added coordinatewise and compared lexicographically. With integer weights the pairs can be packed into numbers: $w'(e) = V\cdot w(e) + 1$. A path with $k\le V-1$ edges has $w'$-length $V\cdot w(P) + k$, and since $k < V$, comparing $w'$-lengths compares the pairs (weight, number of edges) lexicographically.
>
> In the book's graph (figure), 13 of the 17 edges are tight, and the BFS distance of $t$ in the tight dag is 1: the best path is the single edge $s\to t$.
>
> **Answer.** Dijkstra, keep the tight edges, and run breadth-first search from $s$ in that dag: $O(E\log V)$ time.

## Exercise 8.13 — Counting shortest paths

> [!question] Exercise 8.13 (book pp. 300–301)
> Describe and analyze an algorithm that determines the number of shortest paths from $s$ to $t$ in a directed graph with *positive* edge weights; arithmetic takes $O(1)$ time. *(Book's hint: compute shortest-path distances from $s$, throw away every edge that cannot be part of a shortest path from $s$ to another vertex, and look at what is left.)*

> [!hint]- Hint
> What is left is the tight dag of Exercise 8.12. Count paths in a dag by dynamic programming.

> [!solution]- Solution
> Compute $\delta$ by Dijkstra and the tight dag $T$ as in Exercise 8.12. The shortest paths from $s$ to $v$ are exactly the paths from $s$ to $v$ in $T$.
>
> **Function.** $\textsf{NumPaths}(v)$ = the number of paths from $s$ to $v$ in $T$, that is, the number of shortest paths from $s$ to $v$. We want $\textsf{NumPaths}(t)$.
>
> **Recurrence.** Every such path to $v\ne s$ ends with a tight edge $u\to v$, preceded by a path to $u$:
> $$
> \textsf{NumPaths}(s) = 1,\qquad \textsf{NumPaths}(v) = \sum_{u\to v \text{ tight}} \textsf{NumPaths}(u)\quad (v\ne s).
> $$
>
> **Memoization and order.** An array indexed by the vertices, filled in increasing order of $\delta$ — Dijkstra's extraction order, a topological order of $T$ because $\delta$ increases along tight edges. Vertices that $s$ cannot reach get 0.
>
> **Time.** $O(E\log V)$ for Dijkstra, $O(V + E)$ for the table.
>
> In the book's graph (figure), $\textsf{NumPaths}(t) = \textsf{NumPaths}(s) + \textsf{NumPaths}(g) = 1 + 7 = 8$, because the tight edges into $t$ are $s\to t$ and $g\to t$.
>
> **Answer.** Dijkstra, then $\textsf{NumPaths}(v) = \sum_{u\to v\text{ tight}} \textsf{NumPaths}(u)$ in order of increasing distance: $O(E\log V)$ time.

## Exercise 8.14 — Where to meet

> [!question] Exercise 8.14 (book p. 301)
> You and a friend live in cities $p$ and $q$ and want to meet as soon as possible: you choose a city $t$, leave at the same moment and drive toward it. The input is an undirected graph $G = (V, E)$ of cities and roads, where $w(e)\ge 0$ is the time to drive along road $e$. Describe and analyze an algorithm that finds the city $t$ where you can meet soonest.

> [!hint]- Hint
> You meet when the later of you arrives.

> [!solution]- Solution
> **Graph.** $G$ itself (undirected, nonnegative weights).
>
> **Problem.** Meeting at $t$, you meet at time $\max\{\delta(p, t), \delta(q, t)\}$: whoever arrives first waits. The answer is a city minimizing this.
>
> **Algorithm.** Dijkstra's algorithm from $p$ and from $q$; then scan all vertices.
>
> **Time.** $O(E\log V)$.
>
> **Answer.** $\arg\min_t\max\{\delta(p,t), \delta(q,t)\}$, from two runs of Dijkstra: $O(E\log V)$ time.

> [!trap]
> Minimizing $\delta(p, t) + \delta(q, t)$ minimizes the total driving, not the meeting time. On the path $p - a - q$ with two roads of length 1, the sum is 2 at all three cities, but only $a$ gives meeting time 1.

## Exercise 8.15 — Espresso stops

> [!question] Exercise 8.15 (book pp. 301–302)
> A cyclist rides from the vertex $s$ to the vertex $t$ of an undirected graph $G$ whose vertices are espresso stands and whose edges are highway segments, edge $e$ of length $\ell(e)$. After each espresso the cyclist can ride at most $L$ miles.
>
> (a) Describe and analyze an algorithm that decides whether the ride is possible.
>
> (b) Describe and analyze an algorithm that finds the smallest $L$ for which the ride is possible.
>
> (c) A new map $G'$ adds a green vertex for every Starbucks. Describe and analyze an algorithm that finds the minimum number of green vertices on a path from $s$ to $t$ in $G'$ that uses only edges of length at most $L$.

> [!hint]- Hint
> (a) There is coffee at every vertex. (b) The answer is the length of some edge. (c) Charge 1 for entering a green vertex.

> [!solution]- Solution
> **(a)** Every vertex sells espresso, so a ride is possible exactly along a path whose edges all have length at most $L$.
> **Graph:** $G_L$, the undirected subgraph of the edges with $\ell(e)\le L$. **Problem:** reachability of $t$ from $s$. **Algorithm:** whatever-first search from $s$ in $G_L$. **Time:** $O(V + E)$.
>
> **(b)** The smallest $L$ is the minimum, over paths from $s$ to $t$, of the longest edge on the path; it is the length of some edge, and feasibility in (a) is monotone in $L$. Sort the edge lengths and binary-search for the smallest $\ell_i$ for which (a) succeeds with $L = \ell_i$ (if even the longest fails, $t$ is unreachable). **Time:** $O(E\log E)$ for sorting plus $O(\log E)$ runs of (a): $O((V + E)\log E) = O(E\log V)$ for a connected map. (Alternatives: the path between $s$ and $t$ in a minimum spanning tree minimizes the longest edge — see [[2-algorithms/07-minimum-spanning-trees|Chapter 7]]; or Dijkstra with "max" in place of "+", which modifies the algorithm.)
>
> **(c) Graph.** A **directed** graph $H$ on the vertices of $G'$ with, for every edge $uv$ of $G'$ with $\ell(uv)\le L$, the edges $u\to v$ of weight $[v\text{ green}]$ and $v\to u$ of weight $[u\text{ green}]$ (1 for a green head, 0 otherwise).
> **Problem.** A path from $s$ to $t$ in $G'$ that uses only edges of length at most $L$ is a path in $H$, and its length in $H$ is the number of green vertices on it ($s$, a Giggle office, is not green). So the answer is the shortest-path distance from $s$ to $t$ in $H$; a shortest walk can be shortened to a path without visiting more green vertices.
> **Algorithm.** Dijkstra from $s$ in $H$ (weights 0 and 1 are nonnegative).
> **Time.** $O(E\log V)$.
>
> **Answer.** (a) Reachability using edges of length $\le L$, $O(V+E)$. (b) Binary search on the sorted edge lengths with (a), $O(E\log V)$. (c) Dijkstra with weight $[\text{head is green}]$ on the edges of length $\le L$, $O(E\log V)$.

## Exercise 8.16 — Shortest walk with a multiple of 3 edges

> [!question] Exercise 8.16 (book p. 302)
> $G = (V, E)$ is a directed graph with nonnegative edge weights, and $s$, $t$ are vertices. Describe and analyze an algorithm that finds the shortest walk from $s$ to $t$ (vertices and edges may repeat) whose number of edges is divisible by 3. In the book's example, with edges $s\to w$, $w\to t$, $w\to y$, $y\to x$, $x\to s$, $y\to z$, $z\to t$ all of weight 1, the answer is 6, for the walk $s\to w\to y\to x\to s\to w\to t$.

> [!hint]- Hint
> Exercise 5.14 with weights: three copies of every vertex, one for each number of edges mod 3.

> [!solution]- Solution
> **Graph.** A **directed** graph $G'$ with vertices $V\times\{0, 1, 2\}$ and, for every edge $u\to v$ of $G$ and every $i\in\{0, 1, 2\}$, an edge $(u, i)\to(v, (i+1)\bmod 3)$ of weight $w(u\to v)$. $3V$ vertices, $3E$ edges, nonnegative weights.
>
> **Problem.** Walks in $G$ from $s$ correspond one to one, with equal lengths, to walks in $G'$ from $(s, 0)$: the second coordinate counts the edges mod 3. So the answer is the shortest-path distance from $(s, 0)$ to $(t, 0)$ in $G'$ (0 if $s = t$; no such walk if $(t, 0)$ is unreachable).
>
> **Algorithm.** Dijkstra's algorithm from $(s, 0)$. (Breadth-first search, as in [[2-algorithms/05-basic-graph-algorithms-exercises#exercise-514--walks-of-length-divisible-by-3|Exercise 5.14]], no longer suffices because of the weights.)
>
> **Time.** $O(E\log V)$.
>
> On the example, Dijkstra returns 6 (figure).
>
> **Answer.** Dijkstra from $(s,0)$ to $(t,0)$ in $V\times\{0,1,2\}$ with edges $(u,i)\to(v,i+1\bmod 3)$: $O(E\log V)$ time.

## Exercise 8.17 — No three edges of one color in a row

> [!question] Exercise 8.17 (book p. 302)
> In a directed graph $G$ with nonnegative edge weights, every edge is red or blue. Describe an algorithm that finds the shortest walk from $s$ to $t$ in which no three consecutive edges have the same color. In the book's example (the graph of [[2-algorithms/05-basic-graph-algorithms-exercises#exercise-515--no-three-edges-of-one-color-in-a-row|Exercise 5.15]]), with red edges of weight 1 and blue edges of weight 2, the answer is 9.

> [!hint]- Hint
> Exercise 5.15 with weights. What must you remember about the walk so far?

> [!solution]- Solution
> **Graph.** A **directed** graph $G'$ with a start vertex $\textit{start}$ and the vertices $(v, c, k)$ for $v\in V$, $c\in\{\textsf{red}, \textsf{blue}\}$, $k\in\{1, 2\}$ — "at $v$, and the walk so far ends with exactly $k$ edges of color $c$". For every edge $u\to v$ of $G$ with color $c'$ and weight $w$, edges of weight $w$:
>
> - $\textit{start}\to(v, c', 1)$ if $u = s$;
> - $(u, c, k)\to(v, c', 1)$ for $c\ne c'$ and $k\in\{1, 2\}$;
> - $(u, c', 1)\to(v, c', 2)$.
>
> $4V + 1$ vertices, at most $4E$ edges, nonnegative weights.
>
> **Problem.** Legal walks from $s$ correspond one to one, with equal lengths, to walks in $G'$ from $\textit{start}$ (the state records exactly what decides whether the next edge is allowed). The answer is the smallest distance from $\textit{start}$ to the four vertices $(t, c, k)$, or 0 if $s = t$.
>
> **Algorithm.** Dijkstra's algorithm from $\textit{start}$, then the minimum of four distances.
>
> **Time.** $O(E\log V)$.
>
> On the example the answer is 9, for the walk $s\to a\to b\Rightarrow d\to c\Rightarrow a\to b\to t$ (blue edges as $\Rightarrow$; colors red, red, blue, red, blue, red, red; weights $1+1+2+1+2+1+1$). The book prints this walk ending in "$\to c$"; there is no edge $b\to c$, and the walk must end at $t$.
>
> **Answer.** Dijkstra in the graph of (vertex, last color, run length) states: $O(E\log V)$ time.
