> [!abstract] In one breath
> A **minimum spanning tree** (MST) of a connected, undirected graph with real edge weights is a spanning tree of least total weight. If all weights are distinct the MST is unique (Lemma 7.1), and a consistent tie-breaking rule lets every algorithm pretend they are. Almost every MST algorithm is one **generic algorithm**: grow a forest $F$ inside the MST by adding **safe** edges — the lightest edge leaving some component of $F$, which belongs to the MST by an exchange argument (Lemma 7.2, the **cut property**) — and never adding **useless** edges, whose endpoints $F$ already connects. **Borůvka** adds the safe edge of every component at once, at least halving the number of components per phase: $O(E\log V)$. **Jarník** (alias Prim) grows a single tree from a start vertex, which is best-first search with edge weights as priorities: $O(E\log V)$ with a binary heap, $O(E + V\log V)$ with a Fibonacci heap. **Kruskal** scans the edges by increasing weight and keeps each one that joins two different components, which a union-find structure tracks: $O(E\log V)$, dominated by the sort.

## 7.1 Distinct edge weights

> [!definition] Definition — minimum spanning tree
> The input is a **connected, undirected, weighted graph**: $G = (V, E)$ with a real weight $w(e)$ on every edge — positive, negative or zero. A **spanning tree** of $G$ is a subgraph that is a tree and contains every vertex; it has exactly $V - 1$ edges. A **minimum spanning tree** (MST) is a spanning tree $T$ that minimizes
> $$
> w(T) = \sum_{e\in T} w(e).
> $$

The problem as stated can have many answers: if every edge has weight 1, then **every** spanning tree is minimum, with weight $V - 1$. The algorithms are much easier to state and prove when the answer is unique, and one simple condition guarantees that.

> [!key] Lemma 7.1
> If all edge weights of a connected graph $G$ are distinct, then $G$ has a unique minimum spanning tree.

> [!proof]- Proof (click to expand)
> An exchange argument. Suppose $G$ has two different minimum spanning trees $T$ and $T'$; we find two edges of equal weight. Each tree has an edge that the other lacks. Let $e$ be the lightest edge of $T\setminus T'$ and $e'$ the lightest edge of $T'\setminus T$; by symmetry, say $w(e)\le w(e')$.
>
> Adding $e$ to $T'$ closes exactly one cycle $C$, and $C$ passes through $e$. The tree $T$ cannot contain all of $C$, so $C$ has an edge $e''\notin T$. Then $e''\ne e$ (because $e\in T$), so $e''\in T'\setminus T$ and $w(e'')\ge w(e')\ge w(e)$.
>
> Deleting $e''$ from the cycle leaves a spanning tree $T'' = T' + e - e''$ with $w(T'') = w(T') + w(e) - w(e'') \le w(T')$. As $T'$ is minimum, equality holds: $w(e) = w(e'')$, for two different edges $e$ and $e''$.

The converse is false: a graph with repeated weights can still have a unique MST — for instance when $G$ is itself a tree.

**Breaking ties.** An algorithm written for distinct weights still works when weights repeat, provided **every** comparison breaks ties in the same consistent way. The book's rule, ShorterEdge$(i, j, k, l)$, compares two edges $ij$ and $kl$ (vertices numbered $1, \ldots, V$) by weight, then by smaller endpoint, then by larger endpoint — that is, it compares the triples
$$
\textsf{key}(ij) = \big(w(ij),\ \min\{i,j\},\ \max\{i,j\}\big)
$$
lexicographically. Different edges of a simple graph have different endpoints, so different edges get different keys: a strict total order on the edges.

> [!note] Why consistent tie-breaking is safe
> Rank the edges $1, \ldots, E$ in key order, let $r(e)$ be the rank of $e$, and replace each weight by $w(e) + \varepsilon\, r(e)$ for a tiny $\varepsilon > 0$. The new weights are distinct and sort the edges exactly as the keys do, so an algorithm that only compares edges behaves identically on them and returns their unique MST $T^*$. And $T^*$ is minimum for the original weights too: for every spanning tree $T$, $w(T^*) + \varepsilon\,r(T^*) \le w(T) + \varepsilon\,r(T)$, so $w(T^*) - w(T) < \varepsilon VE$, which is smaller than every positive difference between two tree weights once $\varepsilon$ is small enough.

From here on, like the book, assume that the weights are distinct and speak of **the** minimum spanning tree.

Concept page: [[concepts/minimum-spanning-trees]].

## 7.2 The only minimum spanning tree algorithm

Graph traversals are all instances of one generic algorithm, whatever-first search ([[2-algorithms/05-basic-graph-algorithms#55-whatever-first-search|§5.5]]); minimum spanning tree algorithms are all instances of one generic algorithm too. It maintains an acyclic subgraph $F$ of $G$, the **intermediate spanning forest**, with the invariant

$$
F \text{ is a subgraph of the minimum spanning tree of } G.
$$

Initially $F$ consists of $V$ one-vertex trees; edges are added to join its trees, and when one tree is left, the invariant says it is the MST. The whole question is which edges may be added.

> [!definition] Definition — safe, useless and undecided edges
> Fix the forest $F$. An edge of $G$ that is not in $F$ is
> - **useless** if both of its endpoints lie in the same component of $F$;
> - **safe** if it is the lightest edge with exactly one endpoint in some component of $F$ — the **safe edge of that component**; one edge can be the safe edge of two components;
> - **undecided** otherwise.

In the right half of the figure, $F = \{bd, cd, cf, eg\}$ has components $\{a\}$, $\{b, c, d, f\}$ and $\{e, g\}$: the safe edges are $ac$ (safe for both $\{a\}$ and $\{b, c, d, f\}$) and $de$ (for $\{e, g\}$), the useless edges are $bc$ and $df$, and $ab$, $be$, $dg$, $fg$ are undecided.

> [!key] Lemma 7.2 (Prim)
> The minimum spanning tree of $G$ contains every safe edge. More generally — the **cut property** — for every set $S$ of vertices with $\varnothing\ne S\ne V$, the minimum spanning tree contains the lightest edge with exactly one endpoint in $S$.

> [!proof]- Proof (click to expand)
> Again an exchange argument. Let $e = uv$ be the lightest edge with exactly one endpoint in $S$, say $u\in S$ and $v\notin S$ (it is unique because the weights are distinct), and let $T$ be any spanning tree that does not contain $e$.
>
> The path from $u$ to $v$ in $T$ starts in $S$ and ends outside $S$, so at least one of its edges, call it $e'$, has exactly one endpoint in $S$. Deleting $e'$ splits $T$ into two trees, and because $e'$ lies on the path from $u$ to $v$, one tree contains $u$ and the other contains $v$. Adding $e$ joins them again, so $T' = T - e' + e$ is a spanning tree. Since $e'\ne e$ also has exactly one endpoint in $S$, $w(e') > w(e)$, and therefore $w(T') < w(T)$: $T$ is not the minimum spanning tree. So the MST contains $e$. The safe edge of a component of $F$ is the case where $S$ is that component.

> [!key] Lemma 7.3
> The minimum spanning tree contains no useless edge.

Proof: the endpoints of a useless edge are already joined by a path in $F$, which lies inside the MST, so adding the edge to the MST would close a cycle.

The two lemmas need different things. Lemma 7.2 says nothing about $F$: the lightest edge leaving **any** vertex set is in the MST, whatever forest produced that set. Lemma 7.3 needs the invariant: for a forest that is not inside the MST, a "useless" edge can belong to the MST — for $F = \{ab, bc\}$ in the example, $ac$ is useless but it is an MST edge.

```text
GenericMST(V, E):                 ⟨⟨the book's prose, as pseudocode⟩⟩
    F ← (V, ∅)
    while F has more than one component
        add one or more safe edges to F
    return F
```

> [!key] The generic algorithm is correct
> While $F$ has two or more components, some edge of the connected graph $G$ leaves a component, so a safe edge exists. Every safe edge is in the MST (Lemma 7.2), so adding safe edges — one, or several at once — keeps the invariant, and with it keeps $F$ acyclic. Each added edge joins two components, so after $V - 1$ additions $F$ is a single spanning tree inside the MST: the MST itself.

As $F$ grows, undecided edges become safe or useless; a useless edge stays useless forever, because components only merge. An actual algorithm has to say **which** safe edges to add in each iteration and **how** to find them — the next three sections.

> [!template] Template — the cut-property exchange
> To prove that an edge $e$ belongs to the minimum spanning tree (or that a greedy choice is right): \
> "Let $S$ be [a vertex set]; $e$ is the lightest edge with exactly one endpoint in $S$. Let $T$ be any spanning tree without $e$. The path in $T$ between the endpoints of $e$ starts in $S$ and ends outside it, so it contains an edge $e'$ with exactly one endpoint in $S$. Then $T - e' + e$ is a spanning tree, and it is lighter than $T$ because $w(e') > w(e)$. So $T$ is not minimum, and the MST contains $e$."

This is the inductive exchange argument of greedy algorithms ([[2-algorithms/04-greedy-algorithms#43-the-general-pattern|§4.3]]) in its purest form: the greedy choice is the lightest crossing edge, the exchange swaps it for the tree's crossing edge without breaking feasibility, and the generic algorithm is the induction. The mirror image, the **cycle property** — the heaviest edge of any cycle is not in the MST — is Exercise 7.1(a) on the [[2-algorithms/07-minimum-spanning-trees-exercises|exercises page]].

> [!trap] Minimum spanning tree traps
> - **Ties.** With repeated weights, "the" MST may not exist, and Lemma 7.2 weakens to "each safe edge lies in **some** MST" — not necessarily all of them in the same one. An algorithm must break **all** ties with one consistent rule (§7.1); otherwise it can return a non-tree (see Borůvka below).
> - **Negative weights are fine.** The algorithms only compare weights. Adding a constant $c$ to every weight adds $(V-1)\,c$ to every spanning tree, so the MST does not change; a **maximum** spanning tree is an MST for the weights $-w$.
> - **An MST is not a shortest-path tree.** In the example, the MST path from $f$ to $g$ is $f c d e g$ of weight $16 + 3 + 12 + 4 = 35$, while the edge $fg$ has weight 26 (see [[2-algorithms/08-shortest-paths|Chapter 8]]).
> - **The heaviest edge is not automatically excluded.** A bridge — an edge whose removal disconnects $G$ — is in every spanning tree, however heavy.
> - **Disconnected graphs** have no spanning tree. Kruskal then returns a minimum spanning **forest**, one tree per component, and so does Borůvka if it stops after a phase that adds no edge — as written, its loop "while $\mathit{count} > 1$" never ends. Jarník's best-first version spans only the component of its start vertex; the vertex version (§7.4) instead extracts a vertex of priority $\infty$, whose $\mathit{edge}$ is Null, whenever a component is finished, and grows the next tree from it.

Concept page: [[concepts/minimum-spanning-trees]].

## 7.3 Borůvka's algorithm

The oldest MST algorithm, found by Otakar Borůvka in 1926 to design an electrical network, and rediscovered by Choquet (1938), by Florek, Łukaszewicz, Perkal, Steinhaus and Zubrzycki (1951), and by Sollin (1961) — hence the name "Sollin's algorithm" in some texts. In one line:

> [!recipe] Borůvka
> **Add ALL the safe edges and recurse.**

Each phase labels the components of $F$ with CountAndLabel ([[2-algorithms/05-basic-graph-algorithms#56-important-variants|§5.6]]), which returns their number and sets $\mathit{comp}(v)$ for every vertex; then one pass over the edges finds every component's safe edge.

```text
Borůvka(V, E):
    F ← (V, ∅)
    count ← CountAndLabel(F)
    while count > 1
        AddAllSafeEdges(E, F, count)
        count ← CountAndLabel(F)
    return F

AddAllSafeEdges(E, F, count):
    for i ← 1 to count
        safe[i] ← Null
    for each edge uv ∈ E
        if comp(u) ≠ comp(v)
            if safe[comp(u)] = Null or w(uv) < w(safe[comp(u)])
                safe[comp(u)] ← uv
            if safe[comp(v)] = Null or w(uv) < w(safe[comp(v)])
                safe[comp(v)] ← uv
    for i ← 1 to count
        add safe[i] to F
```

An edge with $\mathit{comp}(u) = \mathit{comp}(v)$ is useless or already in $F$, and is skipped; every other edge is a candidate for both of its components. When one edge is the safe edge of two components it appears twice in $\mathit{safe}[\,]$ and is added once ($F$ is a set of edges). Borůvka is the generic algorithm: everything it adds is safe.

> [!key] Running time — $O(E\log V)$
> - **CountAndLabel** is a whatever-first search of $F$, which has at most $V - 1$ edges: $O(V)$ time.
> - **AddAllSafeEdges** spends $O(1)$ time per component, per edge and per vertex: $O(V + E)$, which is $O(E)$ because a connected graph has $V\le E + 1$.
> - **Each phase at least halves the number of components.** Every component has a safe edge and merges with at least one other component, so every new component contains at least two old ones. Starting from $V$ components, at most $\lfloor V/2^i\rfloor$ are left after $i$ phases, so there are at most $\lfloor\log_2 V\rfloor$ phases. (The book says $\lceil\log_2 V\rceil$, which is also an upper bound but is never reached unless $V$ is a power of 2.)
>
> In total: $O(E)$ per phase, $O(\log V)$ phases, $O(E\log V)$ time.

On the example the algorithm takes two phases, the most that any seven-vertex graph can need ($\lfloor\log_2 7\rfloor = 2$; at worst $7\to3\to1$): in phase 1 the seven vertices pick $ac$, $bd$, $cd$, $bd$, $eg$, $cf$, $eg$ (for $a, \ldots, g$), five distinct edges that leave the components $\{a, b, c, d, f\}$ and $\{e, g\}$; in phase 2 both pick $de$. The bound is tight: on the path $v_1 v_2\cdots v_8$ with edge weights $1, 5, 2, 7, 3, 6, 4$ in order, the components merge exactly in pairs, $8\to4\to2\to1$, which takes three phases.

> [!trap] Borůvka needs consistent tie-breaking
> Adding many safe edges at once is safe only because they all lie in the one MST. With equal weights and arbitrary tie-breaking it fails: in a triangle $xyz$ whose three edges all weigh 1, if $x$ picks $xy$, $y$ picks $yz$ and $z$ picks $zx$, all three edges are added — a cycle. Comparing keys (§7.1) instead, $x$ and $y$ both pick $xy$ and $z$ picks $xz$: a tree.

**This is the MST algorithm you want.** The book argues that Borůvka is the algorithm to implement, and lists its advantages: it often needs far fewer than $\lfloor\log_2 V\rfloor$ phases; a variant closer to Borůvka's original (contract each phase's components and discard parallel edges) runs in $O(E)$ time on a broad class of graphs, including planar graphs; each component can be handled in parallel; and every MST algorithm that is asymptotically faster than the three in this chapter generalizes Borůvka's. To **prove** things about MSTs, though, you need the other two as well.

## 7.4 Jarník's (Prim's) algorithm

Vojtěch Jarník described it in a 1929 letter to Borůvka and published it in 1930; it was rediscovered by Kruskal (1956), Prim (1957), Loberman and Weinberger (1957) and Dijkstra (1958), and is usually called **Prim's algorithm**. Here $F$ has only one nontrivial component, a tree $T$ that starts as a single arbitrary vertex $s$ and grows until it spans $G$:

> [!recipe] Jarník
> **Repeatedly add $T$'s safe edge to $T$.**

Each added edge is the safe edge of $T$, so this is the generic algorithm. The tree gains one vertex per step and, unlike Kruskal's forest, does **not** collect the edges in order of weight:

### A priority queue of edges: best-first search

Keep every edge with an endpoint in $T$ in a priority queue, keyed by weight. Extract the lightest; if both of its endpoints are already in $T$ it is useless and is discarded; otherwise add it and its new endpoint to $T$, and insert the new vertex's edges to vertices outside $T$. This is **best-first search** ([[2-algorithms/05-basic-graph-algorithms#56-important-variants|§5.6]], [[concepts/whatever-first-search|best-first search]]) with the priority $w(uv)$ — the "Prim" row of Chapter 5's table:

```text
JarníkBestFirst(V, E, s):        ⟨⟨the book's prose, as pseudocode⟩⟩
    T ← ({s}, ∅)
    for each edge sv
        Insert(sv, w(sv))
    while the priority queue is not empty
        uv ← ExtractMin()              ⟨⟨u is in T⟩⟩
        if v ∉ T                       ⟨⟨else uv is useless: discard⟩⟩
            add v and uv to T
            for each edge vx with x ∉ T
                Insert(vx, w(vx))
    return T
```

The queue always holds every edge with exactly one endpoint in $T$, plus some useless edges, so the first non-useless edge extracted is $T$'s safe edge. Every edge is inserted **exactly once**, by whichever endpoint joins $T$ first, and extracted at most once: $E$ Inserts and at most $E$ ExtractMins, each $O(\log E)$ in a binary heap. Total $O(E\log E) = O(E\log V)$, because $E < V^2$ gives $\log E < 2\log V$.

On the example from $s = g$, the edges come out of the queue in the order $eg$, $de$, $bd$, $cd$, $ac$, then $ab$, $bc$, $dg$ (all useless, discarded), $cf$, then $be$, $fg$, $df$ (discarded): 12 Inserts and 12 ExtractMins for 6 tree edges.

### A priority queue of vertices: DecreaseKey

The book's main version (its Figure 7.5) keeps the **vertices** outside $T$ in the queue instead. The priority of a vertex $v$ is the weight of the lightest edge between $v$ and $T$, or $\infty$ if there is none, and $\mathit{edge}(v)$ is that edge. When a vertex joins $T$, the priorities of its neighbors can only go down.

```text
Jarník(V, E, s):
    JarníkInit(V, E, s)
    JarníkLoop(V, E, s)

JarníkInit(V, E, s):
    for each vertex v ∈ V \ {s}
        if vs ∈ E
            edge(v) ← vs
            priority(v) ← w(vs)
        else
            edge(v) ← Null
            priority(v) ← ∞
        Insert(v)

JarníkLoop(V, E, s):
    T ← ({s}, ∅)
    for i ← 1 to |V| − 1
        v ← ExtractMin()
        add v and edge(v) to T
        for each neighbor u of v
            if u ∉ T and priority(u) > w(uv)
                edge(u) ← uv
                DecreaseKey(u, w(uv))
```

(With adjacency lists, JarníkInit is best written as "set every priority to $\infty$, then scan the edges at $s$", $O(V)$ time plus the Inserts.) There are $V - 1$ Inserts and $V - 1$ ExtractMins, and at most one DecreaseKey per edge — when the first endpoint of $uv$ is extracted the other may decrease, and when the second is extracted the first is already in $T$. (The book says "at most twice for each edge", which is also true.)

| priority queue | Insert | ExtractMin | DecreaseKey | Jarník in total |
|---|---|---|---|---|
| binary heap of edges (best-first search) | $O(\log E)$ | $O(\log E)$ | — | $O(E\log E) = O(E\log V)$ |
| binary heap of vertices | $O(\log V)$ | $O(\log V)$ | $O(\log V)$ | $O(E\log V)$ |
| Fibonacci heap of vertices | $O(1)$ amortized | $O(\log V)$ amortized | $O(1)$ amortized | $O(E + V\log V)$ |
| unsorted array of vertex priorities (the book's Exercise 7.7) | $O(1)$ | $O(V)$ | $O(1)$ | $O(V^2)$ |

A **Fibonacci heap** (Fredman and Tarjan, 1984) runs any sequence of $I$ Inserts, $D$ DecreaseKeys and $X$ ExtractMins in $O(I + D + X\log n)$ time in all. Jarník's algorithm with it takes $O(E + V\log V)$ time, which beats $O(E\log V)$ unless $E = O(V)$ — in theory; in practice its large constants rarely pay off except on huge dense graphs. For dense graphs, $E = \Theta(V^2)$, the plain array of the last row reaches the same $O(V^2)$ with no special data structure, and beats a binary heap's $O(V^2\log V)$.

> [!trap] Jarník is not Dijkstra
> Both are best-first search with a heap of vertices, but the priority of $u$ in Jarník is the weight of **one edge** from $u$ to the tree, $\min_{v\in T} w(uv)$, while in Dijkstra's algorithm ([[2-algorithms/08-shortest-paths#86-best-first-dijkstras-algorithm|§8.6]]) it is the length of a whole path from $s$, $\min_{v} \big(\mathit{dist}(v) + w(v\to u)\big)$. Swapping the keys computes the wrong tree.

## 7.5 Kruskal's algorithm

Kruskal described it in 1956, in the paper where he rediscovered Jarník's algorithm; he had been prompted by a translation of Borůvka's paper, whose algorithm he found "unnecessarily elaborate". Loberman and Weinberger found it again in 1957. In one line:

> [!recipe] Kruskal
> **Scan all edges by increasing weight; if an edge is safe, add it to $F$.**

> [!key] Kruskal's test
> When the edges are scanned in increasing order of weight, the edge being scanned is safe if and only if its endpoints lie in different components of $F$.

> [!proof]- Proof (click to expand)
> If both endpoints are in one component, the edge is useless. Otherwise it joins two components $A$ and $B$. Every lighter edge was scanned earlier, and at that time it was either added to $F$ or had both endpoints in one component; components only grow, so now **every** lighter edge has both endpoints in one component of $F$. Hence no lighter edge has exactly one endpoint in $A$, and the scanned edge is the safe edge of $A$ — and of $B$. So Kruskal is the generic algorithm, always adding the lightest safe edge of all.

The test needs to know which component each vertex is in, while components keep merging. Kruskal's algorithm maintains the partition of $V$ into the vertex sets of the components of $F$ with a **disjoint-set** or **union-find** data structure ([[concepts/union-find]]):

> [!definition] Definition — union-find
> - MakeSet$(v)$: create the set $\{v\}$.
> - Find$(v)$: return an identifier of the set containing $v$ — the same for all members, different for different sets.
> - Union$(u, v)$: replace the sets containing $u$ and $v$ by their union.

```text
Kruskal(V, E):
    sort E by increasing weight
    F ← (V, ∅)
    for each vertex v ∈ V
        MakeSet(v)
    for i ← 1 to |E|
        uv ← ith lightest edge in E
        if Find(u) ≠ Find(v)
            Union(u, v)
            add uv to F
    return F
```

After the sort, Kruskal performs exactly $V$ MakeSets, $2E$ Finds (two per edge) and $V - 1$ Unions (one per MST edge).

**The book's union-find.** Store a **label** at every vertex: Find returns it in $O(1)$ time. Union relabels the **smaller** of the two sets with the label of the larger one, by a whatever-first search of its tree in $F$ (or a list of its members), in time proportional to its size. A vertex is relabeled only when its set at least doubles, so at most $\log_2 V$ times; the $V - 1$ Unions therefore take $O(V\log V)$ time in all, "$O(\log V)$ amortized" each, and the whole union-find work is $O(E + V\log V)$.

> [!key] Running time — $O(E\log V)$
> Sorting the edges takes $O(E\log E) = O(E\log V)$ time and dominates the union-find work, $O(E + V\log V)$; so Kruskal runs in $O(E\log V)$ time — the same bound as Borůvka, and as Jarník with a binary heap. With **union by rank and path compression** every operation takes $O(\alpha(V))$ amortized time, where $\alpha$ is the inverse Ackermann function (at most 4 for any conceivable input); the union-find work drops to $O(E\,\alpha(V))$, but the sort still dominates unless the edges come presorted.

> [!trap] Kruskal and union-find traps
> - **Compare Find$(u)$ with Find$(v)$ at the moment the edge is scanned.** Labels change with every Union, so a label read earlier may be stale.
> - **Union merges the two whole sets**, not just $u$ and $v$: every member of the smaller set must get the new label (in the forest version, the two **roots** are linked).
> - **Relabel the smaller set.** Relabeling an arbitrary side can cost $\Theta(V)$ per Union and $\Theta(V^2)$ in all — for instance when a growing set is always the one relabeled.
> - **The sort is the bottleneck**, not union-find: $O(E\log V)$ either way, unless the weights can be sorted faster.

| Jarník ("Prim") | grow one tree from $s$ | $T$'s safe edge | Fibonacci heap of vertices | $O(E + V\log V)$ |
| Kruskal | scan the edges by increasing weight | the lightest safe edge of all | sort, then union-find | $O(E\log E) = O(E\log V)$ |

On the example all three return the same tree, of weight 42, in different orders: Borůvka adds $\{ac, bd, cd, cf, eg\}$ and then $de$; Jarník from $g$ adds $eg, de, bd, cd, ac, cf$; Kruskal adds $bd, cd, eg, ac, de, cf$.

## Summary

- A minimum spanning tree of a connected, undirected, weighted graph minimizes $w(T) = \sum_{e\in T} w(e)$ over all spanning trees; weights may be negative. With distinct weights it is unique (Lemma 7.1, an exchange argument); with ties, compare $\big(w(ij), \min\{i,j\}, \max\{i,j\}\big)$ lexicographically, consistently, and every algorithm returns one particular MST.
- Generic algorithm: keep a forest $F$ inside the MST and add **safe** edges — the lightest edge leaving a component of $F$. Every safe edge is in the MST (Lemma 7.2, the cut property: swap it for the tree's crossing edge); no **useless** edge is (Lemma 7.3).
- Borůvka: add every component's safe edge, relabel with CountAndLabel, repeat; each phase at least halves the components: $O(E)$ per phase, $O(E\log V)$ in all.
- Jarník (Prim): grow one tree by its safe edge. With a heap of edges it is best-first search with priority $w(uv)$, $O(E\log V)$; with a heap of vertices and DecreaseKey, $O(E\log V)$, or $O(E + V\log V)$ with a Fibonacci heap.
- Kruskal: sort the edges and keep each one whose endpoints have different Find values; $V$ MakeSets, $2E$ Finds, $V-1$ Unions; relabeling the smaller set gives $O(V\log V)$ for the Unions, and the $O(E\log V)$ sort dominates.
- The example graph: MST $\{bd, cd, eg, ac, de, cf\}$ of weight 42; two Borůvka phases; Jarník from $g$ in the order $eg, de, bd, cd, ac, cf$.
- An MST is not a shortest-path tree, and Jarník's priority (one edge) is not Dijkstra's (a whole path).

> [!exam] On the exams
> According to the lecturer (October 22), minimum spanning trees are **not covered in lecture this semester**, and the official Midterm 2 announcement (October 30) does not list them, so this chapter is not on Midterm 2; the course calendar has no MST lecture before the final either. Two ideas from it are still worth carrying into the exams. The **cut property** (Lemma 7.2) is the cleanest instance of the exchange argument that every greedy proof needs — take any optimal solution without the greedy choice, find the element it uses in its place, swap, and show the result is still feasible and no worse — exactly the template of [[2-algorithms/04-greedy-algorithms#43-the-general-pattern|§4.3]] (and a greedy algorithm without such a proof earns no credit). And Jarník's algorithm is **best-first search**, the same priority-queue skeleton as Dijkstra's algorithm ([[2-algorithms/08-shortest-paths#86-best-first-dijkstras-algorithm|§8.6]]), which is lectured: knowing which key each one uses keeps them apart. If a minimum spanning tree is ever needed inside a graph problem, cite any of the three algorithms as a black box, $O(E\log V)$ time, and write the rest as the [[0-toolkit/06-how-exams-are-graded#13-graph-reductions|graph-reduction rubric]] asks.
