> [!abstract] In one breath
> The **all-pairs shortest path** problem asks for $\textsf{dist}(u, v)$ and $\textsf{pred}(u, v)$ for every pair of vertices: two $V\times V$ arrays, whose rows are the $V$ shortest-path trees. The obvious solution runs a single-source algorithm from every vertex: $O(VE)$ with breadth-first search or in a dag, $O(VE\log V)$ with Dijkstra for nonnegative weights, $O(V^2E)$ with Bellman–Ford in general. **Reweighting** removes the penalty for negative edges: with any vertex prices $\pi$, the weights $w'(u\to v) = \pi(u) + w(u\to v) - \pi(v)$ change every path from $u$ to $v$ by the same amount $\pi(u) - \pi(v)$, and if $\pi$ is the distance from a new vertex $s$ with edges of weight 0 to all vertices, every $w'$ is nonnegative. **Johnson's algorithm** — one Bellman–Ford, then $V$ Dijkstras — runs in $O(VE\log V)$ time with any weights. Dynamic programming gives a second family: by the number of edges ($O(V^4)$, Shimbel), by halving the number of edges (repeated **min-plus squaring** of the weight matrix, $O(V^3\log V)$, Fischer–Meyer and Leyzorek), and by the largest intermediate vertex allowed — **Floyd–Warshall**, three nested loops, $O(V^3)$ time, $O(V^2)$ space, and a negative diagonal entry exactly when there is a negative cycle.

## 9.1 Introduction

Chapter 8 computes the shortest paths from **one** source $s$: a shortest-path tree, stored as $\textsf{dist}(v)$ and $\textsf{pred}(v)$ for every vertex $v$ ([[2-algorithms/08-shortest-paths#81-shortest-path-trees|§8.1]]). Here we want them from **every** source.

> [!definition] Definition — the all-pairs shortest path problem
> Given a directed graph $G = (V, E)$ with edge weights $w(u\to v)$ of any sign, compute for every pair of vertices $u, v$
> - $\textsf{dist}(u, v)$, the length of the shortest path from $u$ to $v$, and
> - $\textsf{pred}(u, v)$, the second-to-last vertex of that path.
>
> The boundary cases are those of Chapter 8:
> - no path from $u$ to $v$: $\textsf{dist}(u, v) = \infty$ and $\textsf{pred}(u, v) = \textsf{Null}$;
> - some walk from $u$ to $v$ runs through a negative cycle ($u$ reaches the cycle and the cycle reaches $v$): there are walks of arbitrarily negative length, so $\textsf{dist}(u, v) = -\infty$ and $\textsf{pred}(u, v) = \textsf{Null}$;
> - otherwise the shortest path from $u$ to itself is the empty path: $\textsf{dist}(u, u) = 0$ and $\textsf{pred}(u, u) = \textsf{Null}$.
>
> The output is two $V\times V$ arrays, $\mathit{dist}[\cdot,\cdot]$ and $\mathit{pred}[\cdot,\cdot]$.

Row $u$ of the predecessor array is exactly the shortest-path tree rooted at $u$, so a shortest path from $u$ to $v$ is read backward: $v$, $\textsf{pred}(u, v)$, $\textsf{pred}(u, \textsf{pred}(u, v))$, …, $u$. The two arrays take $O(V^2)$ space although writing out all $V^2$ paths could take $\Theta(V^3)$. Like the book, this page computes mainly the distance array; every algorithm can maintain the predecessors with minor changes (the book's Exercise 1; see §9.8 for Floyd–Warshall). Every algorithm needs $\Omega(V^2)$ time just to write its output.

## 9.2 Lots of single sources

The obvious algorithm fills row $s$ of the distance array with any single-source algorithm, once for every source $s$:

```text
ObviousAPSP(V, E, w):
    for every vertex s
        dist[s, ·] ← SSSP(V, E, w, s)
```

Its running time is $V$ times that of the single-source algorithm, so it depends on the graph, exactly as in Chapter 8:

| graph | single-source algorithm | one source | all pairs | $E = \Theta(V^2)$ |
|---|---|---|---|---|
| unweighted | breadth-first search ([[2-algorithms/08-shortest-paths#84-unweighted-graphs-breadth-first-search\|§8.4]]) | $O(V+E)$ | $O(VE)$ | $O(V^3)$ |
| dag, any weights | relax in topological order ([[2-algorithms/08-shortest-paths#85-directed-acyclic-graphs-depth-first-search\|§8.5]]) | $O(V+E)$ | $O(VE)$ | $O(V^3)$ |
| nonnegative weights | Dijkstra, binary heap ([[2-algorithms/08-shortest-paths#86-best-first-dijkstras-algorithm\|§8.6]]) | $O(E\log V)$ | $O(VE\log V)$ | $O(V^3\log V)$ |
| any weights | Bellman–Ford ([[2-algorithms/08-shortest-paths#87-relax-all-the-edges-bellmanford\|§8.7]]) | $O(VE)$ | $O(V^2E)$ | $O(V^4)$ |

(As in the book, $O(VE)$ stands for $V$ runs of an $O(V+E)$ algorithm, $O(V^2 + VE)$; the extra $V^2$ only matters when $E < V$, and the output needs it anyway.) Dijkstra's algorithm has two other implementations worth knowing for the dense case: with an **unsorted array** instead of a heap it takes $O(V^2)$ time per source, so $O(V^3)$ for all pairs no matter how many edges; with a **Fibonacci heap**, $O(E + V\log V)$ per source, so $O(VE + V^2\log V)$ for all pairs, which is $O(V^3)$ for dense graphs.

The last line is the problem: negative edges cost a factor of $V/\log V$ over Dijkstra. Bellman–Ford from every vertex also detects every negative cycle — but it is slow.

## 9.3 Reweighting

Can we make the weights nonnegative and use Dijkstra? The idea that comes first — **add the same constant to every edge** — does not work. Paths with more edges grow faster than paths with fewer edges, so the shortest path can change.

> [!trap] Adding a constant changes shortest paths
> - The book's Figure 9.1: from $s$ to $t$, one path has two edges of weight 4 (total 8), another three edges of weights 2, 3, 2 (total 7). Adding 2 to every edge makes them 12 and 13: the other path wins.
> - In the running example the most negative weight is $-3$. Adding 3 to every edge turns the shortest path $3\to4\to1\to2$ (length $-2$) into a path of length $6 + 0 + 1 = 7$, while the edge $3\to2$ becomes $1 + 3 = 4$: the answer changes.

What does work is to charge every vertex a **price** instead (the reweighting is usually credited to Johnson, 1973, who credited Edmonds and Karp, 1972; Tomizawa had it in 1971, and Fulkerson in a different form in 1961).

> [!definition] Definition — prices and reduced weights
> Give every vertex $v$ a **price** (or potential) $\pi(v)$, a real number of any sign, and define new weights
> $$
> w'(u\to v) = \pi(u) + w(u\to v) - \pi(v).
> $$
> Think of $\pi(u)$ as an exit tax paid when leaving $u$ and $\pi(v)$ as a gift received when entering $v$.

> [!key] Reweighting preserves shortest paths
> For any prices $\pi$ and any path (or walk) $P$ from $u$ to $v$,
> $$
> w'(P) = \pi(u) + w(P) - \pi(v).
> $$
> So every path from $u$ to $v$ changes by the **same** amount $\pi(u) - \pi(v)$: the shortest paths from $u$ to $v$ are the same for $w$ and $w'$, and $\textsf{dist}'(u, v) = \textsf{dist}(u, v) + \pi(u) - \pi(v)$. Every cycle keeps its length (take $u = v$), so negative cycles stay negative.

> [!proof]- Proof (click to expand)
> For $P = v_0\to v_1\to\cdots\to v_k$ the sum telescopes:
> $$
> w'(P) = \sum_{i=1}^{k} \big(\pi(v_{i-1}) + w(v_{i-1}\to v_i) - \pi(v_i)\big) = \pi(v_0) + w(P) - \pi(v_k).
> $$
> Every intermediate vertex's gift on arrival is paid back as tax on departure. Since all paths from $u$ to $v$ shift by the same constant, their order does not change.

Paths between **different** pairs shift by different amounts, so comparing their reduced lengths means nothing; only paths with the same endpoints are compared. And no choice of prices can remove a negative cycle — which is fine, because then shortest paths are not defined anyway.

Concept page: [[concepts/johnsons-algorithm]].

## 9.4 Johnson's algorithm

The question is how to choose prices that make **every** reduced weight nonnegative. Shortest-path distances do it.

> [!key] Distances are good prices
> Suppose a vertex $s$ reaches every vertex and $G$ has no negative cycle, and set $\pi(v) = \textsf{dist}(s, v)$. Then for every edge
> $$
> w'(u\to v) = \textsf{dist}(s, u) + w(u\to v) - \textsf{dist}(s, v) \;\ge\; 0,
> $$
> because no edge is **tense** once a single-source algorithm has finished ([[2-algorithms/08-shortest-paths#83-the-only-sssp-algorithm|§8.3]]): $\textsf{dist}(s, v) \le \textsf{dist}(s, u) + w(u\to v)$. The edges with $w'(u\to v) = 0$ are exactly the edges on shortest paths from $s$.

If no vertex reaches everything, some prices would be infinite. So Johnson's algorithm always **adds a new vertex** $s$ with an edge $s\to v$ of weight 0 to every vertex and no edge into $s$. No path between two old vertices can use $s$, so their distances do not change, and $s$ is on no cycle, so negative cycles neither appear nor disappear. Every price is at most 0 (the edge $s\to v$ itself): $\pi(v) = \min\{0,\ \min_u \textsf{dist}(u, v)\}$.

```text
JohnsonAPSP(V, E, w):
    ⟨⟨Add an artificial source⟩⟩
    add a new vertex s
    for every vertex v
        add a new edge s→v
        w(s→v) ← 0
    ⟨⟨Compute vertex prices⟩⟩
    dist[s, ·] ← BellmanFord(V, E, w, s)
    if BellmanFord found a negative cycle
        fail gracefully
    ⟨⟨Reweight the edges⟩⟩
    for every edge u→v ∈ E
        w′(u→v) ← dist[s, u] + w(u→v) − dist[s, v]
    ⟨⟨Compute reweighted shortest-path distances⟩⟩
    for every vertex u
        dist′[u, ·] ← Dijkstra(V, E, w′, u)
    ⟨⟨Compute original shortest-path distances⟩⟩
    for every vertex u
        for every vertex v
            dist[u, v] ← dist′[u, v] − dist[s, u] + dist[s, v]
```

- **What it computes:** all distances, or a report that $G$ has a negative cycle.
- **Time:** Bellman–Ford on $V+1$ vertices and $E+V$ edges, $O(VE)$; reweighting $O(E)$; $V$ runs of Dijkstra with a binary heap, $O(VE\log V)$; the conversion loop $O(V^2)$. In all **$O(VE\log V)$** — the same as $V$ Dijkstras: negative edges cost nothing after all. With a Fibonacci heap, $O(VE + V^2\log V)$.
- **Why it is correct:** the reduced weights are nonnegative (the lemma above), so Dijkstra is correct and fast on $w'$; reweighting preserves shortest paths, and the last loop undoes the shift $\pi(u) - \pi(v)$. An unreachable pair keeps $\infty$.

> - **Prices must be distances from one vertex that reaches everything** — hence the new vertex $s$. Distances from an old vertex can be $\infty$, and $\infty - \infty$ is meaningless.
> - Don't forget the **conversion back**: $\textsf{dist}(u, v) = \textsf{dist}'(u, v) - \pi(u) + \pi(v)$, not $\textsf{dist}'(u, v)$.
> - Dijkstra's $O(E\log V)$ bound needs nonnegative weights: on negative edges the usual textbook version (the book's NonnegativeDijkstra) can return wrong distances and the book's Dijkstra can take exponential time ([[2-algorithms/08-shortest-paths#86-best-first-dijkstras-algorithm|§8.6]]). That is the whole reason to reweight.
> - If the weights are already nonnegative, skip Bellman–Ford (all prices 0): it is just $V$ Dijkstras.

## 9.5 Dynamic programming

All-pairs shortest paths can also be computed directly by dynamic programming. **From here on, assume that $G$ has no negative cycle**, and use the conventions $w(u\to v) = \infty$ if there is no edge $u\to v$ and, from §9.6 on, $w(v\to v) = 0$.

The "obvious" recurrence, $\textsf{dist}(u, u) = 0$ and $\textsf{dist}(u, v) = \min_{x\to v}\big(\textsf{dist}(u, x) + w(x\to v)\big)$, works only in a dag; a directed cycle makes the recursion loop forever. As for Bellman–Ford, the fix is an extra parameter that decreases: the number of edges. A shortest path has at most $V - 1$ edges (with no negative cycle, a shortest walk can be taken simple).

> [!definition] Function — $\textsf{dist}(u, v, \ell)$
> For all vertices $u, v$ and $0\le\ell\le V-1$, $\textsf{dist}(u, v, \ell)$ is the length of the shortest walk from $u$ to $v$ with **at most $\ell$ edges** ($\infty$ if there is none). We need $\textsf{dist}(u, v, V - 1)$ for all $u, v$.

$$
\textsf{dist}(u, v, \ell) = \begin{cases} 0 & \text{if } \ell = 0 \text{ and } u = v\\ \infty & \text{if } \ell = 0 \text{ and } u \ne v\\ \min\left\{\begin{array}{l} \textsf{dist}(u, v, \ell - 1)\\ \min_{x\to v}\big(\textsf{dist}(u, x, \ell - 1) + w(x\to v)\big)\end{array}\right\} & \text{otherwise}\end{cases}
$$

The last edge of the walk is some $x\to v$, or the walk has fewer than $\ell$ edges.

- **Memoization:** a three-dimensional array $\mathit{dist}[1\,..\,V,\ 1\,..\,V,\ 0\,..\,V-1]$.
- **Evaluation order:** $\ell$ from $0$ up to $V - 1$ in the outer loop; $u$ and $v$ in any order inside.
- **Time:** for each of the $V$ values of $\ell$ and each $u$, the vertices $v$ together read every edge once, $O(V + E)$: in all $O(V^2(V+E)) = O(V^2E)$, which is $O(V^4)$ for dense graphs.

```text
ShimbelAPSP(V, E, w):
    for all vertices u
        for all vertices v
            if u = v
                dist[u, v, 0] ← 0
            else
                dist[u, v, 0] ← ∞
    for ℓ ← 1 to V − 1
        for all vertices u
            for all vertices v                  ⟨⟨the book prints v ≠ u⟩⟩
                dist[u, v, ℓ] ← dist[u, v, ℓ − 1]
                for all edges x→v
                    if dist[u, v, ℓ] > dist[u, x, ℓ − 1] + w(x→v)
                        dist[u, v, ℓ] ← dist[u, x, ℓ − 1] + w(x→v)
```

Alfonso Shimbel sketched this in 1954 (for a complete matrix of distances, hence $O(V^4)$ regardless of $E$). As printed in the book, the loop over $v$ skips $v = u$, so $\mathit{dist}[u, u, \ell]$ is never assigned for $\ell \ge 1$ — but the entry is read at the next level whenever an edge leaves $u$. Looping over all $v$, as above, fixes it (or set $\mathit{dist}[u, u, \ell] \leftarrow 0$, its value without negative cycles).

As with Bellman–Ford, the index $\ell$ can be dropped and the table overwritten in place:

```text
AllPairsBellmanFord(V, E, w):
    for all vertices u
        for all vertices v
            if u = v
                dist[u, v] ← 0
            else
                dist[u, v] ← ∞
    for ℓ ← 1 to V − 1
        for all vertices u
            for all edges x→v
                if dist[u, v] > dist[u, x] + w(x→v)
                    dist[u, v] ← dist[u, x] + w(x→v)
```

This is exactly $V$ runs of Bellman–Ford, one per source $u$, interleaved: still $O(V^2E)$ time, now $O(V^2)$ space. After iteration $\ell$, every $\mathit{dist}[u, v]$ is at most $\textsf{dist}(u, v, \ell)$ (and never below the true distance), so after $V - 1$ iterations it is correct.

Concept pages: [[concepts/all-pairs-shortest-paths]], [[concepts/dynamic-programming]].

## 9.6 Divide and conquer

Fischer and Meyer (1971) split a path in the **middle** rather than before its last edge. A walk with at most $2\ell$ edges is a walk with at most $\ell$ edges to some middle vertex $x$, followed by a walk with at most $\ell$ edges from $x$. For "at most" to work, a walk may stand still: that is the convention $w(v\to v) = 0$. The base case is now $\ell = 1$, a single edge or nothing.

> [!definition] Function — $\textsf{dist}(u, v, \ell)$ again
> The same function as in §9.5 — the shortest walk from $u$ to $v$ with at most $\ell$ edges — but only for $\ell$ a power of 2, $\ell = 2^i$ with $0\le i\le\lceil\lg V\rceil$. We need $\textsf{dist}(u, v, 2^{\lceil\lg V\rceil})$, the true distance, because $2^{\lceil\lg V\rceil} \ge V - 1$ (and $< 2V$).

$$
\textsf{dist}(u, v, \ell) = \begin{cases} w(u\to v) & \text{if } \ell = 1\\ \min_{x}\big(\textsf{dist}(u, x, \ell/2) + \textsf{dist}(x, v, \ell/2)\big) & \text{otherwise}\end{cases}
$$

The minimum is over **all** vertices $x$, including $u$ and $v$ (with $w(u\to u) = 0$, this keeps walks with fewer edges). The book's display labels the base case "$i = 1$"; it means $\ell = 1$.

- **Memoization:** $\mathit{dist}[u, v, i]$ stores $\textsf{dist}(u, v, 2^i)$: an array $\mathit{dist}[1\,..\,V,\ 1\,..\,V,\ 0\,..\,\lceil\lg V\rceil]$, $O(V^2\log V)$ space.
- **Evaluation order:** $i$ from $0$ up to $\lceil\lg V\rceil$ in the outer loop; $u$, $v$ in any order inside.
- **Time:** $V^2\lceil\lg V\rceil$ entries above the base case, each a minimum over $V$ vertices: $O(V^3\log V)$.

```text
FischerMeyerAPSP(V, E, w):
    for all vertices u
        for all vertices v
            dist[u, v, 0] ← w(u→v)
    for i ← 1 to ⌈lg V⌉                         ⟨⟨ℓ = 2^i⟩⟩
        for all vertices u
            for all vertices v
                dist[u, v, i] ← ∞
                for all vertices x
                    if dist[u, v, i] > dist[u, x, i − 1] + dist[x, v, i − 1]
                        dist[u, v, i] ← dist[u, x, i − 1] + dist[x, v, i − 1]
```

Unlike the earlier algorithms, this is not $V$ runs of any single-source algorithm: the inner loop combines two **paths**, not a path and an edge. The third index can still be dropped. The resulting algorithm, described by Leyzorek et al. in 1957 in the same report that describes Dijkstra's algorithm, uses $O(V^2)$ space:

```text
LeyzorekAPSP(V, E, w):
    for all vertices u
        for all vertices v
            dist[u, v] ← w(u→v)
    for i ← 1 to ⌈lg V⌉                         ⟨⟨ℓ = 2^i⟩⟩
        for all vertices u
            for all vertices v
                for all vertices x
                    if dist[u, v] > dist[u, x] + dist[x, v]
                        dist[u, v] ← dist[u, x] + dist[x, v]
```

Overwriting is safe for the same reason as in AllPairsBellmanFord: every value stored is the length of some walk, so it never drops below the true distance, and reading entries that were already improved in this round can only make it smaller, so after round $i$ it is at most $\textsf{dist}(u, v, 2^i)$.

## 9.7 Funny matrix multiplication

Compare squaring an $n\times n$ matrix, $A'[i, j] = \sum_k A[i, k]\cdot A[k, j]$, with one round of Fischer–Meyer, $D'[u, v] = \min_x\big(D[u, x] + D[x, v]\big)$: the same three loops, with **addition in place of multiplication and minimum in place of addition**. The connection was first noticed by Shimbel and independently by Bellman.

> [!definition] Definition — the min-plus product
> For $n\times n$ matrices with entries in $\mathbb{R}\cup\{\infty\}$, the **min-plus** ("distance", "funny") product is
> $$
> (A\otimes B)[i, j] = \min_{k}\big(A[i, k] + B[k, j]\big).
> $$
> It is associative, so powers $A^{\otimes\ell}$ are well defined, and its identity matrix has $0$ on the diagonal and $\infty$ everywhere else.

| ordinary product | min-plus product |
|---|---|
| $+$ | $\min$ |
| $\times$ | $+$ |
| $0$ (neutral for $+$) | $\infty$ (neutral for $\min$) |
| $1$ (neutral for $\times$) | $0$ (neutral for $+$) |

Let $W$ be the **weight matrix**: $W[u, v] = w(u\to v)$, $0$ on the diagonal, $\infty$ for missing edges. Then by induction on $\ell$:

> [!key] Shortest paths are min-plus powers
> $W^{\otimes\ell}[u, v] = \textsf{dist}(u, v, \ell)$, the shortest walk from $u$ to $v$ with at most $\ell$ edges. Without negative cycles $W^{\otimes\ell} = W^{\otimes(V-1)}$ is the distance matrix for every $\ell\ge V-1$. (With $\infty$ instead of $0$ on the diagonal, the power counts walks with **exactly** $\ell$ edges.)

- **ShimbelAPSP** computes the powers one at a time, $\mathit{dist}[\cdot, \cdot, \ell] = \mathit{dist}[\cdot, \cdot, \ell-1]\otimes W$, starting from the identity: $V-1$ products. (Its inner loop only visits the edges into $v$, the finite entries of column $v$ of $W$.)
- **FischerMeyerAPSP** computes $W, W^{\otimes2}, W^{\otimes4}, \ldots$ by **repeated squaring**, $\lceil\lg V\rceil$ products of $O(V^3)$ each — exactly the fast exponentiation of [[2-algorithms/01-recursion#110-exponentiation|§1.10]].

Can fast matrix multiplication help? Strassen's algorithm multiplies two $n\times n$ matrices with seven half-size products in $O(n^{\lg 7}) = O(n^{2.807355})$ time, and later algorithms are faster still ($O(n^{2.372864})$ as of the book). But all of them **subtract**, and $\min$ has no inverse, so none of them applies to the min-plus product. Special cases are faster: a simple randomized algorithm of Galil and Margalit (1991), simplified by Seidel (1992), computes all distances in an unweighted **undirected** graph in $O(M(V)\log V)$ expected time, where $M(n)$ is the time to multiply two $n\times n$ integer matrices, and its descendants handle directed graphs with small integer weights in truly subcubic time. For general weights, no algorithm running in $O(V^{3-\varepsilon})$ time for a constant $\varepsilon > 0$ is known, and there is some evidence that none exists.

## 9.8 Floyd–Warshall

The $\log V$ factor goes away with a different third parameter. Instead of limiting the **number of edges**, limit **which vertices** a path may pass through. A path **passes through** a vertex if it enters and leaves it: $w\to x\to y\to z$ passes through $x$ and $y$, its **intermediate** vertices. Number the vertices $1, \ldots, V$ arbitrarily.

> [!definition] Function — $\textsf{dist}(u, v, r)$
> For all vertices $u, v$ and $0\le r\le V$, $\textsf{dist}(u, v, r)$ is the length of the shortest path from $u$ to $v$ whose intermediate vertices are all numbered **at most $r$** ($\infty$ if there is none). We need $\textsf{dist}(u, v, V)$, the true distance, for all $u, v$.

$$
\textsf{dist}(u, v, r) = \begin{cases} w(u\to v) & \text{if } r = 0\\ \min\left\{\begin{array}{l} \textsf{dist}(u, v, r - 1)\\ \textsf{dist}(u, r, r - 1) + \textsf{dist}(r, v, r - 1)\end{array}\right\} & \text{otherwise}\end{cases}
$$

with $w(v\to v) = 0$ and $w(u\to v) = \infty$ for non-edges, as before.

> [!proof]- Why the recurrence holds (click to expand)
> For $r = 0$ the path has no intermediate vertex: it is the edge $u\to v$, or the empty path when $u = v$. For $r > 0$, let $P$ be a shortest path from $u$ to $v$ with intermediate vertices at most $r$; with no negative cycle it can be taken simple.
> - If $P$ does not pass through $r$, its intermediate vertices are at most $r - 1$, and it is the shortest such path: length $\textsf{dist}(u, v, r-1)$.
> - If it does, it passes through $r$ exactly once and splits there into a path from $u$ to $r$ and a path from $r$ to $v$, each with intermediate vertices at most $r - 1$, and each as short as possible with that restriction (otherwise replace it by a shorter one): length $\textsf{dist}(u, r, r-1) + \textsf{dist}(r, v, r-1)$.
>
> Conversely, both candidates are lengths of walks from $u$ to $v$ through vertices at most $r$, which are never shorter than the best path. So $\textsf{dist}(u, v, r)$ is the smaller of the two.

- **Memoization:** a three-dimensional array $\mathit{dist}[1\,..\,V,\ 1\,..\,V,\ 0\,..\,V]$ — or one $V\times V$ array updated in place (below).
- **Evaluation order:** $r$ from $0$ up to $V$ in the **outer** loop; $u$ and $v$ in any order inside.
- **Time:** $V^2(V+1)$ entries, $O(1)$ each: $O(V^3)$ time; $O(V^3)$ space, or $O(V^2)$ in place.

```text
KleeneAPSP(V, E, w):
    for all vertices u
        for all vertices v
            dist[u, v, 0] ← w(u→v)
    for r ← 1 to V
        for all vertices u
            for all vertices v
                if dist[u, v, r − 1] < dist[u, r, r − 1] + dist[r, v, r − 1]
                    dist[u, v, r] ← dist[u, v, r − 1]
                else
                    dist[u, v, r] ← dist[u, r, r − 1] + dist[r, v, r − 1]
```

Dropping the third index, and with it the numbering — the order of the vertices was arbitrary — gives Floyd's version:

```text
FloydWarshall(V, E, w):
    for all vertices u
        for all vertices v
            dist[u, v] ← w(u→v)
    for all vertices r
        for all vertices u
            for all vertices v
                if dist[u, v] > dist[u, r] + dist[r, v]
                    dist[u, v] ← dist[u, r] + dist[r, v]
```

> [!key] FloydWarshall
> With no negative cycle, FloydWarshall computes all shortest-path distances in $O(V^3)$ time and $O(V^2)$ space; after the iteration for the $r$-th vertex, the array holds exactly $\textsf{dist}(\cdot, \cdot, r)$. Updating in place is safe because phase $r$ never changes row $r$ or column $r$: $\mathit{dist}[u, r]$ is compared with $\mathit{dist}[u, r] + \mathit{dist}[r, r] = \mathit{dist}[u, r] + 0$, and likewise $\mathit{dist}[r, v]$. So the entries a phase reads are the same whether or not it has already overwritten them.

**History.** Floyd (1962) and, independently, Ingerman (1962) generalized an algorithm Warshall had published earlier that year for the transitive closure; Roy had found Warshall's algorithm in 1959, and Kleene used the same recursion in 1951 to turn finite automata into regular expressions ([[1-models-of-computation/04-nondeterministic-automata#44-kleenes-theorem|§4.4]]; the state elimination of [[1-models-of-computation/04-nondeterministic-automata#48-nfa-to-regular-expression-state-elimination|§4.8]] removes one vertex at a time in the same way). Hence the book's section title, (Kleene–Roy–)Floyd–Warshall(–Ingerman).

LeyzorekAPSP and FloydWarshall have the same loop body over all triples. Leyzorek needs $\lceil\lg V\rceil$ passes with the middle vertex $x$ innermost; Floyd–Warshall needs **one** pass, only because the middle vertex $r$ is the **outermost** loop.

> [!trap] Floyd–Warshall traps
> - **The loop over $r$ must be the outer loop.** With $r$ innermost, one pass is not enough: on the running example, the order $u$, $v$, $r$ leaves $\mathit{dist}[2, 1] = \infty$, although $2\to3\to4\to1$ has length 4 — when entry $(2, 1)$ is computed, neither $\mathit{dist}[2, 4]$ nor $\mathit{dist}[3, 1]$ is known yet.
> - **Initialize the diagonal to 0** and non-edges to $\infty$. (Initializing the diagonal to $\infty$ computes something else — see the tip below.)
> - The recurrence is over **intermediate** vertices: $\textsf{dist}(u, v, 0)$ allows the edge $u\to v$ even if $u$ or $v$ is larger than 0.
> - "Vertex $r$" in the in-place version is just "the $r$-th vertex of the outer loop", in any fixed order.

**Negative cycles.** The book assumes there are none, but FloydWarshall detects them for free.

> [!key] Negative-cycle detection
> Run FloydWarshall, diagonal initialized to 0, on any weighted directed graph (a loop of negative weight is itself a negative cycle; initialize $\mathit{dist}[v, v]$ to $\min\{0, w(v\to v)\}$). Then $G$ has a negative cycle if and only if $\mathit{dist}[v, v] < 0$ for some vertex $v$ at the end, and every vertex of a negative cycle ends with a negative diagonal entry.

> [!proof]- Proof (click to expand)
> Every value stored is the length of a walk between its endpoints, so a negative diagonal entry is a closed walk of negative length, which contains a negative cycle. Conversely, the induction above shows that after phase $r$, $\mathit{dist}[u, v]$ is at most the length of every **simple** path from $u$ to $v$ with intermediate vertices at most $r$ — with $u = v$ allowed, where the "path" is a simple cycle through $u$ (overwriting in place only lowers values). A negative cycle through $v$ is such a closed path once $r$ reaches the last of its vertices, so $\mathit{dist}[v, v] < 0$ at the end.

Off the diagonal, the values are then **not** the $-\infty$ the definition asks for; correcting them is the book's Exercise 2(c).

**Predecessors.** Initialize $\mathit{pred}[u, v] \leftarrow u$ for every edge $u\to v$ and $\textsf{Null}$ otherwise, and whenever the test succeeds set $\mathit{pred}[u, v] \leftarrow \mathit{pred}[r, v]$: the new path ends with the old path from $r$ to $v$. This computes the predecessor array of the first figure in the same $O(V^3)$ time (the book's Exercise 1(b)).

**Transitive closure.** With booleans — $\textsf{True}$ for an edge or $u = v$, "or" in place of $\min$, "and" in place of $+$ — the same loops compute reachability: $\mathit{reach}[u, v] \leftarrow \mathit{reach}[u, v] \lor (\mathit{reach}[u, r] \land \mathit{reach}[r, v])$. This is **Warshall's algorithm**, $O(V^3)$ time; for sparse graphs, one whatever-first search per vertex, $O(V(V+E))$, is faster ([[2-algorithms/06-depth-first-search-exercises#exercise-66--transitive-closure-and-reduction|Exercise 6.6]]).

> [!tip] Shortest cycles
> Initialize the diagonal to $\infty$ instead of 0 (no negative cycles). Then the paths from $v$ to $v$ that the recurrence considers have at least one edge, and FloydWarshall ends with $\mathit{dist}[v, v]$ equal to the length of the **shortest cycle through $v$**. In the running example all four diagonal entries become 2, the cycle $1\to2\to3\to4\to1$.

Concept page: [[concepts/floyd-warshall]].

## The chapter's algorithms at a glance

| algorithm | weights | negative cycles | time | space |
|---|---|---|---|---|
| $V\times$ breadth-first search | unweighted | — | $O(VE)$ | $O(V^2)$ |
| $V\times$ dag dynamic program | dag, any | none possible | $O(VE)$ | $O(V^2)$ |
| $V\times$ Dijkstra (binary heap) | nonnegative | — | $O(VE\log V)$ | $O(V^2)$ |
| $V\times$ Bellman–Ford | any | detects | $O(V^2E)$ | $O(V^2)$ |
| Johnson | any | detects (Bellman–Ford) | $O(VE\log V)$ | $O(V^2)$ |
| Shimbel; AllPairsBellmanFord | no negative cycle | assumed absent | $O(V^2E)$, i.e. $O(V^4)$ | $O(V^3)$; $O(V^2)$ |
| Fischer–Meyer; Leyzorek | no negative cycle | assumed absent | $O(V^3\log V)$ | $O(V^2\log V)$; $O(V^2)$ |
| Kleene; Floyd–Warshall | no negative cycle | Floyd–Warshall detects (diagonal) | $O(V^3)$ | $O(V^3)$; $O(V^2)$ |

For **sparse** graphs ($E = O(V)$) the single-source family wins: $O(V^2\log V)$ with Dijkstra or Johnson. For **dense** graphs ($E = \Theta(V^2)$) Floyd–Warshall's $O(V^3)$ beats Johnson's $O(V^3\log V)$ and is far simpler; Dijkstra with an array (or a Fibonacci heap) matches it for nonnegative weights.

## Summary

- The output is two $V\times V$ arrays, $\mathit{dist}$ and $\mathit{pred}$; row $u$ of $\mathit{pred}$ is the shortest-path tree rooted at $u$. Every algorithm needs $\Omega(V^2)$ time.
- $V$ single-source runs: $O(VE)$ unweighted or in a dag, $O(VE\log V)$ with Dijkstra (nonnegative weights), $O(V^2E)$ with Bellman–Ford.
- Prices $\pi$ give reduced weights $w'(u\to v) = \pi(u) + w(u\to v) - \pi(v)$; every path from $u$ to $v$ changes by $\pi(u) - \pi(v)$, every cycle by 0, so shortest paths are preserved. Adding a constant to every edge does **not** preserve them.
- Johnson: new vertex $s$ with 0-edges to all vertices, Bellman–Ford from $s$ ($\pi = \textsf{dist}(s, \cdot)$, so $w'\ge 0$), $V$ Dijkstras on $w'$, convert back: $O(VE\log V)$ with any weights.
- Dynamic programs (no negative cycles) compute the min-plus power $W^{\otimes(V-1)}$ of the weight matrix: by number of edges, $\textsf{dist}(u, v, \ell)$, in $O(V^2E)$ time; by repeated squaring in $O(V^3\log V)$.
- Floyd–Warshall: $\textsf{dist}(u, v, r) = \min\{\textsf{dist}(u, v, r-1),\ \textsf{dist}(u, r, r-1) + \textsf{dist}(r, v, r-1)\}$ over intermediate vertices at most $r$; $r$ is the outer loop; $O(V^3)$ time, $O(V^2)$ space in place; $\mathit{dist}[v, v] < 0$ at the end exactly when there is a negative cycle.
- Choose by the graph: sparse — Dijkstra or Johnson; dense — Floyd–Warshall.

> [!exam] On the exams
> Shortest paths are lectured in the week of October 26; whether all-pairs shortest paths are on Midterm 2 (November 9) or only on the final (December 11) is on the course website. All of this chapter's algorithms are **standard algorithms you may cite** with their running times: $V$ runs of breadth-first search, Dijkstra or Bellman–Ford, Johnson's $O(VE\log V)$ and Floyd–Warshall's $O(V^3)$. In a graph problem graded by the **graph-reduction rubric**, the 2 points for applying the right algorithm as a black box lose 1 for a **slower algorithm than necessary**: if the question involves distances only from a few fixed vertices $s$ (or to a few fixed $t$), run a single-source algorithm from $s$ in $G$ (or from $t$ in the reversed graph) instead of computing all pairs; for unweighted graphs use breadth-first search, for nonnegative weights Dijkstra, and Floyd–Warshall or Johnson only when the answer really needs many pairs — then pick by density as above. Give the time in the **input's** parameters, not just the $V$ and $E$ of your graph. Modify the graph, not the algorithm; and don't "fix" negative edges by adding a constant. If you design a Floyd–Warshall-style recurrence yourself (for a variant problem), it is graded by the [[0-toolkit/06-how-exams-are-graded#12-dynamic-programming|dynamic programming rubric]]: a named function with explicit parameters ($u$, $v$, $r$), what it means in English — "intermediate vertices at most $r$" is the subproblem's restriction —, base cases, the recurrence, the memoization array, the evaluation order (which loop is outer), and the time. See [[0-toolkit/06-how-exams-are-graded|how exams are graded]].
