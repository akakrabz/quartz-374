> [!abstract] In one breath
> A nondeterministic Turing machine may have several transitions to choose from, and its possible runs form a **computation tree**. It **accepts** an input if *some* branch accepts, but **rejects** it only if *every* branch rejects — an asymmetry that deterministic machines do not have. Nondeterminism adds no computing power: a deterministic machine can search the tree breadth-first (depth-first search could follow an infinite branch forever), or try every sequence of choices — every **advice string** — in order of length. Both simulations take exponential time, and whether that blow-up is avoidable for polynomial-time machines is the P versus NP question. The **Cook–Levin theorem** reduces it to a single problem: if the satisfiability of boolean formulas can be decided in polynomial time, then P = NP.

## 9.1 Definitions

A nondeterministic Turing machine relates to a deterministic one ([[1-models-of-computation/06-turing-machines#62-formal-definitions|§6.2]]) the way an [[concepts/nfa|NFA]] relates to a DFA ([[1-models-of-computation/04-nondeterministic-automata#41-nondeterministic-state-machines|§4.1]]): the transition function returns a set of options.

> [!definition] Definition — nondeterministic Turing machine
> A **nondeterministic Turing machine** $N$ has the same components as a deterministic one — a tape alphabet $\Gamma$ with a blank $\square$, an input alphabet $\Sigma\subseteq\Gamma\setminus\{\square\}$, and a finite set of states $Q$ containing $\textit{start}$, $\textit{accept}$ and $\textit{reject}$ — but its transition function returns a **set** of triples:
> $$
> \delta\colon \big(Q\setminus\{\textit{accept},\textit{reject}\}\big)\times\Gamma \to 2^{\,Q\times\Gamma\times\{-1,+1\}}.
> $$
> In state $p$ reading $a$, the machine may perform **any** transition $(q, b, \Delta)\in\delta(p,a)$: change to state $q$, write $b$, and move by $\Delta$. If $\delta(p,a) = \varnothing$, it moves to the reject state and halts.

> [!definition] Definition — computation tree
> The **computation tree** of $N$ on input $w$ has the initial configuration $(\textit{start}, w, 0)$ as its root. The children of a configuration are the configurations reachable from it by one transition, and accepting and rejecting configurations are leaves. A branch is a path from the root: either finite, ending in a leaf, or infinite. A deterministic machine's tree is a single branch.

**A running example.** The machine $N$ below accepts the strings that contain `11` by **guessing** where the `11` starts. Every transition moves right and rewrites the symbol it reads; when there is a choice, choice 1 is listed first.

| options | choice 1 | choice 2 |
|---|---|---|
| $\delta(\textit{start}, \mathtt{0})$ | $(\textit{start}, \mathtt{0}, +1)$ | — |
| $\delta(\textit{start}, \mathtt{1})$ | $(\textit{start}, \mathtt{1}, +1)$: keep scanning | $(\mathit{got1}, \mathtt{1}, +1)$: guess that `11` starts here |
| $\delta(\textit{start}, \square)$ | $(\textit{reject}, \square, +1)$: give up | $(\mathit{loop}, \square, +1)$: loop forever |
| $\delta(\mathit{got1}, \mathtt{0})$ | $(\textit{reject}, \mathtt{0}, +1)$ | — |
| $\delta(\mathit{got1}, \mathtt{1})$ | $(\textit{accept}, \mathtt{1}, +1)$ | — |
| $\delta(\mathit{got1}, \square)$ | $(\textit{reject}, \square, +1)$ | — |
| $\delta(\mathit{loop}, a)$, every $a$ | $(\mathit{loop}, a, +1)$ | — |

On each `1`, $N$ either keeps scanning or guesses that this `1` begins `11` and checks the next symbol. At the end of the input it may give up (reject) or — a deliberately bad option — loop forever. Let $N'$ be the same machine without the looping option.

## 9.2 Acceptance and rejection

> [!definition] Definition — accepting, rejecting, deciding
> - $N$ **accepts** $w$ if **some** branch of its computation tree on $w$ ends in an accepting configuration. Other branches may reject or run forever.
> - $N$ **rejects** $w$ if **every** branch ends in a rejecting configuration. Then every branch is finite, so the whole tree is finite (each configuration has finitely many children — König's lemma): $N$ halts within some number of steps, whatever it chooses.
> - Otherwise $N$ neither accepts nor rejects $w$.
>
> $N$ **accepts** a language $L$ if it accepts exactly the strings in $L$, and **decides** $L$ if it accepts every string in $L$ and rejects every string not in $L$.

In the example, $N$ accepts `011` through the accepting leaf, although one of its branches never halts. On `010` no branch accepts and the looping branch never halts, so $N$ neither accepts nor rejects `010`: $N$ **accepts** the strings containing `11` but does not decide that language. $N'$ has no looping option; on `010` every branch of $N'$ rejects, and $N'$ **decides** the language.

> [!trap] The asymmetry
> - Accepting needs **one** good branch; rejecting needs **all** branches to reject — so all of them must halt. As for deterministic machines, "$N$ does not accept $w$" is weaker than "$N$ rejects $w$".
> - **Swapping accept and reject does not complement a nondeterministic machine.** With its accept and reject states swapped, $N'$ accepts $w$ whenever *some* branch of $N'$ rejects $w$ — and the branch that never guesses always does. So the swapped machine accepts **every** string, not the strings without `11`. (For deterministic machines the swap works: [[1-models-of-computation/07-undecidability#73-useful-properties|Lemma 1(a) of Chapter 7]].)

Theorem 1 below shows that for computability the asymmetry is harmless: nondeterministic machines accept exactly the acceptable languages and decide exactly the decidable ones, so the complement of a language decided by a nondeterministic machine is decidable — first remove the nondeterminism, then swap. With a time bound it is a real issue: whether the complement of every language in NP is in NP is a famous open question.

## 9.3 Time and space complexity

> [!definition] Definition — complexity classes
> - $\textsf{TIME}(f(n))$: the languages decided by some deterministic multi-tape Turing machine in $O(f(n))$ time.
> - $\textsf{NTIME}(f(n))$: the languages decided by some nondeterministic multi-tape Turing machine in $O(f(n))$ time — on every input of length $n$, every branch halts within $O(f(n))$ steps.
> - $\textsf{SPACE}(f(n))$ and $\textsf{NSPACE}(f(n))$: the same with $O(f(n))$ tape cells instead of steps.
> - $\textsf{P} := \bigcup_{k} \textsf{TIME}(n^k)$ and $\textsf{NP} := \bigcup_{k}\textsf{NTIME}(n^k)$.

**Why multi-tape machines?** The number of tapes changes running times, but only a little: $t$ steps of a $k$-tape machine can be simulated in $O(t\log t)$ steps with two tapes and in $O(t^2)$ steps with one tape, and the quadratic loss is sometimes unavoidable — marked palindromes take $O(n)$ time with two heads but $\Omega(n^2)$ with one ([[1-models-of-computation/06-turing-machines#66-tracks-heads-and-tapes|§6.6]]). Polynomial bounds survive these slowdowns, so $\textsf{P}$ and $\textsf{NP}$ are the same for every fixed number of tapes.

Some inclusions are free: a deterministic machine is a nondeterministic one with a single option each time, so $\textsf{TIME}(f(n))\subseteq\textsf{NTIME}(f(n))$, $\textsf{SPACE}(f(n))\subseteq\textsf{NSPACE}(f(n))$, and $\textsf{P}\subseteq\textsf{NP}$. Theorem 1, whose simulation works the same way for multi-tape machines, gives one in the other direction: $\textsf{NTIME}(f(n))\subseteq\bigcup_c\textsf{TIME}(c^{f(n)})$ for $f(n)\ge n$, so every problem in $\textsf{NP}$ can be solved in exponential time. Whether $\textsf{P} = \textsf{NP}$ is open.

## 9.4 Deterministic simulation via dovetailing

> [!key] Theorem 1
> For every nondeterministic Turing machine $N$ there is a deterministic Turing machine $M$ that accepts exactly the strings $N$ accepts and rejects exactly the strings $N$ rejects. If every branch of $N$ on input $x$ halts within $t$ steps, then $M$ halts on $x$ within $O(t^2 r^{2t})$ steps, where $r$ is the largest number of options in any set $\delta(p, a)$.

> [!recipe] The breadth-first simulation behind Theorem 1
> $M$ keeps a **queue** of encoded configurations on its tape, separated by markers; initially it holds only $(\textit{start}, x, 0)$. Then $M$ repeats:
> 1. If the queue is empty, **reject**.
> 2. Remove the first configuration $c$. If $c$ is accepting, **accept**. If $c$ is rejecting, discard it.
> 3. Otherwise append the (at most $r$) configurations reachable from $c$ in one transition to the end of the queue.

**Correctness.** The queue processes the tree level by level, and each level is finite, so every configuration at depth $d$ is reached after finitely many rounds. If $N$ accepts $x$, an accepting configuration is eventually removed, and $M$ accepts. If $N$ rejects $x$, the tree is finite and has no accepting leaf, so the queue runs empty and $M$ rejects. In the remaining case — no accepting leaf, but an infinite branch — $M$ runs forever, which is right, because $N$ neither accepts nor rejects.

**Why not depth-first?** Backtracking — try choice 1, and only if that subtree fails, choice 2 — is the natural recursive search, but it explores the subtree of choice 1 completely before anything else. If that subtree contains an infinite branch, the search never returns, even when another choice accepts within three steps, as in the figure. Breadth-first search cannot get stuck, because it never goes deeper than level $d+1$ before finishing level $d$.

**Running time.** There are at most $r^t$ configurations at depth $t$, so the tree has $O(r^t)$ nodes (for $r\ge2$); each configuration fits in $O(t)$ cells (assuming $t\ge\lvert x\rvert$), so the queue holds $O(t\,r^t)$ symbols. With one head, copying a configuration of length $O(t)$ to the far end of the queue takes $O(t)$ trips of length $O(t\,r^t)$: $O(t^2r^t)$ steps per configuration, $O(t^2r^{2t})$ in all. With two tapes or two heads, one at each end of the queue, the copying costs $O(t)$ per configuration and the whole simulation $O(t\,r^t)$.

Compare the [[concepts/subset-construction|subset construction]] ([[1-models-of-computation/04-nondeterministic-automata#45-nfa-to-dfa-the-subset-construction|§4.5]]): an NFA's configuration is just a state, so a DFA can track the *set* of current states. A Turing machine's configuration includes the whole tape, so the deterministic simulation tracks a list of whole configurations, which can grow exponentially with the running time.

## 9.5 Nondeterminism as advice

The choices can be supplied in advance. Number the options of every set $\delta_N(p, a)$ as $1, 2, \dots$ in some fixed order, and let $\Omega := \{1, \dots, r\}$. A deterministic machine $M$ reads its input $w$ and also an **advice string** $x\in\Omega^*$ on a separate read-only tape: at each step it reads the next advice symbol $\omega$ and performs option $\omega$ of $\delta_N(q, a)$ (the last option, if there are fewer than $\omega$). So $\delta_N(q,a) = \{\delta_M(q, a, \omega) \mid \omega\in\Omega\}$, so each advice string of length $t$ follows one branch of $N$'s computation tree for up to $t$ steps, and every branch is followed by some advice string.

> [!key] The advice view of nondeterminism
> - $N$ accepts $w$ if and only if $M$ accepts $(w, x)$ for **some** advice string $x$.
> - $N$ rejects $w$ if and only if there is a length $t$ such that $M$ rejects $(w, x)$ within $t$ steps for **every** advice string $x$ of length $t$.

**Example.** For $N$ on `011` (with $\Omega = \{1, 2\}$), the advice strings of length 3 that make $M$ accept are exactly `121`, `122`, `221` and `222`: the second step is the only real choice on the way to the accepting leaf (choice 2, "this `1` begins `11`"), and the other two steps have a single option, so their advice symbols are ignored.

Trying the advice strings in order of length, and running each for as many steps as its length, is **dovetailing**:

```
Dovetail(w):
    for t ← 1, 2, 3, …
        done ← True
        for every advice string x of length t
            if M accepts (w, x) within t steps: accept
            if M has not halted on (w, x) after t steps: done ← False
        if done: reject
```

**Correctness — a second proof of Theorem 1.** If $N$ accepts $w$ through an accepting leaf at depth $\ell$, then in every round $t < \ell$ the first $t$ choices of that branch give a run that has not halted, so $\textsf{Dovetail}$ does not reject; in round $\ell$ the branch's own advice makes $M$ accept. If $N$ rejects $w$, its tree has some finite depth $D$, and in round $D$ every run halts and none accepts, so $\textsf{Dovetail}$ rejects. Otherwise it runs forever.

**Running time.** If every branch halts within $t$ steps, $\textsf{Dovetail}$ stops by round $t$, after simulating $\sum_{s\le t} s\,r^s\le 2t\,r^t$ steps of $M$ (for $r\ge2$): $O(t\,r^t)$ time with three tapes (input, advice, work) and $O(t^2r^t)$ with one tape, where each simulated step shuttles between the work area and the advice. That beats the queue simulation's $O(t^2r^{2t})$: recomputing configurations from scratch is cheaper than storing them and scanning past them.

## 9.6 The Cook–Levin theorem

The advice view describes $\textsf{NP}$ without nondeterministic machines; the advice is a **certificate** that $w\in L$ — a satisfying assignment, a tour, a coloring — that a deterministic **verifier** can check quickly.

> [!definition] Definition — NP, in the form the proof uses
> $L\in\textsf{NP}$ if there are an integer $k$ and a deterministic Turing machine $M$, the **verifier**, such that for every string $w$:
> - if $w\in L$, then $M$ accepts $(w, x)$ for **some** advice string $x$;
> - if $w\notin L$, then $M$ rejects $(w, x)$ for **every** advice string $x$;
> - $M$ always halts within $\max\{1, \lvert w\rvert^k\}$ steps.

$\textsf{SAT}$ is the language of satisfiable boolean formulas: formulas built from variables with $\wedge$, $\vee$ and $\neg$ for which some assignment of $\textsf{True}$/$\textsf{False}$ to the variables makes the formula true.

> [!key] The Cook–Levin theorem
> If $\textsf{SAT}\in\textsf{P}$, then $\textsf{P} = \textsf{NP}$.

**The plan.** Fix $L\in\textsf{NP}$ with verifier $M$ and exponent $k$. Given $w$ of length $n$, let $N := \max\{1, n^k\}$ and build a formula $\Phi_w$ that is satisfiable if and only if some advice string makes $M$ accept $(w, x)$ — that is, if and only if $w\in L$. A fast algorithm for $\textsf{SAT}$ run on $\Phi_w$ then decides $L$.

**The variables** describe a run of $M$ on $w$ followed by an unknown advice string, for every time $0\le t\le N$, state $q$ and symbol $a$:
- $Q_{t,i,q}$ — "after $t$ steps, $M$ is in state $q$ with its head on cell $i$";
- $T_{t,i,a}$ — "after $t$ steps, cell $i$ holds the symbol $a$".

The head starts on cell 1 and moves at most $N$ times, so cells $1, \dots, N+1$ suffice, plus an empty **sentinel** cell on each side, cells $0$ and $N+2$. At time 0, cells $1, \dots, n$ hold $w$, cell $n+1$ holds a blank, and cells $n+2, \dots, N+1$ hold the advice.

**The constraints** come in five kinds:
1. **Boundaries.** The sentinel cells never hold the head or a symbol: all $Q_{t,0,q}$, $Q_{t,N+2,q}$, $T_{t,0,a}$ and $T_{t,N+2,a}$ are false.
2. **Initialization.** At time 0 the head is on cell 1 in state $\textit{start}$ (and no other $Q_{0,i,q}$ is true), cells $1,\dots,n$ hold the symbols of $w$, and cell $n+1$ holds a blank.
3. **Advice.** Each cell $n+2, \dots, N+1$ holds **exactly one** symbol at time 0 — which one is left to the satisfying assignment: this is where the formula guesses the advice.
4. **Transitions.** For $1\le t\le N$ and $1\le i\le N+1$, each variable $Q_{t,i,q}$ and $T_{t,i,b}$ is equivalent to a formula of constant size in the time-$(t-1)$ variables of cells $i-1$, $i$, $i+1$, following $\delta$.
5. **Acceptance.** $Q_{t,i,\textit{accept}}$ is true for some $t$ and $i$.

> [!derivation]- The transition constraints in full (click to expand)
> $$
> Q_{t,i,q} \iff \bigvee_{\delta(p,a) = (q,\,\cdot\,,+1)}\big(Q_{t-1,i-1,p}\wedge T_{t-1,i-1,a}\big)\ \vee \bigvee_{\delta(p,a) = (q,\,\cdot\,,-1)}\big(Q_{t-1,i+1,p}\wedge T_{t-1,i+1,a}\big)
> $$
> $$
> T_{t,i,b} \iff \bigvee_{\delta(p,a) = (\cdot\,,b,\,\cdot)}\big(Q_{t-1,i,p}\wedge T_{t-1,i,a}\big)\ \vee\ \Big(T_{t-1,i,b}\wedge\bigwedge_{q\in Q}\neg Q_{t-1,i,q}\Big)
> $$
> The head is on cell $i$ in state $q$ exactly when it just arrived from a neighboring cell by a transition into $q$. Cell $i$ holds $b$ exactly when the head just wrote $b$ there, or $b$ was there before and the head was elsewhere. Once the advice cells are fixed, these equivalences force the value of every later variable, so a satisfying assignment *is* the run of $M$ on $w$ with that advice — and the acceptance constraint holds exactly when that run accepts.

**Size.** $M$ is fixed, so $\lvert Q\rvert$, $\lvert\Gamma\rvert$ and $\delta$ are constants. There are $(N+1)(N+3)(\lvert Q\rvert+\lvert\Gamma\rvert) = O(N^2)$ variables and $O(N^2)$ constraints of constant size, plus one acceptance constraint with $O(N^2)$ literals. So $\Phi_w$ has size $O(N^2) = O(n^{2k})$, and an algorithm can write it down in $O(n^{2k})$ time.

**Conclusion.** If some algorithm decides $\textsf{SAT}$ in $O(m^c)$ time for formulas of size $m$, then building $\Phi_w$ and testing it decides $w\in L$ in $O(n^{2k}) + O(n^{2kc})$ time, so $L\in\textsf{P}$. Since $L$ was an arbitrary language in $\textsf{NP}$, $\textsf{NP}\subseteq\textsf{P}$; and $\textsf{P}\subseteq\textsf{NP}$ always, so $\textsf{P} = \textsf{NP}$. $\blacksquare$

> [!intuition] What the proof really shows
> The construction is a polynomial-time **reduction from every language in $\textsf{NP}$ to $\textsf{SAT}$**: $w\in L$ if and only if $\Phi_w\in\textsf{SAT}$. So $\textsf{SAT}$ is **NP-hard** — at least as hard as every problem in NP. And $\textsf{SAT}$ is itself in $\textsf{NP}$ (a satisfying assignment is a certificate that a verifier checks in polynomial time), so it is **NP-complete**. The algorithms half of the course starts from here: to prove that another problem $X$ is NP-hard, reduce $\textsf{SAT}$ (or another known NP-hard problem) **to** $X$ in polynomial time — the same direction rule as for undecidability ([[1-models-of-computation/07-undecidability#79-the-halting-problem-via-reduction|§7.9]]). See [[2-algorithms/index|Algorithms]].

> [!trap] Reading "NP" correctly
> - NP stands for *nondeterministic polynomial time*, not "not polynomial": every problem in $\textsf{P}$ is in $\textsf{NP}$.
> - The definition is asymmetric, like acceptance in §9.2: yes-instances have short certificates; nothing promises short certificates for no-instances.
> - Cook–Levin is a statement about **SAT**; the reduction goes from an arbitrary $L\in\textsf{NP}$ *to* $\textsf{SAT}$, never the other way.

Concept page: [[concepts/cook-levin-theorem]].

## Summary

- A nondeterministic TM has $\delta(p,a)\subseteq Q\times\Gamma\times\{-1,+1\}$; its runs form a computation tree rooted at $(\textit{start}, w, 0)$.
- Accept: **some** branch accepts (others may diverge). Reject: **every** branch rejects, so the tree is finite. Swapping accept and reject does not complement a nondeterministic machine.
- $\textsf{TIME}$, $\textsf{NTIME}$, $\textsf{SPACE}$, $\textsf{NSPACE}$ use multi-tape machines; the tape count costs at most a quadratic factor, so $\textsf{P}$ and $\textsf{NP}$ do not depend on it. $\textsf{P}\subseteq\textsf{NP}\subseteq$ exponential time.
- Theorem 1: a deterministic machine accepts and rejects the same strings, by breadth-first search of the tree — $O(t^2r^{2t})$ on one tape, $O(t\,r^t)$ with two. Depth-first search can get stuck on an infinite branch.
- Advice strings $x\in\{1,\dots,r\}^*$ make the choices explicit; dovetailing tries all of length $t$ for $t$ steps, in $O(t\,r^t)$ time with three tapes.
- $\textsf{NP}$ = languages with polynomial-time verifiers and certificates. Cook–Levin: $\Phi_w$ with variables $Q_{t,i,q}$, $T_{t,i,a}$ and five kinds of constraints has size $O(N^2)$ and is satisfiable iff $w\in L$; so $\textsf{SAT}\in\textsf{P}$ implies $\textsf{P} = \textsf{NP}$.

We state the rejection half of the advice view with an explicit length $t$, which keeps it correct when the tree has infinite branches, and we index the Cook–Levin tableau with cells $0, \dots, N+2$ so that a run whose head reaches cell $N+1$ at time $N$ is still represented; we also correct a few index typos in the printed constraints (every variable on the right of a transition constraint refers to time $t-1$, and the left boundary is cell $0$). The computation tree and breadth-first order in the figures, the behavior of $N$, $N'$ and the swapped machine, the advice example, the agreement of breadth-first search and dovetailing (on hundreds of random nondeterministic machines), the counting bounds, the advice view's rejection half, and the Cook–Levin constraints (evaluated literally on two toy verifiers, with both cell windows) are checked by `tools/checks/ch09.py`.
