> [!abstract] In one breath
> A Turing machine is a finite-state control attached to an unbounded tape that it can read, overwrite and walk along in both directions. On a given input it **accepts**, **rejects**, **crashes** off the left end of the tape, or **runs forever**, and the difference between *accepting* a language and *deciding* it (also halting on every input) organizes all of Chapter 7. Designing machines is tedious but mechanical — scan, mark, walk back — and every reasonable variation (stay-put moves, more tracks, heads or tapes, a tape infinite in both directions) accepts and decides exactly the same languages, at most quadratically slower. Turing machines can simulate a real computer and, through a **universal machine**, each other. That generality is the point: they are a terrible model for fast algorithms and the standard model for proving what *cannot* be computed.

In 1936, at the age of 23, Alan Turing defined these machines, described a single machine that can simulate all the others, and proved that no machine solves the halting problem — and therefore that Hilbert's *Entscheidungsproblem* (decide whether a given statement of first-order logic is provable) has no algorithmic solution. Alonzo Church had reached the same conclusion a few months earlier with his λ-calculus; Turing then proved that the two models compute exactly the same functions.

> [!key] The Church–Turing thesis
> Every function that can be computed "by finite means" — by any algorithm whatsoever — can be computed by a Turing machine.
>
> This is a **claim about the world, not a theorem**: "algorithm" has no formal definition to prove it against, and Turing himself called his arguments for it appeals to intuition. The evidence is that every reasonable model proposed since 1936 — the λ-calculus, recursive functions, register machines, programming languages, and the strange systems of [[1-models-of-computation/08-universal-models|Chapter 8]] — computes exactly the same functions.

Concept page: [[concepts/church-turing-thesis]].

## 6.1 Why bother?

Turing machines are a poor model of **speed**. Small changes to the model change running times: reversing an $n$-bit string takes $O(n)$ time on a machine with two tapes but provably $\Omega(n^2)$ time with one. Nobody designs algorithms on them; algorithms are analyzed on random-access models instead.

They are an excellent model of **impossibility**. To prove that *no* algorithm solves a problem, we need a definition of "algorithm" that is

- **simple enough** that one proof can reason about every possible machine at once — a handful of components and a single step rule; and
- **powerful enough** to simulate every other reasonable model, including Turing machines themselves. Self-simulation is what makes the self-referential undecidability proofs of [[1-models-of-computation/07-undecidability|Chapter 7]] possible.

> [!intuition] A DFA with a notebook
> A [[concepts/dfa|DFA]] reads its input once, left to right, and its only memory is its current state. A Turing machine has the same kind of finite control, but its input sits on a tape that it may reread, overwrite and extend without limit, moving in either direction. Finite control plus unbounded rewritable memory is general computation.

## 6.2 Formal definitions

> [!definition] Definition — Turing machine
> A **Turing machine** $M$ consists of
> - a **tape alphabet** $\Gamma$: a finite set with at least two symbols, one of which is the **blank** $\square$;
> - an **input alphabet** $\Sigma\subseteq\Gamma\setminus\{\square\}$, non-empty;
> - a finite set $Q$ of **states** containing three distinct special states $\textit{start}$, $\textit{accept}$ and $\textit{reject}$;
> - a **transition function** $\delta\colon (Q\setminus\{\textit{accept},\textit{reject}\})\times\Gamma\to Q\times\Gamma\times\{-1,+1\}$.
>
> $\delta(p,a) = (q,b,\Delta)$ means: in state $p$, reading $a$, overwrite it with $b$, move the head one cell — to the left if $\Delta = -1$, to the right if $\Delta = +1$ — and enter state $q$. Nothing happens after $\textit{accept}$ or $\textit{reject}$.

The tape has a left end, cell 0, and extends forever to the right; at every moment all but finitely many cells are blank.

> [!definition] Definition — configuration, step, crash
> A **configuration** is a triple $(q, x, i)$: the current state $q$, the tape contents $x\in\Gamma^*$ (followed by infinitely many blanks; trailing blanks may be written or left out, so $(q,x,i)$ and $(q,x\square,i)$ are the same configuration), and the head position $i\ge0$. If $\delta(p,a) = (q,b,\Delta)$ then
> $$
> (p,\ xay,\ i)\ \Rightarrow\ (q,\ xby,\ i+\Delta)\qquad\text{whenever } \lvert x\rvert = i,
> $$
> that is, when the head is on cell $i$, which holds $a$. Every configuration has at most one successor, and $\Rightarrow^*$ means zero or more steps. On input $w\in\Sigma^*$ the machine starts in the **initial configuration** $(\textit{start}, w, 0)$. If a step would move the head to position $-1$, there is no next configuration: the machine **crashes**.

> [!definition] Definition — the four outcomes
> On each input $w$, exactly one of these happens:
> - $M$ **accepts** $w$: $(\textit{start}, w, 0)\Rightarrow^*(\textit{accept}, x, i)$ for some $x$ and $i$;
> - $M$ **rejects** $w$: $(\textit{start}, w, 0)\Rightarrow^*(\textit{reject}, x, i)$ for some $x$ and $i$;
> - $M$ **crashes** on $w$: the run reaches a configuration that tries to move left from cell 0;
> - $M$ **runs forever** on $w$: none of the above, ever.
>
> $M$ **halts** on $w$ if it accepts or rejects $w$; otherwise — if it crashes or runs forever — $M$ **diverges** on $w$. (Chapter 7's set $\textsf{Diverge}(M)$ therefore contains the inputs on which $M$ crashes.)

> [!trap] "Rejects" and "does not accept" are different
> A machine that does not accept $w$ may reject it, crash, or run forever. Accepting and rejecting are definite answers that an observer eventually sees, but "does not accept" may never become visible: a machine that has run for a million steps may still accept at step $10^6+1$. Chapter 7 is built on this distinction — $\textsf{Reject}(M)$ and $\Sigma^*\setminus\textsf{Accept}(M)$ are different sets in general ([[1-models-of-computation/07-undecidability#71-acceptable-versus-decidable|§7.1]]).

> [!definition] Definition — accepting versus deciding a language
> Let $L\subseteq\Sigma^*$, and let $\textsf{Accept}(M)$ be the set of strings that $M$ accepts.
> - $M$ **accepts** (or **recognizes**) $L$ if $\textsf{Accept}(M) = L$: $M$ accepts every string in $L$ and nothing else. On strings outside $L$ it may reject, crash or run forever. $L$ is **acceptable** if some Turing machine accepts it.
> - $M$ **decides** $L$ if $M$ accepts every string in $L$ and rejects every string in $\Sigma^*\setminus L$ — equivalently, $M$ accepts $L$ and halts on every input. $L$ is **decidable** if some Turing machine decides it.

| term used here and in the book | synonyms you will meet |
|---|---|
| acceptable | recognizable (the book's word in §6.2), semi-decidable, semi-computable, recursively enumerable (r.e.) |
| decidable | computable, recursive |
| $M$ accepts $L$ | $M$ recognizes $L$ |
| $M$ decides $L$ | $M$ is a decider for $L$ |

Every decidable language is acceptable, since a machine that decides $L$ also accepts it. The converse fails: the halting problem is acceptable but undecidable ([[1-models-of-computation/07-undecidability#79-the-halting-problem-via-reduction|§7.9]]), and some languages are not even acceptable.

> [!trap] Missing transitions
> The definition makes $\delta$ total on the non-halting states, but tables and diagrams usually leave many transitions out. The convention, in the book and on this site, is that **every missing transition goes to $\textit{reject}$**. Say so explicitly on an exam, exactly as you would mention the omitted dump state of a DFA.

## 6.3 A first example

The language $L = \{\mathtt{0}^n\mathtt{1}^n\mathtt{0}^n \mid n\ge0\}$ is not regular — $\mathtt{0}^*$ is a fooling set, with suffix $\mathtt{1}^i\mathtt{0}^i$ for $\mathtt{0}^i$, as in [[1-models-of-computation/03-finite-state-machines#38-proving-a-language-is-not-regular|§3.8]] — and it is the standard example of a language that is not even context-free (the proof is beyond this course). It is decidable. The machine below follows the book's idea of marking one symbol of each block per round, with one addition: it checks the format of the input first.

> [!recipe] The algorithm in English
> **Phase 1: check the format.** If the input is empty, accept. Otherwise its first symbol must be $\mathtt{0}$; overwrite it with $\mathtt{\#}$, which marks the left end of the tape *and* counts as the first matched 0. Scan right, checking that the input has the form $\mathtt{0}^+\mathtt{1}^+\mathtt{0}^+$, then walk back to the $\mathtt{\#}$.
>
> **Phase 2: match in rounds.** Each round marks the first unmarked $\mathtt{1}$ with $\mathtt{x}$, marks the first unmarked $\mathtt{0}$ after the 1s with $\mathtt{x}$, walks back to the last $\mathtt{\#}$, and marks the next $\mathtt{0}$ of the first block with $\mathtt{\#}$. Once the first block is used up, accept if and only if every remaining symbol is marked.
>
> Whenever a step cannot find the symbol it needs, reject.

In the table, "—" means "write back the symbol that was read". Missing transitions reject.

|---|---|---|---|---|---|
| $\textit{start}$ | $\mathtt{0}$ | $\mathtt{\#}$ | $+1$ | $\mathit{block1}$ | mark the first 0, and with it the left end |
| | $\square$ | — | $+1$ | $\textit{accept}$ | the empty string is in $L$ |
| $\mathit{block1}$ | $\mathtt{0}$ | — | $+1$ | $\mathit{block1}$ | format check: 0s … |
| | $\mathtt{1}$ | — | $+1$ | $\mathit{block2}$ | |
| $\mathit{block2}$ | $\mathtt{1}$ | — | $+1$ | $\mathit{block2}$ | … then 1s … |
| | $\mathtt{0}$ | — | $+1$ | $\mathit{block3}$ | |
| $\mathit{block3}$ | $\mathtt{0}$ | — | $+1$ | $\mathit{block3}$ | … then 0s … |
| | $\square$ | — | $-1$ | $\mathit{rewind}$ | … then the end: format OK |
| $\mathit{rewind}$ | $\mathtt{0}$, $\mathtt{1}$ | — | $-1$ | $\mathit{rewind}$ | walk back to cell 0 |
| | $\mathtt{\#}$ | — | $+1$ | $\mathit{seek1}$ | round 1 continues |

| | $\mathtt{1}$ | $\mathtt{x}$ | $+1$ | $\mathit{seek0}$ | mark it |
| $\mathit{seek0}$ | $\mathtt{1}$, $\mathtt{x}$ | — | $+1$ | $\mathit{seek0}$ | look for the first unmarked 0 after the 1s |

> [!trap] The book's machine skips the format check
> The machine printed in the book's §6.3 (states *start*, *seek1*, *seek0*, *reset*, *verify*) starts matching immediately. Read with a move to the left after it marks a 0 — which is what the text and its traces do; the printed table says $+1$ there, a typo — it also accepts some strings outside $L$, such as `001010` (18 strings of length at most 12 in all), and because its *start* state has no transition on $\square$, it rejects $\varepsilon$, which is in $L$. Its matching idea is sound; it needs a format check like Phase 1. The general lesson: test a design on $\varepsilon$ and on near-misses such as `001010`, `0110` and `00`, not only on members of the language.

> [!recipe] Recipe — designing a Turing machine
> 1. Write the algorithm in English as a few **passes over the tape**: scan for something, mark it, walk back.
> 2. **Mark, don't count.** The state is finite; unbounded counts live on the tape as marked symbols.
> 3. **Mark the left end** before the machine ever walks left, so that it knows where to stop instead of crashing.
> 4. Each pass becomes one or two states, and "keep scanning" becomes a self-loop.
> 5. Write the transition table with a one-line meaning for every state, and say that missing transitions reject.
> 6. Trace the machine on $\varepsilon$, on a short member of the language, and on several near-misses.

> [!exam] Writing a Turing machine on an exam
> Turing machines were not on Midterm 1. If the final asks you to design one, give the transition table (or a state diagram) **together with an English description of what each state does**, use mnemonic state names, and say that missing transitions reject — the standards for DFAs, scaled up. Begin with the phase-by-phase description in English; the table should implement exactly that description.

## 6.4 Variations

The definition above is one choice among many. Books, courses and research papers vary it in harmless ways, and all of these variants accept and decide exactly the same languages:

- **halting:** several accepting and rejecting states; halting whenever no transition applies; only accepting states (a crash then counts as rejection); halting by moving off the left end;
- **moves:** stay-put moves ($\Delta = 0$); moves of several cells at once; steps that either write or move, but not both;
- **transition function:** partial instead of total, with missing transitions rejecting (as in our tables);
- **left end:** an end marker that cannot be overwritten, or a move left at cell 0 that leaves the head where it is instead of crashing.

Two machines are **equivalent** if they accept the same strings and reject the same strings (so they also diverge on the same strings, although one may crash where the other runs forever). To show that a variant adds no power, show that a standard machine can **simulate** it. The cost of the simulation matters for running time, never for decidability.

> [!definition] Construction — removing stay-put moves
> Let $M$ have moves $\Delta\in\{-1,0,+1\}$. Build $M'$ with states $Q' = Q\times\{0,1\}$, start state $(\textit{start},0)$, accepting state $(\textit{accept},0)$, rejecting state $(\textit{reject},0)$, and
> $$
> \delta'\big((p,0),a\big) := \begin{cases} \big((q,1),\,b,\,+1\big) & \text{if } \delta(p,a) = (q,b,0),\\ \big((q,0),\,b,\,\Delta\big) & \text{if } \delta(p,a) = (q,b,\Delta) \text{ with } \Delta\ne0, \end{cases}
> $$
> $$
> \delta'\big((p,1),a\big) := \big((p,0),\,a,\,-1\big)\quad\text{for every state } p \text{ and symbol } a.
> $$
> State $(q,1)$ means "I moved right only because $M$ wanted to stay put; step back". On every input, $M'$ accepts, rejects, crashes or runs forever exactly when $M$ does, with the same final tape, and $t$ steps of $M$ take at most $2t$ steps of $M'$.

## 6.5 Computing functions

> [!definition] Definition — computing a function
> Replace $\textit{accept}$ and $\textit{reject}$ by a single **halting state** $\textit{halt}$. If $M$ halts on input $w$, its **output** $M(w)$ is the tape contents at that moment, without the trailing blanks: $M(w) = x$ if and only if $(\textit{start}, w, 0)\Rightarrow^*(\textit{halt}, x, i)$ for some $i$, where $x$ does not end with $\square$. If $M$ never halts on $w$, then $M$ **diverges** on $w$, written $M(w)\uparrow$, and $M(w)$ is undefined. $M$ **computes** a function $f\colon\Sigma^*\to\Sigma^*$ if $M(w) = f(w)$ for every $w\in\Sigma^*$.

**Shifting.** The book's machine for $w\mapsto\mathtt{0}w$ keeps in its state the symbol it still has to write. In each step it writes that symbol and remembers the one it overwrote. (The book names the states 0 and 1; here they are $\mathit{hold0}$ and $\mathit{hold1}$, and $\mathit{hold0}$ is the start state.)

| state | read | write | move | next state |
|---|---|---|---|---|
| $\mathit{hold0}$ | $\mathtt{0}$ | $\mathtt{0}$ | $+1$ | $\mathit{hold0}$ |
| $\mathit{hold0}$ | $\mathtt{1}$ | $\mathtt{0}$ | $+1$ | $\mathit{hold1}$ |
| $\mathit{hold0}$ | $\square$ | $\mathtt{0}$ | $+1$ | $\textit{halt}$ |
| $\mathit{hold1}$ | $\mathtt{0}$ | $\mathtt{1}$ | $+1$ | $\mathit{hold0}$ |
| $\mathit{hold1}$ | $\mathtt{1}$ | $\mathtt{1}$ | $+1$ | $\mathit{hold1}$ |
| $\mathit{hold1}$ | $\square$ | $\mathtt{1}$ | $+1$ | $\textit{halt}$ |

On `101` it goes through $\mathit{hold0}\colon\underline{\mathtt{1}}\mathtt{01}$, $\mathit{hold1}\colon\mathtt{0}\underline{\mathtt{0}}\mathtt{1}$, $\mathit{hold0}\colon\mathtt{01}\underline{\mathtt{1}}$, $\mathit{hold1}\colon\mathtt{010}\underline{\square}$ and halts with output `0101`. In general it halts after $\lvert w\rvert + 1$ steps. Remembering the last $k$ symbols in the state shifts by $k$ cells.

> [!example] Binary increment = shift, then carry
> Adding 1 to a binary number can carry into a new leading digit (`111` + 1 = `1000`), and a machine that walks left looking for room for the carry would crash at cell 0. Shifting first makes the room: the machine below shifts $w$ one cell to the right with a 0 in front, exactly like the shift machine, and then adds 1 at the right end; the carry stops at that leading 0 at the latest.
>
> | state | read | write | move | next state | meaning |
> |---|---|---|---|---|---|
> | $\mathit{hold0}$, $\mathit{hold1}$ | $\mathtt{0}$, $\mathtt{1}$ | as in the shift machine | $+1$ | $\mathit{hold0}$, $\mathit{hold1}$ | shift right by one cell |
> | $\mathit{hold0}$ | $\square$ | $\mathtt{1}$ | $+1$ | $\textit{halt}$ | the last bit was 0: it becomes 1, no carry |
> | $\mathit{hold1}$ | $\square$ | $\mathtt{0}$ | $-1$ | $\mathit{carry}$ | the last bit was 1: it becomes 0, carry 1 |
> | $\mathit{carry}$ | $\mathtt{1}$ | $\mathtt{0}$ | $-1$ | $\mathit{carry}$ | $1 + 1 = 0$, carry on |
> | $\mathit{carry}$ | $\mathtt{0}$ | $\mathtt{1}$ | $+1$ | $\textit{halt}$ | $0 + 1 = 1$, done |
>
> If $w$ is the binary representation of $n$ (leading zeros allowed), the output is $n+1$ in binary with $\lvert w\rvert + 1$ digits: `1011` ↦ `01100`, `111` ↦ `1000`, and $\varepsilon$ ↦ `1`. Removing the leading 0 would take one more pass. The book's binary adder (its §6.5.2) works in the same style: phases for scanning and adding, with the carry kept in the state.

## 6.6 Tracks, heads, and tapes

More hardware does not add power either. Each variant below is simulated by a standard machine; the last column gives the cost of simulating $t$ steps.

| variant | how a standard machine simulates it | time for $t$ steps |
|---|---|---|
| $k$ tracks | one track over the alphabet $\Gamma_1\times\cdots\times\Gamma_k$ | $t$ |
| tape infinite in both directions | fold it at cell 0 onto two tracks (or interleave the cells), with a marker at cell 0 | $O(t)$ |
| insert or delete a cell | mark the cell, shift everything to its right by one cell, unmark | one shift per operation |
| $k$ heads on one tape | $k$ extra tracks mark the head positions; each step sweeps across all of them | $\Theta(t^2)$ |
| $k$ tapes | $2k$ tracks: each tape's contents and its head mark | $\Theta(t^2)$ |
| $k$ tapes, on a machine with **two** tapes | a cleverer simulation | $O(t\log t)$ |

> [!key] The quadratic slowdown is unavoidable
> After $t$ steps the simulated heads can be up to $t$ cells apart, so one sweep costs $O(t)$ steps and $t$ simulated steps cost $O(t^2)$. No cleverer one-head simulation exists in general: the **marked palindromes** $\{w\,\mathtt{\#}\,w^R \mid w\in\{\mathtt{0},\mathtt{1}\}^*\}$ can be decided in $O(n)$ time with two heads — send one head to the far end, then walk the two heads toward each other, comparing — but need $\Omega(n^2)$ time on a standard machine with one head.

Combining the simulations, any fixed number of tapes, heads and tracks, on tapes infinite in one or both directions, costs at most a quadratic slowdown. So decidability never depends on these details, and neither does running in polynomial time, which is what the classes P and NP of [[1-models-of-computation/09-nondeterministic-turing-machines|Chapter 9]] measure.

## 6.7 Simulating a real computer

Two features of real programs remain, and Turing machines can simulate both.

- **Subroutines and recursion.** Keep a call stack on an extra tape. To call a subroutine, push a record naming the state to return to and enter the subroutine's states; to return, pop the top record and continue in the state it names. With the stack on its own tape, $t$ steps of a machine with recursive calls take $O(t)$ steps on a multi-tape machine, and so $O(t^2)$ steps on a standard one.
- **Random-access memory.** Keep the memory on a tape as a list of pairs $[\textit{address}\bullet\textit{data}]$. A read or write scans the list for the address, and appends a new pair if the address is not there yet. If every address and value has at most $\ell$ bits, the $k$th access costs $O(k\ell)$ steps on a multi-tape machine, so $t$ accesses cost $O(t^2\ell)$ — and $O(t^3\ell^2)$ on a standard one-tape machine.

Every overhead is polynomial. So a Turing machine can run any program a real computer can run, at most polynomially slower, and "computable by a program in your favorite language" means the same thing as "computable by a Turing machine" — evidence for the Church–Turing thesis from the one model we actually build.

## 6.8 Universal Turing machines

A **universal Turing machine** $U$ is an interpreter for Turing machines, written as a Turing machine. Its input is an encoding $\langle M, w\rangle$ of a machine $M$ together with an input $w$ for $M$.

> [!key] The universal machine
> $U$ accepts $\langle M,w\rangle$ if and only if $M$ accepts $w$, and $U$ rejects $\langle M,w\rangle$ if and only if $M$ rejects $w$: on every input, $U$ gives the answer that $M$ would give.

$U$ has one fixed, finite alphabet, but the machines it simulates have arbitrarily large alphabets and state sets, so everything about $M$ is written in binary, with a few punctuation symbols.

> [!definition] The encodings
> - **Symbols:** each $a\in\Gamma$ gets a distinct string $\langle a\rangle$ of $\lceil\lg\lvert\Gamma\rvert\rceil$ bits. A string is written symbol by symbol between brackets: $\langle w\rangle = [\langle w_1\rangle{\bullet}\langle w_2\rangle{\bullet}\cdots{\bullet}\langle w_n\rangle]$.
> - **States:** each $q\in Q$ gets a distinct string $\langle q\rangle$ of $\lceil\lg\lvert Q\rvert\rceil$ bits, with $\langle\textit{start}\rangle = \mathtt{1}\cdots\mathtt{1}$ and $\langle\textit{reject}\rangle = \mathtt{0}\cdots\mathtt{0}$. The book fixes no code for $\textit{accept}$, but $U$ has to recognize it, so fix one as well; this site uses $\langle\textit{accept}\rangle = \mathtt{0}\cdots\mathtt{01}$.
> - **Moves:** $\langle -1\rangle = \mathtt{0}$ and $\langle +1\rangle = \mathtt{1}$.
> - **Transitions:** each $\delta(p,a) = (q,b,\Delta)$ with $q\ne\textit{reject}$ becomes a block $[\langle p\rangle{\bullet}\langle a\rangle\,|\,\langle q\rangle{\bullet}\langle b\rangle{\bullet}\langle\Delta\rangle]$. Transitions into $\textit{reject}$ are left out — they become missing transitions.
> - **The machine:** $\langle M\rangle = [\langle\textit{reject}\rangle{\bullet}\langle\square\rangle]\,\langle\delta\rangle$, where $\langle\delta\rangle$ is the list of all blocks inside one more pair of brackets. The first block tells $U$ how long the codes are.
> - **Configurations:** a list of cells $[\langle q\rangle{\bullet}\langle a\rangle]$, one per tape cell, inside one more pair of brackets. Here $a$ is the cell's symbol, and $q = \textit{reject}$ in every cell except the one under the head, which carries the current state.

> [!example] Encoding the machine of §6.3
> It has $\lvert\Gamma\rvert = 5$ symbols and $\lvert Q\rvert = 12$ states, so symbols take 3 bits and states take 4. Choose $\langle\square\rangle = \mathtt{000}$, $\langle\mathtt{0}\rangle = \mathtt{001}$, $\langle\mathtt{1}\rangle = \mathtt{010}$, $\langle\mathtt{\#}\rangle = \mathtt{011}$, $\langle\mathtt{x}\rangle = \mathtt{100}$, and $\langle\textit{start}\rangle = \mathtt{1111}$, $\langle\textit{reject}\rangle = \mathtt{0000}$, $\langle\textit{accept}\rangle = \mathtt{0001}$, $\langle\mathit{seek1}\rangle = \mathtt{0110}$, $\langle\mathit{seek0}\rangle = \mathtt{0111}$, $\langle\mathit{reset}\rangle = \mathtt{1000}$, with other distinct codes for the other states. Then
> - $\delta(\mathit{seek1},\mathtt{1}) = (\mathit{seek0},\mathtt{x},+1)$ becomes the block `[0110•010|0111•100•1]`;
> - $\langle M\rangle$ is `[0000•000]` followed by a bracketed list of 25 such blocks, one for each transition in the table;
> - the input `010` is `[001•010•001]`;
> - the configuration $(\mathit{reset}, \mathtt{\#0x1x0}, 3)$ drawn in §6.2 is `[[0000•011][0000•001][0000•100][1000•010][0000•100][0000•001]]`.
>
> The book's own example, for its seven-state machine with 3-bit codes, lists $\langle\textit{start}\rangle = \mathtt{111}$ and uses it in the initial configuration, but writes $\textit{start}$ as `001` inside its encoded transitions — a typo; by the rule above the code is `111` there too.

> [!recipe] How $U$ simulates one step of $M$
> $U$ keeps $\langle\delta\rangle$ in one place and the encoded configuration in another (on separate tapes, or tracks of one tape).
> 1. **Find the head:** scan the configuration for the one cell whose state code is not $\langle\textit{reject}\rangle$.
> 2. **Look up the transition:** scan $\langle\delta\rangle$ for the block whose left half matches that cell. If there is none, **reject**.
> 3. **Apply it:** copy the block's $\langle q\rangle{\bullet}\langle b\rangle$ into the cell. If $q = \textit{accept}$, **accept**.
> 4. **Move:** reset this cell's state code to $\langle\textit{reject}\rangle$ and write $\langle q\rangle$ into the neighboring cell in direction $\Delta$; at the right end, first append a fresh cell $[\langle\textit{reject}\rangle{\bullet}\langle\square\rangle]$, so the encoded tape behaves as if it were infinite. Then repeat. (If the head would move left from the first cell, $M$ crashes; then $U$ must not answer either — it can simply loop forever.)
>
> Initialization copies $\langle w\rangle$ into this format, with $\langle\textit{start}\rangle$ in the first cell.

So one fixed machine runs every program: a stored-program computer, described years before one was built. In Chapter 7, $U$ does two jobs. It shows that $\textsf{Accept} = \{\langle M,w\rangle \mid M \text{ accepts } w\}$ is acceptable — $U$ accepts it — and its ability to run a machine on any string, including the machine's own encoding, powers the self-referential arguments that make $\textsf{Accept}$ undecidable ([[1-models-of-computation/07-undecidability#74-code-is-data-data-is-code|§7.4]]). Chapter 8 replaces $U$ by much smaller universal systems.

## Summary

- A Turing machine is a finite control plus an unbounded tape: $\delta\colon (Q\setminus\{\textit{accept},\textit{reject}\})\times\Gamma\to Q\times\Gamma\times\{-1,+1\}$, configurations $(q,x,i)$, start $(\textit{start},w,0)$; a move left from cell 0 crashes.
- On each input a machine accepts, rejects, crashes or runs forever. "Rejects" is not the same as "does not accept".
- $M$ accepts $L$ if $\textsf{Accept}(M) = L$; $M$ decides $L$ if it also halts on every input. Acceptable = recognizable = r.e.; decidable = computable = recursive; every decidable language is acceptable, not conversely.
- Design machines in passes — scan, mark, walk back — with the left end marked; give a table plus an English meaning for every state; missing transitions reject. $\{\mathtt{0}^n\mathtt{1}^n\mathtt{0}^n\}$ is decidable in $O(n^2)$ time.
- All reasonable variants are equivalent: stay-put moves (states $Q\times\{0,1\}$), several halting states, two-way infinite tapes, tracks, heads, tapes. One head costs a $\Theta(t^2)$ slowdown, and that is unavoidable; two tapes cost only $O(t\log t)$.
- For functions: one halting state, the output is the final tape contents, and $M(w)\uparrow$ when $M$ diverges. The shift machine needs two states besides $\textit{halt}$, the increment machine three.
- Recursion and random-access memory cost only a polynomial slowdown, so Turing machines compute everything real programs compute.
- A universal machine $U$ accepts $\langle M,w\rangle$ iff $M$ accepts $w$ and rejects it iff $M$ rejects $w$, by stepping through an encoded configuration.
