> [!abstract] The day in one breath
> Two halves. First, one more reduction to reachability — is there a walk from $s$ to $t$ whose length is divisible by 3? — solved by building three copies of the graph, the technique called **graph layering**. Second, back to whatever-first search: with parent pointers it builds a tree, and the choice of bag decides which tree and at what cost — a queue gives breadth-first search, a priority queue gives Dijkstra's or Prim's algorithm, a stack gives **depth-first search**. The rest of the hour set up depth-first search for its applications: the recursive form, DFSAll, three facts, the clock with starting and finishing times, and the observation that a **back edge** means a cycle.

## What was covered, in order

1. **Recap** of Tuesday: reachability, whatever-first search, the useless states of a DFA.
2. **A second reduction: walks of length divisible by 3** — see the examples below. The tempting approach, modifying the search code to track lengths modulo 3, was rejected: you would then have to prove the modified algorithm correct. Build a new graph and call the standard algorithm instead.
3. **Graph layering.** When a problem looks like a standard graph problem but needs some extra information to be tracked, make several copies of the graph, one per value of that information, and connect them so that moving along an edge updates it. The same idea as taking a product of state sets in a language transformation. The black-box algorithm is then run on the new graph: "It doesn't care where the vertices came from." → [[2-algorithms/05-basic-graph-algorithms#state-in-the-vertices-walks-of-even-length|§5.7, state in the vertices]], [[concepts/graph-reductions]]
4. **Whatever-first search with parents.** Put pairs (parent, vertex) into the bag; when a vertex is marked, record its parent. The parent edges form a tree rooted at $s$ that contains every vertex $s$ can reach — in an undirected graph, a spanning tree of the component of $s$. Different bags give different trees, and the running time is $O(V + E\cdot T)$ for a bag whose operations take time $T$. → [[2-algorithms/05-basic-graph-algorithms#56-important-variants|§5.6]]
5. **A queue: breadth-first search.** Vertices are marked in order of their number of steps from $s$; the tree is a shortest-path tree for unweighted edges; $O(V + E)$. → [[2-algorithms/05-basic-graph-algorithms#queue-breadth-first|§5.6, queue]], [[concepts/breadth-first-search]]
6. **A priority queue: "best-first" search.** With non-negative edge weights and the priority of $u\to v$ set to the tree distance to $u$ plus $w(u\to v)$, this is **Dijkstra's algorithm** (correctness postponed to next week). In an undirected graph with priority $w(uv)$ alone, it is **Prim's algorithm** for minimum spanning trees — which the course will not cover this semester. With a binary heap: $O(V + E\log E) = O(V + E\log V)$ for a simple graph. → [[2-algorithms/05-basic-graph-algorithms#priority-queue-best-first|§5.6, priority queue]], [[concepts/dijkstras-algorithm]], [[concepts/minimum-spanning-trees]]
7. **A stack: depth-first search**, $O(V + E)$ — introduced as the one variant without a one-sentence motivation, so the lecture started from the algorithm and looked for problems afterwards. → [[2-algorithms/05-basic-graph-algorithms#stack-depth-first|§5.6, stack]]
8. **Recursive depth-first search and DFSAll.** DFS($v$): mark $v$; for every edge $v\to w$ with $w$ unmarked, set the parent of $w$ to $v$ and call DFS($w$). DFSAll: unmark everything, then call DFS on every vertex that is still unmarked, so that the whole graph is covered. $O(V + E)$. → [[2-algorithms/06-depth-first-search#60-depth-first-search-recursively|§6.0]], [[concepts/depth-first-search]]
9. **Three facts about DFSAll.** (1) Every vertex gets marked: DFS is called on every vertex. (2) Every vertex that $v$ can reach through unmarked vertices is marked before DFS($v$) returns. (3) If DFS($v$) calls DFS($w$), directly or indirectly, there is a path from $v$ to $w$.
10. **The clock.** DFS increments a clock when it starts a vertex ($v.\mathit{pre}$) and when it finishes it ($v.\mathit{post}$). The **active intervals** $[v.\mathit{pre}, v.\mathit{post}]$ of two vertices are disjoint or nested, never partly overlapping, because the calls sit on a stack. Sorting by starting time gives a preorder (said to be of little use in this course), by finishing time a **postorder** (the useful one). → [[2-algorithms/06-depth-first-search#61-preorder-and-postorder|§6.1]]
11. **Detecting cycles, first half.** Motivation: the dependency graph of a recursive algorithm must have no cycle, or the recursion never ends. If DFS($v$) has, directly or indirectly, called DFS($u$) and there is an edge $u\to v$, that edge is a **back edge** and closes a cycle. Which edges turn out to be back edges depends on the order of the loops. Whether the absence of back edges implies the absence of cycles was left for Tuesday. → [[2-algorithms/06-depth-first-search#62-detecting-cycles|§6.2]]

## Examples and problems worked in class

- **A walk of length divisible by 3.** Given a directed graph $G = (V, E)$ and vertices $s$ and $t$: is there a walk from $s$ to $t$ (vertices and edges may repeat) whose length is divisible by 3? Two inputs were shown. In the first the answer is yes: the shortest path has length 2, but $s\to w\to y\to x\to s\to w\to t$ has length 6. In the second there are infinitely many walks from $s$ to $t$ and none has length divisible by 3. The answer given in class:
  - *Graph:* $G' = (V', E')$ with $V' = V\times\{0, 1, 2\}$ and $E' = \{(u, i)\to(v, (i + 1)\bmod 3) \mid u\to v\in E\}$.
  - *Problem:* can $(s, 0)$ reach $(t, 0)$ in $G'$?
  - *Algorithm:* whatever-first search from $(s, 0)$; answer yes if and only if $(t, 0)$ is marked.
  - *Time:* $G'$ has $3V$ vertices and $3E$ edges, so $O(V + E)$.

  This is [[2-algorithms/05-basic-graph-algorithms-exercises#exercise-514--walks-of-length-divisible-by-3|Exercise 5.14]] on this site; [[3-homework-and-exams/lab-09a|Lab 9a]], Problem 3, is the same idea with 5 in place of 3.
- **A run of DFSAll** on a small directed graph, with vertices and edges taken in alphabetical order: the search from $a$ reaches $b, f, g, c, h, d$ along tree edges; a later call from $e$ starts a second tree. The active intervals of the same run were drawn as nested bars.
- **The dependency graph of Fibonacci again:** $F(8)$ needs $F(7)$ and $F(6)$; a cycle in such a graph would make the recursion run forever.

## What the instructor said about homework and exams

> [!quote] On modifying a standard algorithm instead of reducing to it
> "This idea could work in principle, but it's very dangerous because it's very easy to mess up when you're trying to modify the code of a non-trivial algorithm."

> [!quote] On when to use layering
> "Basically, if you have some problem that really looks like it involves a simple graph, something like reachability in a graph, or next week shortest paths, or this homework shortest paths, and you need to track some extra information, you probably want to use graph layering."

> [!exam] Points made about grading and scope
> - A whatever-first search with nothing else said is assumed to use a queue or a stack, "just so it's fast".
> - A reduction answer says what the new graph is (vertices, edges), what problem is solved on it and why that answers the question, which algorithm is called and what is done with the result, and the running time in terms of the original graph.
