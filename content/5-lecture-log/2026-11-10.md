> [!abstract] The day in one breath
> The first lecture after Midterm 2 turns the course around: instead of finding fast algorithms, argue that some problems probably have none. The setting is **decision problems** (yes-or-no questions), which lose nothing against optimization problems and are the same thing as **languages**. Since almost nothing can be proved impossible outright, hardness is argued by comparison: a **polynomial-time many-one reduction** — a Karp reduction — from $A$ to $B$, written $A\le_P B$, shows that $B$ is at least as hard as $A$. If $B$ has a polynomial-time algorithm then so does $A$; the course will use the contrapositive. The examples were **independent set**, **clique** and **vertex cover**, and the first reduction: independent set to clique, by complementing the graph, with both directions of its proof.

## What was covered, in order

1. **The course in three parts.** Models of computation (what can a computer do at all, asked about strings); algorithms (what can be done quickly); and now the reverse questions, in reverse order: which problems seem to have no fast algorithm, then which have no algorithm at all.
2. **Optimization problems and decision problems.** So far, mostly optimization: among the feasible solutions find the best, as in shortest paths. A **decision problem** has a yes-or-no answer: given a directed graph, two vertices and an integer $k$, is the distance from $s$ to $t$ at most $k$? Each kind solves the other: answer the decision question from the optimum, or find the optimum by asking the decision question for every $k$ from 0 to $V$. From here on: decision problems, because the interface is cleaner. → [[2-algorithms/12-np-hardness#122-p-versus-np|§12.2]], [[3-homework-and-exams/lab-12a|Lab 12a]]
3. **Decision problems are languages.** Encode the input as a string; the strings of the YES instances form a language $L_A$. Conversely, a language is the decision problem of whether a given string belongs to it. The two words will be used interchangeably — problems for the next two weeks, languages in the last week. → [[2-algorithms/12-np-hardness#124-formal-definitions|§12.4]], [[concepts/languages]]
4. **How to argue that a problem is hard.** There are very few ways to prove outright that something cannot be done fast: sorting by comparisons needs $n\log n$ time, but nobody can prove that shortest paths with negative edges need more than linear time. The tool that exists is comparison: show that the problem is at least as hard as one believed to be hard, by a reduction. → [[concepts/comparison-lower-bounds]], [[concepts/np-hardness]]
5. **Reductions, so far.** Solving one problem with a black box for another (useless states of a DFA by reachability), and recursion (a big instance by smaller ones).
6. **Many-one reductions.** A many-one reduction from a decision problem $A$ to a decision problem $B$ is an algorithm $f$ that turns every instance $x$ of $A$ into an instance $f(x)$ of $B$ with the same answer: $x$ is a YES instance of $A$ **if and only if** $f(x)$ is a YES instance of $B$. It has to be computable, it need not be one-to-one (many inputs may map to one output — hence the name) and it need not be onto.
7. **Karp reductions.** A many-one reduction that runs in time polynomial in the length of $x$. Notation: $A\le_P B$, read as: $A$ is no harder than $B$, up to a polynomial amount of extra work. → [[2-algorithms/12-np-hardness#125-reductions-and-sat|§12.5]], [[concepts/polynomial-time-reductions]]
8. **The lemma.** If $A\le_P B$ and $B$ has a polynomial-time algorithm, so does $A$: transform the input with $f$ and run the algorithm for $B$. If $f$ takes $\lvert x\rvert^c$ time, its output has length at most $\lvert x\rvert^c$; if the algorithm for $B$ takes $\lvert y\rvert^d$ time, the total is about $\lvert x\rvert^{cd}$ — polynomials compose.
9. **The contrapositive, which is the point.** If $A\le_P B$ and $A$ has **no** polynomial-time algorithm, then neither does $B$. So to argue that a new problem $B$ is hard, reduce a problem believed to be hard **to** it — backwards from six weeks of reducing new problems to familiar ones.
10. **Three problems.** Each takes an undirected graph $G$ and an integer $k\ge 0$. **Independent set:** is there a set of $k$ vertices no two of which share an edge? **Clique:** is there a set of $k$ vertices every two of which share an edge? **Vertex cover:** is there a set of $k$ vertices that touches every edge? (For the first two, large sets are the hard ones to find; for vertex cover, small ones.) No polynomial-time algorithm is known for any of them; the claim is that one for any of the three would give one for all three. → [[2-algorithms/12-np-hardness#127-maximum-independent-set-from-3sat|§12.7]], [[2-algorithms/12-np-hardness#129-clique-and-vertex-cover-from-independent-set|§12.9]], [[concepts/independent-set]]
11. **Independent set $\le_P$ clique** — see the examples below.
12. **Next time:** independent set to vertex cover, and the reason for believing that none of the three has a fast algorithm.

## Examples and problems worked in class

- **Shortest path as a decision problem:** "is the distance from $s$ to $t$ at most $k$?", and the two-way conversion with the optimization version.
- **One graph on eight vertices**, with an independent set of size 4, a clique of size 4 and a vertex cover marked on it.
- **Independent set reduces to clique.** The reduction given in class, for an instance $(G, k)$ of independent set with $G = (V, E)$:
  - *Construction:* $G' = (V, E')$ with the same vertices and $uv\in E'$ if and only if $uv\notin E$ — the complement graph — and $k' = k$.
  - *Time:* $O(V^2)$, checking every pair: polynomial.
  - *Claim:* $G$ has an independent set of size $k$ if and only if $G'$ has a clique of size $k'$.
  - *⇒* If $S$ is independent in $G$ with $\lvert S\rvert = k$, no two vertices of $S$ share an edge of $G$, so every two share an edge of $G'$: $S$ is a clique in $G'$.
  - *⇐* If $S'$ is a clique of size $k'$ in $G'$, every two of its vertices share an edge of $G'$, so none of those pairs is an edge of $G$: $S'$ is an independent set in $G$, of size $k$.

  The same construction reduces clique to independent set, which the instructor called very rare. On this site: [[2-algorithms/12-np-hardness#129-clique-and-vertex-cover-from-independent-set|§12.9]].
- A question from the class settled what a reduction may know: it transforms the input $(G, k)$ only. It does not know an independent set of $G$, or whether one exists.

> [!exam] The three things shown for a reduction
> In the instructor's summary of the example: the **algorithm** that transforms an instance of the first problem into an instance of the second; the statement that it **runs in polynomial time**; and the proof that it really is a many-one reduction, in **both directions** — YES instances become YES instances, and a YES instance that comes out of the reduction came from a YES instance ("this is an if and only if statement. We should show both halves, please"). These are the items of the [[0-toolkit/06-how-exams-are-graded#14-np-hardness|NP-hardness rubric]]; the boilerplate is [[0-toolkit/02-proof-templates#23-proving-a-problem-np-hard|template §23]].
