> [!abstract] The day in one breath
> Shortest paths beyond positive weights. Breadth-first search is the unit-weight case. With negative edges, Ford's algorithm is really looking for shortest *walks*, which exist — and are simple paths — exactly when no negative cycle can be reached. In a **dag** there are no cycles at all, and distances come from a dynamic program evaluated in **topological order**, in $O(V + E)$ time; a dynamic program that looks at *outgoing* edges, such as longest paths to $t$, is evaluated in **postorder** instead. For general graphs with negative edges but no negative cycles, the class built a dag of $V$ layers — one per number of edges used — and ran the dag algorithm on it: $O(VE)$ time, including a test for negative cycles. For homework and labs this may be called Bellman–Ford.

## What was covered, in order

1. **Recap** of Tuesday: Ford's $\mathit{dist}$ and $\mathit{pred}$, tense edges and relaxation; Dijkstra's two ideas and its $O(E\log V)$ time for positive weights. → [[5-lecture-log/2026-10-27|Tue Oct 27]]
2. **Breadth-first search as a shortest-path algorithm.** When every weight is 1, use a plain queue in place of the priority queue: initialize, push $s$, and repeatedly pull a vertex and relax its tense outgoing edges, pushing their heads. It examines vertices in the same order as Dijkstra's algorithm would. $O(V + E)$. → [[2-algorithms/08-shortest-paths#84-unweighted-graphs-breadth-first-search|§8.4]], [[concepts/breadth-first-search]]
3. **What negative edges change.** Ford's algorithm finds shortest *walks*. Finding shortest *simple paths* when negative cycles are present is NP-hard. With positive weights a shortest walk never repeats a vertex. If $s$ can reach a **negative cycle**, there is no shortest walk to the vertices on it (go around once more). If there is no negative cycle, cycles can be cut out of a walk without making it longer, so shortest walks exist and can be taken to be simple paths. The corrected claim from Tuesday: **if $G$ has no negative cycle, Ford's algorithm finds the distances and shortest paths** — with no promise about time. → [[2-algorithms/08-shortest-paths#82-negative-edges|§8.2]]
4. **Dijkstra's algorithm with negative edges.** The version from Tuesday, which puts a vertex back into the priority queue whenever its distance drops, is still Ford's algorithm and still correct without negative cycles; only its running-time analysis needed positive weights, and it can be very slow. The version often taught, which loads every vertex into the queue at the start and never reinserts, is always fast but can be **wrong** with even one negative edge. → [[2-algorithms/08-shortest-paths#negative-edges|§8.6, negative edges]]
5. **Shortest paths in a dag, by dynamic programming.** Let $\mathit{distance}(v)$ be the true distance from $s$ to $v$. A shortest path to $v$ has a last edge $u\to v$, so
   $$
   \mathit{distance}(v) = \begin{cases} 0 & \text{if } v = s,\\ \min_{u\to v}\bigl(\mathit{distance}(u) + w(u\to v)\bigr) & \text{otherwise.}\end{cases}
   $$
   The dependency graph of this recurrence is the reversal of $G$, so in a dag it can be memoized, evaluating the vertices **in topological order**. Time $O(V + E)$: not (number of subproblems) × (worst time per subproblem), because each edge is looked at in exactly one subproblem. The same algorithm in Ford's vocabulary: for each vertex in topological order, relax its incoming edges. → [[2-algorithms/08-shortest-paths#85-directed-acyclic-graphs-depth-first-search|§8.5]], [[concepts/dynamic-programming-on-dags]]
6. **A dynamic program that depends on outgoing edges: longest paths.** Let $\mathit{longest}(u)$ be the length of the longest path from $u$ to $t$ in a dag: 0 if $u = t$, and otherwise the maximum over edges $u\to v$ of $w(u\to v) + \mathit{longest}(v)$. Now $v$ must be solved before $u$ for every edge $u\to v$: evaluate the vertices **in postorder** (the reverse of a topological order). $O(V + E)$. → [[2-algorithms/06-depth-first-search#dynamic-programming-in-dags|§6.4, dynamic programming in dags]]
7. **Memoization is a postorder.** For any recursive algorithm, the dependency graph says which subproblem must be solved first; memoizing solves them in postorder of that graph. The nested loops of edit distance are a neat postorder that needs no search; memoized Fibonacci is literally a depth-first search returning its results in postorder. → [[2-algorithms/06-depth-first-search#64-memoization-and-dynamic-programming|§6.4]], [[concepts/memoization]]
8. **Which algorithm so far.** Positive weights: Dijkstra, $O(E\log V)$. All weights 1: breadth-first search, $O(V + E)$. A dag, any weights: the dag algorithm, $O(V + E)$. → [[2-algorithms/08-shortest-paths#which-algorithm-when|which algorithm when]]
9. **Negative edges and cycles, but no negative cycle: a reduction by layering** — see the examples below. Result: $O(VE)$ time.
10. **Detecting a negative cycle** with the same algorithm: copy the computed values into $\mathit{dist}$ and look at every edge once more. If any edge is tense, $s$ can reach a negative cycle; if none is, the values are the distances. Still $O(VE)$. → [[2-algorithms/08-shortest-paths#87-relax-all-the-edges-bellmanford|§8.7]], [[concepts/bellman-ford]]

## Examples and problems worked in class

- **Lab 10a, Problem 1, revisited** (shortest paths with a single negative edge, from the lab the day before). Most solutions split the problem into two shortest-path computations around the negative edge. The instructor's remark: plain Dijkstra, in the reinserting version, would have been correct as it stands, and with one negative edge each vertex re-enters the queue at most once, so the time is still $O(E\log V)$. → [[3-homework-and-exams/lab-10a|Lab 10a]], [[2-algorithms/08-shortest-paths-exercises#exercise-82--a-few-negative-edges|Exercise 8.2]]
- **The dag algorithm on a small example**, vertices drawn left to right in topological order: a vertex with incoming edges of weight 12 (from a vertex at distance 3) and 5 (from a vertex at distance 8) gets distance $\min(15, 13) = 13$.
- **Single-source longest paths in a dag** — the subroutine that was allowed in the lab of the previous Friday ([[3-homework-and-exams/lab-09b|Lab 9b]]).
- **Shortest paths with negative edges by layering.** The answer given in class, for a directed graph $G = (V, E)$ with weights $w$ and no negative cycle:
  - *Graph:* $G'$ with vertices $(v, i)$ for every vertex $v$ and every $i\in\{0, 1, \dots, V - 1\}$, and an edge $(u, i - 1)\to(v, i)$ of weight $w(u\to v)$ for every edge $u\to v$ and every $1\le i\le V - 1$. The second coordinate always increases, so $G'$ is a dag.
  - *Problem:* the distance in $G'$ from $(s, 0)$ to $(v, i)$ is the length of the shortest walk from $s$ to $v$ in $G$ with **exactly $i$ edges**. Without negative cycles a shortest walk is a path with at most $V - 1$ edges, so the distance from $s$ to $v$ in $G$ is the minimum over $i$ of these values ($\infty$ if $v$ is unreachable).
  - *Algorithm:* the dag shortest-path algorithm from $(s, 0)$, then a minimum over $i$ for every $v$.
  - *Time:* $G'$ has $V^2$ vertices and about $VE$ edges, so $O(VE)$ for a connected graph.

  The counts of walks with exactly $i$ edges are correct even when negative cycles exist; only the last step — that a shortest walk is a path — needs their absence.

> [!quote] On evaluation orders in dags
> "If your dependencies are based on incoming edges, make sure to go in topological order. And if your dependencies are based on outgoing edges, make sure to go in post-order."

> [!exam] Points made about write-ups
> - **"For all vertices $v$ in topological order"** is an acceptable line in a dynamic program on a dag — "it's fine if you just write that line down" — and so is "for all vertices in post-order": computing the order first is assumed and does not change the running time.
> - You may cite Bellman–Ford as a black box: it runs in $O(VE)$ time and can detect a negative cycle.
> - If you need shortest paths with a few negative edges, the reinserting version of Dijkstra's algorithm is still correct; the preloaded version is not. "You need to be willing to put things back in there in order for Dijkstra's to always be right, even with negative weight edges."
