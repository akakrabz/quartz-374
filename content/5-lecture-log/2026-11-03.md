> [!abstract] The day in one breath
> The last algorithms lecture before Midterm 2, and two more uses of dynamic programming. **Bellman–Ford:** the recurrence that defines the distance to $v$ through its best last edge loops on a cycle, so add a parameter — $\mathit{dist}_{\le i}(v)$, the shortest walk from $s$ to $v$ with **at most $i$ edges** — which gives an $O(VE)$ dynamic program; three small simplifications turn it into the familiar loop — $V - 1$ rounds, each relaxing every tense edge. **All-pairs shortest paths:** running a single-source algorithm from every vertex costs up to $O(V^4)$ with negative edges; counting edges does no better; halving the number of edges gives $O(V^3\log V)$; and restricting which vertices a path may pass through gives **Floyd–Warshall**, $O(V^3)$. For the exam, these algorithms are black boxes.

## What was covered, in order

1. **Recap** of Thursday: negative edges are fine without negative cycles; the dag case; the layered reduction — whose $O(VE)$ time was, until a couple of years ago, thought to be the best possible for negative weights, but which is not how the algorithm is usually presented and stores the whole layered graph. → [[5-lecture-log/2026-10-29|Thu Oct 29]]
2. **Why the dag recurrence fails in general.** $\mathit{distance}(v) = \min_{u\to v}(\mathit{distance}(u) + w(u\to v))$ depends on itself around every cycle: the dependency graph contains the reversal of every cycle of $G$. A recurrence needs a parameter that moves toward a base case.
3. **A parameter that counts edges.** $\mathit{dist}_{\le i}(v)$ is the smallest length of a walk from $s$ to $v$ with **at most $i$ edges** (Thursday's layers used *exactly* $i$). Either the best such walk uses at most $i - 1$ edges, or it has a last edge $u\to v$ after a walk to $u$ with at most $i - 1$ edges:
   $$
   \mathit{dist}_{\le i}(v) = \begin{cases} 0 & \text{if } i = 0 \text{ and } v = s,\\ \infty & \text{if } i = 0 \text{ and } v\ne s,\\ \min\Bigl\{\mathit{dist}_{\le i-1}(v),\ \min_{u\to v}\bigl(\mathit{dist}_{\le i-1}(u) + w(u\to v)\bigr)\Bigr\} & \text{otherwise.}\end{cases}
   $$
   Without negative cycles a shortest walk is a path, so the distance is $\mathit{dist}_{\le V-1}(v)$. The recurrence itself is true even with negative cycles. → [[2-algorithms/08-shortest-paths#dynamic-programming-formulation|§8.7, dynamic programming formulation]]
4. **The dynamic program** (attributed to Bellman): a table indexed by $i$ and by vertex, filled for $i$ from 0 up to $V - 1$, vertices in any order. Each value of $i$ looks at every edge once: $O(VE)$ time, $O(V^2)$ space.
5. **Three simplifications.** (a) Move the loop over edges outside the loop over vertices: first copy row $i - 1$ into row $i$, then go through all edges in any order. (b) Read $\mathit{dist}[i, u]$ instead of $\mathit{dist}[i - 1, u]$: the values can only be smaller, and are still lengths of actual walks. (c) Now the index $i$ only copies rows, so drop it and overwrite one array. In Ford's vocabulary the result is: initialize; **repeat $V - 1$ times: for every edge, if it is tense, relax it**; then check every edge once more, and report a negative cycle if one is still tense. "This is what people usually call the Bellman-Ford algorithm." $O(VE)$ time. → [[2-algorithms/08-shortest-paths#87-relax-all-the-edges-bellmanford|§8.7]], [[concepts/bellman-ford]]
6. **A reminder** to always use the best algorithm for the weights and structure at hand (the four cases reviewed on Thursday). → [[2-algorithms/08-shortest-paths#which-algorithm-when|which algorithm when]]
7. **All-pairs shortest paths.** Compute $\mathit{dist}(u, v)$ for every pair of vertices — the table of distances between cities on a paper map. First idea: a single-source algorithm from every vertex. With positive weights, Dijkstra $V$ times: $O(VE\log V)$, which is $O(V^3\log V)$ for a dense graph. With negative edges, Bellman–Ford $V$ times: $O(V^2E)$, up to $O(V^4)$. Johnson's algorithm (Bellman–Ford once, reweight the edges so that all are non-negative, then Dijkstra from every vertex) was mentioned and recommended as reading, but not covered. → [[2-algorithms/09-all-pairs-shortest-paths#92-lots-of-single-sources|§9.2]], [[concepts/all-pairs-shortest-paths]], [[concepts/johnsons-algorithm]]
8. **Dynamic programming, counting edges.** $\mathit{dist}(u, v, \ell)$, the shortest walk from $u$ to $v$ with at most $\ell$ edges, by the same last-edge recurrence — an algorithm credited to Shimbel (1954). After the same clean-up it runs in $O(V^2E)$ time, up to $O(V^4)$: it is Bellman–Ford from every source with the loops interleaved, and does not exploit that all pairs are computed together. → [[2-algorithms/09-all-pairs-shortest-paths#95-dynamic-programming|§9.5]]
9. **Halving the number of edges.** Guess a vertex $x$ in the *middle* of the walk instead of its last edge: $\mathit{dist}(u, v, \ell) = \min_x\bigl(\mathit{dist}(u, x, \ell/2) + \mathit{dist}(x, v, \ell/2)\bigr)$, with the edge weight (or $\infty$ if there is no edge) as the case $\ell = 1$. Only powers of two are needed, so there are about $\log V$ rounds of $O(V^3)$ work: $O(V^3\log V)$. The pseudocode was shown from the book, which calls it Fischer–Meyer. It matches repeated Dijkstra on dense graphs although it allows negative edges. → [[2-algorithms/09-all-pairs-shortest-paths#96-divide-and-conquer|§9.6]]
10. **Floyd–Warshall.** Number the vertices 1 to $V$, and let $\mathit{dist}(u, v, r)$ be the length of the shortest path from $u$ to $v$ that **passes through only vertices numbered at most $r$**. Either the path avoids vertex $r$, or it goes from $u$ to $r$ and from $r$ to $v$ through vertices numbered below $r$ — no guessing:
    $$
    \mathit{dist}(u, v, r) = \begin{cases} w(u\to v) & \text{if } r = 0,\\ \min\bigl\{\mathit{dist}(u, v, r - 1),\ \mathit{dist}(u, r, r - 1) + \mathit{dist}(r, v, r - 1)\bigr\} & \text{otherwise.}\end{cases}
    $$
    The answer is $\mathit{dist}(u, v, V)$. Three nested loops, $r$ outermost, constant work inside: $O(V^3)$. Dropping the third index as before leaves the usual three-line algorithm. The structure of this dynamic program is older than its use for shortest paths: it is the one that turns an NFA into a regular expression in the proof of Kleene's theorem. → [[2-algorithms/09-all-pairs-shortest-paths#98-floydwarshall|§9.8]], [[concepts/floyd-warshall]], [[concepts/kleenes-theorem]]
11. **Closing remark.** There have been recent research improvements for shortest paths with negative weights and for all pairs; they are not needed for this class, and pointers were promised on the course Discord and in the lecture notes.
