## What was covered, in order

1. **Recap** of depth-first search with a clock: DFSAll, $v.\mathit{pre}$ and $v.\mathit{post}$, postorders, and the fact that DFS($u$) reaches every vertex that $u$ can reach through unmarked vertices. → [[5-lecture-log/2026-10-22|Thu Oct 22]], [[2-algorithms/06-depth-first-search#61-preorder-and-postorder|§6.1]]
2. **A back edge means a cycle** (from Thursday): if DFS($v$) has indirectly called DFS($u$) and $u\to v$ is an edge, the path of recursive calls from $v$ down to $u$ plus that edge is a directed cycle.
3. **A cycle means a back edge.** Proof sketch: let $C$ be a cycle, $v$ the first vertex of $C$ that DFSAll calls DFS on, and $u$ the vertex just before $v$ on $C$. When DFS($v$) starts, the rest of $C$ is unmarked, so DFS($v$) will, perhaps indirectly, call DFS($u$); then $u\to v$ is a back edge. So $G$ has a cycle if and only if DFSAll finds a back edge — and on every cycle some edge becomes a back edge, though which one depends on the order of the loops. → [[2-algorithms/06-depth-first-search#62-detecting-cycles|§6.2]]
4. **Testing for back edges with the clock.** Erickson's book keeps a status (new, active, finished) at each vertex. The lecture used finishing times instead: for an edge $u\to v$, a back edge means $v.\mathit{pre} < u.\mathit{pre} < u.\mathit{post} < v.\mathit{post}$, and because intervals never partly overlap and DFS($u$) cannot finish before $v$ has been started, it is enough to test $u.\mathit{post} < v.\mathit{post}$. Algorithm: run DFSAll with the clock, then look at every edge; if some edge has $u.\mathit{post} < v.\mathit{post}$ the graph has a cycle, otherwise it is acyclic. $O(V + E)$. → [[2-algorithms/06-depth-first-search#classifying-vertices-and-edges|§6.1, classifying edges]]
5. **Topological order.** A total order of the vertices in which $u$ comes before $v$ for every edge $u\to v$. A graph with a cycle has none. In a graph without cycles every edge $u\to v$ has $v.\mathit{post} < u.\mathit{post}$, so **the reverse of a postorder is a topological order**, computed in $O(V + E)$ time. (A dependency graph wants the opposite order — solve $v$ before $u$ — which is where dynamic programming comes in on Thursday.) → [[2-algorithms/06-depth-first-search#63-topological-sort|§6.3]], [[concepts/topological-sort]]
6. **Single-source shortest paths.** A directed graph with a real weight on every edge — positive, zero or negative. The distance from $s$ to $t$ is the smallest total weight of a path from $s$ to $t$. Every algorithm the instructor knows of for one distance finds the distances from $s$ to *all* vertices, so that is the problem: SSSP. Negative weights are meaningful (Friday's lab and the homework use them); **today the weights are positive**. → [[2-algorithms/08-shortest-paths#81-shortest-path-trees|§8.1]], [[concepts/shortest-paths]]
7. **Shortest-path trees.** Every subpath of a shortest path is a shortest path. So if two shortest paths from $s$ split and rejoin, one of the two detours can be dropped; doing this repeatedly leaves a tree rooted at $s$. The goal: every distance from $s$, and this tree.
8. **Ford's generic algorithm** (Lester Ford, 1956). Every vertex stores $v.\mathit{dist}$, the length of *some* path from $s$ to $v$ or $\infty$, and $v.\mathit{pred}$, the vertex before $v$ on that path. Start with $s.\mathit{dist} = 0$ and everything else $\infty$, all predecessors empty. An edge $u\to v$ is **tense** if $u.\mathit{dist} + w(u\to v) < v.\mathit{dist}$; to **relax** it, set $v.\mathit{dist}$ to that sum and $v.\mathit{pred}$ to $u$. Repeat: find a tense edge, relax it. Stated without proof: with positive weights this stops, and when it stops every $v.\mathit{dist}$ is the true distance — but with a bad choice of edges it can take exponential time. → [[2-algorithms/08-shortest-paths#83-the-only-sssp-algorithm|§8.3]]
9. **Dijkstra's algorithm**, from two observations. An edge $u\to v$ that is not tense can become tense only when $u.\mathit{dist}$ drops, so it is enough to remember the vertices whose distance just dropped, as in whatever-first search. And with positive weights the best vertex to process is the one with the smallest $\mathit{dist}$. So: initialize; insert $s$ into a priority queue with key 0; while the queue is not empty, extract the vertex $u$ with the smallest key, and for every tense edge $u\to v$ relax it and either decrease the key of $v$ (if $v$ is in the queue) or insert $v$. The queue is *not* loaded with all vertices at the start. → [[2-algorithms/08-shortest-paths#86-best-first-dijkstras-algorithm|§8.6]], [[concepts/dijkstras-algorithm]]
10. **Its running time.** With positive weights the keys come out of the queue in increasing order, and distances only decrease, so no vertex is extracted twice: at most $V$ insertions and extractions, and each edge is examined once. With a binary heap, $O(E\log V)$ for a connected simple graph ($\log E\le 2\log V$). → [[2-algorithms/08-shortest-paths#no-negative-edges|§8.6, no negative edges]]
