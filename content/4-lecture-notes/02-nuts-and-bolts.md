> [!abstract] In one breath
> You have $n$ nuts and $n$ bolts of distinct sizes, each nut fitting exactly one bolt, and the only possible test compares a nut with a bolt: too big, too small, or just right. Matching them is sorting in disguise, and the natural algorithm is **quicksort**: test a pivot bolt against every nut, test the nut that fits it against every other bolt, and recurse on the smaller and the larger pairs — $2m - 1$ tests for $m$ pairs, and $n^2$ tests in the worst case. With the pivot bolt chosen **uniformly at random**, the expected number of tests is exactly $4nH_n - 7n + 4H_n = \Theta(n\log n)$ for **every** input, because the randomness is in the algorithm, not in the data. The note derives this three ways: a quick but not quite rigorous "good pivot" recurrence; an exact **indicator-variable** argument — bolt $i$ and nut $j$ are compared exactly when the first pivot chosen among the sizes between them is $i$ or $j$, which has probability $2/(\lvert i-j\rvert+1)$; and a brute-force solution of the full-history recurrence. Along the way it defines worst-case expected running time and solves the warm-up problem of finding one bolt's nut in $(n+1)/2 - 1/n$ expected tests.

## 2.1 Nuts and bolts

The problem (Gregory Rawlins, around 1992): given $n$ nuts and $n$ bolts of distinct sizes, where each nut matches exactly one bolt, match every nut to its bolt. The sizes are too close to compare two nuts or two bolts by eye; the only operation is a **test** of one nut against one bolt, which says whether the nut is too big, too small, or just right.

A warm-up: **find the nut that fits one given bolt.** Test the nuts one at a time until one fits. If the first $n - 1$ tests all fail, the last nut must be the match and need not be tested, so this takes **exactly $n - 1$ tests in the worst case**. "On average" it should take about $n/2$ — but averaged over what?

## 2.2 Deterministic vs. randomized algorithms

> [!definition] Definition — three running times
> The **worst-case** running time of an algorithm is the maximum over all inputs $X$ of size $n$:
> $$
> T_{\text{worst-case}}(n) = \max_{\lvert X\rvert = n} T(X).
> $$
> The **average-case** running time is an expectation over inputs drawn from some distribution: $T_{\text{average-case}}(n) = \sum_{\lvert X\rvert = n}T(X)\cdot\Pr[X]$. A **randomized** algorithm makes random choices, so its running time $T(X)$ on a fixed input is a random variable; its **worst-case expected** running time is
> $$
> T_{\text{worst-case expected}}(n) = \max_{\lvert X\rvert = n}\operatorname{E}[T(X)].
> $$

The trouble with the average case is the distribution: we rarely know how likely each input is, and "all inputs equally likely" describes real data badly — real data is random, if at all, in unpredictable ways. A **deterministic** algorithm always performs the same computation on the same input; a **randomized** one also bases its behavior on random choices, so it may compute differently each time it runs. Worst-case expected time makes **no assumption about the input**: the expectation is over the algorithm's own coins, which we control, and the maximum is over all inputs.

## 2.3 Back to nuts and bolts

Randomize the warm-up: at each step, test a nut chosen uniformly at random from the untested ones.

```text
FindMatch(b, N):         ⟨⟨bolt b; nuts N, one of which fits b⟩⟩
    while |N| > 1
        remove a uniformly random nut x from N
        if x fits b                  ⟨⟨one test⟩⟩
            return x
    return the last nut in N         ⟨⟨no test needed⟩⟩
```

Let $T(n)$ be the number of tests with $n$ nuts. Because the order is random, the input (even the order in which the nuts are given) does not matter, so $T$ depends only on $n$: $T(1) = 0$, $T(2) = 1$, and for $n\ge 2$, $T(n)$ is a random variable between 1 and $n - 1$. The matching nut is equally likely, with probability $1/n$, to be the $k$th nut drawn for each $k$, and if it is the $k$th the algorithm makes $\min\{k, n - 1\}$ tests. Hence
$$
\Pr[T(n) = k] = \begin{cases}1/n & \text{if } 1\le k<n-1,\\ 2/n & \text{if } k = n-1,\end{cases}
$$
and therefore
$$
\operatorname{E}[T(n)] = \sum_{k=1}^{n-2}\frac kn + \frac{2(n-1)}{n} = \sum_{k=1}^n\frac kn - \frac1n = \frac{n+1}{2} - \frac1n.
$$

**The same answer recursively.** The first test always happens; with probability $1/n$ it finds the match, and otherwise (probability $1 - 1/n$) the algorithm faces the same problem with $n - 1$ nuts:
$$
\operatorname{E}[T(1)] = 0,\qquad \operatorname{E}[T(n)] = 1 + \frac{n-1}{n}\operatorname{E}[T(n-1)].
$$
Multiplying by $n$, the function $t(n) = n\operatorname{E}[T(n)]$ satisfies $t(1) = 0$ and $t(n) = n + t(n-1)$, so $t(n) = \sum_{k=2}^n k = n(n+1)/2 - 1$ and again $\operatorname{E}[T(n)] = t(n)/n = (n+1)/2 - 1/n$.

## 2.4 Finding all matches

Three algorithms for matching all $n$ pairs, by worst-case number of tests:

- **Test every nut against every bolt**: $n^2$ tests.
- **Repeat the warm-up**: find the nut for one bolt among the $i$ remaining nuts, $i - 1$ tests, and remove the pair; in the worst case $\sum_{i=1}^n(i-1) = (n^2 - n)/2$ tests — only a factor of 2 better.
- **Rawlins' partitioning**, quicksort with a pivot pair:

```text
MatchNutsAndBolts(B, N):    ⟨⟨equal-size sets of bolts and nuts⟩⟩
    if B = ∅
        return
    b ← a pivot bolt in B                ⟨⟨random from §2.6 on⟩⟩
    test b against every nut in N        ⟨⟨|N| tests⟩⟩
    x ← the nut that fits b
    test x against every other bolt      ⟨⟨|B| − 1 tests⟩⟩
    output the pair (b, x)
    MatchNutsAndBolts(bolts < x, nuts < b)
    MatchNutsAndBolts(bolts > x, nuts > b)
```

(The note describes the algorithm in words; the pseudocode is ours.) A subproblem with $m$ pairs costs $2m - 1$ tests, and the two recursive calls get the $k - 1$ pairs smaller and the $n - k$ pairs larger than a pivot of rank $k$. The algorithm not only matches the pairs, it **sorts** them: the output pairs come in increasing order of size. With an adversarial pivot,
$$
T(n) = 2n - 1 + \max_{1\le k\le n}\big(T(k-1) + T(n-k)\big) = 2n - 1 + T(n-1),\qquad T(0) = 0,
$$
so $T(n) = \sum_{i=1}^n(2i - 1) = n^2$: **in the worst case it tests every nut against every bolt.** (The note prints the sum as $\sum_{i=1}^n(2n-1)$, which is $n(2n-1)$; the summand should be $2i - 1$.) Skipping tests whose outcome is already known — for instance, when every other nut turns out to be larger than the pivot bolt, no bolt needs to be tested against the pivot nut — does not help much: each partition must still test the pivot bolt against the other $m - 1$ nuts, so a pivot that is always the smallest bolt still costs at least $\sum_{m=1}^n(m - 1) = n(n-1)/2\approx n^2/2$ tests.

Since the algorithm is quicksort, and quicksort is "known" to take $\Theta(n\log n)$ time on average, one expects $\Theta(n\log n)$ tests on average — and that is exactly right **if the pivot bolt is chosen uniformly at random**, for every input.

## 2.5 Reductions to and from sorting

Matching nuts and bolts and sorting them are equivalent up to $O(n\log n)$ extra tests:

- **Sorting ⇒ matching.** If the bolts are sorted, each nut finds its bolt by binary search, at most $\lfloor\log_2 n\rfloor + 1$ tests per nut: $O(n\log n)$ in all.
- **Matching ⇒ sorting.** If the pairs are matched, mergesort the pairs, comparing two pairs by testing the bolt of one against the nut of the other: $O(n\log n)$ tests.

So an $O(n\log n)$ algorithm for either problem gives one for the other. But since no two bolts (or nuts) can be compared directly, heapsort or mergesort cannot simply be run on the bolts. A deterministic $O(n\log n)$ algorithm exists — Komlós, Ma and Szemerédi (SIAM J. Discrete Math. 1998), and a slightly simpler one by Bradford (1995) — but both algorithms and analyses are very technical and the hidden constants are large. The randomized algorithm is simple.

## 2.6 Recursive analysis

From now on the pivot bolt is chosen **uniformly at random** from the subproblem's bolts, so its rank $k$ is uniform on $\{1,\ldots,n\}$. Write $\overline T(n)$ for the expected number of tests on $n$ pairs (it does not depend on the input order). By total expectation over the rank of the pivot,
$$
\overline T(n) = 2n - 1 + \frac1n\sum_{k=1}^n\big(\overline T(k-1) + \overline T(n-k)\big),\qquad \overline T(0) = 0.
$$
(So $\overline T(1) = 1$: the lone bolt is tested against its nut. Setting $\overline T(1) = 0$ would save a few tests but complicates the algebra.)

**A conservative argument.** Call a pivot **good** if it lies in the middle half: at least $n/4$ bolts smaller and at least $n/4$ larger. A random pivot is good with probability $1/2$ (exactly, when $n$ is a multiple of 4), and then the larger subproblem has at most $3n/4$ pairs; a bad pivot is still no worse than starting over. So
$$
\overline T(n)\le 2n - 1 + \frac12\Big(\overline T\big(\tfrac{3n}4\big) + \overline T\big(\tfrac n4\big)\Big) + \frac12\overline T(n)
\quad\Longrightarrow\quad
\overline T(n)\le 4n - 2 + \overline T\big(\tfrac{3n}4\big) + \overline T\big(\tfrac n4\big).
$$
In its [[2-algorithms/01-recursion#17-recursion-trees|recursion tree]] every level sums to at most $4n$ and there are $\log_{4/3}n = O(\log n)$ levels, so $\overline T(n) = O(n\log n)$; a similar argument gives $\Omega(n\log n)$.

> [!warning] Not a proof
> The two "worst case" steps — a good pivot is at worst a $3n/4$ : $n/4$ split, a bad pivot at worst a restart — assume that $\overline T$ is **convex**, $\overline T(n+1) + \overline T(n-1)\ge 2\overline T(n)$, which has not been proved. It is true (the closed form of §2.7 has second difference exactly $4/(n+1) > 0$), but using the closed form to justify the argument that was supposed to find it would be circular, and proving convexity directly is about as hard as solving the recurrence. The bound is also loose: this recurrence grows like $7.1\,n\ln n$, while the truth is $4\,n\ln n$.

## 2.7 Iterative analysis

The recursive calls of quicksort form a binary tree of subproblems, and the usual recursion solves them depth-first, left before right. **Any order in which every subproblem comes after its parent performs the same tests.** So run the algorithm iteratively: pick a pivot bolt, find its nut and partition; pick a second pivot bolt and partition whichever subset contains it; and so on — each pivot adds one matched pair and one more subset — until every bolt has been a pivot.

If each new pivot is chosen **uniformly at random among the bolts that have not been pivots**, then, whichever subset contains it, it is uniform within that subset — exactly the distribution of the recursive algorithm. By induction the iterative algorithm performs the same set of tests as the recursive one, with the same probabilities, possibly in a different order. Equivalently: **the pivot order is a uniformly random permutation of the bolts.**

Let $B_i$ be the $i$th smallest bolt and $N_j$ the $j$th smallest nut, and let $X_{ij}$ be the indicator that the algorithm tests $B_i$ against $N_j$. No pair is tested twice, so the number of tests is $T(n) = \sum_{i=1}^n\sum_{j=1}^n X_{ij}$, and by linearity of expectation
$$
\operatorname{E}[T(n)] = \sum_{i=1}^n\sum_{j=1}^n\operatorname{E}[X_{ij}] = \sum_{i=1}^n\sum_{j=1}^n\Pr[X_{ij} = 1].
$$

> [!key] Key lemma — when are $B_i$ and $N_j$ tested?
> For $i\ne j$: the algorithm tests $B_i$ against $N_j$ **if and only if the first pivot chosen from $\{B_{\min(i,j)},\ldots,B_{\max(i,j)}\}$ is $B_i$ or $B_j$**. These $\lvert i-j\rvert + 1$ bolts are equally likely to come first, so
> $$
> \operatorname{E}[X_{ij}] = \frac{2}{\lvert i-j\rvert + 1}\quad(i\ne j),\qquad X_{ii} = 1.
> $$

> [!proof]- Proof (click to expand)
> Take $i<j$ (the other case is symmetric). Every test involves the current pivot bolt or its nut and an item of the same subset. As long as no bolt of rank between $i$ and $j$ has been a pivot, $B_i$ and $N_j$ lie in the same subset, because each earlier pivot is smaller or larger than both. Consider the first pivot $B_k$ with $i\le k\le j$. If $i<k<j$, then $B_i$ is smaller and $N_j$ larger than the pivot pair, they go to different subsets, and they are never tested against each other (they were not before: neither was a pivot or a pivot's nut). If $k = i$, the pivot bolt $B_i$ is tested against every nut in its subset, including $N_j$. If $k = j$, the pivot's nut $N_j$ is tested against every other bolt in its subset, including $B_i$. Finally $X_{ii} = 1$ because every bolt is a pivot once and is tested against its own nut. $\square$

Adding up — the diagonal gives $n$, and the pairs $(i,j)$ and $(j,i)$ have the same probability:
$$
\begin{aligned}
\operatorname{E}[T(n)] &= n + 4\sum_{i=1}^n\sum_{j=i+1}^n\frac1{j-i+1}
= n + 4\sum_{i=1}^n\sum_{k=2}^{n-i+1}\frac1k
= n + 4\sum_{k=2}^n\frac{n-k+1}{k}\\
&= n + 4\Big((n+1)\sum_{k=2}^n\frac1k - (n-1)\Big)
= n + 4\big((n+1)(H_n - 1) - (n-1)\big),
\end{aligned}
$$
substituting $k = j - i + 1$ and then exchanging the order of summation.

> [!key] Expected number of tests
> With uniformly random pivot bolts, on every input of $n$ pairs,
> $$
> \operatorname{E}[T(n)] = 4nH_n - 7n + 4H_n = \Theta(n\log n)\qquad(\approx 4n\ln n).
> $$
> For example 1, 4, $25/3$ and $41/3$ tests for $n = 1, 2, 3, 4$, and $2929/70\approx 41.84$ for $n = 8$, against $n^2 = 64$ in the worst case.

> [!trap] Analysis traps
> - **What is random is the pivot order, not the input.** The bound holds for every arrangement of nuts and bolts; nothing is assumed about the data.
> - **$X_{ij}$ is not independent of $X_{i'j'}$**, and linearity does not care.
> - **The event is about the first pivot among the sizes from $i$ to $j$**, not among all bolts: a pivot outside that range does not separate $B_i$ from $N_j$.

## 2.8 Masochistic analysis

The note stars this section as optional ("this won't be on the test"): it solves the recurrence of §2.6 exactly, by two "magic steps", and gets the same answer.

> [!derivation]- The derivation (click to expand)
> Combine the symmetric terms and multiply by $n$:
> $$
> \overline T(n) = \frac2n\sum_{k=0}^{n-1}\overline T(k) + 2n - 1,\qquad n\overline T(n) = 2\sum_{k=0}^{n-1}\overline T(k) + 2n^2 - n.
> $$
> **Magic step 1: turn full history into limited history** by subtracting the same equation for $n - 1$, $(n-1)\overline T(n-1) = 2\sum_{k=0}^{n-2}\overline T(k) + 2n^2 - 5n + 3$:
> $$
> n\overline T(n) - (n-1)\overline T(n-1) = 2\overline T(n-1) + 4n - 3,\qquad\text{so}\qquad \overline T(n) = \frac{n+1}{n}\overline T(n-1) + 4 - \frac3n.
> $$
> **Magic step 2: divide by $n + 1$.** With $t(n) = \overline T(n)/(n+1)$ and $t(0) = 0$, and partial fractions $\frac{1}{n(n+1)} = \frac1n - \frac1{n+1}$,
> $$
> t(n) = t(n-1) + \frac4{n+1} - \frac3{n(n+1)} = t(n-1) + \frac7{n+1} - \frac3n,
> $$
> a recurrence that is just a sum:
> $$
> t(n) = \sum_{i=1}^n\Big(\frac7{i+1} - \frac3i\Big) = 7(H_{n+1} - 1) - 3H_n = 4H_n - 7 + \frac7{n+1},
> $$
> using $H_{n+1} = H_n + \frac1{n+1}$. Multiplying back, $\overline T(n) = (n+1)t(n) = 4(n+1)H_n - 7(n+1) + 7 = 4nH_n - 7n + 4H_n$. $\square$

## Quicksort and quickselect

Rawlins' algorithm *is* randomized quicksort with a costlier partition: $2m - 1$ tests instead of the $m - 1$ comparisons of Partition in [[2-algorithms/01-recursion#15-quicksort|§1.5]]. The key lemma holds verbatim for quicksort with a uniformly random pivot: the elements of ranks $i<j$ are compared exactly when the first pivot among ranks $i,\ldots,j$ is one of them, with probability $2/(j-i+1)$, and each pair is compared at most once. So the expected number of comparisons of randomized quicksort, on every input of $n$ distinct elements, is (not in the note)
$$
\sum_{1\le i<j\le n}\frac2{j-i+1} = 2(n+1)H_n - 4n\approx 2n\ln n\approx 1.39\,n\log_2 n,
$$
and the nuts-and-bolts count is $n$ plus twice it. This makes Chapter 1's remark about random pivots precise in expectation — in contrast with the textbook's "average case", which assumes a random input order. (The book claims more, $O(n\log n)$ time with high probability; that needs a tail bound, [[4-lecture-notes/04-tail-inequalities|note 4]].)

The note's Exercise 5 asks for the same analysis of **quickselect** with a random pivot ([[2-algorithms/01-recursion#18-linear-time-selection|§1.8]]): the probability that it compares the $i$th and $j$th smallest elements, and a proof that its expected running time is $\Theta(n)$ for every $k$ — the randomized alternative to the median of medians.

## Summary

- Nuts and bolts: tests compare one nut with one bolt (too big, too small, fits); no two nuts or two bolts can be compared. Matching is equivalent to sorting up to $O(n\log n)$ tests; deterministic $O(n\log n)$ exists but is complicated.
- Worst-case expected time $= \max_{\text{inputs}}\operatorname{E}[\text{time}]$: randomness from the algorithm, no assumption about inputs (unlike average case).
- One bolt among $n$ nuts in random order: $\Pr[T = k] = 1/n$ for $k<n-1$, $2/n$ for $k = n-1$; $\operatorname{E}[T(n)] = (n+1)/2 - 1/n$ (also from $\operatorname{E}[T(n)] = 1 + \frac{n-1}n\operatorname{E}[T(n-1)]$).
- Partitioning around a pivot pair costs $2m - 1$ tests; worst case $T(n) = 2n-1+T(n-1) = n^2$.
- Random pivot: $\overline T(n) = 2n - 1 + \frac1n\sum_k(\overline T(k-1) + \overline T(n-k))$; good pivots (middle half, probability $\approx 1/2$) give $O(n\log n)$ if one assumes convexity.
- Exact: $B_i$ meets $N_j$ iff the first pivot among sizes $i..j$ is $i$ or $j$, probability $2/(\lvert i-j\rvert+1)$; by linearity $\operatorname{E}[T(n)] = 4nH_n - 7n + 4H_n = \Theta(n\log n)$, confirmed by solving the recurrence ($t(n) = \overline T(n)/(n+1)$).
- Randomized quicksort: $2(n+1)H_n - 4n\approx 1.39\,n\log_2 n$ expected comparisons on every input.
- The note ends with 10 exercises (a random second-minimum, choosing the largest bolt, Pareto-optimal points, reservoir sampling from a stream, randomized quickselect, the median of a sorted matrix, search in a sorted linked list, and randomized evaluation of game trees and majority trees).
