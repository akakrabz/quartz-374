> [!abstract] In one breath
> Once a dynamic program works, its table usually has more structure than the recurrence uses, and exploiting it saves space or time. **Space (D.1):** Hirschberg's trick computes, along with the edit distance, *where* an optimal alignment crosses the middle row, then recurses on the two halves; the recursive calls cost about as much as the first pass, so an optimal **alignment** — not just its cost — takes $O(mn)$ time and $O(m+n)$ space. **Sparseness (D.2):** an LCS table is determined by its $K$ **match points**, giving $O(m\log m + n\log n + K^2)$ time. **Monotonicity (D.3–D.4):** the optimal roots of optimal binary search trees move monotonically (Knuth), which cuts the $O(n^3)$ algorithm to $O(n^2)$; more generally the row minima of a **monotone** array can be found in $O(m + n\log m)$ time. **Total monotonicity (D.5–D.7):** if every $2\times2$ subarray is monotone — for example in a **Monge** array, $M[i,j] + M[i',j'] \le M[i,j'] + M[i',j]$ — the **SMAWK** algorithm finds all row minima in $O(m+n)$ time, which speeds up Bellman–Ford from $O(n^3)$ to $O(n^2)$ on a geometric example. ## D.1 Saving space: divide and conquer

Edit distance needs only the previous row of its table to compute the next, so keeping two rows computes $\textsf{Edit}(m,n)$ in $O(mn)$ time and $O(m+n)$ space — the same **sliding window** that makes Fibonacci numbers cheap, and it works for most (not all) dynamic programs. But the window throws away the table, and with it the walk back from $(m,n)$ that recovers an optimal alignment.

**Hirschberg's idea (1975).** An optimal alignment of $A[1\,..\,m]$ with $B[1\,..\,n]$ splits into an alignment of $A[1\,..\,m/2]$ with $B[1\,..\,h]$ and one of $A[m/2+1\,..\,m]$ with $B[h+1\,..\,n]$, for some $h$: the column where its path in the table crosses the middle row. Compute $h$ alongside the distances, in the same sweep; then recurse.

> [!definition] Function — $\textsf{Half}(i, j)$
> For $m/2\le i\le m$ and $0\le j\le n$, $\textsf{Half}(i,j)$ is an index $h$ such that some optimal alignment of $A[1\,..\,i]$ with $B[1\,..\,j]$ contains an optimal alignment of $A[1\,..\,m/2]$ with $B[1\,..\,h]$ — the column where that alignment's path leaves row $m/2$. We need $h = \textsf{Half}(m,n)$. (Here $m/2$ means $\lfloor m/2\rfloor$; the note sets $\textsf{Half} = \infty$ above row $m/2$, entries that are never used.)

$$
\textsf{Half}(i,j) = \begin{cases} j & \text{if } i = m/2\\ \textsf{Half}(i-1,j) & \text{if } i > m/2 \text{ and } \textsf{Edit}(i,j) = \textsf{Edit}(i-1,j)+1\\ \textsf{Half}(i,j-1) & \text{if } i > m/2 \text{ and } \textsf{Edit}(i,j) = \textsf{Edit}(i,j-1)+1\\ \textsf{Half}(i-1,j-1) & \text{otherwise}\end{cases}
$$

Each case follows the last step of an optimal alignment back — a deletion, an insertion, or a (possibly free) substitution — until the path reaches row $m/2$. Ties can be broken either way.

- **Memoization:** sweep the rows as for edit distance, keeping two rows of $\textit{Edit}$ and two of $\textit{Half}$.
- **Evaluation order:** rows $i$ from 0 to $m$ (outer loop), $j$ from 0 to $n$ (inner loop), $\textit{Edit}[i,j]$ before $\textit{Half}[i,j]$.
- **Time:** $O(mn)$, and $O(n)$ space (the note says $O(m)$, which is what a column-by-column sweep gives; either works).

**The note's example.** For $A = $ ALTRUISTIC and $B = $ ALGORITHM, $m/2 = 5$; row 5 of $\textit{Half}$ (letter U) is $0, 1, \ldots, 9$, and rows 6–10 all read $0,1,2,3,4,5,5,5,5,5$, so $h = \textsf{Half}(10,9) = 5$. The problem splits into ALTRU → ALGOR (distance 3) and ISTIC → ITHM (distance 3), total 6, the edit distance.

```text
Align(A[1 .. m], B[1 .. n]):
    if m ≤ 1 or n ≤ 1
        return an optimal alignment from the full table   ⟨⟨O(m + n) time⟩⟩
    h ← Half(m, n)                     ⟨⟨one two-row sweep, O(mn) time⟩⟩
    return Align(A[1 .. m/2], B[1 .. h])
           followed by Align(A[m/2 + 1 .. m], B[h + 1 .. n])
```

(The note describes the recursion in words; the pseudocode is ours.) Its running time satisfies
$$
T(m,n) = \begin{cases} O(n) & \text{if } m\le1\\ O(m) & \text{if } n\le1\\ O(mn) + T(m/2,\,h) + T(m/2,\,n-h) & \text{otherwise.}\end{cases}
$$
Guessing $T(m,n)\le 2\alpha mn$ and substituting gives $\alpha mn + 2\alpha(m/2)h + 2\alpha(m/2)(n-h) = 2\alpha mn$, **whatever $h$ is**: the subproblems of each level of the recursion tree have about half the rows of the level above and column ranges that split $[0, n]$, so the level sums form a decreasing geometric series. The answer is an optimal alignment in $O(mn)$ time and $O(m+n)$ space (two rows, a recursion stack of depth $\lceil\log_2 m\rceil$, the output).

> [!note] How tight is "at most twice the first pass"?
> The note's induction ignores the base cases and the rounding of $m/2$. The worst case of the recurrence (cost $mn$ per call, base costs $m$ or $n$) can exceed $2mn$ — $T(5,40) = 442 > 400$ — but it stays below $2mn + (m+n)\log_2 m$ for all $2\le m,n\le40$, and $T(m,n) = O(mn)$ does hold: the guess $T(m,n)\le 4mn+m+n$ survives the induction, base cases and rounding included. Measured on random strings, all calls together compute between 2.05 and 2.36 times as many table entries as the first sweep, closer to 2 for longer strings.

**Why problems ask for the cost.** Hirschberg's trick applies to almost any dynamic program: an optimal *structure* can be built in the same time and space as its *cost*. That is why the note almost always asks only for the cost — the value of an optimal solution. The note's own to-do remarks add that Hirschberg's paper describes the algorithm differently and that a divide-and-conquer method of Chowdhury and Ramachandran (2006) might replace this section.

## D.2 Saving time: sparseness

An instance is **sparse** when almost every subproblem is resolved the same way — for edit distance, when the two strings have few letters in common, so the table has few free substitutions. Simplify to edit distance **without substitutions** (or with a substitution costing 2): its value is $m + n - 2\,\textsf{LCS}$, so minimizing it means maximizing the number of free substitutions — the length of a **longest common subsequence** (LCS).

> [!definition] Function — $\textsf{LCS}(i, j)$
> For $0\le i\le m$, $0\le j\le n$, $\textsf{LCS}(i,j)$ is the length of a longest common subsequence of $A[1\,..\,i]$ and $B[1\,..\,j]$. We need $\textsf{LCS}(m,n)$. (The note's text fixes $A[1\,..\,n]$ and $B[1\,..\,m]$ and then uses $A[1\,..\,m]$, $B[1\,..\,n]$ everywhere else; the page uses the latter.)

$$
\textsf{LCS}(i,j) = \begin{cases} 0 & \text{if } i = 0 \text{ or } j = 0\\ \textsf{LCS}(i-1,j-1) + 1 & \text{if } A[i] = B[j]\\ \max\{\textsf{LCS}(i,j-1),\ \textsf{LCS}(i-1,j)\} & \text{otherwise}\end{cases}
$$

Memoized in an $(m+1)\times(n+1)$ array filled row by row, $O(mn)$ time. Figure D.1 of the note shows the table for ALGORITHMS and ALTRUISTIC (LCS 5, for example A L R I S), with extra rows and columns for **sentinels** « and »: its 7 entries in column O from row U down are printed as 3, but $\textsf{LCS}(\text{ALTRU}, \text{ALGO}) = 2$ (only A and L are common), and those entries are all 2.

**Match points.** Call $(i,j)$ a **match point** if $A[i] = B[j]$. Only match points are interesting: add unique sentinels $A[0] = B[0]$ and $A[m+1] = B[n+1]$, and every entry of the table is determined by the match points alone,
$$
\textsf{LCS}(i,j) = \begin{cases} 0 & \text{if } i = j = 0\\ 1 + \max\{\textsf{LCS}(i',j') \mid A[i'] = B[j'],\ i' < i,\ j' < j\} & \text{if } A[i] = B[j]\\ \max\{\textsf{LCS}(i',j') \mid A[i'] = B[j'],\ i' \le i,\ j' \le j\} & \text{otherwise,}\end{cases}
$$
with strict inequalities for match points and non-strict ones otherwise. The sentinels make every set non-empty, and the answer is $\textsf{LCS}(m,n) = \textsf{LCS}(m+1,n+1) - 1$, a value at a match point.

**Finding the $K$ match points** takes $O(m\log m + n\log n + K)$ time: sort each string, remembering original positions, and merge the two sorted lists; each run of equal letters in $A$ against the run of the same letter in $B$ reports all pairs. The note's FindMatches needs three fixes: the main loop must run while $i\le m$ and $j\le n$ (it prints $<$, and misses the last letters — on $A = B = $ AB it finds only $(1,1)$); the run loop must advance with $ii\leftarrow ii+1$ (it prints $ii\leftarrow i+1$, which loops forever on a run of length 2); and both run loops need bounds, or they run off the arrays.

> [!definition] Function — $\textit{LCS}[k]$ (sparse LCS)
> List the match points in lexicographic (row-major) order, $\textit{Match}[1\,..\,K]$, followed by the end sentinel $\textit{Match}[K+1] = (m+1, n+1)$. $\textit{LCS}[k]$ is $\textsf{LCS}$ at the $k$-th match point: 1 plus the largest $\textit{LCS}[\ell]$ over earlier match points $\ell$ strictly above and to the left, or just 1 if there is none (the start sentinel, value 0). We need $\textit{LCS}[K+1] - 1$.

```text
SparseLCS(A[1 .. m], B[1 .. n]):
    Match[1 .. K] ← FindMatches(A, B)
    Match[K + 1] ← (m + 1, n + 1)                ⟨⟨end sentinel⟩⟩
    sort Match lexicographically
    for k ← 1 to K + 1                           ⟨⟨the note: to K⟩⟩
        (i, j) ← Match[k]
        LCS[k] ← 1                               ⟨⟨from the start sentinel⟩⟩
        for ℓ ← 1 to k − 1
            (i′, j′) ← Match[ℓ]
            if i′ < i and j′ < j
                LCS[k] ← max{LCS[k], 1 + LCS[ℓ]}    ⟨⟨the note: min⟩⟩
    return LCS[K + 1] − 1
```

- **Memoization:** a one-dimensional array $\textit{LCS}[1\,..\,K+1]$.
- **Evaluation order:** $k$ increasing; lexicographic order puts every match point strictly above and to the left of $(i,j)$ before it.
- **Time:** the inner loop runs $K(K+1)/2$ times: $O(m\log m + n\log n + K^2)$ in all, faster than $O(mn)$ whenever $K = o(\sqrt{mn})$. As printed, with $\min$ and the loop stopping at $K$, the entry $\textit{LCS}[K+1]$ is never computed.

In the example, $K = 8$, and the chain « A L R I S » of the figure is a longest chain of match points, each strictly below and to the right of the previous one. With more work the bound improves to $O(m\log m + n\log n + K\log K)$; that is the note's Exercise 2.

## D.3 Saving time: monotonicity

Recall [[2-algorithms/03-dynamic-programming#39-optimal-binary-search-trees|§3.9]]: given frequencies $f[1\,..\,n]$ with interval sums $F[i,j]$, the total search cost $\textsf{OptCost}(i,j)$ of an optimal binary search tree for the keys $i$ to $j$ satisfies $\textsf{OptCost}(i,j) = F[i,j] + \min_{i\le r\le j}\{\textsf{OptCost}(i,r-1) + \textsf{OptCost}(r+1,j)\}$, with $\textsf{OptCost}(i,i-1) = 0$; the straightforward algorithm takes $O(n^3)$ time. The useful structure is not in the costs but in the table of **optimal roots**: let $\textit{OptRoot}[i,j]$ be the root of an optimal tree for $f[i\,..\,j]$ — to be definite, the **leftmost** $r$ that attains the minimum.

> [!key] Knuth's monotonicity lemma
> $$\textit{OptRoot}[i, j-1] \;\le\; \textit{OptRoot}[i,j] \;\le\; \textit{OptRoot}[i+1,j]\qquad\text{for all } i<j.$$
> Moving either end of the interval moves the optimal root in the same direction or not at all: every row and every column of $\textit{OptRoot}$ is sorted.

The note calls this "nontrivial" and does not prove it. It holds with the leftmost and with the rightmost optimal root, but **not** for an arbitrary choice among tied roots: with $f = [1,1,1,1,1]$ the optimal roots of $f[1\,..\,4]$ are 2 and 3 and those of $f[1\,..\,5]$ are 2, 3 and 4, and choosing 3 for the first and 2 for the second violates $\textit{OptRoot}[1,4]\le\textit{OptRoot}[1,5]$. So the root must be chosen by a fixed rule, and the algorithm below takes the leftmost.

**The faster algorithm** searches for the root of $f[i\,..\,j]$ only between $\textit{OptRoot}[i,j-1]$ and $\textit{OptRoot}[i+1,j]$:

```text
FasterOptimalSearchTree(f[1 .. n]):
    InitF(f[1 .. n])
    for i ← 1 to n + 1                       ⟨⟨the note: for i ← 1 downto n⟩⟩
        OptCost[i, i − 1] ← 0
    for i ← 1 to n
        OptCost[i, i] ← f[i];  OptRoot[i, i] ← i
    for d ← 1 to n − 1                       ⟨⟨the note: d ← 0 to n⟩⟩
        for i ← 1 to n − d                   ⟨⟨the note: i ← 1 to n⟩⟩
            ComputeCostAndRoot(i, i + d)
    return OptCost[1, n]

ComputeCostAndRoot(i, j):
    OptCost[i, j] ← ∞
    for r ← OptRoot[i, j − 1] to OptRoot[i + 1, j]
        tmp ← OptCost[i, r − 1] + OptCost[r + 1, j]
        if OptCost[i, j] > tmp
            OptCost[i, j] ← tmp;  OptRoot[i, j] ← r
    OptCost[i, j] ← OptCost[i, j] + F[i, j]
```

(As printed, "for $i\leftarrow 1$ downto $n$" initializes nothing for $n\ge2$, the base cases $\textit{OptCost}[n+1,n]$ and $\textit{OptRoot}[i,i]$ are missing — the note's $\textit{OptRoot}[i,i-1] = i$ makes the range for $d = 0$ include $r = j+1$ — and $j = i+d$ runs past $n$. The page makes the length-1 intervals base cases.) The strict $>$ keeps the leftmost minimizer in the range, which by the lemma is the leftmost optimal root overall.

- **Memoization and order:** as in §3.9 — arrays $\textit{OptCost}$ and $\textit{OptRoot}$, filled by diagonals $d = j - i$ increasing.
- **Time:** for a fixed $d$ the ranges of consecutive calls overlap only at their ends, so the loop over $r$ runs $\sum_i(\textit{OptRoot}[i+1,i+d] - \textit{OptRoot}[i,i+d-1] + 1) = \textit{OptRoot}[n-d+1,n] - \textit{OptRoot}[1,d] + (n-d) \le 2n$ times: $O(n)$ per diagonal, **$O(n^2)$ in all**.

> [!example] Example — $f = [5, 2, 1, 3, 4]$ (the example of §3.9)
> The leftmost optimal roots $\textit{OptRoot}[i,j]$ (rows $i$, columns $j$):
>
> | $i\backslash j$ | 1 | 2 | 3 | 4 | 5 |
> |---|---|---|---|---|---|
> | 1 | 1 | 1 | 1 | 1 | **4** |
> | 2 | | 2 | 2 | 4 | 4 |
> | 3 | | | 3 | 4 | 4 |
> | 4 | | | | 4 | 5 |
> | 5 | | | | | 5 |
>
> Rows increase to the right and columns increase downward, as the lemma says. The root of the whole tree is $A[4]$, $\textit{OptCost}[1,5] = 31$. For $d\ge1$ the plain algorithm tries 30 roots, the faster one 24 — the savings grow with $n$: $\Theta(n^3)$ against $O(n^2)$.

For **optimal external trees** — keys at the leaves, pivots at internal nodes — Hu and Tucker found an $O(n\log n)$ algorithm (1971; a simpler one by Garsia and Wachs, 1977), cited by the note without details.

## D.4 Saving time: more monotonicity

Knuth's speedup is an instance of a common hidden step: **finding the minimum of every row of a two-dimensional array.** For a fixed $d$, the calls $\textsf{ComputeCostAndRoot}(i, i+d)$ find the row minima of
$$
M[i,r] = \begin{cases}\textit{OptCost}[i,r-1] + \textit{OptCost}[r+1,i+d] & \text{if } i\le r\le i+d\\ \infty & \text{otherwise.}\end{cases}
$$

> [!definition] Definition — leftmost minima, monotone array
> For an $m\times n$ array $M$, let $\textit{LM}(i)$ be the column of the smallest entry of row $i$, the leftmost one if there are ties. $M$ is **monotone** if $\textit{LM}(1)\le\textit{LM}(2)\le\cdots\le\textit{LM}(m)$: each row's leftmost minimum is directly below or to the right of the previous row's.

By Knuth's lemma the array $M$ above is monotone: its leftmost minima are the optimal roots $\textit{OptRoot}[i,i+d]$. The note's $5\times5$ example (left in the figure of D.5) has leftmost minima in columns $1,2,2,4,4$.

**Even–odd algorithm.** Recursively find the leftmost minima of the odd-numbered rows (any subset of the rows of a monotone array is monotone). Then each even row $2i$ needs only the columns between them: $\textit{LM}(2i-1)\le\textit{LM}(2i)\le\textit{LM}(2i+1)$, where $\textit{LM}(m+1)$ means $n$. Scanning that range costs $\textit{LM}(2i+1) - \textit{LM}(2i-1)$ comparisons, and these telescope: at most $n$ comparisons for all even rows together, plus $O(1)$ per row. So
$$
T(m,n) = T(m/2,\,n) + O(m+n) = O(m + n\log m).
$$

**Divide and conquer.** Alternatively, find $h = \textit{LM}(m/2)$ by brute force ($O(n)$), then recurse on the upper-left part $M[1\,..\,m/2-1,\ 1\,..\,h]$ and the lower-right part $M[m/2+1\,..\,m,\ h\,..\,n]$ — monotonicity guarantees that the minima of the earlier rows are in columns $\le h$ and those of the later rows in columns $\ge h$. The recursion tree has $\log_2 m$ levels and $O(m)$ nodes; the column ranges of one level overlap only at their ends, so each level costs $O(n)$ plus $O(1)$ per node: again $O(m + n\log m)$.

The note calls the two algorithms "morally identical", the even–odd one a breadth-first traversal of the divide-and-conquer recursion tree. Literally, for $m = 2^k - 1$ rows, divide and conquer scans exactly the entries of the version that recurses on the **even**-numbered rows (it starts from the middle row); the printed version, which recurses on the odd rows, starts its full scan at row 1 and examines a different set. The bounds are the same.

## D.5 Saving more time: total monotonicity

Aggarwal, Klawe, Moran, Shor and Wilber (1987) found row minima in **linear** time — the **SMAWK** algorithm ("smoke") — under a stronger condition.

> [!definition] Definition — totally monotone
> $M$ is **totally monotone** if every subarray formed by any subset of its rows and any subset of its columns (not necessarily consecutive) is monotone. Equivalently, **every $2\times2$ subarray is monotone**: there are no rows $i<i'$ and columns $j<j'$ with $M[i,j] > M[i,j']$ but $M[i',j]\le M[i',j']$. (A subarray that is not monotone has two rows whose leftmost minima are out of order, and those two rows and two columns form such a $2\times2$ subarray.)

### The Monge property

The most common totally monotone arrays are Monge arrays.

> [!definition] Definition — Monge array
> $M$ is **Monge** if $M[i,j] + M[i',j'] \le M[i,j'] + M[i',j]$ for all rows $i<i'$ and columns $j<j'$ — "straight" pairs never cost more than "crossing" pairs. Also called the **quadrangle inequality** or **submodularity**. It suffices to check adjacent rows and columns: $M$ is Monge iff $M[i,j] + M[i+1,j+1] \le M[i,j+1] + M[i+1,j]$ for all $i, j$ (sum the local inequalities over a rectangle), so Monge-ness can be tested in $O(mn)$ time.

> [!key] Lemma — every Monge array is totally monotone
> If $M$ is not totally monotone, some $i<i'$, $j<j'$ have $M[i,j] > M[i,j']$ and $M[i',j]\le M[i',j']$; adding the two inequalities gives $M[i,j] + M[i',j'] > M[i,j'] + M[i',j]$, so $M$ is not Monge.

**Monge's own example (1781).** Put points $p_1,\ldots,p_m$ on a line $\ell$ and $q_1,\ldots,q_n$ on a parallel line $\ell'$, both numbered in the same direction, and let $M[i,j] = \lvert p_iq_j\rvert$, the Euclidean distance. (The note's formula subtracts the coordinates of $q_i$; it means $q_j$.) Then $M$ is Monge:

> [!proof]- Proof (click to expand)
> For $i<i'$ and $j<j'$, the segments $p_iq_{j'}$ and $p_{i'}q_j$ cross at a point $x$. By the triangle inequality,
> $$\lvert p_iq_j\rvert + \lvert p_{i'}q_{j'}\rvert \le \lvert p_ix\rvert + \lvert xq_j\rvert + \lvert p_{i'}x\rvert + \lvert xq_{j'}\rvert = \big(\lvert p_ix\rvert + \lvert xq_{j'}\rvert\big) + \big(\lvert p_{i'}x\rvert + \lvert xq_j\rvert\big) = \lvert p_iq_{j'}\rvert + \lvert p_{i'}q_j\rvert,$$
> the last step because $x$ lies on both crossing segments. $\square$

> [!key] Lemma — building Monge arrays
> The following are Monge: (a) any array with constant rows; (b) any array with constant columns; (c) any 0/1 array whose 1s form a rectangular block containing the **upper-right corner**; (d) likewise for the **lower-left corner**; (e) a positive multiple of a Monge array; (f) the sum of two Monge arrays; (g) the transpose of a Monge array.

Each part is a direct check of the definition (for (f), add the two inequalities). In (c) and (d) the block must touch the corner: a single 1 in the middle of a $3\times3$ array of 0s is not Monge, and neither is a block in the upper-**left** corner. Conversely, every Monge array is a row-constant array plus a column-constant array plus a non-negative combination of upper-right blocks (the coefficient of the block of rows $1\,..\,a$ and columns $b\,..\,n$ is the local slack $M[a,b] + M[a+1,b-1] - M[a,b-1] - M[a+1,b]\ge0$); the note credits this characterization to Rudolf and Woeginger, Bein and Pathak, and Burdyuk and Trofimov, independently.

## D.6 The SMAWK algorithm

SMAWK alternates two subroutines: for **tall** arrays (more rows than columns) the even–odd recursion of D.4; for **wide** arrays a reduction to at most $m$ columns. Comparing two entries in one row kills part of a column. For a row $i$ and columns $p<q$, total monotonicity gives:
- if $M[i,p]\le M[i,q]$, then $M[h,p]\le M[h,q]$ for every $h\le i$, so $\textit{LM}(h)\ne q$: the right entry **and everything above it** is **dead**;
- if $M[i,p] > M[i,q]$, then $M[h,p] > M[h,q]$ for every $h\ge i$, so $\textit{LM}(h)\ne p$: the left entry **and everything below it** is dead.

**Reduce** keeps a stack $S[1\,..\,t]$ of candidate columns ($t\le m$), comparing the newest column $k$ with the top of the stack in row $t$:

```text
Reduce(M[1 .. m, 1 .. n]):
    t ← 1;  S[1] ← 1
    for k ← 2 to n                              ⟨⟨the note: k ← 1⟩⟩
        while t > 0 and M[t, S[t]] > M[t, k]    ⟨⟨the note: ≥⟩⟩
            t ← t − 1                           ⟨⟨pop: column S[t] is dead⟩⟩
        if t < m
            t ← t + 1;  S[t] ← k                ⟨⟨push k⟩⟩
    return S[1 .. t]
```

**Invariants:** $S[1\,..\,t]$ is increasing; the top $j-1$ entries of column $S[j]$ are dead; every column left of $k$ that is not on the stack is dead in every row. If $M[t,S[t]]\le M[t,k]$, column $k$ is dead in rows $1..t$, so it is pushed onto level $t+1$ — unless $t = m$ already (the note says $t = n$), when it is dead everywhere. If $M[t,S[t]] > M[t,k]$, column $S[t]$ is dead in rows $t..m$ and, by the invariant, above row $t$: pop it. Each comparison either pops a column or ends the loop for $k$, so Reduce makes **at most $2n$ comparisons**, $O(n)$ time, and returns at most $m$ columns (the note says "$t<m$"; it is $t\le m$) that contain every leftmost row minimum.

The pseudocode needs the strict $>$: on a tie, the right column is the one that is dead. The note's $\ge$ pops the left column instead, which loses leftmost minima — for the totally monotone array with rows $(1,1)$ and $(0,5)$, the printed Reduce keeps only column 2, although both rows have their leftmost minimum in column 1. (With distinct entries in every row the two versions agree; starting $k$ at 2 avoids pushing column 1 twice once the comparison is strict.)

```text
SMAWK(M, rows R[1 .. m], columns C[1 .. n]):       ⟨⟨leftmost minimum of every row⟩⟩
    if m = 0: return
    if n > m: C ← Reduce(M restricted to R × C)     ⟨⟨now at most m columns⟩⟩
    SMAWK(M, R[2], R[4], R[6], …, C)                ⟨⟨every other row, recursively⟩⟩
    for each remaining row R[i]
        scan C between the minima of rows R[i − 1] and R[i + 1]    ⟨⟨O(m + n) in all⟩⟩
```

(The note describes SMAWK in words; the pseudocode is ours.) After Reduce the recursive call has $m/2$ rows and at most $\min\{m,n\}$ columns, so
$$
T(m,n) \le \begin{cases} O(m) + T(m/2,\,n) & \text{if } m\ge n\\ O(n) + T(m/2,\,m) & \text{if } m<n\end{cases}
$$
and after the first Reduce both dimensions halve at every level: **$O(m+n)$ time**. (On random Monge arrays up to $1000\times1000$, SMAWK made at most $2.2(m+n)$ comparisons.) Later variants handle rows revealed one at a time, each row's minimum needed before the next row is given, still in $O(m+n)$ total — the form needed to speed up dynamic programs whose table is totally monotone.

## D.7 Using SMAWK

The note's (admittedly artificial) application is to shortest paths. Bellman–Ford ([[2-algorithms/08-shortest-paths#87-relax-all-the-edges-bellmanford|§8.7]]) relaxes every edge $V-1$ times. Rewrite each round to find, for every vertex, the **tensest edge** into it first and then relax only those edges — closer to the natural dynamic program:

> [!definition] Function — $\textit{dist}_k(v)$ (ModBellmanFord)
> $\textit{dist}_k(v)$ is the length of a shortest walk from $s$ to $v$ with at most $k$ edges; $\textit{dist}_0(s) = 0$ and $\textit{dist}_0(v) = \infty$ for $v\ne s$, and
> $$\textit{dist}_k(v) = \min\Big\{\textit{dist}_{k-1}(v),\ \min_u\big(\textit{dist}_{k-1}(u) + w(u\to v)\big)\Big\}.$$
> Without negative cycles, $\textit{dist}_{V-1}(v)$ is the shortest-path distance. Memoize one array per round (two suffice); rounds $k = 1, \ldots, V-1$ in order.

Each round is a **row-minima problem**: with $M[v,u] = \textit{dist}_{k-1}(u) + w(u\to v)$, the inner minimum for $v$ is the minimum of row $v$. Done naively that costs $O(E)$ per round, $O(VE)$ in all.

**The example.** Points $p_1,\ldots,p_n$ on a line and $q_1,\ldots,q_n$ on a parallel line, numbered in the same direction; $G$ is the complete bipartite graph on them, each edge $p_iq_j$ weighted by its Euclidean length. Standard Bellman–Ford takes $O(VE) = O(n^3)$ time. Order the rows and columns of $M$ as $p_1,\ldots,p_n,q_1,\ldots,q_n$; then
$$
M = \begin{pmatrix}\infty & U\\ V & \infty\end{pmatrix},\qquad U[i,j] = \textit{dist}(q_j) + \lvert p_iq_j\rvert,\qquad V[i,j] = \textit{dist}(p_j) + \lvert p_jq_i\rvert .
$$
With $P[i,j] = \textit{dist}(p_j)$, $Q[i,j] = \textit{dist}(q_j)$ (constant columns, so Monge) and $D[i,j] = \lvert p_iq_j\rvert$ (Monge by the geometric lemma), $U = Q + D$ and $V = P + D^{\mathsf T}$ are Monge by parts (b), (f) and (g). Two calls to SMAWK find all $2n$ row minima in $O(n)$ time, computing each entry of $U$ or $V$ on demand in $O(1)$ time without ever building $M$. With $2n-1$ rounds, Bellman–Ford runs in **$O(n^2)$** time instead of $O(n^3)$. (As the note admits in a footnote, Dijkstra's algorithm with a Fibonacci heap, $O(E + V\log V) = O(n^2)$, does as well here.)

## Summary

- **Hirschberg (space):** compute $\textsf{Half}(m,n)$ — where an optimal path crosses row $m/2$ — in the same two-row sweep as the edit distance, then recurse on the two halves: an optimal alignment in $O(mn)$ time and $O(m+n)$ space; the level costs halve, so the recursion costs about one extra sweep. Any DP's optimal structure can be recovered this way, which is why problems ask for costs.
- **Sparse LCS:** only the $K$ match points matter (sentinels at both ends); find them by sorting and merging, $O(m\log m + n\log n + K)$, then a DP over match points in lexicographic order, $O(K^2)$ more ($O(K\log K)$ with more work).
- **Knuth:** leftmost optimal BST roots satisfy $\textit{OptRoot}[i,j-1]\le\textit{OptRoot}[i,j]\le\textit{OptRoot}[i+1,j]$; searching only that range gives $O(n)$ per diagonal, $O(n^2)$ total (a fixed tie rule is required).
- **Monotone arrays** ($\textit{LM}$ non-decreasing): row minima in $O(m + n\log m)$ by even–odd recursion or by divide and conquer on the middle row.
- **Totally monotone** = every $2\times2$ subarray monotone; **Monge** ($M[i,j]+M[i',j']\le M[i,j']+M[i',j]$, checkable locally) implies totally monotone; distances between two parallel lines, constant rows or columns, corner blocks, sums, positive multiples and transposes are Monge.
- **SMAWK:** Reduce (a stack, $\le 2n$ comparisons, strict $>$) cuts a wide array to $\le m$ columns; recurse on every other row; fill in: $O(m+n)$ time for all row minima.
- **Using it:** each Bellman–Ford round is a row-minima problem; on the bipartite Euclidean graph the blocks are Monge, so each round takes $O(n)$ and the whole algorithm $O(n^2)$.
