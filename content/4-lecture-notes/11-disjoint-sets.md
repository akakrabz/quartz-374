> [!abstract] In one breath
> A **disjoint-set** (union-find) structure maintains a partition of $n$ objects under MakeSet, Find and Union. Storing each set as a **reversed tree** (every node points to its parent, the root is the leader) makes Union cheap and Find as slow as the tree is deep; **union by depth** keeps every tree's depth at most $\lg n$, so both run in $O(\log n)$ worst-case time. Storing each set as a **threaded tree** (every node points straight to its leader) makes Find $O(1)$, and relabeling the **smaller** set in Union makes any $n$ Unions cost $O(n\log n)$ in all. **Path compression** — every Find re-points the nodes it walks past at the root — together with **union by rank** brings the amortized cost of Find down to $O(\log^* n)$ and then, by "turning the crank" of Seidel and Sharir's recursive analysis, to $O(\alpha(n))$, where $\alpha$ inverts the Ackermann hierarchy and is at most 3 for any $n$ anyone will meet. That bound is tight, for path compression and for every pointer-based disjoint-set structure (Tarjan).

> [!note] Where this fits
> Union-find is the data structure inside Kruskal's algorithm ([[2-algorithms/07-minimum-spanning-trees#75-kruskals-algorithm|§7.5]]); the book implements it with labels and "relabel the smaller set" — §11.2 below — and mentions union by rank and path compression only in passing. This note supplies those structures and their analysis. The amortized arguments use the aggregate method of [[4-lecture-notes/09-amortized-analysis|note 9]] ([[concepts/amortized-analysis]]). **Not assigned in CS 374 this semester** (CS 473 material at Illinois); it explains the $O(E\,\alpha(V))$ union-find cost quoted for Kruskal.

> [!definition] Definition — disjoint sets
> A collection of disjoint sets, each identified by one of its members, its **leader**:
> - MakeSet$(x)$: create the set $\{x\}$ ($x$ must not be in any set yet); its leader is $x$.
> - Find$(x)$: return the leader of the set containing $x$.
> - Union$(x, y)$: replace the sets containing $x$ and $y$ by their union. The arguments may be any members, so Union$(x,y)$ behaves like Union(Find$(x)$, Find$(y)$).
>
> Applications: Kruskal's algorithm (one set per component of the growing forest), connected components of a graph to which vertices and edges are added.

## 11.1 Reversed trees

Store each set as a rooted tree with one node per element and pointers **up**: every node points to its parent, and the leader is the root, which points to itself. There are no child pointers.

```text
MakeSet(x):            Find(x):                      Union(x, y):
    parent(x) ← x          while x ≠ parent(x)           x̄ ← Find(x);  ȳ ← Find(y)
                               x ← parent(x)             parent(ȳ) ← x̄
                           return x
```

MakeSet takes $\Theta(1)$ time, Union $O(1)$ plus two Finds, and Find$(x)$ time proportional to the depth of $x$. That can be $\Theta(n)$: after MakeSet$(1), \ldots,$ MakeSet$(n)$, the Unions $(2,1), (3,1), \ldots, (n,1)$ build the path $1\to 2\to\cdots\to n$ — each Union finds the current leader of 1 and hangs it below the new element — so they cost $(n-1)(n-2)/2$ steps in all, and a final Find$(1)$ walks $n-1$ edges.

**Union by depth.** Store the depth (height) of each tree at its root and always hang the shallower tree below the root of the deeper one:

```text
MakeSet(x):            Union(x, y):
    parent(x) ← x          x̄ ← Find(x);  ȳ ← Find(y)
    depth(x) ← 0           if depth(x̄) > depth(ȳ)
                               parent(ȳ) ← x̄
                           else
                               parent(x̄) ← ȳ
                               if depth(x̄) = depth(ȳ)
                                   depth(ȳ) ← depth(ȳ) + 1
```

> [!key] Union by depth: logarithmic depth
> Every set with leader $\bar x$ has at least $2^{\mathit{depth}(\bar x)}$ elements. Hence no tree is deeper than $\lfloor\lg n\rfloor$, and Find and Union run in $O(\log n)$ worst-case time.

> [!proof]- Proof (click to expand)
> Induction on time. A new singleton has depth 0 and 1 element. The depth of a leader becomes $d > 0$ for the first time only when two trees whose roots both have depth $d-1$ are merged; each has at least $2^{d-1}$ elements by induction, so the union has at least $2^d$. Later Unions may add elements without changing the depth, which only helps. With at most $n$ elements, $2^{\mathit{depth}}\le n$. $\square$

The bound is attained: merging $2^k$ singletons in balanced rounds (pairs, then pairs of pairs, …) produces a tree of depth exactly $k = \lg n$.

> [!trap] Union of two elements of the same set
> The pseudocode assumes the two sets are different. If Find$(x) =$ Find$(y)$, the union-by-depth code above takes the `else` branch and increments the depth of a tree that did not grow — a singleton ends with depth 1 — breaking the invariant. Real implementations start Union with "if $\bar x = \bar y$, return" (as on [[concepts/union-find]]).

## 11.2 Shallow threaded trees

Alternatively, every object points **directly to its leader**, so MakeSet and Find take $O(1)$ time. Union must re-point every element of one set, so each set also carries a **thread**: a linked list through its elements that starts at the leader and ends in Null. Merging two threads takes $O(1)$ time.

```text
MakeSet(x):            Find(x):                 Union(x, y):
    leader(x) ← x          return leader(x)         x̄ ← Find(x);  ȳ ← Find(y)
    next(x) ← Null                                  y ← ȳ;  leader(y) ← x̄
                                                    while next(y) ≠ Null
                                                        y ← next(y);  leader(y) ← x̄
                                                    next(y) ← next(x̄)
                                                    next(x̄) ← ȳ     ⟨⟨splice⟩⟩
```

The last two lines splice the thread of $\bar y$ into the thread of $\bar x$, right after $\bar x$.
(The note's MakeSet sets next$(x)\gets x$, but its Union walks the thread until Null; with a self-pointer the loop never ends. The thread must end in Null, as here.)

Union$(x, y)$ relabels the whole set of $y$, so its cost is proportional to that set's size, which can be $\Theta(n)$. A sequence of $n$ MakeSets and $n - 1$ Unions can take $\Theta(n^2)$ time: MakeSet(1), then for $i = 2, \ldots, n$, MakeSet$(i)$ and Union$(i, 1)$ — the growing set of 1 is relabeled every time, $1 + 2 + \cdots + (n-1) = n(n-1)/2$ leader updates. (The note's version calls Union$(1, i)$, which relabels only the singleton $\{i\}$: $n - 1$ updates in all.)

**WeightedUnion.** We cannot choose the order of the operations, but we can choose which set to relabel: keep the size of every set at its leader and relabel the **smaller** one.

```text
MakeWeightedSet(x):        WeightedUnion(x, y):
    leader(x) ← x              x̄ ← Find(x);  ȳ ← Find(y)
    next(x) ← Null             if size(x̄) > size(ȳ)
    size(x) ← 1                    Union(x̄, ȳ);  size(x̄) ← size(x̄) + size(ȳ)
                               else
                                   Union(ȳ, x̄);  size(ȳ) ← size(x̄) + size(ȳ)
```

> [!key] Theorem 1
> A sequence of $m$ MakeWeightedSet and $n$ WeightedUnion operations takes $O(m + n\log n)$ time in the worst case. So each WeightedUnion takes $O(\log n)$ **amortized** time (aggregate method), although a single one can take $\Theta(n)$.

> [!proof]- Proof (click to expand)
> When an object's leader changes, its set is the smaller of the two being merged, so the size of the set containing it at least doubles. After $k$ leader changes its set has at least $2^k$ elements. Each WeightedUnion of two different sets lowers the number of sets by one, so after $n$ of them every set has at most $n + 1$ elements, and every object has changed leader at most $\lfloor\lg(n+1)\rfloor$ times. Only objects in non-singleton sets ever change leader, and there are at most $2n$ of those (each Union puts at most two new objects into non-singleton sets). So the leader updates total $O(n\log n)$, and everything else costs $O(1)$ per operation. $\square$
>
> (The note says "at most $n$ members" and "at most $n$ objects are not in singleton sets"; one Union of two singletons makes a set of $2 = n+1$ members, and $n$ Unions of disjoint pairs leave $2n$ objects in non-singleton sets. The bound $O(n\log n)$ is unaffected.)

The bound is tight: merging $2^k$ singletons in balanced rounds takes $n = 2^k - 1$ WeightedUnions and $k\,2^{k-1} = \tfrac{n+1}{2}\lg(n+1)$ leader updates — and no sequence building a set of $s$ objects does more than $\tfrac s2\lg s$. This is exactly the labeling scheme the book uses for Kruskal's algorithm.

## 11.3 Path compression

Reversed trees with union by depth: Find $O(\log n)$, the rest $O(1)$. Threaded trees with WeightedUnion: Union $O(\log n)$ amortized, the rest $O(1)$. A third idea makes both almost constant. Go back to reversed trees; once Find$(x)$ has found the root, re-point $x$ — and every ancestor of $x$ on the way — directly at the root. This is **path compression**, easiest to write recursively:

```text
Find(x):
    if x ≠ parent(x)
        parent(x) ← Find(parent(x))
    return parent(x)
```

```text
MakeSet(x):            Union(x, y):

    rank(x) ← 0            if rank(x̄) > rank(ȳ)

                           else
                               parent(x̄) ← ȳ
                               if rank(x̄) = rank(ȳ)
                                   rank(ȳ) ← rank(ȳ) + 1
```

A rank is an upper bound on the height of a node's subtree, so Find still takes $O(\log n)$ time in the worst case; path compression adds at most a constant factor. But it memoizes: a second Find on the same element right away takes one step. The analysis below shows the **amortized** cost of Find is far smaller. It is measured with the **iterated logarithm**
$$
\lg^* n = \begin{cases} 1 & \text{if } n\le 2,\\ 1 + \lg^*(\lg n) & \text{otherwise,}\end{cases}
$$
the number of times $\lg$ must be applied to bring $n$ down to at most 1 (for $n\ge 2$; the note says "less than 1", which would give 2 for $n = 2$, not the formula's 1). It is 1 for $n\le 2$, 2 for $n\le 4$, 3 for $n\le 16$, 4 for $n\le 65536$ and 5 for $n\le 2^{65536}$.

> [!key] Properties of ranks (union by rank + path compression)
> 1. If $x$ is not a leader, $\mathit{rank}(x) < \mathit{rank}(\mathit{parent}(x))$.
> 2. Whenever $\mathit{parent}(x)$ changes, the new parent has larger rank than the old one.
> 3. Whenever the leader of $x$'s set changes, the new leader has larger rank than the old one.
> 4. $\mathit{size}(\bar x)\ge 2^{\mathit{rank}(\bar x)}$ for every leader $\bar x$; hence every rank is at most $\lfloor\lg n\rfloor$.
> 5. For every $r$, at most $n/2^r$ objects have rank $r$.

> [!proof]- Proof of 5 (click to expand)
> Only leaders change rank, and a rank never decreases. Fix $r$. Whenever a leader's rank goes from $r-1$ to $r$, mark every object in its set. An object is marked at most once: its leader's rank only increases afterwards, and a later leader has larger rank still (property 3). Each object of rank $r$ triggers at least $2^r$ marks (property 4, at the moment it reached rank $r$), and there are only $n$ objects to mark. $\square$
>
> Properties 1–3 follow from the code (path compression re-points a node at its root, whose rank is larger than that of the old parent; a root linked under another root gets a parent of at least its own rank, and if the ranks were equal the new parent's rank goes up); 4 is the union-by-depth argument of §11.1.

## 11.4 O(log\* n) amortized time

(★ in the note: advanced.) Raimund Seidel and Micha Sharir (2005) found a short recursive analysis; earlier proofs used intricate charging schemes. It works with two operations on a fixed forest:

```text
Compress(x, y):          ⟨⟨y is an ancestor of x⟩⟩      Shatter(x):
    if x ≠ y                                               if parent(x) ≠ x
        Compress(parent(x), y)                                 Shatter(parent(x))
        parent(x) ← parent(y)                                  parent(x) ← x
```

Compress$(x, y)$ re-points every node on the path from $x$ up to (but not including) $y$ at $\mathit{parent}(y)$; Shatter$(x)$ makes every node on the path from $x$ to the root a root. **Find$(x)$ is Compress$(x, y)$, where $y$ is the child of the root on $x$'s path** (as in the note's figure on p. 6): every node below $y$ is re-pointed at the root. Its running time is $O(1)$ plus the number of pointer assignments of this Compress.

**Unions first.** Assume every Union links two leaders, in $O(1)$ time. A Union changes only the parent of a root, and a Compress never touches the pointer of its top node $y$ or of anything above it; so all the Unions can be moved before all the Compresses without changing any Compress's pointer assignments. (The note's text takes $y$ to be the leader. Then Compress points the path at $\mathit{parent}(y)$, which after the reordering may be a newer, higher root, and later costs change: if $x\to a$ and $c\to b$, ranks 1, the sequence Find$(x)$, Union$(a, b)$, Find$(x)$ makes $1 + 2$ assignments, but only $1 + 1$ after the reordering. With $y$ below the root the counts agree exactly.)

So it suffices to bound $T(m, n, r)$, the largest number of pointer assignments in any sequence of at most $m$ Compresses on a forest of at most $n$ nodes with ranks satisfying properties 1 and 5, all ranks at most $r$.

> [!key] Theorem 2
> $T(m, n, r)\le nr$.

> [!proof]- Proof (click to expand)
> Every assignment gives a node a parent of strictly larger rank than before (property 2 — with $y$ below the root, every assignment really changes the pointer). Ranks lie between 0 and $r$, so each node changes parent at most $r$ times. $\square$

**Splitting the forest.** Fix a rank $s$. The **low** forest $F_-$ consists of the nodes of rank at most $s$, the **high** forest $F_+$ of those of rank greater than $s$; since ranks increase upward, every ancestor of a high node is high. Let $n_\pm$ be their sizes, $m_+$ the number of Compresses whose path reaches a high node, $m_- = m - m_+$. Split every Compress of the sequence $C$ the same way, with one rule: in $F_-$ a low node never gets a high parent — it becomes its own parent instead.
- Its high part, if any, is a Compress in $F_+$ (from the parent of the topmost low node $z$ up to $y$): these form $C_+$.
- Its low nodes that are re-pointed at a low node form a Compress in $F_-$: these form $C_-$.
- Its low nodes that move from a low parent to a high one become roots of $F_-$: a **Shatter**. After that their parent is high forever, so every node is shattered at most once — at most $n$ assignments in all.
- The node $z$, if its old parent was already high, moves from one high parent to another; the mirrored assignment $\mathit{parent}(z)\gets z$ happens at most once per Compress that reaches $F_+$ — at most $m_+$ in all.

$$
T(F, C)\le T(F_+, C_+) + T(F_-, C_-) + m_+ + n.
$$

**Choosing $s$.** By property 5, $n_+\le\sum_{i>s} n/2^i = n/2^s$, and $F_+$ has fewer than $r$ distinct ranks, so Theorem 2 gives $T(F_+, C_+) < rn/2^s$. With $s = \lceil\lg r\rceil$ this is at most $n$, and
$$
T(F, C) - m\;\le\; T(F_-, C_-) - m_- + 2n,
\qquad\text{so}\qquad
T'(m, n, r)\le T'(m, n, \lceil\lg r\rceil) + 2n
$$
for $T' = T - m$. Unrolling, $\lceil\lg r\rceil$ is applied $\lg^* r - 1$ times before the rank drops to 2 ($\lg^*$ changes value only at the integers 2, 4, 16, 65536, …, so rounding up costs nothing), and $T'\le nr\le 2n$ when $r\le 2$:

> [!key] Theorem 3
> $T(m, n, r)\le m + 2n\lg^* r$. Hence, with union by rank and path compression, Find runs in $O(\log^* n)$ amortized time.

(The note takes $s = \lg r$ and writes the recurrence with $\lfloor\lg r\rfloor$. Ranks are integers, and with $s = \lfloor\lg r\rfloor$ the bound $rn/2^s\le n$ fails — $r = 3$ gives $1.5n$; rounding up repairs it and leaves Theorem 3 as stated.)

## 11.5 Turning the crank

(★ in the note.) The analysis bounded the high forest with the crude Theorem 2. Use Theorem 3 there instead, with $s = \lg^* r$ (an integer): $n_+\le n/2^{\lg^* r}$, so
$$
T(F_+, C_+)\le m_+ + 2n\,\frac{\lg^* r}{2^{\lg^* r}}\le m_+ + 2n,
$$
which gives $T(F, C)\le T(F_-, C_-) + 2m_+ + 3n$, i.e. $T''(m,n,r)\le T''(m,n,\lg^* r) + 3n$ for $T'' = T - 2m$, and so
$$
T(m, n, r)\le 2m + 3n\lg^{**} r,
\qquad
\lg^{**} r = \begin{cases} 1 & r\le 2,\\ 1 + \lg^{**}(\lg^* r) & \text{otherwise.}\end{cases}
$$
Each turn of the crank adds $m$ to the bound and replaces one more level of iterated logarithm: after $c$ turns, for every positive integer $c$,
$$
T(m, n, r)\le cm + (c+1)\,n\lg^{*^c} r,
\qquad
\lg^{*^c} r = \begin{cases} \lg r & c = 0,\\ 1 & r\le 2,\\ 1 + \lg^{*^c}\!\bigl(\lg^{*^{c-1}} r\bigr) & \text{otherwise.}\end{cases}
$$
More turns help until the $cm$ term dominates. Stop at
$$
\alpha(r) = \min\bigl\{c\ge 1 \bigm| \lg^{*^c} r\le 3\bigr\}.
$$
(Threshold 3 because the threshold 2 is never reached from 5: $\lg^{*^c} 5 = 3$ for every $c\ge 1$. The note writes "$\ge 2$", and $n$ for $r$ inside the definition.)

> [!key] Theorem 4
> $T(m, n, r)\le m\,\alpha(r) + 3n(\alpha(r) + 1)$. Since $r\le\lg n$ and, ignoring singletons, one may assume $m\ge n$, this is $O(m\,\alpha(n))$: **with union by rank and path compression, Find runs in $O(\alpha(n))$ amortized time.**

A finer count uses $\alpha(m, n) = \min\{c\ge 1\mid \lg^{*^c}(\lg n)\le m/n\}$: the note states that $\alpha(m,n) = \Theta(\alpha(n))$ when $m = \Theta(n)$ and $\alpha(m,n) = O(1)$ when $m\ge n\lg^{*\cdots*}n$ for any constant number of stars — so with slightly more Finds than nodes, a Find costs $O(1)$ amortized. (As printed, the minimum is empty when $m < 3n$ and $n\ge 17$: then $\lg n > 4$, so $\lg^{*^c}(\lg n)\ge 3 > m/n$ for every $c$. The first claim needs $m\ge 3n$, or a right-hand side of at least 3.) And $O(\alpha(m,n))$ is **tight**: no better bound holds for path compression, and Tarjan (1979) proved that every pointer-based disjoint-set structure needs $\Omega(\alpha(m,n))$ amortized time per Find.

## 11.6 The Ackermann function and its inverse

The iterated logarithms invert a hierarchy of functions going back to Wilhelm Ackermann (1928); the note uses R. Creighton Buck's cleaner version, in Knuth's up-arrow notation:
$$
2\uparrow^c n = \begin{cases} 2 & \text{if } n = 1,\\ 2n & \text{if } c = 0,\\ 2\uparrow^{c-1}\bigl(2\uparrow^c(n-1)\bigr) & \text{otherwise.}\end{cases}
$$
Each row increases in $n$ (the columns of the table below), and the rows grow ever faster: $2\uparrow n = 2^n$; $2\uparrow\uparrow n$ is the **tower** $2^{2^{\cdot^{\cdot^{2}}}}$ of $n$ twos; $2\uparrow\uparrow\uparrow n = 2\uparrow\uparrow 2\uparrow\uparrow\cdots\uparrow\uparrow 2$ ($n$ twos) is Conway's **wower**.

| $2\uparrow^c n$ | 1 | 2 | 3 | 4 | 5 |
|---|---|---|---|---|---|
| $2n$ | 2 | 4 | 6 | 8 | 10 |
| $2\uparrow n$ | 2 | 4 | 8 | 16 | 32 |
| $2\uparrow\uparrow n$ | 2 | 4 | 16 | 65536 | $2^{65536}$ |
| $2\uparrow\uparrow\uparrow n$ | 2 | 4 | 65536 | tower of 65536 twos | tower of $2\uparrow\uparrow 65536$ twos |
| $2\uparrow^4 n$ | 2 | 4 | tower of 65536 twos | $2\uparrow\uparrow\uparrow$(tower of 65536 twos) | … |

Every row starts $2, 4$, and the third column climbs one row at a time: $2\uparrow^{c+1} 3 = 2\uparrow^c 4$.

**Inverses.** For each $c\ge 1$, $\lg^{*^c} n = \min\{k\ge 1\mid 2\uparrow^{c+1} k\ge n\}$: $\lg^{*^c}$ inverts row $c+1$ ($\lg^*$ inverts the tower). For all $n\le 2^{256}$, $\lg^* n\le 5$, $\lg^{**}n\le 4$ and $\lg^{*^c} n\le 3$ for every $c\ge 3$. Since $\lg^{*^c} n\le 3$ exactly when $n\le 2\uparrow^{c+1} 3$,
$$
\alpha(n) = \min\{c\ge 1\mid 2\uparrow^{c+1} 3\ge n\}:
$$
$\alpha(n) = 1$ for $n\le 16$, $2$ for $n\le 65536$, $3$ up to a tower of 65536 twos. (The note writes $2\uparrow^{c+2} 3$ and calls $\alpha(n) + 2$ the inverse of the third column; with its own definition of $\alpha$ the index is $c+1$ — for instance $\alpha(17) = 2$, while $2\uparrow^{3} 3 = 65536\ge 17$ would give 1 — so it is $\alpha(n) + 1$.) This $\alpha$ is called the **inverse Ackermann function**; it grows more slowly than $\lg^{*^c}$ for every fixed $c$, but it is not $O(1)$. Other books define it slightly differently ([[2-algorithms/07-minimum-spanning-trees#75-kruskals-algorithm|§7.5]] and [[concepts/union-find]] quote "at most 4" for any conceivable input); the note's footnote 5 gives a version $\tilde\alpha(n) = \min\{c\ge 1\mid \lg^{*^c} n\le c\}$, which for large $n$ satisfies $\tilde\alpha(n)\le\alpha(n)\le\tilde\alpha(n) + 2$. Such differences do not matter in $O(\alpha(n))$ bounds.

## 11.7 To infinity and beyond

One can keep going: the **iterated inverse Ackermann function** $\alpha^*(n) = 1$ for $n\le 4$ and $1 + \alpha^*(\alpha(n))$ otherwise, then $\alpha^{*^c}$, then a diagonal version, "and so on ad nauseam". Such functions almost never appear in algorithm analysis; the note's one natural example is Seth Pettie's 2008 result on splay trees used as double-ended queues: $m$ deque operations on an $n$-node splay tree take $O\bigl((m+n)\,\alpha^*(m+n)\bigr)$ time in all, i.e. $O(\alpha^*)$ amortized per operation when $m\ge n$ (the note just says $O(\alpha^*(n))$ per operation; see [[4-lecture-notes/10-scapegoat-and-splay-trees|note 10]]).

## Summary

- **Reversed trees** (parent pointers, leader = root): Find costs the depth. **Union by depth/rank** — hang the shallower tree under the deeper root — gives $\mathit{size}\ge 2^{\mathit{depth}}$, depth $\le\lfloor\lg n\rfloor$, $O(\log n)$ worst case.
- **Threaded trees** (leader pointers + a Null-terminated thread): Find $O(1)$; Union relabels one whole set. **Relabel the smaller set** (WeightedUnion): an object's set doubles with each relabeling, so $m$ MakeSets and $n$ Unions cost $O(m + n\log n)$ — Union $O(\log n)$ amortized; tight for balanced merging.
- **Path compression**: Find re-points the whole path at the root. With union by rank: ranks increase toward the root, every new parent has larger rank, $\mathit{size}\ge 2^{\mathit{rank}}$, at most $n/2^r$ nodes of rank $r$.
- **Seidel–Sharir**: split the forest at rank $s$; $T(F,C)\le T(F_+,C_+) + T(F_-,C_-) + m_+ + n$. With $s = \lceil\lg r\rceil$: $T\le m + 2n\lg^* r$; turning the crank: $T\le cm + (c+1)n\lg^{*^c} r$; at $c = \alpha(r)$: $T\le m\alpha(r) + 3n(\alpha(r)+1)$ — **Find in $O(\alpha(n))$ amortized time**, which is tight (Tarjan).
- $\lg^* n\le 5$ and $\alpha(n)\le 3$ for every $n\le 2^{65536}$; $\alpha(n) = \min\{c\ge 1\mid 2\uparrow^{c+1}3\ge n\}$ inverts the Ackermann hierarchy $2\uparrow^c n$.
- The note ends with 8 exercises (union by weight, $\Omega(m\log n)$ without compression, labeling everything in $O(n)$, NextWhite, strings, black components of a bitmap, a guessing game in $O(\alpha(n))$ rounds).
