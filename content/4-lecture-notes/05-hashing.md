> [!abstract] In one breath
> A **hash table** stores $n$ keys from a huge universe in an array of $m\approx n$ slots, key $x$ at slot $h(x)$. Every *fixed* $h$ has inputs on which all keys collide, so $h$ is drawn **at random** from a family when the table is built: the input is arbitrary, only $h$ is random. If the family is **universal** — two distinct keys collide with probability at most $1/m$ — a search in a **chained** table takes $O(1+\alpha)$ expected time, $\alpha = n/m$; $((ax+b)\bmod p)\bmod m$ is universal, and one multiplication and one shift is near-universal. Expected is not worst case: with $\alpha = 1$ the longest chain has $\Theta(\log n/\log\log n)$ keys, but a table of size $n^2$ is collision-free with probability $> 1/2$, and a **two-level** table (slot $j$ gets its own collision-free table of size $2n_j^2$) uses $O(n)$ expected space and searches in $O(1)$ worst-case time. **Open addressing** probes a sequence of slots instead: at most $1/(1-\alpha)$ expected probes with ideal random probe sequences, and $O(1)$ for **binary probing** at load $\le 1/4$, even with 5-uniform hashing. ## 5.1 Introduction

The keys come from a fixed **universe** $\mathcal U$ of size $u$; we store a set of $n$ of them. A **hash table** is an array $T[0\,..\,m-1]$ of **table size** $m$, usually $m\ll u$, and a **hash function** is any $h\colon\mathcal U\to\{0,1,\ldots,m-1\}$; key $x$ **hashes to** slot $T[h(x)]$. With $m = u$ and $h(x) = x$ this is a **direct-access table** — an ordinary array, too large in most applications; ideally $m$ is about $n$, the number of keys actually stored. Then distinct keys $x\ne y$ **collide** when $h(x) = h(y)$, and a design has two parts: a hash function that is fast and causes few collisions, and a way to resolve the collisions that do occur.

## 5.2 The importance of being random

If the set of keys were known in advance one could look for a collision-free ("perfect") function, but usually it is not, and then no fixed function is safe: by pigeonhole, **every fixed $h$ sends at least $\lceil u/m\rceil$ keys of $\mathcal U$ to the same slot**, and an unlucky or malicious input drawn from that set makes every operation slow (a real attack on network routers). The only provable defense is to choose $h$ **at random**, from a fixed family $\mathcal H$ of functions $\mathcal U\to\{0,\ldots,m-1\}$, when the table is created. The note's slogan: *the input data is not random, so good hash functions must be.*

The textbook favorite $h(x) = x\bmod m$ (the "division method") is a fixed function: it uses only the low-order bits of $x$ when $m$ is a power of 2, and even for prime $m$, $h(x + am) = h(x)$ for all integers $a$ — keys whose difference is a multiple of $m$ collide with certainty.

## 5.3 ...But not too random

The cleanest model is an **ideal random** hash function: $h$ is uniform over **all** $m^u$ functions $\mathcal U\to[m]$, as if each key rolled its own $m$-sided die. It is a fantasy — storing such an $h$ needs a table indexed by the keys, which is what we were building — so one looks for small families with just enough of its properties. Write $[m] = \{0,1,\ldots,m-1\}$.

> [!definition] Definition — uniform, universal, near-universal, $k$-uniform families
> In each condition the keys and hash values are **arbitrary but fixed**; the probability is over the choice of $h$ uniformly from $\mathcal H$ — nothing else is random.
> - **Uniform:** $\Pr_h[h(x) = i] = 1/m$ for every key $x$ and every $i\in[m]$.
> - **Universal:** $\Pr_h[h(x) = h(y)]\le 1/m$ for all keys $x\ne y$.
> - **Near-universal:** $\Pr_h[h(x) = h(y)]\le 2/m$ for all $x\ne y$ (any fixed constant would do in place of 2).
> - **$k$-uniform** (strongly $k$-universal): $\Pr_h\big[h(x_1) = i_1\wedge\cdots\wedge h(x_k) = i_k\big] = 1/m^k$ for all distinct keys $x_1,\ldots,x_k$ and all values $i_1,\ldots,i_k$.
>
> Ideal random functions satisfy all of these, for every $k$.

Uniformity alone is worthless: the $m$ **constant** functions $\textsf{const}_a(x) = a$ form a uniform family in which every pair of keys collides with probability 1. Conversely a universal family need not be uniform: the family $\mathcal{MB}^+$ of §5.5.2 with $p = 5$ and $m = 3$ has $\Pr[h(x) = 0] = 2/5$ for every key. The analyses below use universality, pair by pair. (Universality is often, misleadingly, called the "uniform hashing assumption".) A $k$-uniform family is uniform and, for $k\ge 2$, universal; a standard example (not in the note) is the polynomials of degree less than $k$ over $\mathbb Z_p$, with $m = p$.

> [!trap] What is random
> - **The keys are not random.** "Universal" is a statement about every fixed pair of keys; an average over random keys proves nothing about an adversary's input.
> - **$h$ is chosen once**, when the table is created, and then fixed: a key is always found where it was put.
> - **Pairwise statements only.** Universality says nothing about three keys at once; anything that needs more (the analysis of binary probing in §5.10) needs $k$-uniformity.

## 5.4 Chaining

In a **chained** hash table, $T[i]$ points to a linked list of all stored keys that hash to $i$. Let $\ell(x)$ be the length of the list $T[h(x)]$. Searching for $x$ computes $h(x)$ and scans that list: $O(1 + \ell(x))$ time; insertions and deletions cost the same.

**Expected list length.** Suppose $x$ is not stored, and let $C_{x,y} = [h(x) = h(y)]$ (Iverson bracket). Then $\ell(x) = \sum_{y\in T} C_{x,y}$, and if $h$ is drawn from a universal family, $\operatorname{E}[C_{x,y}] = \Pr[h(x) = h(y)]\le 1/m$ for every stored $y\ne x$, so by linearity of expectation
$$
\operatorname{E}[\ell(x)] = \sum_{y\in T}\Pr[h(x) = h(y)] \le \frac nm =: \alpha,
$$
the **load factor**. (The note writes "$= 1/m$" and "$= n/m$"; universality gives only "$\le$", with equality for ideal random hashing.) With a near-universal family, $\operatorname{E}[\ell(x)]\le 2\alpha$.

> [!key] Chaining with (near-)universal hashing
> An unsuccessful search takes $\Theta(1+\alpha)$ **expected** time, the expectation over the choice of $h$ only, for every fixed set of stored keys; a successful search has the same bound with a smaller constant. With $m = \Theta(n)$ every search takes $O(1)$ expected time.

Two variations. Storing each chain in a balanced binary search tree (for an ordered universe) makes a search $O(1 + \log\ell(x))$, hence $O(1 + \log\alpha)$ expected by Jensen's inequality. Storing each chain in a further hash table, recursively, gives a tree of hash tables; the note asserts, without proof, that with every table of size $m$ the expected search time is $O(\log_m n)$, constant for $m = \sqrt n$.

> [!warning] Caveat lector
> Constant expected time *per search* does not make the **slowest** search fast. The expected worst-case search time is $O(1 + L)$ with $L = \max_x\ell(x)$, and even with ideal random hashing and $\alpha = 1$, $\operatorname{E}[L] = \Theta(\log n/\log\log n)$: independent uniform choices produce a distribution that is far from even (§5.6). In the figure, $\alpha = 1$ leaves three of eight slots empty and puts three keys in one list.

## 5.5 Multiplicative hashing

**Multiplicative hashing**, introduced by Lawrence Carter and Mark Wegman in the late 1970s, is the simplest near-universal method. Each hash function is determined by an integer, its **salt**, chosen uniformly at random when the table is created and fixed for the table's lifetime; all probabilities are over the salt. Notation: $[n] = \{0,\ldots,n-1\}$ and $[n]^+ = \{1,\ldots,n-1\}$.

### 5.5.1 Prime multiplicative hashing

Fix a prime $p > \lvert\mathcal U\rvert$ (so keys are integers in $[p]$). For each salt $a\in[p]^+$ let
$$
\textsf{multp}_a(x) = (a x\bmod p)\bmod m,\qquad \mathcal{MP} = \{\textsf{multp}_a \mid a\in[p]^+\}.
$$

> [!key] Lemmas 1–3
> **Lemma 1.** Every $a\in[p]^+$ has a unique inverse $a^{-1}\in[p]^+$ with $a a^{-1}\bmod p = 1$: multiplication by $a$ permutes $[p]^+$, because $p$ is prime.
>
> **Lemma 2.** For $a, x, y\in[p]^+$: **if** $\textsf{multp}_a(x) = \textsf{multp}_a(y)$, **then** $x = y$, or $\textsf{multp}_a((x-y)\bmod p) = 0$, or $\textsf{multp}_a((y-x)\bmod p) = 0$.
>
> **Lemma 3.** For every $z\in[p]^+$, exactly $\lfloor (p-1)/m\rfloor$ salts give $\textsf{multp}_a(z) = 0$, so $\Pr_a[\textsf{multp}_a(z) = 0]\le 1/m$.
>
> Hence, by the union bound, $\Pr_a[\textsf{multp}_a(x) = \textsf{multp}_a(y)]\le 2/m$ for $x\ne y$: **$\mathcal{MP}$ is near-universal.**

> [!proof]- Proof sketch (click to expand)
> Lemma 2: if $ax\bmod p = ay\bmod p$, multiplying by $a^{-1}$ gives $x = y$ (the only use of primality). If $ax\bmod p > ay\bmod p$, their difference is $a(x-y)\bmod p$, and two numbers are congruent mod $m$ exactly when their difference is, so a collision means $(a(x-y)\bmod p)\bmod m = 0$; the case $<$ is symmetric with $y - x$. Lemma 3: as $a$ ranges over $[p]^+$, $az\bmod p$ ranges over $[p]^+$ exactly once (Lemma 1), and $\lfloor (p-1)/m\rfloor$ of those values are multiples of $m$. $\square$
>
> The note states Lemma 2 as "if and only if". Only the direction above holds, and only it is used: for $p = 7$, $m = 3$, $a = 1$, $x = 1$, $y = 2$, $\textsf{multp}_1(6) = 0$ but $\textsf{multp}_1(1) = 1\ne 2 = \textsf{multp}_1(2)$.

The factor 2 cannot be removed: Carter and Wegman observed that if $p\bmod(m+1) = 1$, then $\Pr_a[\textsf{multp}_a(1) = \textsf{multp}_a(m+1)] = 2/(m+1) > 1/m$ (checked for every such pair with $p < 400$). For $p = 5$, $m = 3$ the four salts give $(\textsf{multp}_a(1), \textsf{multp}_a(4)) = (1,1), (2,0), (0,2), (1,1)$: probability $1/2 > 1/3$. **$\mathcal{MP}$ is not universal.**

### 5.5.2 Actually universal hashing

Adding a second salt fixes this. For $a\in[p]^+$ and $b\in[p]$ let
$$
h_{a,b}(x) = \big((ax + b)\bmod p\big)\bmod m,\qquad \mathcal{MB}^+ = \{h_{a,b}\mid a\in[p]^+,\ b\in[p]\},
$$
a family of $p(p-1)$ functions.

> [!key] Theorem 1
> $\mathcal{MB}^+$ is universal. More precisely, for $2\le m < p$ and **every** pair $x\ne y$,
> $$
> \Pr_{a,b}\big[h_{a,b}(x) = h_{a,b}(y)\big] = \frac{(p - p\bmod m)\,(p - (m - p\bmod m))}{m\,p\,(p-1)} < \frac1m .
> $$

> [!proof]- Proof (click to expand)
> Fix $x\ne y$ in $[p]$. For any $r\ne s$ in $[p]$, the system $ax + b\equiv r$, $ay + b\equiv s\pmod p$ has exactly one solution, $a = (r-s)(x-y)^{-1}\bmod p$ (non-zero, since $r\ne s$) and $b = (sx - ry)(x-y)^{-1}\bmod p$. So $(a,b)\mapsto\big((ax+b)\bmod p, (ay+b)\bmod p\big)$ is a bijection from the $p(p-1)$ salts onto the $p(p-1)$ ordered pairs $(r,s)$ with $r\ne s$, and the collision probability is $N/(p(p-1))$, where $N$ counts the pairs $r\ne s$ with $r\equiv s\pmod m$. Each $r$ has at most $\lceil p/m\rceil - 1\le (p-1)/m$ such partners $s$ (the note writes $\lfloor p/m\rfloor$, the same number when $m\nmid p$), so $N\le p(p-1)/m$. Counting exactly — $p\bmod m$ residue classes of size $\lfloor p/m\rfloor + 1$ and the others of size $\lfloor p/m\rfloor$ — gives the formula. $\square$

For $p = 5$ and $m = 3$ the formula gives $\tfrac{3\cdot 4}{3\cdot 5\cdot 4} = \tfrac15 < \tfrac13$; the note confirms it by printing all twenty functions (keys 1 and 4 collide for 4 of the 20 salts). The chained table above uses $h_{23,8}$ with $p = 101$, $m = 8$.

### 5.5.3 Binary multiplicative hashing

A variant without large primes, analyzed by Dietzfelbinger, Hagerup, Katajainen and Penttonen (1997): hash $w$-bit words to $\ell$-bit labels, $\mathcal U = [2^w]$ and $m = 2^\ell$. For an **odd** salt $a\in[2^w]$,
$$
\textsf{multb}_a(x) = \left\lfloor\frac{(a\cdot x)\bmod 2^w}{2^{w-\ell}}\right\rfloor ,
$$
the top $\ell$ bits of the low word of the $2w$-bit product. In a language whose $w$-bit unsigned arithmetic wraps around, that is one multiplication and one right shift — in C, `((a)*(x) >> (WORDSIZE-HASHBITS))`. The family is $\mathcal{MB} = \{\textsf{multb}_a\mid a \text{ odd}\}$.

> [!key] Lemma 4 and Theorem 2
> **Lemma 4.** For odd $x$ and odd $z$ in $[2^w]$, exactly one odd $a$ has $ax\bmod 2^w = z$ (multiplication by an odd number permutes the odd words).
>
> **Theorem 2.** $\mathcal{MB}$ is near-universal: $\Pr_a[\textsf{multb}_a(x) = \textsf{multb}_a(y)]\le 2/2^\ell$ for all $x\ne y$. For $\ell\le w-2$ it is not universal (some pairs exceed $1/2^\ell$); for $\ell\ge w-1$ it is (not in the note).

> [!proof]- Proof sketch (click to expand)
> If $x < y$ collide, the top $\ell$ bits of $a(y-x)\bmod 2^w$ are all 0s or all 1s, so $\textsf{multb}_a(y-x)\in\{0, m-1\}$. Write $y - x = q\,2^r$ with $q$ odd and $0\le r < w$. By Lemma 4, $aq\bmod 2^w$ is a uniformly random odd word — $w-1$ random bits and a final 1 — so $aq2^r\bmod 2^w$ is $w-r-1$ random bits, a 1, and $r$ zeros. Three cases for the top $\ell$ bits:
> - $r < w-\ell$: $\ell$ random bits; each of the values $0$ and $m-1$ has probability $1/2^\ell$.
> - $r = w-\ell$: $\ell - 1$ random bits and a 1; probability 0 and $2/2^\ell$.
> - $r > w-\ell$: random bits, a 1, then at least one 0 — never all 0s or all 1s; probability 0 and 0. (The note's third case reads "$r < w-\ell$" again; it must be $r > w-\ell$.)
>
> In every case the two probabilities add up to at most $2/2^\ell$. $\square$

## 5.6 High probability bounds: balls and bins

(★ in the note: optional.) With ideal random hashing, the longest chain is the fullest bin when $n$ balls are thrown independently and uniformly into $n$ bins.

> [!key] Lemma 5
> If $n$ balls are thrown independently and uniformly into $n$ bins, then with high probability the fullest bin contains $O(\log n/\log\log n)$ balls.

> [!proof]- Proof (click to expand)
> Let $X_j$ be the number of balls in bin $j$. A fixed set of $k$ balls all lands in bin $j$ with probability $n^{-k}$, so by the union bound over the $\binom nk$ sets,
> $$
> \Pr[X_j\ge k]\le\binom nk\frac1{n^k}\le\frac{n^k}{k!}\cdot\frac1{n^k} = \frac1{k!}.
> $$
> Take $k = 2c\lg n/\lg\lg n$. Since $k!\ge (k/e)^k$ and $k/e\ge\sqrt{\lg n}$ for all large $n$, $k!\ge(\sqrt{\lg n})^{k} = 2^{c\lg n} = n^c$; so $\Pr[X_j\ge k]\le n^{-c}$. The fullest bin exceeds $k$ only if **some** bin does, and by the union bound over the $n$ bins that has probability at most $n^{1-c}$. $\square$
>
> The note's version of the middle step, $k!\ge k^{k/2} = (2c\lg n/\lg\lg n)^{2c\lg n/\lg\lg n}\ge(\sqrt{\lg n})^{2c\lg n/\lg\lg n}$, is wrong twice — the exponent of $k^{k/2}$ is $k/2$, not $k$, and $k^{k/2}\ge(\sqrt{\lg n})^k$ would need $k\ge\lg n$ — and its conclusion $k!\ge n^c$ fails for small $n$: for $n = 2^{16}$ and $c = 1$, $k = 8$ and $8! = 40320 < 65536$. It does hold once $\lg n\ge 36$ (for $c = 1$), which is all the lemma needs. The note also writes the event "$\max_j X_j > k$" as "$X_j > k$ for all $j$"; it is "for **some** $j$".

A more complicated argument shows the bound is tight: with high probability the fullest bin has $\Omega(\log n/\log\log n)$ balls. The numbers grow slowly — exactly, $\operatorname{E}[\max_j X_j]\approx 2.75$ for $n = 10$ and $4.23$ for $n = 100$; in simulation about $8.7$ for $n = 10^6$, where $\ln n/\ln\ln n\approx 5.3$.

**Making collisions disappear.** Let $C$ be the number of colliding pairs of balls among $n$ balls in $m$ bins. Each of the $\binom n2$ pairs collides with probability $1/m$, so $\operatorname{E}[C] = \binom n2/m$; for $m = n^2$ that is $(n-1)/(2n) < 1/2$, and by Markov's inequality the probability of even one collision is less than $1/2$. The argument needs only near-universal hashing: then $\operatorname{E}[C]\le\binom n2\cdot\frac2m = n(n-1)/m$, less than $1/2$ for $m = 2n^2$.

> [!key] Lemma 6
> For any constant $\varepsilon > 0$, if $n$ balls are thrown independently and uniformly into $m = n^{2+\varepsilon}$ bins, then with probability at least $1 - 1/n^\varepsilon$ no bin contains more than one ball.

> [!proof]- Proof (click to expand)
> Truncating binomial expansions, $\Pr[X_j = 0] = (1-1/m)^n > 1 - n/m$ and $\Pr[X_j = 1] = \frac nm(1-\frac1m)^{n-1}\ge\frac nm - \frac{n(n-1)}{m^2}$ (equality for $n = 2$; the note writes ">"), so $\Pr[X_j > 1] < n(n-1)/m^2$. The union bound over the $m$ bins gives $\Pr[\max_j X_j > 1] < n(n-1)/m < n^2/m = n^{-\varepsilon}$. $\square$

(The Markov argument above already gives the same: $\Pr[C\ge 1]\le\operatorname{E}[C] < n^2/(2m)$.)

## 5.7 Perfect hashing

Small tables give fast average searches but a $\Theta(\log n/\log\log n)$ slowest search; tables of quadratic size have no collisions but waste space. **Two-level hashing** (the scheme of Fredman, Komlós and Szemerédi, 1984, not named in the note) gets both: linear expected space and constant **worst-case** search time, for a set of keys known when the table is built.

> [!recipe] Recipe — two-level hash table
> 1. **Primary table** of size $m = n$, with $h$ from a near-universal family. Let $n_j$ be the number of keys with $h(x) = j$.
> 2. **Secondary tables:** slot $j$ gets a table $T_j$ of size $2n_j^2$ with its own near-universal function $h_j$. By the computation above, $T_j$ has no collision with probability at least $1/2$; if it has one, draw a new $h_j$ and rebuild $T_j$ (expected at most 2 tries).
> 3. **Search** for $x$: look in cell $h_{h(x)}(x)$ of $T_{h(x)}$ — two hash evaluations and one comparison, $O(1)$ worst-case time.

> [!key] Lemma 7
> With near-universal hashing in the primary table, $\operatorname{E}\big[\sum_j n_j^2\big]\le 3n - 2 < 3n$. So the expected total size, $n + \sum_j 2n_j^2$, is $O(n)$ (at most $7n - 4$).

> [!proof]- Proof (click to expand)
> Count ordered pairs of keys that share a slot: $\sum_j n_j^2 = \sum_j\big(\sum_x[h(x) = j]\big)^2 = n + 2\sum_{x<y}[h(x) = h(y)]$ — each key paired with itself, plus twice the colliding pairs. By linearity of expectation and near-universality with $m = n$,
> $$
> \operatorname{E}\Big[\sum_j n_j^2\Big] = n + 2\sum_{x<y}\Pr[h(x) = h(y)]\le n + 2\binom n2\frac2n = 3n - 2. \qquad\square
> $$

With a universal family the same computation gives $2n - 1$, the value for ideal random hashing. In the figure, $\sum_j n_j^2 = 4 + 9 + 1 + 1 + 1 = 16\le 3\cdot 8 - 2$, and the five secondary salts each worked at the first try.

> [!trap] What is random, and what is guaranteed
> - **The search time is worst-case** once the table is built; the **space** (and the building time) is a random variable, over the primary salt and the secondary salts.
> - **Quadratic sizes are what make the secondary tables collision-free.** In a secondary table of linear size, collisions become almost certain as $n_j$ grows (with ideal hashing, 10 keys in 20 cells collide with probability above 0.93), so the retries would not end quickly.
> - Lemma 7 bounds the *expected* space. (Not in the note: redrawing the primary function whenever $\sum_j n_j^2 > 6n$ — probability at most $1/2$, by Markov — makes the space $O(n)$ in the worst case at the price of expected rebuilds.)

## 5.8 Open addressing

**Open addressing** stores the keys in the table itself and resolves collisions by looking elsewhere: each key $x$ has a **probe sequence** $\langle h_0(x), h_1(x), \ldots, h_{m-1}(x)\rangle$, a permutation of $[m]$, and is stored in the first empty slot of its sequence. The load factor is therefore at most 1.

```text
OpenAddressSearch(x):
    for i ← 0 to m − 1
        if T[h_i(x)] = x
            return h_i(x)
        else if T[h_i(x)] = ∅
            return 'absent'
    return 'full'
```

It returns the slot of $x$, or 'absent' when it reaches an empty slot (where an insertion of $x$ would go), or 'full'. Insertion is the same loop with `return 'absent'` replaced by $T[h_i(x)]\leftarrow x$. It is correct because there are no deletions: when $x$ was inserted, every slot before its position in its own probe sequence was occupied, and stays occupied. Time: $O(\text{number of probes})$.

The analysis assumes an idealization that cannot be implemented but predicts practice well:

> [!definition] Strong uniform hashing assumption
> For each key $x$, the probe sequence $\langle h_0(x),\ldots,h_{m-1}(x)\rangle$ is equally likely to be any of the $m!$ permutations of $[m]$ (independently for different keys).

Two consequences: each single probe $h_i(x)$ is uniform on $[m]$, and after the first probe the rest of the sequence is a uniformly random permutation of the other $m-1$ slots. So for an unsuccessful search with $n$ keys stored, the first probe hits an occupied slot with probability $n/m$, and then the search continues as an unsuccessful search in a table of $m - 1$ slots holding $n - 1$ keys:
$$
\operatorname{E}[T(m,n)] = 1 + \frac nm\operatorname{E}[T(m-1,n-1)],\qquad T(m,0) = 1 .
$$

> [!key] Expected probes, unsuccessful search
> $$
> \operatorname{E}[T(m,n)] \le \frac{m}{m-n} = \frac1{1-\alpha}\qquad (n < m).
> $$
> In fact the recurrence solves exactly to $\operatorname{E}[T(m,n)] = \dfrac{m+1}{m-n+1}$ (not in the note; checked against the recurrence for $m\le 60$ and by brute force over all probe permutations for $m\le 6$). Either way, $O(1)$ unless the table is nearly full: at most 2 probes at $\alpha = 1/2$, 10 at $\alpha = 0.9$.

> [!proof]- Proof (click to expand)
> Induction on $n$: $T(m,0) = 1 = m/m$, and $1 + \frac nm\cdot\frac{m-1}{m-n} < 1 + \frac nm\cdot\frac m{m-n} = \frac m{m-n}$. For the exact value, $1 + \frac nm\cdot\frac{m}{m-n+1} = \frac{m+1}{m-n+1}$. $\square$

## 5.9 Linear and binary probing

Ideal random permutations cannot be generated, so practical schemes derive the whole probe sequence from one or two hash functions.

- **Linear probing:** $h_i(x) = (h(x) + i)\bmod m$. Simple, and the best for caches, since it scans consecutive slots. The note states (without proof) that its expected probe count is constant whenever $\alpha < 1$, even for hash functions of limited independence, but grows quickly as $\alpha\to 1$ because occupied slots **cluster** into long runs — which in turn means each cache line loaded holds several useful slots.
- **Binary probing**, for $m = 2^\ell$: $h_i(x) = h(x)\oplus i$ (bitwise exclusive-or). With an aligned table it finishes each aligned block of $2^k$ slots — a cache line, a disk page — before touching the next, and it is slightly easier to analyze (§5.10).
- **Quadratic probing** $h_i(x) = (h(x) + i^2)\bmod m$ and **double hashing** $h_i(x) = (h(x) + i\cdot h'(x))\bmod m$ have some theoretical advantages but are slower in practice, again because of caches. Note that neither need produce the permutation that §5.8 requires: quadratic probing visits only $(m+1)/2$ slots when $m$ is an odd prime (and never all $m$ slots for $m\ge 3$), and double hashing visits every slot exactly when $\gcd(h'(x), m) = 1$.

## 5.10 Analysis of binary probing

(★ in the note: optional.)

> [!key] Lemmas 8 and 9
> In a table of size $m = 2^\ell$ holding $n\le m/4$ keys, built by binary probing, every search takes $O(1)$ expected time, assuming ideal random hashing (**Lemma 8**) — and even assuming only 5-uniform hashing (**Lemma 9**).

**Blocks.** For $0\le k\le\ell$, cut $H[0\,..\,m-1]$ into $m/2^k$ aligned **level-$k$ blocks** $H[c2^k\,..\,(c+1)2^k-1]$; they form a complete binary tree. For an upper bound, pretend the search reads each uncle block **entirely**, stopping after the first block that contains $x$ or an empty cell:

```text
LooseBinaryProbe(x):
    if H[h(x)] = x
        return True
    if H[h(x)] is empty
        return False
    for k ← 0 to ℓ − 1
        found ← False;  empty ← False
        for each index j ∈ B′_k(x), in any order
            if H[j] = x
                found ← True
            if H[j] is empty
                empty ← True
        if found
            return True
        if empty
            return False
    return Full
```

This repairs the note's procedure, whose inner test "if $\mathit{first}\ne\textsf{Dunno}$" never fires (so it always answers Full); with "$= \textsf{Dunno}$" it would record whichever of $x$ and an empty cell it meets first, which in an arbitrary order can be the empty cell although $x$ is in the block. The version above agrees with binary probing and reads at least as many cells. The proof assumes $x$ is absent; a present key is found no slower.

**The proof of Lemma 8.** The loose search reads $B'_k(x)$ only after $B'_{k-1}(x)$ was full, so
$$
\operatorname{E}[T(x)]\le\sum_{k=0}^{\ell-1}O(2^k)\cdot F_k,
$$
where $F_k$ is the probability that a fixed level-$k$ block is full (all blocks of a level are alike under ideal random hashing). Call a level-$k$ block **popular** if at least $2^k$ stored keys hash into it; popular blocks are full, but not conversely.

> [!key] Full blocks have popular relatives
> If a block is full, then it or one of its uncles (the siblings of it and of its ancestors) is popular.

> [!proof]- Proof (click to expand)
> Let $B$ be full and not popular. Then some key $y$ stored in $B$ hashes outside $B$; take the first such $y$ inserted. Binary probing put $y$ into $B'_j(y)\supseteq B$, which happens only when $B_j(y)$, an uncle of $B$, was already full. Let $U$ be the first uncle of $B$ to become full. Keys from outside $U$ can enter $U$ only while one of $U$'s own uncles is full; those are $B$ or an ancestor of $B$ (not full yet, since $y$ later found room in $B$) or uncles of $B$ (not full yet, since $U$ was the first). So every key in $U$ hashes into $U$, and $U$ is popular. $\square$

(Checked on 3,000 random binary-probing tables.) Hence, with $P_k$ the probability that a fixed level-$k$ block is popular, $F_k\le 2P_k + \sum_{j>k}P_j$. Each key lands in a fixed level-$k$ block with probability $2^k/m$, so by the union bound over sets of $2^k$ keys and $s!\ge (s/e)^s$,
$$
P_k\le\binom{n}{2^k}\Big(\frac{2^k}{m}\Big)^{2^k} < \Big(\frac{en}{m}\Big)^{2^k}\le\Big(\frac e4\Big)^{2^k}
$$
(the note writes "$P_k =$"; it is a union bound). Since $e < 4$, this is less than $4^{-k}$ for $k\ge 4$, so $F_k = O(4^{-k})$ and $\operatorname{E}[T(x)] = \sum_k O(2^k)\,O(4^{-k}) = O(1)$. $\square$ In simulation, at $n = m/4$ an unsuccessful search averages about 1.4 probes ($m = 2^{10}$ and $2^{14}$).

**Lemma 9: five-wise independence suffices.** Only the bound on $P_k$ changes. Fix $x$ and the block $B'_k(x)$; for each of the $n$ stored keys $y$ let $P_y = [h(y)\in B'_k(x)]$, with mean $p = 2^k/m$, and $Q_y = P_y - p$, with mean 0. With $h$ 5-uniform, the $Q_y$ are 4-wise independent (one degree of independence is spent on $h(x)$, which locates the block; see [[4-lecture-notes/04-tail-inequalities#42-independence|§4.2 of note 4]]). The block is popular when $\sum_y P_y\ge 2^k$, that is, when $Q = \sum_y Q_y\ge 2^k - pn$, and $n\le m/4$ makes this threshold at least $\tfrac34 2^k\ge 2^{k-1}$. Apply Markov's inequality to $Q^4$ — a fourth-moment bound, as in [[4-lecture-notes/04-tail-inequalities#44-higher-moment-inequalities|§4.4 of note 4]]: expanding $\operatorname{E}[Q^4]$, every term in which some index occurs only once vanishes, leaving
$$
\operatorname{E}[Q^4] = \sum_y\operatorname{E}[Q_y^4] + 6\sum_{y<z}\operatorname{E}[Q_y^2]\operatorname{E}[Q_z^2] < np + 3n^2p^2\le 2^{k-2} + 3\cdot 2^{2(k-2)}\le 2^{2(k-1)}\quad(k\ge 2),
$$
using $\operatorname{E}[Q_y^2] = p(1-p) < p$, $\operatorname{E}[Q_y^4] = p(1-p)\big((1-p)^3 + p^3\big) < p$ and $np\le mp/4 = 2^{k-2}$. So $P_k\le\operatorname{E}[Q^4]/2^{4(k-1)}\le 2^{-2(k-1)}$ for $k\ge 2$, again $O(4^{-k})$. $\square$

The note's computation (pp. 16–17) sums over $n-1$ keys with the threshold $2^k - 1$, and has four slips, none affecting the result: it rewrites $2^k - 1 - 2^k(n-1)/m$ as $2^k(1 - n/m - 1/m) - 1$ instead of $2^k(1 - n/m + 1/m) - 1$; its step to the threshold $2^{k-1}$ holds only for $k\ge 2$; its "$<$" between $mp/4 + 3(mp/4)^2$ and $2^{k-2} + 3\cdot 2^{2(k-2)}$ is an equality ($mp = 2^k$); and its final "$<$" holds only for $k\ge 3$ (equality at $k = 2$). Finitely many small $k$ contribute $O(1)$ anyway.

## Summary

- Choose $h$ **at random** from a family when the table is built; the keys are arbitrary, and every expectation is over $h$ alone. Uniform: each key's hash is uniform. Universal: $\Pr[h(x) = h(y)]\le 1/m$; near-universal: $\le 2/m$; $k$-uniform: any $k$ distinct keys get independent uniform hashes.
- Chaining with (near-)universal hashing: expected list length $\le\alpha$ ($2\alpha$), search $\Theta(1+\alpha)$ expected. The **longest** list is $\Theta(\log n/\log\log n)$ at $\alpha = 1$, even with ideal hashing.
- $((ax+b)\bmod p)\bmod m$ is universal (collision probability exactly $\frac{(p - p\bmod m)(p - (m - p\bmod m))}{mp(p-1)} < \frac1m$); $(ax\bmod p)\bmod m$ is only near-universal ($2/(m+1)$ when $p\bmod(m+1) = 1$); the top $\ell$ bits of $ax\bmod 2^w$, odd $a$, is near-universal — one multiply and one shift.
- $\binom n2/m$ expected collisions: none with probability $> 1/2$ at $m = n^2$ (ideal) or $2n^2$ (near-universal); none with probability $\ge 1 - n^{-\varepsilon}$ at $m = n^{2+\varepsilon}$.
- Two-level (perfect) hashing: primary size $n$, secondary sizes $2n_j^2$ redrawn until collision-free; $\operatorname{E}[\sum n_j^2]\le 3n - 2$, so $O(n)$ expected space and $O(1)$ worst-case search.
- Open addressing under strong uniform hashing: unsuccessful search $\frac{m+1}{m-n+1}\le\frac1{1-\alpha}$ expected probes. Linear probing clusters (about $\frac12(1 + (1-\alpha)^{-2})$ probes); binary probing at $\alpha\le 1/4$ is $O(1)$ expected, with ideal or 5-uniform hashing, by the popular-block argument.
- The note ends with 4 exercises (finding a perfect hash function by trial with ideal random functions; families separating uniform, universal, $k$-uniform and pairwise-independent; $\mathcal{MB}$ is neither uniform nor pairwise independent, and a strongly near-universal variant; the longest probe sequence in open addressing at $\alpha\le 1/2$).

> [!exam] For CS 374
> Nothing on this page is examined: the note is not assigned this semester, and hashing is CS 473 material at Illinois. Its one point of contact with the course is a rule worth understanding: the dynamic-programming rubric gives **no credit for a hash table as the memoization structure** ([[0-toolkit/06-how-exams-are-graded#12-dynamic-programming|how exams are graded]]). The reason is visible here — a hash table's $O(1)$ is an **expected** bound over the random choice of $h$ (and the slowest of $n$ lookups costs $\Theta(\log n/\log\log n)$ even with ideal hashing), whereas an array indexed by the subproblem's parameters gives worst-case $O(1)$ access, which is what a worst-case running-time analysis of the dynamic program needs. Likewise, a "fast adjacency list" ([[2-algorithms/05-basic-graph-algorithms#54-data-structures|§5.4]]) answers edge queries in $O(1)$ *expected* time.
