*Midterm 2 practice test 2 · CS/ECE 374 A, Fall 2026 · five problems in the exam's format · the other tests: [[3-homework-and-exams/midterm-2-practice-1|test 1]], [[3-homework-and-exams/midterm-2-practice-3|test 3]], [[3-homework-and-exams/midterm-2-dp-practice|DP practice]] · how it is graded: [[0-toolkit/06-how-exams-are-graded|rubrics]] · on one page: [[0-toolkit/09-midterm-2-cheat-sheet|cheat sheet]]*

> [!abstract] In one breath
> **Problem 1** marks four structures on one weighted dag: a depth-first tree from $v$ and a breadth-first tree from $w$ (each covers only what its root reaches — nothing enters $t$), the shortest-path tree from $t$ (negative edges are harmless in a dag: relax in topological order), and the dag's only topological order, $t, v, w, u, z, y, x$, which is forced because consecutive vertices are joined by edges. **Problem 2** finds the vertices reachable by a walk without two consecutive edges of the same color: put the color of the last edge into the vertex, $(v, c)$, and run whatever-first search, $O(V+E)$. **Problem 3** is an interval dynamic program: $\textsf{SquareDepth}(i, j)$ counts whether $X[i\,..\,j]$ is a square and adds the better of the two deletions; the square tests dominate, $O(n^4)$. **Problem 4** merges $k$ sorted arrays by merging the two halves of the list of arrays recursively, $T(k) = 2T(k/2) + O(nk) = O(nk\log k)$. **Problem 5** schedules classes: the earliest term of class $v$ is the number of vertices on a longest path ending at $v$ (a dag DP in $O(V+E)$), and for 75% of the classes the answer is the smallest $T$ with at least $3V/4$ classes of earliest term at most $T$.

## Problem 1 — Search trees and a topological order

> [!question] Problem 1
> Clearly indicate the following structures in the directed graph below, or write NONE if the structure does not exist. The graph has seven vertices and fifteen weighted edges: $t\to u$ (4), $t\to v$ (3), $t\to x$ (6), $t\to y$ (2), $u\to x$ (1), $u\to z$ (4), $v\to u$ (2), $v\to w$ (6), $v\to z$ ($-2$), $w\to u$ (5), $w\to y$ (2), $w\to z$ (4), $y\to x$ (2), $z\to x$ (1), $z\to y$ ($-7$).
>
> (a) A depth-first search tree rooted at $v$. (b) A breadth-first search tree rooted at $w$. (c) A shortest-path tree rooted at $t$. (d) A list of vertices in topological order.

*Concepts: [[concepts/depth-first-search]], [[concepts/breadth-first-search]], [[concepts/shortest-paths]], [[concepts/topological-sort]] · the algorithms: [[2-algorithms/06-depth-first-search#61-preorder-and-postorder|§6.1]], [[2-algorithms/08-shortest-paths#84-unweighted-graphs-breadth-first-search|§8.4]], [[2-algorithms/08-shortest-paths#85-directed-acyclic-graphs-depth-first-search|§8.5]], [[2-algorithms/06-depth-first-search#63-topological-sort|§6.3]]*

Two facts decide most of the problem. **No edge enters $t$**, so no search from another vertex reaches $t$; and **the graph is a dag** (part (d) exhibits a topological order), so it has no cycles at all, negative or not. Where the search has a choice, take the neighbors in alphabetical order; any tree the search can produce is a correct answer.

> [!key] Answer (a): depth-first tree rooted at $v$
> $v\to u$, $u\to x$, $u\to z$, $z\to y$, $v\to w$. It spans the six vertices other than $t$, which $v$ does not reach.

(Alphabetical order: from $v$ go to $u$, from $u$ to $x$ (a dead end), then to $z$, from $z$ to $y$; back at $v$, the next unvisited neighbor is $w$, whose neighbors are all visited.) Other neighbor orders give other correct trees, for example $v\to w$, $w\to u$, $u\to x$, $u\to z$, $z\to y$.

> [!key] Answer (b): breadth-first tree rooted at $w$
> $w\to u$, $w\to y$, $w\to z$, $u\to x$. The levels are $\{w\}$, $\{u, y, z\}$, $\{x\}$; $t$ and $v$ are not reachable from $w$.

The parent of $x$ can be $u$, $y$ or $z$ — all three are at distance 1 and have an edge to $x$ — so there are three correct answers; the one above follows alphabetical order.

> [!key] Answer (c): shortest-path tree rooted at $t$
> $t\to u$, $t\to v$, $v\to w$, $v\to z$, $z\to y$, $y\to x$, with distances $u$ 4, $v$ 3, $w$ 9, $z$ 1, $y$ $-6$, $x$ $-4$. This tree is unique.

Relax the edges in topological order (DagSSSP — the right black box for any weights on a dag): $\mathit{dist}(v) = 3$; $\mathit{dist}(w) = 3 + 6 = 9$; $\mathit{dist}(u) = \min\{4,\ 3 + 2,\ 9 + 5\} = 4$; $\mathit{dist}(z) = \min\{4 + 4,\ 3 - 2,\ 9 + 4\} = 1$; $\mathit{dist}(y) = \min\{2,\ 9 + 2,\ 1 - 7\} = -6$; $\mathit{dist}(x) = \min\{6,\ 4 + 1,\ -6 + 2,\ 1 + 1\} = -4$. Every minimum is attained by exactly one edge. The tempting shortcut $t\to y$ (weight 2) is not in the tree: $t\to v\to z\to y$ has length $-6$.

> [!key] Answer (d): topological order
> $t, v, w, u, z, y, x$ — the only one.

Every topological order must put $t$ first (it is the only source) and $x$ last (the only sink). It is unique because each pair of consecutive vertices is joined by an edge — $t\to v$, $v\to w$, $w\to u$, $u\to z$, $z\to y$, $y\to x$ — so the dag has a path through all seven vertices, and that path fixes the order.

> [!exam] How this is graded
> No standard rubric covers Problem 1; each structure is right or wrong. The usual losses: a search tree that includes an unreachable vertex ($t$), a breadth-first tree with an edge that skips a level, a "shortest-path tree" built by Dijkstra's algorithm — the version that never extracts a vertex twice finishes $y$ with distance 2 before it relaxes $z\to y$ (weight $-7$) and ends with $\mathit{dist}(x) = 2$ instead of $-4$ — and a topological order read off the preorder. Method and drill: [[0-toolkit/08-review-algorithms#1-the-exam-and-how-to-attack-each-problem|review §1, type 1]], [[0-toolkit/08-review-algorithms#10-short-answer-drill|review §10, drill D]].

## Problem 2 — Rainbow walks

> [!question] Problem 2
> Each edge of a directed graph $G = (V, E)$ is colored red, green or blue. The edges have no weights, and $G$ is not necessarily a dag. A **rainbow walk** is a walk in $G$ that does not contain two consecutive edges of the same color. Describe and analyze an algorithm to find all vertices of $G$ that are reachable from a given vertex $s$ through a rainbow walk.

*Template: [[0-toolkit/02-proof-templates#22-solving-a-problem-by-graph-reduction|graph reduction]] · concepts: [[concepts/graph-reductions]], [[concepts/whatever-first-search]] · the same trick: [[2-algorithms/05-basic-graph-algorithms#state-in-the-vertices-walks-of-even-length|state in the vertices]]*

Whether the walk may take an edge depends on the color of the **previous** edge, so that color goes into the vertex. Write $\mathit{col}(u\to v)$ for the color of an edge.

> [!key] Answer
> - **The graph.** A **directed** graph $H$ with a vertex $(v, c)$ for every vertex $v\in V$ and color $c\in\{\text{red}, \text{green}, \text{blue}\}$ — "the walk is at $v$, and its last edge had color $c$" — plus one start vertex $(s, \text{none})$. For every edge $u\to v$ of $G$, with color $c' = \mathit{col}(u\to v)$, $H$ has the edges $(u, c)\to(v, c')$ for the two colors $c\ne c'$, and, if $u = s$, the edge $(s, \text{none})\to(v, c')$. No weights.
> - **The problem on it.** Reachability from $(s, \text{none})$ in $H$. A vertex $v$ is reachable from $s$ by a rainbow walk if and only if $v = s$ or some vertex $(v, c)$ is reachable from $(s, \text{none})$.
> - **The algorithm.** Whatever-first search from $(s, \text{none})$ (black box), then one pass over the marked vertices to collect their first components.
> - **The time.** $H$ has $3V + 1$ vertices and at most $3E$ edges (two per edge of $G$, plus one for each edge leaving $s$), and it can be built in $O(V + E)$ time; the search takes $O(V + E)$: **$O(V + E)$** in all.

**Why it is correct.** By construction, walks in $H$ from $(s, \text{none})$ correspond one-to-one to rainbow walks in $G$ from $s$: a walk in $H$ ending at $(v, c)$ is a rainbow walk in $G$ that ends at $v$ with an edge of color $c$, because $H$ only allows an edge whose color differs from the one stored in the vertex.

> [!trap] Modifying the search instead of the graph
> "Run depth-first search and skip an edge with the same color as the edge we arrived by" is wrong: a vertex is marked once, by whichever color reaches it first, and a walk that arrives later with a different last color — and could continue along edges the first arrival could not take — is cut off. That is exactly why the color belongs in the vertex.

> [!exam] How this is graded
> Graph-reduction rubric ([[0-toolkit/06-how-exams-are-graded#13-graph-reductions|§13]]): **3** for the graph (vertices $(v, c)$, edges as an explicit function of $G$'s edges and colors, "directed"; there are no weights); **3** for the problem — reachability from $(s, \text{none})$, and how to read the answer off the marked vertices; **2** for whatever-first search (breadth- or depth-first costs ½ as more specific than necessary); **2** for $O(V+E)$ in the input's parameters.

## Problem 3 — Square-depth

> [!question] Problem 3
> Given an $n$-digit integer $X$, repeatedly delete one digit from either end of $X$ (your choice) until no digits are left. The **square-depth** of $X$ is the maximum number of perfect squares that you can see during this process. For example, 32492 has square-depth 3, by the deletions $32492\to 3249\to 324\to 24\to 4\to\varepsilon$, which show $3249 = 57^2$, $324 = 18^2$ and $4 = 2^2$. Describe and analyze an algorithm to compute the square-depth of $X$, given as an array $X[1\,..\,n]$ of digits. A subroutine $\textsf{IsSquare}$ decides whether a $k$-digit number (given as an array of digits) is a perfect square in $O(k^2)$ time.

*Template: [[0-toolkit/02-proof-templates#20-writing-up-a-dynamic-program|dynamic program]] · concept: [[concepts/dynamic-programming]] · the interval shape: [[0-toolkit/08-review-algorithms#4-chapter-3--dynamic-programming|subproblem shapes]]*

Every number seen along the way is a contiguous piece $X[i\,..\,j]$ of the original digits, and the only decision is which end to delete next: an interval dynamic program.

> [!key] Answer
> **Function.** For $1\le i\le n+1$ and $i - 1\le j\le n$, let $\textsf{SquareDepth}(i, j)$ be the square-depth of the number with digits $X[i\,..\,j]$: the most perfect squares that can be seen when starting from $X[i\,..\,j]$ (counting $X[i\,..\,j]$ itself) and deleting digits from either end until none are left. We need $\textsf{SquareDepth}(1, n)$.
>
> **Recurrence.** Write $\textsf{Sq}(i, j) = 1$ if $\textsf{IsSquare}(X[i\,..\,j])$ and 0 otherwise. If $i > j$ (no digits left), $\textsf{SquareDepth}(i, j) = 0$; if $i\le j$,
> $$
> \textsf{SquareDepth}(i, j) = \textsf{Sq}(i, j) + \max\big\{\textsf{SquareDepth}(i+1, j),\ \textsf{SquareDepth}(i, j-1)\big\}.
> $$
> **Memoization.** An array $\textsf{SquareDepth}[1\,..\,n+1, 0\,..\,n]$, using the entries with $j\ge i - 1$.
>
> **Evaluation order.** $i$ from $n+1$ down to 1 in the outer loop, $j$ from $i - 1$ up to $n$ in the inner loop: $(i+1, j)$ is in a later row, already filled, and $(i, j-1)$ is to the left in the same row.
>
> **Time.** $O(n^2)$ entries. Entry $(i, j)$ calls $\textsf{IsSquare}$ on $j - i + 1$ digits, $O((j-i+1)^2)$ time, plus $O(1)$; summed over all intervals, $\sum_{i\le j}(j-i+1)^2\le n^2\cdot n^2$, so **$O(n^4)$** time.

On the example, $\textsf{SquareDepth}(1, 5) = 3$ for $X = 32492$, along the deletions shown in the problem (32492 itself is not a square).

> [!exam] How this is graded
> Dynamic-programming rubric ([[0-toolkit/06-how-exams-are-graded#12-dynamic-programming|§12]]): **3** for describing $\textsf{SquareDepth}(i, j)$ in terms of the interval $X[i\,..\,j]$ — "the digits still left" is not a description, the interval is; **4** for the recurrence, with the empty interval as base case; **3** for the array, the order and the time. The time must include the cost of $\textsf{IsSquare}$: $O(n^2)$ entries but $O(n^4)$ time.

## Problem 4 — Merging k sorted arrays

> [!question] Problem 4
> You are given $k$ arrays $A_1[1\,..\,n], A_2[1\,..\,n], \ldots, A_k[1\,..\,n]$, each of length $n$ and sorted in increasing order. Describe an algorithm to merge them into a single sorted array, and analyze its running time as a function of $n$ and $k$.

*Template: [[0-toolkit/02-proof-templates#18-writing-up-a-divide-and-conquer-algorithm|divide and conquer]] · concepts: [[concepts/divide-and-conquer]], [[concepts/recursion-trees]] · the black box: the linear-time merge of [[2-algorithms/01-recursion#14-mergesort|mergesort, §1.4]]*

Merging the arrays one after another into a growing result costs $2n + 3n + \cdots + kn = \Theta(nk^2)$. Pairing them up like mergesort does better.

> [!key] Answer
> **What the recursive algorithm returns.** For $1\le i\le j\le k$, $\textsf{MergeAll}(i, j)$ returns one sorted array containing all elements of $A_i, A_{i+1}, \ldots, A_j$. We call $\textsf{MergeAll}(1, k)$.
>
> **Base case.** If $i = j$, return $A_i$ (a copy, if the input must not be modified).
>
> **Divide.** Let $m = \lfloor(i+j)/2\rfloor$; compute $L = \textsf{MergeAll}(i, m)$ and $R = \textsf{MergeAll}(m+1, j)$.
>
> **Conquer.** Return $\textsf{Merge}(L, R)$, mergesort's merge of two sorted arrays, which takes time linear in their total length.
>
> **Time.** A call on $\kappa$ arrays merges two arrays of total length $\kappa n$, $O(\kappa n)$ time:
> $$
> T(k) = T(\lceil k/2\rceil) + T(\lfloor k/2\rfloor) + O(nk),\qquad T(1) = O(n).
> $$
> In the recursion tree every level merges all $nk$ elements once, $O(nk)$ per level, and there are $\lceil\lg k\rceil$ levels: **$T(k) = O(nk\log k)$**.

A different $O(nk\log k)$ algorithm keeps the current front element of every array in a min-heap of size $k$ and repeatedly extracts the minimum.

> [!exam] How this is graded
> Recursive-algorithm rubric ([[0-toolkit/06-how-exams-are-graded#11-recursive-algorithms|§11]]): **3** for what $\textsf{MergeAll}(i, j)$ returns, **1** for the base case, **2** for splitting the list of arrays in half, **2** for merging the two results with the standard merge (cited, not re-explained), **2** for the recurrence and $O(nk\log k)$. The time must be in both $n$ and $k$; "$O(N\log N)$" without saying what $N$ is loses a point.

## Problem 5 — Speed-running a degree

> [!question] Problem 5
> A university's degree requires a fixed set of classes with strictly enforced prerequisites; there is no limit on the number of classes per term.
>
> (a) You are given a directed acyclic graph $G = (V, E)$, where every vertex is a required class and an edge $u\to v$ means that $u$ must be completed before $v$ can begin. Describe an algorithm that computes a schedule using the minimum number of terms: for each class, the term in which you take it.
>
> (b) Describe an algorithm that computes the minimum number of terms needed to take at least 75% of the classes in $G$, while still obeying all prerequisite constraints. *[Hint: use the output of part (a).]*

*Template: [[0-toolkit/02-proof-templates#20-writing-up-a-dynamic-program|dynamic program]] · concepts: [[concepts/dynamic-programming-on-dags]], [[concepts/topological-sort]] · the method: [[2-algorithms/06-depth-first-search#dynamic-programming-in-dags|DP in dags, §6.4]]*

### (a) The earliest term of every class

Take every class as early as its prerequisites allow. Class $v$ can be taken in term 1 if it has no prerequisites, and otherwise one term after the latest of its prerequisites.

> [!key] Answer (a)
> **Function.** For every class $v$, let $\textsf{Term}(v)$ be the earliest term in which $v$ can be taken — equivalently, the number of vertices on a longest path in $G$ that ends at $v$. The schedule takes every class $v$ in term $\textsf{Term}(v)$.
>
> **Recurrence.**
> $$
> \textsf{Term}(v) = 1 + \max\big\{\textsf{Term}(u) \;\big|\; u\to v\in E\big\},\qquad\text{with } \max\varnothing = 0.
> $$
> **Memoization.** A field $v.\mathit{term}$ in every vertex.
>
> **Evaluation order.** A topological order of $G$ (decreasing finishing time of a depth-first search), so that every prerequisite is evaluated before the class that needs it. To read the in-edges, build the reversed graph first, or push values forward: process the vertices in topological order and, for each edge $v\to w$, raise $w.\mathit{term}$ (initially 1) to at least $v.\mathit{term} + 1$.
>
> **Time.** Topological sort $O(V + E)$; every edge is looked at once: **$O(V + E)$**. The number of terms is $\max_v\textsf{Term}(v)$.

**Why it is optimal.** The schedule is valid: an edge $u\to v$ gives $\textsf{Term}(v)\ge\textsf{Term}(u) + 1$. And no valid schedule does better: by induction in topological order, any valid schedule takes each class $v$ in a term $\mathit{term}(v)\ge\textsf{Term}(v)$ — if $v$ has no prerequisites, $\mathit{term}(v)\ge 1$; otherwise $\mathit{term}(v)\ge\mathit{term}(u) + 1\ge\textsf{Term}(u) + 1$ for every prerequisite $u$. So every schedule uses at least $\max_v\textsf{Term}(v)$ terms, and this one uses exactly that many.

### (b) Three quarters of the classes

> [!key] Lemma
> *For every $T\ge 0$, the largest number of classes that can be taken in $T$ terms is $\lvert\{v \mid \textsf{Term}(v)\le T\}\rvert$.*
>
> **Proof.** Taking class $v$ requires completing all its prerequisites, and theirs, so a longest path ending at $v$ must be taken in strictly increasing terms: $v$ itself is taken no earlier than term $\textsf{Term}(v)$. Hence every class taken within $T$ terms has $\textsf{Term}(v)\le T$. Conversely, the set $\{v \mid \textsf{Term}(v)\le T\}$ contains every prerequisite of its members (an edge $u\to v$ gives $\textsf{Term}(u) < \textsf{Term}(v)$), and the schedule of part (a) takes all of it in $T$ terms. $\square$

> [!key] Answer (b)
> Compute $\textsf{Term}(v)$ for every class as in (a). Count the classes per term: $\mathit{count}[\tau] = \lvert\{v \mid \textsf{Term}(v) = \tau\}\rvert$ for $1\le\tau\le V$, one pass over the vertices. Then scan $\tau = 1, 2, \ldots$ while accumulating $\mathit{count}[1] + \cdots + \mathit{count}[\tau]$, and return the first $\tau$ at which the sum reaches $\tfrac34 V$. By the lemma this is the minimum number of terms. **Time:** $O(V + E)$ for part (a) and $O(V)$ for the counting and the scan: **$O(V + E)$**. (Sorting the vertices by $\textsf{Term}$ instead also works, in $O(V\log V + E)$.)

> [!exam] How this is graded
> Part (a) is a dynamic program on a dag (or, equivalently, a longest-path computation in a dag, which is also how a graph-reduction answer would phrase it): **3** for what $\textsf{Term}(v)$ means, **4** for the recurrence with its base case (no prerequisites: term 1), **3** for the field per vertex, the topological order and $O(V + E)$ — [[0-toolkit/06-how-exams-are-graded#12-dynamic-programming|§12]]. "Longest path" is easy only because $G$ is a dag; in general graphs it is NP-hard. In (b) the point to justify is that taking the classes with the smallest $\textsf{Term}$ values is optimal — that is the lemma.
