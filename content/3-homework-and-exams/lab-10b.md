> [!abstract] In one breath
> Problem 1 asks what one wrong edge weight does to an all-pairs distance array. Everything rests on one fact: a shortest path is simple, so it uses the edge $u\to v$ at most once, and shortest paths **into $u$** or **out of $v$** never use it — column $u$ and row $v$ of the array are right whatever the weight. If the true weight is **smaller**, a new shortest path is an old one or "old path to $u$, the edge, old path from $v$", so $\mathit{dist}[x, y]\leftarrow\min\{\mathit{dist}[x, y],\ \mathit{dist}[x, u] + w'(u\to v) + \mathit{dist}[v, y]\}$ repairs every entry in $O(V^2)$ time, and the old array was right iff $\mathit{dist}[u, v]\le w'(u\to v)$ — one comparison. Any array, whatever the weights did, is checked like a single-source distance array from every source: diagonal 0, no tense edge, and every finite entry reached from its source along **tight** edges, $O(VE)$ — and since only the entry $(u, v)$ really matters, one such search from $u$ is enough. Yet *repairing* after an increase is as hard as computing all distances from scratch: a two-vertex gadget turns any repair algorithm into an all-pairs shortest-path algorithm. Problem 2 is the classic arbitrage reduction: with edge weights $-\ln R[i, j]$, a sequence of trades multiplies the money by $e^{-\text{length}}$, so the most of each currency is a shortest path (Bellman–Ford from currency 1, $O(n^3)$), and an **arbitrage cycle is a negative cycle** — detected by Bellman–Ford from a new source and returned by walking its predecessor pointers, both $O(n^3)$.

## Problem 1 — One wrong edge weight

> [!question] Problem 1
> You have just computed the array $\mathit{dist}[1\,..\,V, 1\,..\,V]$ of shortest-path distances between **all** pairs of vertices of an edge-weighted directed graph $G = (V, E)$ — and then you discover that you entered the weight of a single edge $u\to v$ incorrectly. Was all that CPU time wasted? Maybe your distances are correct after all. Let $w(u\to v)$ be the weight you used and $w'(u\to v)$ the correct weight of $u\to v$. There is no negative cycle in $G$ with either weight.
>
> (a) Suppose $w(u\to v) > w'(u\to v)$: the weight you used was larger than the true one. Describe an algorithm that repairs the distance array in $O(V^2)$ time. *(Handout's hint: for every pair of vertices $x$ and $y$, either $u\to v$ is on the shortest path from $x$ to $y$ or it isn't.)*
>
> (b) Maybe even that was too much work. Describe an algorithm that decides in $O(1)$ time whether your original array is actually correct, again assuming $w(u\to v) > w'(u\to v)$. *(Hint: either $u\to v$ is the shortest path from $u$ to $v$ or it isn't.)*
>
> (c) *To think about later:* Describe an algorithm that decides in $O(EV)$ time whether your distance array is actually correct, even if $w(u\to v) < w'(u\to v)$.
>
> (d) *To think about later:* Argue that when $w(u\to v) < w'(u\to v)$, repairing the distance array *requires* recomputing shortest paths from scratch, at least in the worst case.

> [!note] Notation, and the fact everything rests on
> - $\delta(x, y)$ is the distance from $x$ to $y$ with the weight $w$ — the array we have: $\mathit{dist}[x, y] = \delta(x, y)$. $\delta'(x, y)$ is the distance with the correct weight $w'$. All other edges weigh the same in both. We take $u\ne v$: a loop lies on no path, so its weight would not matter.
> - Neither weighting has a negative cycle, so in both, the distance is the length of a shortest **simple path**, or $\infty$ if there is none ([[2-algorithms/08-shortest-paths#82-negative-edges|§8.2]]), and no walk is shorter than the distance between its ends. Both weightings have the same edges, so $\delta(x, y) = \infty$ iff $\delta'(x, y) = \infty$.
> - **Simple paths and $u\to v$.** A simple path uses $u\to v$ at most once. A simple path that **ends at $u$** never uses it (it would leave $u$ and have to come back), nor does one that **starts at $v$**; and a simple path **from $u$ to $v$** uses it only if it *is* the one-edge path $u\to v$.
>
> Hence, whichever weight is right,
> $$
> \delta'(x, u) = \delta(x, u)\quad\text{and}\quad\delta'(v, y) = \delta(v, y)\qquad\text{for all vertices } x, y:
> $$
> **column $u$ and row $v$ of the array are always correct.**

### (a) A lighter edge: repair in O(V²)

> [!hint]- Hint
> A new shortest path from $x$ to $y$ either avoids $u\to v$ or uses it once. In the second case, what are the pieces before and after the edge, and does the array already know their lengths?

> [!solution]- Solution
> **The idea.** Lowering the weight of one edge can only help paths that use it. A new shortest path from $x$ to $y$ that uses $u\to v$ uses it once, as "a path from $x$ to $u$, then $u\to v$, then a path from $v$ to $y$", and the best such pieces are the old shortest paths, whose lengths $\mathit{dist}[x, u]$ and $\mathit{dist}[v, y]$ are still exact (column $u$, row $v$). So every entry needs one comparison: the old value, or the detour through the lighter edge. It is a single phase of Floyd–Warshall ([[2-algorithms/09-all-pairs-shortest-paths#98-floydwarshall|§9.8]]) with the edge $u\to v$ in the middle — compare [[2-algorithms/08-shortest-paths-exercises#exercise-85--reinserting-one-edge|Exercise 8.5]], where one edge is put back into a graph.
>
> ```text
> RepairDecrease(dist[1 .. V, 1 .. V], u→v, w′):
>     for every vertex x
>         for every vertex y
>             if dist[x, y] > dist[x, u] + w′(u→v) + dist[v, y]
>                 dist[x, y] ← dist[x, u] + w′(u→v) + dist[v, y]
> ```
>
> With $\infty + c = \infty$, a pair with $\mathit{dist}[x, u] = \infty$ or $\mathit{dist}[v, y] = \infty$ keeps its value.
>
> **Lemma.** If $w'(u\to v) < w(u\to v)$, then for all vertices $x, y$
> $$
> \delta'(x, y) = \min\{\delta(x, y),\ \delta(x, u) + w'(u\to v) + \delta(v, y)\}.
> $$
>
> *At most.* Only $u\to v$ changed, and it got lighter, so no walk is longer under $w'$ than under $w$. A shortest path from $x$ to $y$ for $w$ is thus a walk of $w'$-length at most $\delta(x, y)$; and if $\delta(x, u)$ and $\delta(v, y)$ are finite, a shortest path from $x$ to $u$, the edge $u\to v$ and a shortest path from $v$ to $y$ form a walk of $w'$-length at most $\delta(x, u) + w'(u\to v) + \delta(v, y)$. $\delta'(x, y)$ is at most the length of either walk.
>
> *At least.* If $\delta'(x, y) = \infty$, both sides are $\infty$. Otherwise let $P$ be a shortest simple path from $x$ to $y$ for $w'$. If $P$ avoids $u\to v$, it has the same length for $w$, so $\delta'(x, y) = w(P)\ge\delta(x, y)$. If $P$ uses $u\to v$, it uses it once: $P = P_1\cdot(u\to v)\cdot P_2$, where $P_1$ is a simple path from $x$ to $u$ and $P_2$ one from $v$ to $y$, and neither contains $u\to v$. So $w'(P_1) = w(P_1)\ge\delta(x, u)$ and $w'(P_2) = w(P_2)\ge\delta(v, y)$, and $\delta'(x, y) = w'(P)\ge\delta(x, u) + w'(u\to v) + \delta(v, y)$. $\square$
>
> **Updating in place is safe.** The loop reads only column $u$ and row $v$, and it never changes them: for $y = u$ the candidate is $\mathit{dist}[x, u] + \big(w'(u\to v) + \mathit{dist}[v, u]\big)$, and the bracket is the $w'$-length of a cycle $u\to v\leadsto u$ (the path from $v$ to $u$ avoids $u\to v$), which is $\ge 0$ because $w'$ creates no negative cycle; the same holds for $x = v$. So every entry is computed from old values, and by the lemma it ends up equal to $\delta'(x, y)$.
>
> **Time.** $V^2$ entries, $O(1)$ each: $O(V^2)$. That is optimal in the worst case: lowering one weight can change $\Theta(V^2)$ entries (lower $w(u\to v)$ from $M$ to 0 in the graph of (d)).
>
> **Example.** In the running example of [[2-algorithms/09-all-pairs-shortest-paths#91-introduction|Chapter 9]], suppose $w(2\to3) = 4$ was a typo for $w'(2\to3) = 2$ (the cycle $1\to2\to3\to4\to1$ then has length 0, which is allowed). Column 2 is $(-2, 0, -2, -5)$ and row 3 is $(0, -2, 0, 3)$, so for instance $\mathit{dist}[1, 4]\leftarrow\min\{5,\ -2 + 2 + 3\} = 3$ and $\mathit{dist}[4, 3]\leftarrow\min\{-1,\ -5 + 2 + 0\} = -3$. Six entries change, and the rows become $(0, -2, 0, 3)$, $(2, 0, 2, 5)$, $(0, -2, 0, 3)$, $(-3, -5, -3, 0)$ — what Floyd–Warshall computes from scratch.
>
> **Answer.** For all $x, y$, in place: $\mathit{dist}[x, y]\leftarrow\min\{\mathit{dist}[x, y],\ \mathit{dist}[x, u] + w'(u\to v) + \mathit{dist}[v, y]\}$; $O(V^2)$ time.

### (b) A lighter edge: is the old array still right? O(1)

> [!hint]- Hint
> Look at the entry $(u, v)$. If the corrected edge is no shorter than $\mathit{dist}[u, v]$, can it shorten anything?

> [!solution]- Solution
> **The idea.** By the lemma of (a), the cheapest way from $x$ to $y$ through the lighter edge costs $\delta(x, u) + w'(u\to v) + \delta(v, y)$. If $w'(u\to v)$ is at least the old distance from $u$ to $v$, this is at least $\delta(x, u) + \delta(u, v) + \delta(v, y)$, the length of a route the old array already took into account. So a single entry decides.
>
> **Algorithm.** Answer "correct" if $\mathit{dist}[u, v]\le w'(u\to v)$, and "wrong" otherwise: one comparison, $O(1)$ time.
>
> **Proof.**
> - *If $\mathit{dist}[u, v] > w'(u\to v)$, the array is wrong:* the edge $u\to v$ alone is a path of $w'$-length $w'(u\to v)$, so $\delta'(u, v)\le w'(u\to v) < \mathit{dist}[u, v]$.
> - *If $\mathit{dist}[u, v]\le w'(u\to v)$, the array is correct:* for all $x, y$, shortest paths from $x$ to $u$, from $u$ to $v$ and from $v$ to $y$ form a walk from $x$ to $y$, so
> $$
> \delta(x, u) + w'(u\to v) + \delta(v, y)\ \ge\ \delta(x, u) + \delta(u, v) + \delta(v, y)\ \ge\ \delta(x, y),
> $$
> and the lemma of (a) gives $\delta'(x, y) = \delta(x, y)$. $\square$
>
> In other words, the array is wrong exactly when the corrected edge $u\to v$ is **tense** for it ([[concepts/shortest-paths|tense edges]]): when the edge alone is a strictly shorter way from $u$ to $v$. Since $\mathit{dist}[u, v]\le w(u\to v)$, that always happens if $u\to v$ was a shortest path from $u$ to $v$, and otherwise only if the weight dropped far enough.
>
> **Example.** In the running example, $\mathit{dist}[3, 2] = -2$ (along $3\to4\to1\to2$) while $w(3\to2) = 1$. If the true weight of $3\to2$ is 0, or even $-2$, the array is still correct; if it is $-3$, it is wrong ($\delta'(3, 2) = -3$). For the typo of (a), $\mathit{dist}[2, 3] = 4 > 2$: wrong.
>
> **Answer.** The original array is correct if and only if $\mathit{dist}[u, v]\le w'(u\to v)$: $O(1)$ time.

### (c) Checking an array when the weight may have grown (harder)

> [!hint]- Hint
> Check the array one source at a time, as in [[2-algorithms/08-shortest-paths-exercises#exercise-80--checking-distances-and-predecessors|Exercise 8.0(a)]]. After an increase no edge is ever tense, so the test that matters is the other one: is every finite entry the length of an actual path?

> [!solution]- Solution
> **The idea.** A claimed distance can be wrong in two ways. *Too high:* then some edge is **tense** — one more edge beats the claimed value. *Too low:* then no path has that length, and this shows up as a vertex that cannot be reached from the source along **tight** edges. Ruling out both, for every source, proves the whole array correct. After a weight increase only the second kind of error can occur: every edge other than $u\to v$ kept its weight, and $\mathit{dist}[x, v]\le\mathit{dist}[x, u] + w(u\to v)\le\mathit{dist}[x, u] + w'(u\to v)$, so no edge is tense.
>
> ```text
> CheckAPSP(G, w′, dist[1 .. V, 1 .. V]):
>     for every vertex x
>         if dist[x, x] ≠ 0
>             return False
>         for every edge a→b
>             if dist[x, a] + w′(a→b) < dist[x, b]     ⟨⟨a→b is tense⟩⟩
>                 return False
>         T ← the vertices reachable from x along tight edges
>         if some vertex y ∉ T has dist[x, y] < ∞
>             return False
>     return True
> ```
>
> For the source $x$, an edge $a\to b$ is **tight** if $\mathit{dist}[x, a] < \infty$ and $\mathit{dist}[x, a] + w'(a\to b) = \mathit{dist}[x, b]$; $T$ is found by [[concepts/whatever-first-search|whatever-first search]] from $x$ in the subgraph of tight edges.
>
> **Correctness.** Fix a source $x$ and write $d(y) = \mathit{dist}[x, y]$. The three tests for $x$ pass if and only if $d(y) = \delta'(x, y)$ for every $y$; so CheckAPSP returns True if and only if the whole array is correct for $w'$.
>
> - *Correct labels pass.* $\delta'(x, x) = 0$. No edge $a\to b$ is tense: a shortest walk to $a$ followed by $a\to b$ is a walk to $b$. If $\delta'(x, y) < \infty$, take a shortest simple path from $x$ to $y$; every prefix of it is a shortest path, so all its edges are tight, and $y\in T$.
> - *Passing labels are not too high.* Along any walk $x = v_0\to v_1\to\cdots\to v_k$, no edge is tense, so $d(v_j)\le d(v_{j-1}) + w'(v_{j-1}\to v_j)$; by induction from $d(x) = 0$, $d(v_k)$ is at most the length of the walk. So $d(y)\le\delta'(x, y)$, and in particular $d(y) < \infty$ whenever $x$ reaches $y$.
> - *Passing labels are not too low.* If $d(y) < \infty$, then $y\in T$: a path $x = a_0\to a_1\to\cdots\to a_k = y$ of tight edges exists, and its equalities telescope to $d(y) = d(x) + \sum_j w'(a_{j-1}\to a_j)$, the length of a path from $x$ to $y$. So $d(y)\ge\delta'(x, y)$. If $d(y) = \infty$, the previous point says that $x$ does not reach $y$, so $\delta'(x, y) = \infty$ too.
>
> **Time.** For each source, one pass over the edges, one whatever-first search and one scan of the row: $O(V + E)$. In all $O(V(V + E))$ — the $O(VE)$ asked for, in the book's convention that $O(VE)$ stands for $V$ runs of an $O(V + E)$ algorithm ([[2-algorithms/09-all-pairs-shortest-paths#92-lots-of-single-sources|§9.2]]); the extra $V^2$ is the size of the array.
>
> **Faster: one search from $u$ is enough.** CheckAPSP never uses the fact that the array was correct for $w$. With it, only the entry $(u, v)$ matters.
>
> *Lemma.* The array is correct for $w'$ if and only if $\delta'(u, v) = \mathit{dist}[u, v]$.
>
> *Proof.* "Only if" is immediate, and so is $w' = w$. For "if": when $w' < w$, the lemma of (a) at $(u, v)$ gives $\delta'(u, v) = \min\{\mathit{dist}[u, v], w'(u\to v)\}$, so $\delta'(u, v) = \mathit{dist}[u, v]$ means $\mathit{dist}[u, v]\le w'(u\to v)$, and (b) applies. When $w' > w$, no walk is shorter under $w'$ than under $w$, so $\delta'\ge\delta$ everywhere. Conversely, let $x, y$ be vertices with $\delta(x, y) < \infty$ and $P$ a shortest simple path from $x$ to $y$ for $w$. If $P$ avoids $u\to v$, then $\delta'(x, y)\le w'(P) = w(P) = \delta(x, y)$. Otherwise $P = P_1\cdot(u\to v)\cdot P_2$, and the edge, a piece of a shortest path, is a shortest path itself: $w(u\to v) = \delta(u, v) = \delta'(u, v)$. Replace it by a shortest path $Q$ from $u$ to $v$ for $w'$: the walk $P_1 Q P_2$ has $w'$-length $w(P_1) + \delta'(u, v) + w(P_2) = w(P)$, so again $\delta'(x, y)\le\delta(x, y)$. $\square$
>
> *Testing $\delta'(u, v) = \mathit{dist}[u, v]$ after an increase.* Use row $u$ as prices, as in reweighting ([[2-algorithms/09-all-pairs-shortest-paths#93-reweighting|§9.3]]). For every edge $a\to b$ with $\mathit{dist}[u, a] < \infty$, its **slack** $\mathit{dist}[u, a] + w'(a\to b) - \mathit{dist}[u, b]$ is $\ge 0$, since no edge is tense. Along any path $P$ from $u$ to $v$ the slacks telescope: $w'(P) = \mathit{dist}[u, v] + (\text{the sum of the slacks of } P)$. So $\delta'(u, v) = \mathit{dist}[u, v]$ iff some path from $u$ to $v$ has slack 0 on every edge — iff a search from $u$ along the tight edges of row $u$ reaches $v$. (The edge $u\to v$ itself has slack $w'(u\to v) - \mathit{dist}[u, v]\ge w'(u\to v) - w(u\to v) > 0$; the search must find another way.) The whole test takes $O(V + E)$ time:
> - if $w'(u\to v)\le w(u\to v)$, test $\mathit{dist}[u, v]\le w'(u\to v)$, as in (b);
> - otherwise, search from $u$ along the edges $a\to b$ with $\mathit{dist}[u, a] < \infty$ and $\mathit{dist}[u, a] + w'(a\to b) = \mathit{dist}[u, b]$: the array is correct iff $v$ is reached.
>
> A shortcut: if the weight grew and $\mathit{dist}[u, v] < w(u\to v)$, the edge lay on no shortest path at all, and the array is correct without any search.
>
> **Example.** In the running example, raising the weight of $3\to2$ or of $4\to3$, by any amount, changes nothing: $\mathit{dist}[3, 2] = -2 < 1$ and $\mathit{dist}[4, 3] = -1 < 2$. Raising any of the other four edges, even by 1, makes the array wrong: each of them is the only path from its tail to its head. For $1\to2$, say, the new slack of $1\to2$ is $0 + (-1) - (-2) = 1$, and 1 has no other outgoing edge, so the search from 1 reaches nothing.
>
> **Answer.** CheckAPSP — for every source $x$: $\mathit{dist}[x, x] = 0$, no edge tense with $w'$, and every finite $\mathit{dist}[x, y]$ reached from $x$ along tight edges — decides correctness in $O(VE)$ time. Using that the array was right for $w$, one comparison (if the weight dropped) or one tight-edge search from $u$ (if it grew) suffices: $O(V + E)$.

> [!trap] Traps in Problem 1
> - **The repair rule of (a) cannot handle an increase.** A minimum only lowers entries; after an increase the entries that are too low stay too low.
> - **(b)'s test proves nothing after an increase:** $\mathit{dist}[u, v]\le w(u\to v) < w'(u\to v)$ always holds.
> - **"$\mathit{dist}[x, x] = 0$ and no edge is tense" does not make an array correct.** It rules out values that are too high, not values that are too low — and after an increase, the old array always passes it.
> - **The tight edges must be reachable from the source.** "Every finite entry has a tight incoming edge" is not enough when the graph has a cycle of length 0: in the figure, $v$ and $b$ prop each other up. > [!solution]- Solution
> **What "requires" can mean.** Nobody knows how to prove that all-pairs shortest paths need more than the $\Omega(V^2)$ time it takes to write the answer, and for general weights no algorithm running in $O(V^{3-\varepsilon})$ time, for a constant $\varepsilon > 0$, is known ([[2-algorithms/09-all-pairs-shortest-paths#97-funny-matrix-multiplication|§9.7]]). So the claim cannot be an unconditional lower bound. It is a **reduction**: any algorithm that repairs the array after an increase can be turned into an algorithm that computes all distances of an **arbitrary** graph from scratch, with $O(V^2)$ extra work. In the worst case, repairing is therefore exactly as hard as recomputing: any asymptotic speedup for repairing would be the same speedup for all-pairs shortest paths. (Recomputing from scratch is always possible, so repairing is not harder either.)
>
> **The construction.** Let $H$ be any directed graph with $n$ vertices, $m$ edges and nonnegative weights. Build $G$ from $H$ by adding
> - a vertex $u$, and an edge $x\to u$ of weight 0 from every vertex $x$ of $H$;
> - a vertex $v$, and an edge $v\to y$ of weight 0 to every vertex $y$ of $H$;
> - the edge $u\to v$, with wrong weight $w(u\to v) = 0$ and correct weight $w'(u\to v) = M$, where $M$ is 1 plus the sum of all weights of $H$.
>
> $G$ has $n + 2$ vertices and $m + 2n + 1$ edges, all of nonnegative weight under both weightings, so there is no negative cycle.
>
> - **The old array is all zeros.** With $w(u\to v) = 0$, every vertex of $G$ reaches every vertex at cost 0 (for instance $x\to u\to v\to y$), and no distance is negative. So the old array is written down without looking at $H$, in $O(n^2)$ time — it carries no information about $H$.
> - **The corrected array contains $H$'s distances.** For vertices $x, y$ of $H$, a path from $x$ to $y$ in $G$ either stays inside $H$ or passes through $u$ (the only way into $v$ is from $u$); then it continues along $u\to v$, the only edge out of $u$, and costs at least $M$, while $x\to u\to v\to y$ costs exactly $M$. So $\delta'(x, y) = \min\{\delta_H(x, y), M\}$. Every finite $\delta_H(x, y)$ is the length of a simple path, at most the total weight of $H$, which is less than $M$. Hence $\delta_H(x, y) = \delta'(x, y)$ if $\delta'(x, y) < M$, and $\delta_H(x, y) = \infty$ if $\delta'(x, y) = M$.
>
> **The reduction.** Given $H$, build $G$ and its all-zero array in $O(n^2 + m)$ time, run the repair algorithm, and decode the entries between vertices of $H$ in $O(n^2)$ time. If repairing took $T(V, E)$ time, all-pairs shortest paths with nonnegative weights would take $T(n + 2, m + 2n + 1) + O(n^2 + m)$ time. For instance, an $O(V^2)$ repair like the one in (a) would compute all distances of a dense graph in $O(n^2)$ time — linear in the size of the input — while the best algorithms known for dense graphs take nearly $n^3$. (If $H$ has negative edges but no negative cycle, first reweight it with Johnson's prices, [[2-algorithms/09-all-pairs-shortest-paths#94-johnsons-algorithm|§9.4]], at the cost of one single-source computation; the distances convert back in $O(n^2)$ time.)
>
> **Why the two directions differ.** After a decrease, every old shortest path is still available, and the only new candidates use the lighter edge once — (a). After an increase, the old shortest paths through $u\to v$ may all become useless, and the array has no record of the second-best paths. In the construction, every old distance between vertices of $H$ is 0, the length of the route through $u\to v$, and the second-best paths are all of $H$. (Deciding *whether* anything changed is still cheap — (c).)
>
> **Example.** In the figure, $H$ has the edges $p\to q$ (2), $q\to r$ (1) and $r\to q$ (3), so $M = 7$. The old array is all zeros; the repaired one has $\delta'(p, q) = 2$, $\delta'(p, r) = 3$, $\delta'(q, r) = 1$ and $\delta'(r, q) = 3$, the distances in $H$, and $\delta'(q, p) = \delta'(r, p) = 7 = M$: $q$ and $r$ cannot reach $p$ in $H$.
>
> **Answer.** Add to an arbitrary graph $H$ (nonnegative weights) a vertex $u$ with 0-edges from all of $H$, a vertex $v$ with 0-edges to all of $H$, and $u\to v$ with wrong weight 0 (old array: all zeros) and true weight $M > $ the total weight of $H$ (new array between vertices of $H$: $\min\{\delta_H, M\}$). Any repair algorithm thus computes all distances of $H$, so in the worst case repairing is no faster than recomputing from scratch.

## Problem 2 — Arbitrage

> [!note] How we read Problem 2
> - An **arbitrage cycle** is a cycle of distinct currencies $c_1\to c_2\to\cdots\to c_k\to c_1$, $k\ge 2$, whose rates multiply to **more than 1**; a product of exactly 1 is not arbitrage. A round trip with product $> 1$ that repeats a currency contains an arbitrage cycle: split it at the repeated currency into two round trips, and one of them has product $> 1$.
> - Trading a currency for itself is pointless, so we ignore the diagonal $R[i, i]$. (If $R[i, i] > 1$ were possible, that single trade would itself be arbitrage: check the diagonal first, in $O(n)$ time.)
> - A rate $R[i, j] = 0$ means the trade is worthless: it is not an edge. All other rates are positive.
> - Trades are linear and unlimited, so splitting the money among several routes never beats putting all of it on the best one: $\mathit{MaxCurrency}[i]$ is the best product of rates over all sequences of trades from currency 1 to currency $i$.

### (a) The most of each currency, without arbitrage

> [!hint]- Hint
> Logarithms turn products into sums, and a minus sign turns "most" into "shortest".

> [!solution]- Solution
> **The idea.** A sequence of trades $1 = c_0\to c_1\to\cdots\to c_k = i$ turns one unit of currency 1 into $\prod_{t=1}^{k} R[c_{t-1}, c_t]$ units of currency $i$. Give the trade $c\to c'$ the length $-\ln R[c, c']$. Then the product is $e^{-L}$, where $L$ is the total length, and since $e^{-L}$ shrinks as $L$ grows, **the most money is the shortest walk**. A rate above 1 has negative length, so Dijkstra is out; Bellman–Ford is the right tool.
>
> - **Vertices.** The $n$ currencies.
> - **Edges.** Directed: $i\to j$ for every $i\ne j$ with $R[i, j] > 0$ — the complete directed graph if every rate is positive; at most $n(n-1)$ edges.
> - **Values.** $w(i\to j) = -\ln R[i, j]$, of either sign.
> - **Relationship.** Sequences of trades from currency 1 to currency $i$ are exactly the walks from 1 to $i$, and a walk $W$ turns one unit into $e^{-w(W)}$ units. A cycle has product $> 1$ iff its length is negative, so without arbitrage there is no negative cycle, and the shortest walk from 1 to $i$ is a shortest path, of length $\textsf{dist}(1, i)$. Hence $\mathit{MaxCurrency}[i] = e^{-\textsf{dist}(1, i)}$, with $e^{-\infty} = 0$ for a currency that cannot be obtained at all, and $\mathit{MaxCurrency}[1] = e^0 = 1$: every round trip loses money or breaks even.
> - **Algorithm.** Bellman–Ford from vertex 1 ([[2-algorithms/08-shortest-paths#87-relax-all-the-edges-bellmanford|§8.7]]), then $\mathit{MaxCurrency}[i]\leftarrow e^{-\textsf{dist}(1, i)}$ for every $i$.
> - **Time.** Building the graph $O(n^2)$; Bellman–Ford $O(VE) = O(n\cdot n^2) = O(n^3)$; converting $O(n)$. In all, $O(n^3)$.
>
> **Without logarithms.** Bellman–Ford can run on the amounts themselves, through the order-reversing map $d\mapsto e^{-d}$: start with $\mathit{amt}[1] = 1$ and $\mathit{amt}[i] = 0$ for $i\ne 1$; then $n - 1$ times, for every pair $i\ne j$, if $\mathit{amt}[i]\cdot R[i, j] > \mathit{amt}[j]$, set $\mathit{amt}[j]\leftarrow\mathit{amt}[i]\cdot R[i, j]$. A zero rate never passes the test, so it needs no special case, and with exact fractions nothing is rounded (see the traps).
>
> **Example.** In the figure's market, change the euro-to-dollar rate from 1.2 to 0.8. Then every cycle has product at most 1 (dollar → yen → euro → dollar now gives $120\cdot0.01\cdot0.8 = 0.96$), and starting with one dollar, $\mathit{MaxCurrency} = (1, 120, 1.2)$ for (dollar, yen, euro): the direct trade gives only 0.8 euros, the detour through yen $120\cdot0.01 = 1.2$.
>
> **Answer.** Edge weights $-\ln R[i, j]$ on the directed graph of currencies; Bellman–Ford from currency 1, and $\mathit{MaxCurrency}[i] = e^{-\textsf{dist}(1, i)}$ (0 if unreachable): $O(n^3)$ time.

### (b) Is there an arbitrage cycle?

> [!hint]- Hint
> An arbitrage cycle is a negative cycle — but it need not pass through currency 1, or even be reachable from it. Where should Bellman–Ford start?

> [!solution]- Solution
> **The idea.** By the relationship in (a), an arbitrage cycle is exactly a **negative cycle** of the currency graph, anywhere in it. Bellman–Ford detects the negative cycles that its source can reach, and a new source with an edge of weight 0 to every currency reaches them all. In money terms: start with one unit of *every* currency.
>
> - **Vertices.** The $n$ currencies and a new vertex $s$.
> - **Edges.** Directed: the edges of (a), and $s\to i$ for every currency $i$.
> - **Values.** $w(i\to j) = -\ln R[i, j]$ as in (a), and $w(s\to i) = 0$ (rate 1).
> - **Relationship.** The rates create an arbitrage cycle iff the currency graph has a negative cycle. No edge enters $s$, so $s$ lies on no cycle and the cycles are those of the currency graph; and $s$ reaches every vertex. So there is arbitrage iff a negative cycle is reachable from $s$.
> - **Algorithm.** Bellman–Ford from $s$ ([[2-algorithms/08-shortest-paths#87-relax-all-the-edges-bellmanford|§8.7]]): after $V - 1 = n$ rounds, report arbitrage iff some edge is still tense.
> - **Time.** $n + 1$ vertices and $O(n^2)$ edges: $O(n^3)$.
>
> If every rate is positive, the graph is complete and currency 1 already reaches every cycle; the new source is what handles zero rates. **Alternatively,** run Floyd–Warshall on the currency graph and report arbitrage iff some diagonal entry ends negative ([[2-algorithms/09-all-pairs-shortest-paths#98-floydwarshall|§9.8]], negative-cycle detection), also $O(n^3)$ — or, in max-product form, $M[i, j]\leftarrow\max\{M[i, j],\ M[i, r]\cdot M[r, j]\}$ with $M[i, i] = 1$ and $M[i, j] = R[i, j]$ at the start, and arbitrage iff some $M[i, i] > 1$ at the end.
>
> **Answer.** Arbitrage cycles are the negative cycles of the $-\ln R$ graph: Bellman–Ford from a new source with 0-weight edges to every currency (or Floyd–Warshall's diagonal) detects one in $O(n^3)$ time.

### (c) Returning an arbitrage cycle (harder)

> [!hint]- Hint
> Keep predecessor pointers. If a trade is still tense after the last round, make it once more and walk back along the pointers. Can the walk ever run out?

> [!solution]- Solution
> **The idea.** Bellman–Ford with predecessor pointers can hand over its negative cycle: after the last round, relax a still-tense edge and walk back $V$ predecessor pointers from its head. The walk cannot run out, so it ends on a cycle of pointers, and every cycle of pointers is negative ([[2-algorithms/08-shortest-paths-exercises#exercise-86--bellmanford-with-certificates|Exercise 8.6(a)]]; the same walk appears in [[2-algorithms/09-all-pairs-shortest-paths-exercises#exercise-93--returning-a-negative-cycle|Exercise 9.3]]). Here it is with amounts instead of logarithms: $\mathit{amt}[i] = e^{-\mathit{dist}(i)}$, "tense" becomes $\mathit{amt}[i]\cdot R[i, j] > \mathit{amt}[j]$, and starting every amount at 1 is the new source $s$ of (b) after its first round, with a $\textsf{Null}$ pointer standing for $s$.
>
> ```text
> ArbitrageCycle(R[1 .. n, 1 .. n]):
>     for every currency i
>         amt[i] ← 1;  pred[i] ← Null               ⟨⟨one unit of every currency⟩⟩
>     repeat n − 1 times
>         for all currencies i ≠ j
>             if amt[i] · R[i, j] > amt[j]           ⟨⟨trade i→j is tense⟩⟩
>                 amt[j] ← amt[i] · R[i, j];  pred[j] ← i
>     for all currencies i ≠ j
>         if amt[i] · R[i, j] > amt[j]
>             amt[j] ← amt[i] · R[i, j];  pred[j] ← i
>             x ← j
>             repeat n times
>                 x ← pred[x]
>             list x, pred[x], pred[pred[x]], … until x comes up again
>             return the list in reverse order          ⟨⟨trading order⟩⟩
>     return "no arbitrage"
> ```
>
> **Why it is correct.** Write $\mathit{dist}(i) = -\ln\mathit{amt}[i]$: this is Bellman–Ford on the graph of (a), with every label starting at 0.
> - *Every label is the length of a walk that ends at its vertex* (the empty walk at the start), and *after $k$ rounds, $\mathit{dist}(j)$ is at most the length of every walk with at most $k$ edges that ends at $j$*, wherever it starts — the induction of Lemma 8.6 ([[2-algorithms/08-shortest-paths#87-relax-all-the-edges-bellmanford|§8.7]]) with every start label 0.
> - *No arbitrage, no cycle returned.* Without negative cycles, the shortest walk ending at $j$ is a path (possibly empty) with at most $n - 1$ edges. After $n - 1$ rounds $\mathit{dist}(j)$ is at most its length, while $\mathit{dist}(i) + w(i\to j)$, the length of a walk ending at $j$, is at least it. So no trade is tense in the last pass.
> - *Arbitrage: a tense trade is found.* All labels are finite. If no edge of a negative cycle $C$ were tense, adding $\mathit{dist}(j)\le\mathit{dist}(i) + w(i\to j)$ around $C$ would give $0\le w(C) < 0$.
> - *The walk back ends on an arbitrage cycle.* As in Exercise 8.6(a), every pointer satisfies $\mathit{dist}(j)\ge\mathit{dist}(\mathit{pred}[j]) + w(\mathit{pred}[j]\to j)$ at all times, and every cycle of pointers is negative. If the pointers from $j$ led to a currency $r$ with $\mathit{pred}[r] = \textsf{Null}$ (so $\mathit{dist}(r) = 0$), they would form a simple path $Q$ from $r$ to $j$ with at most $n - 1$ edges, and the inequalities along $Q$ would give $\mathit{dist}(j)\ge w(Q)$; but $\mathit{dist}(j)$ was at most $w(Q)$ after $n - 1$ rounds, and the last relaxation lowered it. So the pointers never run out; at most $n - 1$ steps from $j$ lead onto a cycle of pointers, so after $n$ steps $x$ is on it. That cycle is negative: an arbitrage cycle. Each pointer goes from a currency back to the one it was bought with, so the list, reversed, is in trading order.
>
> **Time.** $n - 1$ rounds of $n(n - 1)$ tests, one more pass, and $O(n)$ for the walk: $O(n^3)$. With Floyd–Warshall instead, keep its predecessor pointers and use [[2-algorithms/09-all-pairs-shortest-paths-exercises#exercise-93--returning-a-negative-cycle|Exercise 9.3(b, c)]], also $O(n^3)$.
>
> **Example.** On the figure's market, with the currencies in the order dollar, yen, euro, the amounts start at $(1, 1, 1)$ and are $(1.44, 120, 1.2)$ after round 1 and $(2.0736, 172.8, 1.728)$ after round 2 — each lap around the cycle multiplies them by 1.44. In the test pass, the trade dollar → yen is still tense ($2.0736\cdot120 = 248.832 > 172.8$). Three steps back from yen visit dollar, euro and yen again; the list yen, dollar, euro, reversed, is the cycle euro → dollar → yen → euro — the handout's cycle, starting at the euro.
>
> **Answer.** Bellman–Ford with predecessor pointers from a virtual source (every amount starts at 1); on a trade still tense after $n - 1$ rounds, make it and walk back $n$ pointers; the pointer cycle reached, read backward, is an arbitrage cycle: $O(n^3)$ time.

> [!trap] Traps in Problem 2
> - **Dijkstra does not apply:** a rate above 1 is a negative weight, and the graph has cycles. The black box is Bellman–Ford (or Floyd–Warshall).
> - **Mind the sign.** Shortest paths minimize, and we want the largest product: the weight is $-\ln R[i, j]$, not $\ln R[i, j]$ — and not $R[i, j]$, which would add rates instead of multiplying them.
> - **Arbitrage anywhere, not only through currency 1.** With zero rates, Bellman–Ford from currency 1 sees only the cycles it can reach. Use the new source — one unit of every currency — or Floyd–Warshall.
> - **A product of exactly 1 is not arbitrage.** It is a cycle of length 0, not a negative one — yen → euro → yen in the figure. Every test must be strict.
> - **Floating point.** Logarithms are rounded: the rates $1/6$, 2 and 3 multiply to exactly 1, but in double precision $-\ln(1/6) - \ln 2 - \ln 3$ comes out as about $-2.2\cdot10^{-16}$, a phantom arbitrage. Compare against a small tolerance, or run the max-product version with exact fractions.

> [!exam] On the exam
> Problem 2 is a textbook graph reduction, graded by the [[0-toolkit/06-how-exams-are-graded#13-graph-reductions|graph-reduction rubric]]: the graph — one vertex per currency, **directed** edges, weights $-\ln R[i, j]$ —, the relationship — the best amount is $e^{-\text{distance}}$, and arbitrage is a negative cycle —, Bellman–Ford (or Floyd–Warshall) invoked as a black box, never Dijkstra, and the time $O(n^3)$ in terms of $n$. Problem 1 is not a reduction but a set of algorithms *about* a distance array, and the points are in the proofs: that a shortest path uses $u\to v$ at most once, that column $u$ and row $v$ never change, and both directions of every "if and only if".
